# 指挥官统一三级LOD — 实施与接入约定

## 2026-09-30：爆炸消费者补齐（源码待编译）

法术场激活爆炸和单位死亡爆炸接入同一策略，现有逐视图总览遮罩处理已经生成的爆炸；静态检查与地图相关实体/引用回读完成，新修复尚未构建或进入PIE。当前用户PIE保持运行，原先导弹有限验收不能当作本次修复通过。[实现、现场证据与验收步骤](20260930-指挥官三档镜头与总览LOD.md#2026-09-30第二档爆炸缺失修复源码待编译)。

## 实现与所有权

均位于既有GuLiStrike运行时模块，无新增模块依赖，无资产类迁移。依赖方向为表现消费者→公共LOD服务→纯C++策略类型/引擎视图接口；公共服务不引用导弹或创建特效。

| 归属 | 实现 | 责任 |
|---|---|---|
| 公共策略 | `Commander/Presentation/GuLiCommanderLODPolicy.h/.cpp` | Full=0、Reduced=1、Minimal=2；阈值、配置约束、查询结果及消费者统计结构 |
| World服务 | `UGuLiCommanderLODSubsystem` | 客户端Game/PIE World创建，专用服务器不创建；每帧缓存本地视图并计算结果，持有基线和临时覆盖 |
| 调试入口 | `GuLiCommanderLODCommands.cpp` | 非Shipping的List/Get/Set/Reset/Stats，全部解析调用命令的World |
| 首批消费者 | `UGuLiMissileClusterPresentation` | 上报完整包围盒，使用公共判断；自行执行预算、专用裁剪、交接与生命周期 |
| 验证入口 | `GuLiMissileFixture.cpp`及场景脚本 | 扩展已有Camera命令的lod0/lod1/lod2参数，复用真实F4和六组发射场景 |

纯C++策略/查询/统计类型不增加反射或网络字段，只有WorldSubsystem使用UCLASS。`GuLiCombatEffectPresentationSubsystem`显式初始化LOD依赖；公共服务不可用时导弹池就绪判断返回false，沿用旧飞行表现。

## 公共配置与决策

`Config/DefaultGame.ini`的`[GuLiCommanderLOD]`集中提供以下键：

| 键 | 默认值 |
|---|---|
| `near.enter_distance_cm` / `near.hold_distance_cm` | 7200 / 8800 |
| `near.enter_screen` / `near.hold_screen` | 0.012 / 0.008 |
| `mid.enter_distance_cm` / `mid.hold_distance_cm` | 14000 / 16000 |
| `mid.enter_screen` / `mid.hold_screen` | 0.003 / 0.002 |
| `minimum_residence_seconds` | 0.35 |

距离为相机到完整包围盒的最近距离；尺度为包围盒半径/最近距离乘投影缩放，沿用当前导弹公式，并非精确屏幕像素占比。每个可见视图单独分级后取最高细节，避免把一个视图的距离与另一个视图的尺度拼接成不存在的近景。

先判断LOD0再判断LOD1；当前实际LOD0使用近档保持阈值，当前LOD0/1使用中档保持阈值。新分配或重新入镜立即选档，既有对象通过`bCanTransition`遵守最短驻留。视锥裁剪不受驻留延迟约束。公共服务没有200米硬裁剪。

配置来源顺序为CppDefault→Config→LocalOverride。数值必须有限非负，距离阈值有序，尺度阈值反向有序；非法启动配置组回退编译默认值，非法临时改动不提交。Reset单键若与其他覆盖产生冲突则拒绝，Reset all恢复整组基线。覆盖不写盘，World销毁即清除。

## 后续消费者接入约定

1. 通过当前World获取`UGuLiCommanderLODSubsystem`，提交`FGuLiCommanderLODQuery`，包含位移后几何、特效历史和退场部分的完整包围盒、当前实际档位和上次实际切换的World时间。
2. 读取`Evaluate`返回的可见性、目标档位、距离、投影尺度和原因。公共策略输出与具体资源预算分离；实现自己的三级映射，不复制距离/尺度阈值到消费者。
3. 按`bCanTransition`及自身过渡资源条件切换；成功后才更新实际档位和时间。资源不足可降低实际细节，同时报告预算限制。导弹、模型、血条的资源量纲不合并成一个容量。
4. 每帧用稳定消费者名提交完整`ReportConsumer`快照；消费者重置、局次变化或退出时`ClearConsumer`，自身对象代次/历史同步清理。服务销毁清除视图、配置覆盖和所有消费者统计。

首个消费者名为`WM01MissileBatches`，统计单位是空间批次。`Target[0/1/2]`为公共目标，`Applied[0/1/2]`为实际组件档位；另列无视图、视锥、非法包围盒、距离/尺度裁剪、预算限制、等待交接和资源未就绪。每份快照标记帧号，Stats显示其年龄，不把旧快照作为当前测量。

单位模型、升级特效、悬浮和血条本轮未迁入；它们后续优化统一采用上述入口。已有单位“远距离不消失”规则和网格自身LOD保持；全局三级是表现策略，不等于把四级网格资源删成三级。

## 导弹适配及当前资产基线

公共Full/Reduced/Minimal显式转换为既有Niagara质量2/1/0，即24/8/0段烟迹。旧私有视图采样、72/88/140/160米阈值和0.35秒驻留常量已从导弹池移出。

9月29日用户明确保留v2的2.4秒寿命和1.5倍尺寸；后续导弹v3已独立完成烟迹/尾焰尺寸表驱动。9月30日接续时沿用当前Projectiles表及既有原生解析，不回退视觉参数。烟迹寿命2.4秒、0.15秒交接、2.45秒退场回收、历史与退场包围盒、代次隔离及自然消散保持；包围盒扩展现随表中尺寸计算。当前视觉参数见[消费者资产回读](../../Artifacts/CommanderLOD/20260930/consumer-assets-readback.json)，数值与v3更改依据归[原导弹任务](20260929-重防号导弹解锁与肉鸽卡牌.md)。本轮没有改写这些数值、材质图或正式资产开关。

导弹池继续自管64枚/批、512条完整烟迹、65536粒子容量，历史和退场资源计入预算；最低弹体资源预留规则保留。`gs.MissileCluster.Distance`默认20000cm与`MinScreenFraction`默认0.001仍属导弹专用裁剪。`FullTrails`、`Particles`及候选开关仍由原导弹入口管理。
