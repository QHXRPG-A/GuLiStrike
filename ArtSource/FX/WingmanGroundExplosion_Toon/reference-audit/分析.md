# 动漫爆炸样板与现有资源的差距

2026-09-16。只读审查；未修改、保存参考资源或当前游戏资产。

## 结论

上一版的制作方法把“动漫、低模、简约纹理”压缩成了“低面数球体 + 分段颜色 + 整体缩放”，丢掉了爆炸最重要的形态演变、分层时序和火焰内部动画。偏差主要来自视觉方案与制作流程，不能归因于 UE、CPU 模拟或低粒子数限制。

简约纹理允许少量精心制作的动画贴图和遮罩。完全不用贴图并不是本次参考要求；这是制作时过度简化的选择。预先围绕 4 发射器、22 粒子构造方案，也让视觉验证晚于预算取舍。

## 实际检查范围

两个目录各登记 25 个 Niagara System。深入检查第一套 `NS_Explosion_01 / 12 / 25`，第二套 `N_Stylized_Explosion_1A_Classic_Explosion / 4B_With_Gradient / 5A_Classic_Explosion`，包括发射器、模块、RI 参数、渲染器、材质实例和父材质图；阶段截图抽查其中 5 个。

原始读取：`inventory.json`、`systems.json`、`renderer-ri.json`、`materials.json`、四份 `*.graph.json`。结论仅推广到已检查样本，不声称完整审查 50 个系统。

## 两种已证实的制作路线

| 项目 | 第一套 NS_Explosion_01 | 第二套 1A / 4B / 5A | 当前样板 |
|---|---|---|---|
| 结构 | 18 个 CPU 发射器；Cloud、Core、Glow、Bullet、Dust、Ground 等分工 | 抽查各 3 个 CPU 发射器：Explosion_Flipbook、Distortion、OmnidirectionalBurst | 4 个 CPU 发射器 |
| 主体 | 多层 Mesh 烟团与内核，混合 Sprite 辅助层 | 主爆炸由 1 个 Sprite 粒子播放 Flipbook | 8 个相同团块的缩放与颜色变化 |
| 形态 | Mesh 朝向/旋转、尺寸与速度曲线，材质 WPO 位移 | 贴图各帧包含轮廓与内部结构变化 | 膨胀后形状基本固定，最后收缩 |
| 材质 | M_MasterCloud_01：Masked、Unlit、火焰遮罩、噪声溶解、可选分色、WPO | M_Stylized_Explosion：Unlit、Translucent；动画相位、RGBA 通道和独立颜色控制 | 法线分色、视线角度边缘色、末段简单三角函数溶解 |
| 烟火过渡 | 可移动阈值改变燃烧区域，烟团与内核同时存在 | RGB 分别参与轮廓、烟色、火焰计算；Alpha 提供透明度 | 八团同龄，同步整体从火色变烟色 |

第一套材质的实际节点链：`Noise → VertexNormalWS → WPO_Str → DynamicParameter → WorldPositionOffset`，同时接有 `Time + ParticleRandom`、`WPO_Speed`；表示顶点本身持续运动。火焰区域通过 SphereMask/Step 与动态 `Explosion_Mask` 参数控制。存在 `MF_Posterize` 分色色阶与开关，但并非所有实例都会启用所有功能。

第二套材质用 DynamicParameter 的 `Animation` 驱动引擎 FlipBook 函数。1A 的行列配置为 6×6，5A 为 8×8；这些是图集格数，不能仅凭格数断言有效动画帧全部非空。SplitComponents 中 G 参与烟色混合，B 参与火焰颜色/发光，R 与 Alpha 组合生成轮廓遮罩。轮廓并不需要额外网格壳。

## 需要补齐并实际应用的知识

1. **爆炸动画的节奏与构图。** 起爆压缩、快速扩张、局部续燃、烟团翻卷、消散应有先后；不同区域需要不同相位。当前只有总体尺寸曲线，同龄团块看上去像同一块物体在膨胀。
2. **Flipbook 与通道打包。** 烟火动画预制到贴图中，颜色/明暗/轮廓/透明度可以独立重映射；序列帧并不意味着必须使用写实火焰。它能让很少的粒子承载丰富的动画。
3. **3D 烟团的形态动画。** 掌握平滑法线、圆润的主次轮廓、非均匀缩放、旋转、受控顶点位移，以及少量粒子的时间错开。当前硬折面和视角边缘条带容易被读成岩石裂纹。
4. **Niagara 与材质的联合驱动。** 动态参数同时控制燃烧阈值、烟色、位移幅度、发光与溶解。当前的年龄混色让火焰整团退色，缺少火区在烟团表面迁移、分裂的过程。
5. **明度层次和边缘设计。** 奶黄高亮核心、橙红热边、暗烟的遮挡需要空间分工；轮廓粗细应有主次，不能用统一视角阈值替代所有烟火轮廓。Bloom 可增强光感，但不能代替内部动画，也无需新增动态灯。
6. **面向视觉目标的优化。** 贴图采样数、发射器数、粒子数都只是成本的一部分。还需要考虑透明覆盖、像素着色复杂度、材质/渲染器批次、CPU 实例成本和回收。第一套的多层系统与程序噪声不宜整包照搬；第二套仅 3 发射器也不能单凭数量断言便宜。

## 制作流程应调整的位置

- 在确定实现方案前，先用项目中的成熟参考拆解“哪个层产生哪种观感”。上一版没有先做这一步。
- 优先把一颗爆炸的主轮廓、火区变化和三个阶段做到接近目标，再压缩次要层；预算应保住最关键的动画信息。
- 针对原先俯视、奶黄火球和块状烟团的目标，优先借鉴 `NS_Explosion_01 / M_MasterCloud_01` 的 3D 烟火转换方法；再评估第二套通道动画作为火焰补充或远景版本。此判断是基于构图与视角的制作建议，尚未做同条件性能对照。
- 保留 4 个发射器的目标仍可探索：火烟层内部区分不同年龄/随机相位，并采用材质动画或小图集；不需要为了改善动画直接增加到 18 个发射器。
- 接受标准应包含起爆、峰值、转烟、消散的连续播放。编译成功与接入成功不足以判定美术达标。

## 证据限制

阶段截图位于 `frames/`，为直接 UE SceneCapture。各资产用不同取景距离便于观察内部结构，因此不用于直径或性能对比。参考组件的 Preview LOD Distance 临时设为 0，避免原资产的距离裁剪；检查用地面下移以避免遮挡动画。第二套图集暂时请求完整 mip 驻留，未更改纹理资产设置。材质中的 Time 节点仍使用世界时间，所以这些截图不构成完全锁定随机相位的性能基准。

所有临时检查演员在完成后销毁；没有修改场景光照或全局渲染设置。
