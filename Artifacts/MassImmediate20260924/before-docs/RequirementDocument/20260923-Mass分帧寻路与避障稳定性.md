# Mass分帧寻路与避障稳定性

## 已确认行为

- 手动移动、自动推进、导航修复及个人恢复共享规划预算。完成一批后在10Hz权威边界提交；未完成成员继续原指令。
- 规划默认2ms/世界帧，位置与连接校验最多64次、路径查询最多4次；提交0.5ms且最多100成员。单次引擎查询不可抢占，超预算需记录。
- 规划按最多25人处理；保留未提交成员旧预约。改令、停止、死亡、运输和导航代次变化不能复活旧结果。默认无进展5秒、总计30秒超时。
- 复用v19可靠状态流、1000字节批次及4批在途窗口；终点与命令状态配对，客户端绘制等待不阻塞网络确认。
- 已选中、存活、正在执行的成员显示命令起点到最终终点的绿色细线；每帧维护最多128条或0.5ms。旧线失效优先处理，相机移动不需要重新计算终点。
- 校验lane与slot目标，环境障碍参与预测，绕行侧保持滞回；贴障降速，前方受阻衰减归位修正，以真实位移回写速度。

## 验收

- [ ] 首批无需等待整条命令；无预算旁路、重复提交或预约冲突。
- [ ] 绿线分批出现、持续显示，停止/到达/改令后不复活。
- [ ] 建筑拐角、窄通道、矿体及机甲旁不持续顶撞；不可达成员稳定失败。
- [ ] 覆盖25/500/2000移动及10000选择容量处理、连续改令、重连和导航重建。

实施交付已完成源码静态检查与场景保存/实体数据核对；用户随后授权的源码版Editor编译及BuildId核对通过，玩家效果尚未验证。专项部署曾阻塞PIE，现已移除并恢复红蓝各250名默认军队；500/2000/10000单方规模的合法部署入口尚未完成，当前场景和具体验收点见[开发记录](../DevelopmentDocumentation/20260923-Mass分帧寻路与避障稳定性.md)。上方效果验收复选框保留待验收。

后续玩家已报告首条绿线近1秒，服务端日志首批等待705～3992ms。当前PIE的60秒现场采样与源码诊断定位到共享查询次数额度饱和和全局失效重算机制，详见[诊断归档](../Archive/20260923-Mass首条绿线延迟现场诊断.md)。本次尚未实施响应优化；原有预算、同步及合法性要求不变，不能把编译和场景前置检查通过当作响应验收通过。
