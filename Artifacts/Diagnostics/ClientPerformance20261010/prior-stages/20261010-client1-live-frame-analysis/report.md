# Client1 当前实战 PIE 截帧分析

当前平均帧率主要受游戏线程限制。30 秒采样平均 **30.11 FPS**；整帧 33.21 ms、游戏线程 33.18 ms、GPU 12.97 ms。

| 指标 | 平均 | P95 |
|---|---:|---:|
| 整帧 | 33.21 ms | 40.86 ms |
| 游戏线程 | 33.18 ms | 40.80 ms |
| GPU | 12.97 ms | 14.59 ms |

## 测量范围

用户授权解除当前暂停并分析 Client1。本轮通过编辑器 Pause 快捷键继续原 PIE，没有重启 PIE、启动压力入口、停用优化、修改质量、移动镜头或写入游戏资源。捕获时 Client1 为 **1505×1115**，Client2 为 **640×484**，两个窗口的镜头及分辨率在测量前后完全相同。首次暂停探测时 Client1 为 2353×1640；本轮结果按采样时的实际尺寸记录，不将不同尺寸的结果混用。

当前是一个编辑器进程承载专服、双客户端及编辑器 World。CSV/整帧 GT/GPU 是进程口径，不能把 33.18 ms 全部归到 Client1。项目计时按 World/LocalPlayer 分开保存。CSV 有 905 帧，QPC 时间窗内 902 个完整引擎帧用于 Insights 分析；计时资格通过。这是当前实战诊断，未执行三轮配对或此前 600移动单位/500弹丸的固定压力矩阵，不能据此计算累计优化收益。

## 持续热点

原生 UWorld Tick 的平均累计成本约 **23.40 ms/引擎帧**。完整帧分组后，服务器分支平均 **12.61 ms**，两个客户端分支平均 **5.55/4.97 ms**。服务器身份由其权威逻辑子事件确认；CPU 的两个客户端 UWorld Scope 没有 World 元数据，保留分支 A/B，不依据 Tick 顺序伪造 Client1 专属总耗时。

窗口 Slate 布局与绘制平均 **5.26 ms**，其中 Prepass 平均 1.94 ms，PaintSlowPath 包含子项平均 2.90 ms。该成本包含编辑器和两个游戏窗口。Client1 场景 UI 自身 Update/Paint 分别仅约 **0.294/0.406 ms**，不能将全部 Slate 时间归因于场景 UI 缓存。

| Scope | 平均包含子项 ms/帧 | 平均独占 ms/帧 | 最大单次 ms |
|---|---:|---:|---:|
| 全窗口 Slate 布局/绘制 | 5.262 | 0.013 | 8.171 |
| 服务器 Mass StateTree | 1.558 | 1.558 | 7.866 |
| 采矿/建造车辆 CharacterMovement | 2.091 | 1.516 | 0.506 |
| 服务器与双客户端网络 Tick | 2.750 | 0.915 | 4.935 |
| 两个客户端单位插值 | 0.838 | 0.783 | 1.093 |
| 避障候选查询 | 0.566 | 0.566 | 2.893 |
| 批量命中特效 Niagara 系统 | 0.019 | 0.018 | 0.117 |

表中包含子项时间存在嵌套，不能相加。CharacterMovement 在普通/P95帧中均为 102 次调用：每个 World 34 次，与场内 16 采矿车、18 建造车一致。工厂门 `SK_RPF_Door` 等骨骼动画仍在更新，其平均包含子项耗时约 1.41 ms，说明非 Mass Actor/机械组件持续 Tick 也是剩余成本。新屏外单位降频并没有自动替代这些 CharacterMovement 与机械动画路径。

## 慢帧与卡顿

| 捕获帧 | 引擎 GT | 服务器 World Tick |
|---|---:|---:|
| 普通帧 | 32.48 ms | 12.06 ms |
| P95代表帧 | 40.86 ms | 16.43 ms |
| 最慢帧 | 60.55 ms | 10.27 ms |

P95 代表帧中的服务器 Mass StateTree 独占 **4.90 ms**，该帧服务器 Tick 为 **16.43 ms**。整个窗口该 Processor 平均 1.56 ms/引擎帧，310 次调用、每次约 4.53 ms、最大 7.87 ms；处理集中发生时形成周期性峰值。源码中该 Processor 明确要求游戏线程执行，并逐实体创建 StateTree 执行上下文和执行需要更新的行为。下一步应细分实际 StateTree 任务并压低批次峰值。

最慢帧 **60.55 ms** 中，`GameThreadWaitForTask` 独占 **21.35 ms**。引擎 RenderCore 源码确认该 Scope 是游戏线程等待渲染线程任务；同期多线程出现 D3D12 新资源/上传堆分配，单次 4–6 ms，路径涉及 DynamicPrimitive、EditorPrimitives、PrePass 和 Nanite Readback。它们是渲染资源分配导致额外卡顿的排查入口；当前 Trace 没有足够的资源身份元数据，尚不能归到某一具体游戏资产。不同线程的时间互相重叠，不能叠加为 GT。

本构建 CSV 的 RenderThreadTime 接近 0.001 ms，与实际 RenderThread 0 事件不符，未用该字段判断渲染线程没有成本。渲染等待结论使用真实 Trace 事件和源码调用合同。

## 新特效现状与 GPU

裁剪、生命周期、三档LOD、单位屏外5Hz、弹丸屏外呈现、僚机表现与预警等开关均为1，命中 BatchMode=2；既有 DataPool、避障和 UI 投影缓存也为1。当前窗口 Client1 新接纳批量命中220次，回退0；当前批量命中 Niagara 的 GT 独占平均 **0.018 ms**，纯飞行预测约 **0.043 ms**，避障查询约 **0.563 ms**。这些均不是当前约33 ms整帧的主要热点。

Client1 项目单位呈现平均 **0.586 ms**、飞行呈现 **0.414 ms**；Client2 分别 **0.549/0.229 ms**。计时边界的普通数据池弹丸为183→333，没有Ship飞行Actor；僚机新表现活跃数为0。本轮未覆盖所有优化功能的压力上限。

计时窗之后捕获 GPU 实帧38697：Graphics队列15.231 ms、Compute队列3.505 ms；队列并行，不能相加。GPU Ribbon组 **0.356 ms / 96 Dispatch**，是该单帧的组耗时，不具备全部资产归属，且与30秒计时/客户端截图不是同一同步帧。它已不是这次的主要限帧因素。

## 后续优先级

1. 优先细分服务器 StateTree 行为并将昂贵处理错峰，降低约4–8 ms的集中批次。
2. 盘点采矿/建造车辆和工厂机械组件的静止、屏外更新，减少表现与动画的持续 Tick；保持服务器移动、碰撞和可靠状态合同。
3. 分别核对编辑器和游戏 HUD 的 Slate 成本，再处理动态网格/上传缓冲池的渲染资源分配峰值。

本轮只诊断，未实施以上追加优化或承诺 FPS 收益。PIE保持运行，GPU CSV与ProfileGPU选项已恢复，项目临时计时已关闭。没有改动源代码、正式资源或地图，原计划玩家验收和暂缓性能矩阵的状态保持。
