# Mass移动数据优化：玩家验证入口

新代码直接接入正常移动流程。继续使用10 Hz、原主动侧绕、0.5秒让路、同命令不互让、小向大或同尺寸让路，以及直接邻居次步传递。每个单位完成移动后立即更新权威位置和碰撞圆，下一个单位读取新位置。

## 在编辑器中操作

打开 `/Game/Maps/LVL_CommanderMassPrototype`，Play选择指挥官，正常框选单位并右键下令。地图中的 `CircleAvoidanceReview_Entry` 为操作说明，`CircleAvoidanceReview_View` 为观察相机。

现有预置场景入口：在项目根目录PowerShell执行：

```powershell
.\Scripts\Performance\Open-CircleAvoidanceReview.ps1 -Scenario crossing
```

可选 `hold / gather / mixed / attack / buildings / ore / work`。入口先回放30秒命令，再保留PIE供玩家继续操作；停止PIE后自动恢复编辑器设置。

## 本轮观察重点

- 对穿、静止挡路和大小混合：侧绕方向、让路时机与当前版本保持一致。
- 矿车进出工厂、工程车施工：任务与移动衔接维持原流程。
- 本轮是数据访问优化，未修改既有两点往返或无进展恢复策略。

## 结果与复现

[性能对比](性能对比.md)、[完整统计](comparison.json)、[逐步轨迹](trajectories.json)。耗时单位为每个10 Hz逻辑步的CPU毫秒数，不能直接当作每帧FPS提升。

原始窗口保存在 `Artifacts/CircularAvoidance20261110/new-<场景>-mass-data-before-<轮次>/` 与 `new-<场景>-mass-data-after-<轮次>/`，清单为同目录的 `mass-data-before-suite.json` 和 `mass-data-after-suite.json`。

报告生成命令：

```powershell
python Scripts/Performance/report_circular_avoidance.py --root Artifacts/CircularAvoidance20261110 --old-prefix '@mass-data-before-suite.json' --new-prefix '@mass-data-after-suite.json' --output Artifacts/MassMovementData20261111/comparison.json
python Scripts/Performance/report_movement_data_optimization.py --comparison Artifacts/MassMovementData20261111/comparison.json --output Artifacts/MassMovementData20261111
```

单位权威状态与Hybrid协议不变；删除无消费者的移动目标、受力和落位副本，保留的Mass位置、速度及指令结果按Chunk写回。结构化轨迹核对不代替玩家手感与视觉验收。
