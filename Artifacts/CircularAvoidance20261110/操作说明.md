正式玩法改为 Demo 多角度“原主动绕侧”（`demo-active-steering-v3`），替换此前限次分支。打开 `/Game/Maps/LVL_CommanderMassPrototype`，Play 后选择指挥官；正常框选、右键移动或攻击即可体验。重防号属于低空层，先驱号、扫荡者、矿车和建造车属于地面层。

如需直接查看预置情形，在项目根目录的 PowerShell 运行：

```powershell
.\Scripts\Performance\Open-CircleAvoidanceReview.ps1 -Scenario crossing
```

先停止已有 PIE。脚本会准备完整 632 单位开局并回放 30 秒命令，然后保留窗口供继续操作；停止 PIE 后恢复原编辑器设置。此预览独立输出，不混入正式前后对比数据。

| Scenario | 内容 | 重点观察 |
|---|---|---|
| crossing | 两队对穿，关闭自动射击 | 接触后绕侧、迎面相遇和短暂停步 |
| hold | 一队静止，另一队通过 | 静止队伍不被推开，移动队从可用空隙绕行 |
| gather | 地面和低空在同一区域集结 | 两层互不阻挡，同层保持圆形间距 |
| mixed | 大小单位混合集结 | 目标落位、大小单位的空间需求 |
| attack | 围攻指令，单独启用射击 | 冻结站位已在射程内，只覆盖停驻射击；不覆盖接敌包围 |
| buildings | 建筑、工厂与矿簇附近移动 | 多圆墙体、门口和坡道通行 |
| ore | 5/10 秒改变阶段，15 秒采空，22 秒恢复 | 局部矿簇与路线更新 |
| work | 采矿、回厂与施工 | 原卸货点进出、采矿和施工衔接 |

普通移动进入目标区域、约 1.05 秒无进展后就地落位；矿车和工程车仍使用实际工作点。工厂使用原卸货点，已移除额外的单车入口预约。玩家主要体验对穿、绕行与集结是否流畅；局部侧绕仍可能堵塞，不承诺解决所有拥堵。用户已接受穿透，不以零穿透作为交付条件。

## 调参数

唯一源表为 [GuLiStrikeAvoidance.xlsx](../../data/Excel/GuLiStrikeAvoidance.xlsx)。前三行是列名、类型、必要性，第 4 行起是数据。

| 工作表 | 用途 |
|---|---|
| Units | 6 个兵种的半径、净距、前探、7个侧绕角与两侧选择偏好 |
| BuildingCircles | 建筑局部圆心、半径、高度和生效施工阶段；工厂墙体使用多个圆 |
| OreClustering | 矿石合并半径、面积及局部更新限制 |
| _说明 | 中文字段说明和修改流程，不导出 |

单位初始半径按 UnitTypeId 1–6 为 3、6、1.5、1.5、1.5、15 米；净距 0、数值余量 2 厘米、前探 0.2 秒。左右均按20°、37°、55°、73°、91°、111°、134°依次寻找可行方向，再按转角、可走距离与上一侧偏好比较。`ClearancePreference=0.0425`、`SidePreferenceRadians=0.38` 对应原Demo代价；直行完全畅通后清除侧向记忆。限次分支的增角档位和重试冷却已删除。

`RadiusMeters` 不再按 3 米格取整。`GridReferenceDiameterMeters` 独立控制原模型尺寸与占格参考，修改避障半径不会改变模型大小。接触后最多一次切线滑动，合成位移经一次 NavMesh 表面约束后应用，立即更新该单位在空间索引中的位置。

保持原选路行为的优化：缓存角度正余弦、沿途空间格查询、复用选中方向的前探命中、圆覆盖格不变时只更新位置。畅通时只扫1次；最坏为1次直行+14次侧向+1次滑动，共16次，比原Demo省去一次重复移动扫圆。当前版本已完成24个性能窗口，耗时与行为边界见[新报告](原主动绕侧性能对比.md)。

修改后保存 Excel，停止 PIE，并在原型地图执行：

```powershell
python Tools/DataPipeline/export_data_from_excel.py
python Scripts/commander_editor_python.py --file Scripts/import_avoidance_data.py --timeout 90
```

导入会逐行核对 4 张 DataTable，并更新、校验正式 200/600 兵 Hybrid 清单。重新开始对局后使用新配置。只改数值不需要重新编译；新增反射字段需要导出、编译和重启编辑器后再导入。不要直接维护生成的 JSON 或 DataTable。

## 证据

[旧版有效基线](old-suite.json)与[当前原主动绕侧](active-steering-suite.json)各24个有效窗口，逐一使用相同冻结配方。6个移动场景主线程移动耗时降低76.7%～82.2%、到达数提高；工作场景移动完成记录由每轮4次降至3次，采矿、接驳和施工仍有记录。围攻窗口为停驻射击，不能据此评价移动包围；对穿仍记录少数单位持续往返。[当前报告](原主动绕侧性能对比.md)、[原始汇总](active-steering-comparison.json)和[分项CSV](原主动绕侧分项统计.csv)提供完整结果。收益包括移除旧版固定步外的额外移动、统一10Hz以及落位策略变化，不是单次避障函数的纯算法加速比。

[废弃防御性试版](rejected-guarded-suite.json)的22个窗口及[历史报告](对比报告.md)独立保留，未参与上述对比。当前批次结束后已恢复编辑器设置并结束所有测试子进程，见[结束状态](active-steering-performance-finish.json)。

地图内的 `CircleAvoidanceReview_Entry` 为说明入口，`CircleAvoidanceReview_View` 为观察位置，均只在编辑器中存在。编译、实体回读和性能记录不代表玩家手感或视觉验收；本轮不使用截图、录屏或视口目检。

## 简易让路 Web 实验

[打开本机 Demo](http://127.0.0.1:61229/?v=yield-1)。默认原主动绕侧、10Hz、双单位示意；可切换大小、两队对穿、静止挡路，开关让路并选择0.2/0.3/0.5秒横移。青色箭头为行进者绕侧，橙红箭头为阻挡者让路。

只有不大于行进者的单位会让路；按用户追加要求，同一命令ID的成员之间不触发让路，已落位成员也保留该归属。不同命令或无命令的停驻者仍可参与，原侧绕与碰撞保持。行进者实际侧绕后，首个阻挡单位从下一步朝相反横向移动，默认0.3秒；移动单位随后继续原命令，静止单位停在让开处。让路中不递归要求第三者让路，也不额外增加同一步位移。该实验仅在网页中，未加入UE正式实现或以上性能数据。源文件位置及检查范围见[Demo记录](simple-yield-demo.json)。
