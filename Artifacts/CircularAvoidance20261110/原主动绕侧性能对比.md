# 原主动绕侧同场景性能对比

当前版本为 `demo-active-steering-v3`：左右7角度比较、侧向记忆、接触滑动，以及空间查询、角度缓存和扫圆复用优化。旧版为本次替换前已经采集的NavMesh + 预测避让 + 软分离/让路版本。废弃防御性试版的数据不参与本报告。

两版各 8 个场景、每场景 3 次、每次 30 秒。完整开局为 600 个战斗单位、16 辆矿车、16 辆工程车；准备与预热在计时窗口外。

## 分项口径

完整均值、P95、P99、每活动单位成本及计数在 [原主动绕侧分项统计.csv](原主动绕侧分项统计.csv)；每次测量单独列出，不将三个P95平均后当成合并P95。时间单位为毫秒，桶/圆/方向/重寻路指标单位为次。每活动单位以该逻辑步实际产生位移的单位计数，零活动步仍计入总耗时，结合到达率阅读。

| 职责 | 旧版指标 | 新版指标 |
|---|---|---|
| 索引 | Avoidance.GridMs / SharedGeometryMs | Movement.GT.CircleIndexMs / StaticIndexUpdateMs |
| 实时避障 | Avoidance.QueryMs / SolveMs；Movement.GT.EnvironmentMs；Avoidance.SoftMs | Movement.GT.CircleSolveMs |
| 碰撞处理 | 旧 Environment/Soft 与提交相互包含，不作相加 | 扫圆与滑动已包含在CircleSolveMs，无额外提交扫圆 |
| 提交总计 | Movement.GT.CommitInclusiveMs | 同名指标，包含内部求解/扫掠/导航等 |
| NavMesh移动 | Movement.GT.NavMeshMoveMs | 同名指标 |
| 重寻路 | Navigation.RepathMs / RepathQueries | 同名指标 |
| 导航位置修复 | Navigation.RepairMs | 同名指标；未触发时为0或无样本 |
| 矿簇更新 | Ore.ResourceTickMs（旧版无聚合阶段） | Movement.GT.OreClusterMs；Ore.ClusterUpdates/MemberPairChecks/Merges/PassageRejections |
| 桶与圆检测 | Avoidance.BucketVisits/ExactCandidates/SoftCandidatePairs | Movement.CircleBucketVisits/CircleChecks |
| 侧绕查询 | 旧版不使用本算法 | Movement.DirectionProbes/SideProbes；后者为前者子集 |

两版冻结的 hotspot mask 均为31，未启用旧版 GameplayWorker 位32，因此本次移动与避障成本均在主线程，工作线程移动成本为0；Hybrid网络工作线程保留原负载，不把它们混算为避障线程。后台NavMesh建图仍属引擎职责，本表的NavMesh指标仅为移动查询。

总移动成本包含旧版固定10Hz调用、命令引发的额外即时调用，以及在TickAuthority之外运行的预测处理器；新版圆形求解已经包含在移动调用内，不重复加计。嵌套分项不能直接相加。静止单位仍参加动态索引，报告同时核对活动单位与到达数据。

## 证据和边界

- 原始窗口由 [old-suite.json](old-suite.json) 与 [active-steering-suite.json](active-steering-suite.json) 指定；每个目录含完整配方、场景、采样、命令回执和结束状态。
- 旧版有效基线通过后才删除旧逻辑；详见 [baseline-qualification-current.json](baseline-qualification-current.json)。
- 当前源码版构建见 [build-active-steering.log](build-active-steering.log)，版本和源码/配置身份见 [采样版本记录](active-steering-performance-provenance.json)。本次只执行获准的性能窗口，没有重跑其他自动化测试。
- 两版冻结单位身份、归属、位置、健康值、矿量、建筑布局、相机与画质。编辑器说明实体与导航准备会改变地图文件大小或时间，原始元数据变化单列于 map-reserialization.json；实际布局/源数据指纹、建筑矿石清单和完整开局必须匹配。
- 旧版静态扫掠观察只覆盖旧登记的矿石/玩家圆，建筑原本由物理凸包/NavMesh限制；新版观察包含建筑圆，因此两版静态命中总数覆盖范围不同。动态穿透使用同一观察方法。
- 矿石恢复可能在单位当前位置生成静态圆。静态扫掠观察另列初始重叠退出，不把它当作新穿入。观察数据不参与运动提交；穿透和接触滑动不作为额外验收门槛。
- 矿量事件改变的是测量用世界投影，不伪装成资源结算命令；实际采矿与卸货由work场景的正常业务流程观测。
- 进程内存增量含分配器、网络与GC波动，不是避障独占内存。
- 原主动绕侧的手感与视觉效果仍由玩家验收。新增简易让路只装在网页Demo，本次UE采样不包含它。测试包含编辑器/本地Hybrid对局环境，不能直接视为打包版本或端到端FPS提升。
