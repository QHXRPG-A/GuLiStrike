## 启动固定场景

用源码引擎打开项目和上述地图，保持无 PIE，然后在项目目录的 PowerShell 执行：

```powershell
python Scripts/Performance/run_snapshot_parallel_review.py --phase inspect --scenes dense200
```

压力场景把 `dense200` 换为 `stress`。入口使用已有原生测试人口与四来源飞行物接口，同进程专服＋双客户端、1280×720、正式 250000 B/s 连接预算。进入场景前保存原控制项，退出后恢复。压力附加飞行物持续补充最多 120 秒，超过后仍可观察，但不能当作固定压力窗口。

脚本提示 `PIE ready` 后，两客户端应有移动/避障与自然交火；200 单位场景应能看到实际枪口。压力场景可能因为已确认的可靠事件积压而没有真实枪口，本轮没有修改协议解决它。

## 可操作检查

在脚本终端输入命令后回车：

| 输入 | 操作与预期 |
|---|---|
| `front` | 返回原近距离固定镜头；恢复当前单位姿态，不补播屏外历史枪口 |
| `back` | 两客户端看向屏外，服务器继续移动/交火 |
| `split` | 客户端 1 屏外、客户端 2 正常；两个 World 的可见性独立 |
| `mixed` | 使用本轮保存的混合视角角度；每轮实际比例以样本为准 |
| `stop` | 对测试单位发停止命令；检查是否及时停下 |
| `reverse` | 反向移动并触发正常改令/避障 |
| `forward` | 恢复正向移动 |
| 空行回车 | 结束捕获、停止 PIE、恢复进入前的临时设置 |

每次操作前结束上一段原生采集，操作后另开新段。段文件写入 `Artifacts/PerformanceOptimization20261010/Rollback/Manual/<时间>/`，避免把 Python 操作开销当作正式性能样本。玩家检查是功能/可读性验证，不替代 30 秒无干预的性能配对。

左上角沿用现有 FPS、延迟和网络 HUD：客户端收发/总吞吐、包速率、丢包、连接预算，以及 PIE 服务器对应连接和飞行队列。两端是同一条连接，不相加；`1 KB = 1000 B`。原生捕获进一步保存事件产量、实际批数、预算阻塞、队首/接收年龄、未确认可靠 bunch 与 State/Pose 载荷。
