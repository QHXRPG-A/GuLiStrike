# 工程车地面动态避障

## 背景与目标

两种工程车已经填写 Soldiers 表并使用 NavMesh MoveTo，但使用普通 PathFollowing，尚无动态避让。用户要求完善避障，确认采用 Detour Crowd：NavMesh 决定路线，局部避让调整眼前速度。

## 需求与边界

- 工程车提前避让对向、交叉和停放车辆；空间不足时减速等待，原采矿／施工／移动任务仍由任务组件维护。
- 地面士兵提供只读位置、速度及占地，工程车绕行；不改变 Mass 士兵的指令或移动权威。
- 工程车避让占地参考实际模型，使用既有大单位导航网格；高速移动须提前预测冲突。
- 厂内轨迹不接收避让转向，但作为被动障碍被其他车避开；运输相位车辆退出地面避让，合法落地后重新加入。
- 服务端计算避让，客户端使用既有车辆移动复制；飞船不作为地面避让对象。
- 用户追加确认：建筑、据点模型和矿体也必须阻挡地面路线。按真实碰撞体积生成导航占位，放置／摧毁／采空后更新，不能只有物理碰撞而导航仍视为通路。
- 保持当前模块和组件边界；必要数据、容量及初始化错误明确暴露。长期堵塞是否需要新的全局路径策略，以实测为依据。

## 验收

- [x] 两种工程车对向会车与交叉行驶能避让并抵达。
- [x] 移动车辆绕过停放车辆，停放车辆不被避让系统推走。
- [x] 工程车在地面士兵附近避让，士兵命令仍由原权威推进。
- [x] 厂内车辆保持既定轨迹；空中相位退出、出站恢复地面避让。
- [x] 源码版 Editor／Game 构建与 BuildId 检查；已有相关验证及实际观察如实记录。
- [x] 建筑及矿体跨障碍移动绕行，运行时建筑生成／销毁、矿体采空后导航占位更新。

勾选仅对应[本轮证据](../../TestResults/EngineeringAvoidance/README.md)中的具体场景，不扩展为密集狭路、长期堵塞、600单位性能或全部地图均通过。旧BuildingWorld测试失败未改写为通过。
