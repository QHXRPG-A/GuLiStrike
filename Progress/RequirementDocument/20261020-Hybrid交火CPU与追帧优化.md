# Hybrid交火CPU与追帧优化

依据交火采集 `D:/UE5.7/PerformanceCaptures/GuLiStrike/20261020-165637-F53A52FE`：平均帧间隔35.513ms、P95 53.891ms；Hybrid主线程22.649ms/帧，弹丸服务4.151ms/帧。最慢100.190ms帧集中应用14个逻辑步，主线程应用批次76.681ms。

保持60Hz逻辑时钟、每个被接纳逻辑步及其顺序、伤害与出生/结束身份、事务回执与捕获一致性。不得以丢步骤、减少人口/弹丸/反馈、降低画质或改变相机来替代优化。保留已实现UI和四档LOD行为。

验收沿用 `/Game/Maps/LVL_CommanderMassPrototype`、2359×1748前台视口；编辑器主窗口保持最小化，两项窗口条件均由原生逐帧计数确认。固定交火准备、相机、质量及模块版本。评估版本取舍时采用三轮配对、每轮热身10秒并记录30秒，报告均值及合并P95；不将单轮微小差值视为稳定收益。15ms是此前的整帧目标，当前不再据此推进或宣称达标。核对逻辑频率、交火吞吐、队列及状态一致性；GPU队列与CPU分别报告。禁止助手读图测试，视觉由用户自行核验。

2026-10-21 用户最终明确本机模拟的指挥官响应目标，替代此前的固定100ms及通信延迟加20ms口径：

- 绿线在下指令的当前帧立即提交，不等待规划完成或网络回执。它先表达本地意图，正式落点返回后交接；失败、取消、换选区、对象失效和会话退出须清理，不伪造接受回执。
- 正常持有模拟权的己方Mass单位，从本机收到移动输入到首次权威位移、模型实例提交均严格小于20ms。不得再增加RTT容差；稳定所有权下不需要网络往返才能本地起步。交接中的身份与权威校验继续保留，另列该状态的证据。
- 分别记录输入、规划/发出、最终回执、权威位移、绿线Slate提交和模型实例提交。合成语义输入只能证明对应程序入口，不能登记为完整鼠标/操作系统到显示器的验收。
- CPU提交、显示呈现和玩家感知分开记录。不得用假位移绕过权威路径；不可直接减少全体单位插值缓冲而忽略抖动、回拉和跨所有者交接。
- 本机已经提交的姿态不应等待网络发送或远端插值缓冲。接触修正、机械姿态、合法位置提交和远端抗抖动仍保留；只消除没有必要的排队与重复计算。
- 起步的位移阈值属于诊断标准，不是游戏主动等待条件。新增更早的观察点时同时保留原2cm指标并报告实际位移，不把阈值变化冒充运行性能收益。
