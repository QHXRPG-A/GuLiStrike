# 扫荡者远端姿态与导航恢复修复

## 背景与目标

用户报告敌方不攻击扫荡者、选中单位无法移动，并确认蓝方扫荡者进入红方射程后仍无反应。界面颜色按敌我关系显示，诊断以实际阵营、对象身份和模拟拥有者为准。

## 需求与边界

- 扫荡者是运行时召唤的兵种 `UnitTypeId=5`；先驱号为 `UnitTypeId=1`，重防号为 `UnitTypeId=2`。不得通过改名、改射程、调整阵营或伤害绕过问题。
- 远端逻辑进程必须接收并应用新生单位的姿态，使用其实际位置索敌；保留现有协议、频率和拥有权校验。
- 导航重建后，原地仍有可走导航面的单位应恢复有效引用并继续原指令；实际挪动身体仍须遵守碰撞、障碍和距离约束。
- 不实施尚待用户决定的最高优先级插队；不将本轮功能诊断计为20–30ms响应或15ms整帧验收。
- 只读诊断默认关闭，空间准备仅允许显式调用的PIE入口。技术数据不替代玩家视觉验收。

## 验收标准

- [x] 扫荡者在本机移动后，敌方逻辑进程位置随之更新，姿态应用计数增长且无持续解码失败。
- [x] 扫荡者进入有效射程后，敌方攻击并走现有伤害结算；先驱号对照组正常，未调整重防号战斗规则。
- [x] 原复现的9个重防号在同一斜坡位置、导航引用重建后可继续接令移动；不依赖停战或变更网络拥有权。
- [x] 原地引用恢复不引入单位位置跳变；非原地恢复保留现有身体碰撞检查。
- [x] 在 `/Game/Maps/LVL_CommanderMassPrototype` 保存默认停用的验证入口及实体读回，供用户操作核验。
- [ ] 玩家核验扫荡者被攻击、受击和移动观感；助手不读图。

编译、结构化功能检查、性能验收与玩家体验分别记录。
