# 场景 UI 环境隔离与本地阵营配色

## 2026-10-09 后续执行状态

[最新开发与证据](../DevelopmentDocumentation/20261008-统一模型目录与本地阵营改色.md)接续本计划：已编译加载、十四模型及扫荡者分别按用户放行入库，双方本地配色及六环境指定敌环ROI核对完成。旧对照及早期阶段记录保留，不要求重复旧A候选审批。

## 背景与目标

用户先要求 Mass 脚环统一 20 cm，再明确场景 UI 不受环境影响、玩家看到己方为蓝色、敌方为非蓝色，并批准实施完整计划。显示规则以本地玩家真实阵营判定敌我，不改变服务器阵营、控制权限或网络协议。

## 需求描述

己方模型的可变区采用蓝方配色；敌方使用每模型配置的非蓝色，允许红色之外的色系。脚环永远己方蓝、敌方红，未知阵营不显示；选中仅在外缘增加四个同色短标记。环带保持世界径向宽度 20 cm，沿用现有表现位置、外半径与地面高度；不改为固定像素线宽。

脚环、血条、世界图标、选区、指令与路径线、建筑放置与范围、阵营提示轮廓统一在场景后处理之后绘制。主体不透明，隔离灯光、阴影、雾、曝光、泛光、色调映射与背景混色，保留血量、路径、放置合法性等功能色。每个本地玩家仅一个 UMG 容器承载 Slate 批量绘制，复用数据与缓存，不为每单位增加 Widget/Actor；旧场景绘制停用，处理视口/DPI/近裁剪/相机后方，且不抢焦点、退出解绑。

模型先交付相同姿态、相同相机的红蓝并排预览与黄色变色区标注。优先使用现有遮罩和明确分区，缺少标记时只提出彩色装甲或阵营标识候选。机械机构、线稿、固定功能色、三档明暗参数、几何、动画与 LOD 保持原样。对照采用独立派生资源，每模型记录分区、蓝红参考和敌方非蓝配置，用户确认分区后才接入运行时。

## 范围与边界

- 四种 Mass：先驱号 Id1、重防号 WM01/Id2、扫荡者 Id5、彼之矛 Id6。
- 八类玩法建筑：防空炮、哨戒炮、前哨、基础兵营、护盾发生器、矿厂、地图据点、彼之矛施工体。
- 六座既有 SSF：空军基地、克隆中心、指挥中心、军工厂、反应堆、战略中心；沿用资源用途，不增加建筑玩法类型。
- 采矿车、建造车、玩家 Ground 地面机甲和 DIY 飞船模型不改色；已有世界 UI 仍纳入环境隔离。
- 对照阶段不切换真实模型引用。默认静态检查、编辑器美术预览及对应地图保存回读；不增加测试、不自动启动游戏。原生编译须另有明确用户授权。

## 验收标准

- [x] 18 个现有模型提供蓝/红/黄色分区共 54 张实际 UE 预览及每模型配置。
- [ ] 用户确认可变区只覆盖指定色块，固定区域、线稿与风格保持一致。
- [x] UI 源码完成本地只读配色、20 cm 世界投影、同色选择标记、绘制迁移与生命周期处理，完成静态检查。
- [x] 在 `/Game/Maps/LVL_CommanderMassPrototype` 保存环境验收入口并重载回读本轮实体。
- [ ] 新代码获准编译加载后，四种 Mass 环带均为 20 cm；昼夜、灯光、阴影、浓雾、曝光、泛光、调色与背景变化时 UI 主体颜色一致。
- [ ] 双方客户端各自看到己方蓝/敌方红脚环；选中、减选、真实归属变化后配色正确；未知阵营不误标，选择标记不覆盖阵营色。
- [ ] 经分区确认后，另行接入实际模型的本地蓝/非蓝配色。
