# 单颗矿石采空与异步导航恢复

## 行为与边界

矿簇仍负责管理、选矿、总量和统计，阻挡改为每颗矿石独立。剩余量从3降为2、1时保持初始阻挡；从正数归零时先更新资源状态和显示，随后解除该颗阻挡。邻矿、建筑、地形和单位体型仍决定路线能否通过，300厘米占位格不替代精细导航。

| 默认参数 | 值 | 语义 |
|---|---|---|
| 合批窗口 | 200毫秒 | 从首个待处理事件计时，新事件不延后截止时间 |
| 每帧节点上限 | 64颗 | 按入队顺序，超出部分后续帧推进 |
| 主线程软预算 | 0.5毫秒 | 保持选中节点各层一致；原子操作及最终发布可能超时 |

保留原资源布局资产格式及Hybrid提交、目录同步协议。物理碰撞使用初始阶段ModelId对应模型的简化凸碰撞，最多24个隐藏ISM组件，禁止逐颗Actor和整簇物理大球。每簇一个导航组件导出活跃节点的NavArea_Null；导航和避障共用凸碰撞的世界XY外接圆、高度范围。

独立静态矿石索引按簇保存共享数据块与存活位，机甲移动不能重建矿石索引。节点删除只撤销自身占位贡献。后台局部Recast生成完成前继续使用旧导航；不阻塞游戏线程，不重建全图，不强制所有单位重新寻路。有效作业与路径保留，相关不可达缓存按需重查。

目录重同步、重连和世界退出清空队列并推进世界代次；初始化直接根据最新已提交剩余量建立存活节点。增加队列、最老等待、批次节点数/耗时、存活碰撞/避障节点数及静态索引发布次数诊断。

## 玩家检查参考

工作项已按用户指令完成收尾。下列人工玩法检查保留为参考，未提供新的逐项验收结果；编译及性能实测证据见开发记录。

在 `/Game/Maps/LVL_CommanderMassPrototype` 准备并保存单颗采空、连续通道、邻矿保留、跨Tile、批量及重同步入口。编译后玩家检查：

- [ ] 3→2→1不缩小阻挡；归零显示立即更新，随后只解除该颗阻挡。
- [ ] 邻矿及其他贡献保留；小单位能通过的缺口不保证大单位也能通过。
- [ ] 连续与跨Tile采空最终按局部新导航通行，其他单位移动持续。
- [ ] 合批不被新事件无限延后；超过64颗时继续分帧，诊断计数正确。
- [ ] 待处理期间重同步、退出/重连不会将旧队列用于新场景。
