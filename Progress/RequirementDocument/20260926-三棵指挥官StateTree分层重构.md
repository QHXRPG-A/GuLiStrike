# 三棵指挥官 StateTree 分层重构

## 目标与边界

将 `ST_CommanderMiner`、`ST_CommanderBuilder`、`ST_CommanderMass` 就地改为“控制与任务管理 → 业务流程 → 持续执行阶段”。保持命令协议、兵种绑定、Actor／Mass Schema、自动任务生命周期、现有重试时间和移动准入预算。

移动、采集、卸货、施工与占领保持 Running，业务结果出现后由显式转换离开阶段。安全退出、持续停止和移动替换从父状态打断；普通恢复在业务分支内处理。

本次不新增自动化测试，不启动 PIE 或性能验收，不增加玩法超时或修改玩法数值。原生编译按项目技能单独确认。运行效果由玩家验收，不预先承诺性能提升。

## 三棵业务树

| 树 | 业务分组 | 恢复／交接 |
|---|---|---|
| Miner | 采矿位选择、前往、采集；共用返货分支的选厂、返厂、卸货；重试等待与循环交接 | 矿位恢复在采矿分支；卸货点／工厂恢复在返货分支；独立返厂和采矿循环共享返货；自动与人工失败遵循原规则 |
| Builder | 选目的地、前往、抵达抢位；持续施工；退单；完成 | 失败位置保留排除记录；退单交还取单层；本地优先、途中换单、100cm 到位抢位、开始施工不自动换单 |
| Mass | 选择据点、推进、占领、阶段交接、无目标等待、排除失败目标 | 不可达排除并重选；无目标限频等待；占领后继续推进或交给人工队列；人工接管后不恢复 InitialOnce |

## C++ 与资产职责

- Actor／Mass 共用持续动作逻辑，进入时提交，接受后观察；延后执行只按原节拍重试。
- 操作请求携带单位、命令版本、执行 ID 和动作序号，区分 Queued、Deferred、Applied、Failed、Stale。
- 结果观察与任务收尾分离。终态锁存，释放和队列／资格交接执行一次。
- 保留 10Hz、最多四轮即时处理、Mass 遍历结束后的主线程提交及原导航预算。
- C++ 负责导航、结算、占位和安全清理；树负责可编辑阶段与恢复转换。
- 迁移前备份资产，顺序为 Miner → Builder → Mass。迁移工具记录 V2，已迁移资产不再生成。
- 常规生成命令及相关脚本改为只读检查。Xmind 读取真实资产递归导出，包括层级、条件、任务、转换目标、优先级。
