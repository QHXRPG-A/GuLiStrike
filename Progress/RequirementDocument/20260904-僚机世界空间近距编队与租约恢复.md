# 僚机世界空间近距编队与租约恢复

## 背景

`/Game/Maps/LVL_ShipTest` 中持续按住 Q/E 偏航时，旧双环槽位把飞船完整 Transform 当作编队坐标系。船头持续旋转会额外扫动全部槽位目标，僚机既要完成自身盘旋，又被迫追逐母舰旋转产生的高速目标；连续候选样本被世界门或运动包络拒绝后，租约会沿 Stale、Unavailable、ActiveLeaseRevoked 路径失去活动资格。

玩家期望编队只以飞船位置为护航中心，不跟着船头方向转；现有 600/900 米双环也离母舰过远。同时，未来其他持续校验失败也不应直接导致仍存活的僚机组永久消失。

## 需求描述

1. 编队以飞船 `Position` 为中心平移，但不继承飞船的 Yaw、Pitch 或 Roll。飞船只旋转而位置不变时，不得因此整体扫动僚机槽位。
2. 僚机仍保留各自的双环相位、自主盘旋、固定翼积分、避障与归队；“不跟船头转”不等于停止盘旋或把僚机吸附到固定点。
3. 收近双环。因本次未指定目标数值，采用等比缩小 50% 的最小合理假设：
   - 内环：13 架，半径 600→300 米，高度偏移 +150→+75 米；
   - 外环：12 架，半径 900→450 米，高度偏移 -150→-75 米；
   - 归队边界同步收紧：CatchUp 1200→600 米，Recovery 2500→900 米。
4. 运行期候选连续失败到 3 秒时必须保留组级权威数据与本地私有模拟。若尚无备份 Owner 接管，原 Owner 可复用现有 `RequestResume`、可靠 Bootstrap ACK 和全 Flight 原子候选批次恢复 Active。
5. Resume 请求必须限频，且服务端继续核验 Group、Owner、LeaseEpoch、六类权威 Scope、运动包络和世界门；不得通过放宽静态碰撞/导航规则实现兜底。
6. 飞船销毁、显式拆组或初始化失败产生的真正终局 `Lifecycle::Revoked` 仍不可恢复，防止旧代次实体复活。

## 边界

- 不改变僚机数量、Flight 划分、角速度、最低/巡航/追赶速度、武器、补给或伤害规则。
- 不增加服务器僚机运动 Tick，不允许服务器生成位置、速度或姿态。
- 不放宽 WorldStatic Sweep、FlightNav、速度/加速度/转向包络。
- 不新增或扩充自动化测试；本轮只运行与需求直接相关的既有验证。
- 不在本需求中改变 Q/E 的飞船偏航手感。

## 验收标准

- [ ] 飞船位置固定并持续按住 Q/E 时，编队中心和同一时刻的世界空间槽位不随船头旋转；槽位只受自身相位推进影响。
- [ ] 飞船平移时，双环中心仍随飞船位置移动，僚机能在新边界内追赶/恢复。
- [x] 运行时读取的 Formation DataAsset 为 Revision 2：内/外环 `30000/45000 cm`、高度 `+7500/-7500 cm`、CatchUp/Recovery `60000/90000 cm`。
- [ ] 连续拒绝跨过 3 秒阈值后，本地组不因运行期租约撤销被销毁；无备份接管时原 Owner 以不高于 1Hz 的请求频率重试 Resume。
- [ ] 恢复只有在 Bootstrap ACK 和完整原子 Resume Candidate 通过服务器原有校验后才回到 Active。
- [ ] 显式终局 Revoked 仍清理组且拒绝恢复。
- [x] UE 5.7 Editor 目标编译通过。
- [ ] 既有 Wingman 定向验证无失败。（Relay 21 项已通过；DebugGame 下 H4000 ServerValidator 性能预算待优化配置复验。）
