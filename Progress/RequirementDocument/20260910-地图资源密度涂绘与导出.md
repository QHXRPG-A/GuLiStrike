# 地图资源密度涂绘与导出

## 背景与目标

现有地图标注插件能编辑离散 Marker 和命名区域，但红矿、蓝矿需要表达覆盖全图的连续相对分布。目标是在同一 Editor 工具内增加类似笔刷的密度棋盘，并用据点 `Territory` 多边形给密度格做稳定归属与汇总，为后续玩法系统提供确定性数据。

## 需求描述

- 地图持久保存一个 Editor-only 密度图 Actor；默认世界对齐 25m 网格，数据按通用 `LayerKey` 和稀疏 `32×32` 瓦片保存。
- 首版自动补齐 `BlueOre/蓝矿`、`RedOre/红矿`，两个图层相互独立且可以重叠；`0..255` 只表示相对生成权重。
- 资源涂绘页提供图层选择/显隐、加深/擦除、半径、强度、软硬边、格尺寸、清层和退出；默认半径 200m、强度 25%、Falloff 50%。
- 一次鼠标拖拽对应一次 Undo 事务；路径按固定世界距离补点，同一笔内每格只结算最大覆盖，Esc 能恢复整笔前值。
- 新建 Outpost 预设同时含 `Capture` 与独立 `Territory` 多边形；已有类型资产和 Marker 不自动迁移。
- 密度存在时在原六文件批次中增加 `density_layers.json`、`density_cells.csv`、`density_territories.csv`，并保留原子发布与字节确定性。
- 暴露 `EnsureDensityMap`、`GetDensitySnapshot`、`UpdateDensityCells` 给 UE Python/Blueprint Editor 自动化。

## 边界

- 本期不修改 `GuLiStrike` Runtime，不定义全图矿量、单矿储量、刷新、采集、阵营收益或生成 Actor。
- `layout.json` 继续使用 schema v1；密度扩展有独立 schema v1。没有密度 Actor 的旧地图仍严格导出原六文件。
- Territory 汇总仅表达 `Σ(density/255)` 与加权面积，不解释为实际矿量。
- 贴地热图和笔刷为编辑辅助，不创建逐格 Actor/Component，不进入 PIE。
