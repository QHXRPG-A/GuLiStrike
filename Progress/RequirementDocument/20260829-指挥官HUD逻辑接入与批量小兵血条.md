# 指挥官 HUD 逻辑接入与批量小兵血条

## 背景

三岛式指挥官 HUD、命令图标和小兵血条已经完成纯视觉审核，但尚未进入游戏视口、读取权威数据或处理输入。项目同时采用 500 名 Mass Soldier 与稳定 ISM 表现层，运行时接入必须避免逐兵 Widget、逐兵 Actor 和对既有表现性能优化的覆盖。

## 需求描述

- 由现有 `AGuLiCommanderHUD` 创建已审核的 `WBP_CommanderHUD`，逻辑位于原生 C++，WBP 保持无 EventGraph、无属性绑定、无 MVVM、无 Tick。
- 接入已有真实数据：玩家队伍/角色/同步状态、比赛时长、选取 Cohort、移动 ACK、小地图、己方存续兵力和 Soldier Health。
- 没有权威来源的目标、比分、战术点和能量明确显示为“未启用/--”；攻击、停止、坚守、巡逻和集结保持禁用。
- 命令输入采用：默认选取；`1`/移动槽进入一次性移动；`7`/选取槽回到选取；`+` 在 80/200/450m 三档循环；保留右键立即移动与 Shift+左键 Toggle。
- 使用一个本地 ISM 批量渲染双方“选中或受伤”的存活单位血条，300m 裁切并接受场景深度遮挡。
- Soldier 可靠状态同步 `MaxHealth`，确保运行时修改最大生命后血条比例仍正确。

## 边界

- 不新增比分、目标、经济或五种缺失命令的玩法系统/RPC。
- 不修改地图、Config、Build.cs、Commander Units、Navigation、Resolver 或现有 `GuLiCommanderPresentationActor.*`。
- 不创建逐兵 WidgetComponent、UUserWidget、Actor 或逐兵 Tick。
- Review Board 继续作为静态审核资产，不加入运行时视口。

## 验收标准

- [ ] HUD 在 Commander 原型运行时自动出现，旧 Canvas 面板不再重复绘制。
- [ ] 真实身份、时间、编队、兵力、ACK、小地图和生命数据能够刷新；缺失系统不显示伪数据。
- [ ] `1/7/+`、左右键、Shift 和 Esc 行为符合已确认合同，三个 HUD 岛均阻止世界点击穿透。
- [ ] 血条使用一个 ISM 批次，100/75/55/15%、选中、死亡和 MaxHealth Set/Reset 均正确。
- [ ] WBP 仍为 0 EventGraph/绑定/MVVM/Tick，500 兵性能与网络预算通过。
- [ ] 变更边界、运行截图、测试与性能证据完成归档。
