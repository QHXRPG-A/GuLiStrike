# 红蓝矿棋盘与自动采矿闭环

## 背景与目标

把既有蓝矿/红矿设定、地图标注与密度工具、Commander Mass 导航和建筑放置串成一个可运行的纵向切片。矿藏在当前战局开始时一次性初始化、不可再生；采矿车默认由系统调度，Commander 可临时下达 RTS 命令，命令结束后三秒恢复自动。

## 需求描述

- `/Game/Maps/LVL_CommanderMassPrototype` 的可玩区为 5.6×5.6 km，按 5×5 共 25 个无缝 Territory 覆盖；红方 R1C3、蓝方 R5C3，其他中立。
- 使用 GuLiMapAuthoring 保存 Outpost、Territory 与 25 m 红蓝密度；运行时通过项目 Editor 烘焙层消费，不依赖 Editor-only 插件类型。
- 固定生成 200 个蓝矿簇、40 个红矿簇；每簇 26 个单位矿和 40 原矿，中心到外缘使用 Full/Partial/Remnant 渐变，方向与微缩放确定性随机。
- 服务器权威执行采集、运输、加工、团队库存和建筑蓝矿扣费；每队开局蓝 40、红 0，一座工厂和一辆白盒采矿车。
- 采矿车自动选择己方 Territory 内最近可达矿簇；Commander 可下达移动、采矿、返厂命令，结束/失败/取消后三秒恢复系统调度。
- 活跃矿簇同时阻挡 Actor、NavMesh 与 Mass 预测避障；仅在整簇耗尽时移除障碍并局部重建导航，不全停 Mass 编队。
- 库存、矿车货物和工厂队列仅己方可见；矿物耗尽和 Territory 归属公开并支持晚加入。

## 边界

- 本期不实现正式占领流程；只提供服务器 Territory 归属接口和非 Shipping 调试命令。
- 本期红矿可以采集、加工和入库，但没有消费入口。
- 不实现维护费、最终美术/VFX、磁盘 SaveGame 或客户端权威导航。
- 前哨站建筑不改变 Territory 归属。

## 验收标准

- [x] 地图拥有 25 个稳定 Territory、正确初始归属及 200/40 矿簇预算，烘焙结果确定且可检测过期。
- [x] 6240 个单位矿用批量实例表现，储量按 3/2/1 递减并在新局外不复生。
- [x] 双方采矿车完成自动采集、装载、返厂、加工与入库，Commander 命令结束三秒后恢复自动。
- [x] 仅己方 Territory 可采；调试切换归属后权限即时更新。
- [x] 建筑放置按 10/20/40 蓝矿幂等扣费，失败完整退款。
- [x] 活跃矿簇阻挡 Actor/Mass；最后一个节点耗尽后局部导航开放且不会全体停军。
- [x] 双客户端及晚加入只获得允许范围的经济信息并重建正确矿场状态。

## 验收结论

- 固定烘焙产物为 25 个 Territory、240 个矿簇、6240 个节点，布局哈希 `2714f7bb7668d56638f0d7a4d752e194a9657996`。
- 双客户端 PIE 的 16 项运行时检查全部通过，覆盖归属公开、OwnerOnly 经济、矿量差量、39/40 原矿障碍边界、工厂 FIFO、人工命令覆盖及三秒回归自动。
- 资源专项 6/6、Commander/Mass/Building 相关回归 60/60；Editor、Game、Server 构建及 Cook/Stage/Pak 均成功。
- 最终 Cooked 包在 12.64 秒内达到资源导航 Ready 并生成 500 个服务器权威 Mass 单位，未出现缺失运行时资产、资源错误、断言或 Fatal。
