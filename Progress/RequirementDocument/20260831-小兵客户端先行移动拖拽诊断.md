# 小兵客户端先行移动拖拽诊断

## 背景

用户反馈指挥官移动小兵时，客户端先行表现有明显拖拽感，要求分析原因。该项与本次框选、范围选取切换和快捷指令 UI 并行交付。

## 需求描述

1. 核对真实下令、排队选择、移动 ACK、姿态到达、插值与预测收敛的时序。
2. 提供默认算法不变的非 Shipping 单兵轨迹记录和临时禁用位移预测 A/B，产出可复查证据。
3. 分开记录静态推断、公式验证、编译检查和真实运行时复现，给出按证据排序的改进建议。

## 边界

- 本次仅诊断，不改变预测曲线、默认参数、服务器寻路/避让与网络频率。
- 测试覆盖不写入配置、不复制，结束必须恢复。
- 编辑器生命周期、编译、PIE 运行由主代理统一调度；诊断子任务不自行启动或停止。
- 已有用户修改保持原状。本文档不代表全部 UI/选兵需求，也不更新 README 索引。

## 验收标准

- [x] 静态检查列出候选原因、源码位置和区分步骤。
- [x] 提供临时 baseline/no_offset 记录工具与 CSV 分析器。
- [x] 分析器能识别有符号倒退并区分仅表现倒退，合成检查明确标识为非运行时证据。
- [x] 最终 C++ 编译及独立 ACK 订阅补强通过；61 项自动化（58 项 Commander），0 失败。
- [x] 真实鼠标正常网/约534ms RTT 双向5%丢包、导航绕行 baseline/no_offset A/B 完成；最终6条ACK全部按ID记录一次，选择依赖55→66→移动通过。
- [x] 正常 Stop 恢复和网络清零已实测；到时/重置恢复有代码路径但未实测，开发文档明确未覆盖项。
