# 玩家地面机甲与Mass单位立体碰撞

## 背景与目标

Mass士兵继续保持数据实体，不为每个单位增加Actor、Chaos刚体或碰撞组件。玩家地面机甲通过10Hz碰撞快照和空间网格查询附近数据圆柱，在保留CharacterMovement预测、校正和外部位移版本控制的前提下获得可玩的立体接触。

## 需求描述

- 存活且未相位化的Mass单位阻挡地面机甲侧向穿越，斜向接触允许沿侧面滑动；接触距离为机甲胶囊半径加单位`MassAvoidanceRadiusCm`，不附加最小净距。
- 只有机甲胶囊和单位模型的世界Z区间实际重叠时才产生侧面阻挡。未来机甲使用`MOVE_Flying`飞到模型上方后可自由通过；切回`MOVE_Falling`后恢复顶部着陆检测。
- 下落中的机甲连续检测胶囊底面穿越单位顶面，选择最高顶面，同高时以最小稳定士兵ID决胜。着陆后单位作为虚拟移动平台，只继承平移和顶面高度变化，不继承朝向。
- 支撑单位死亡、相位化、消失，机甲走出单位水平半径，发生传送或外部位移，或进入飞行模式时立即清除支撑；没有普通地面承接则进入下落。
- 权威端普通地面行走的机甲注册为带阵营的动态障碍。移动中的Mass单位沿用现有避障；闲置或已到达的友军最多每台机甲选择最近16个，以正常移速25%在NavMesh上退让，离原锚点不超过1250cm，压力消失0.5秒后返回。闲置敌军不退让。
- 当前支撑士兵ID只复制给机甲拥有者；其他客户端继续使用CharacterMovement位姿复制。客户端从士兵列表、姿态流和单位定义构建同构快照，不增加网络DTO字段。

## 边界

- 本项不实现飞行输入、践踏伤害、玩家推动敌军、Mass全体严格净距算法或逐单位物理碰撞。
- 不修改相邻“玩家地面机甲开火与升级配置”的武器组件、动画、弹池、伤害账本、战斗网络类型、特效资源、数据表或测试。
- 只新增已获用户授权的`GuLiGroundMechMassCollisionTests.cpp`，不新增PIE脚本。

## 验收标准

- [x] 水平阻挡、滑动、有限退嵌和高速连续扫掠自动化通过。
- [x] 垂直分离时自由通过；快速下降选择最高顶面并以稳定ID决胜。
- [x] 真实移动组件进入专用支撑模式，移动支撑携带机甲；外部位移及支撑消失后下落。
- [x] 友军候选上限、阵营过滤、退让目标和1250cm锚点限制通过；敌军不进入退让候选。
- [x] 动态障碍更新保持句柄稳定，旧静态资源障碍行为保留。
- [x] 500个合成碰撞体的局部查询不扫描全部单位；500单位、400步压力无dropped steps。
- [x] GroundMech、导航、Mass战斗专项回归通过；网络组唯一失败为相邻任务遗留的协议14/旧断言13不一致。
- [ ] Listen Server与Dedicated Server中人工确认客户端贴边、落地和搭乘移动单位时无持续位置回拉或抖动。
