# FireReview双阵营靶场与敌方描边

## 背景与目标

`/Game/Maps/LVL_GroundMech_FireReview` 原有战争机器和蜘蛛机甲仅为展示参考，没有战斗血量与阵营组件，也没有双阵营部署点。保留这些参考与环境，为地面机甲提供真实可受击目标。

## 需求描述

- 红蓝双方各4台扫荡者（兵种1）和4台战争机器（兵种2），每种采用2×2阵型，总计16台Mass单位。
- 单位默认待命且不自动开火，保留原伤害、血量、碰撞、受击闪白和销毁逻辑。
- 玩家继续使用FireReview地面机甲；单人默认红方，蓝方属于敌军。
- 敌军使用现有特效目录ID 15显示红色描边；友军不显示敌方描边，不增加透墙显示。
- 在原地图保存部署点、导航边界和玩家起点，提供可重复执行的定向布置脚本。

## 边界

不制作新模型或特效资源，不改变武器与伤害配置，不关闭既有友军碰撞退让。编译仅执行已授权的源码版UE5.7 Editor Development；不运行PIE、自动化、压力测试或截图验收，不新增测试用例。

后续用户指令“PIE已开，看看是否创建成功”允许读取其已启动的当前PIE；本次未启动或停止游玩，未扩展自动化或压力测试范围。实际检查发现导航构建状态持续阻塞生成，见开发记录。

用户继续要求解决生成问题后，在原会话关闭12个动态装饰网格的导航影响，双端读回各16台；随后沿用已有结束PIE与Editor构建重启许可保存地图、修复资产校验器。不主动启动新的PIE，不新增测试文件。

## 验收标准

- [x] 四个持久化部署点保存并读回：两队各8台、全部停火，16个位置满足权威导航投影与间距规则。
- [x] 敌方描边按实例所属阵营写入模板值，换阵营迁移实例，死亡后正常机体隐藏且残骸不描边；已完成静态代码审查与Editor编译，实际视觉效果待玩家确认。
- [x] 用户已开启的双端PIE中恢复16台存活单位；装饰导航排除项已保存重载，FireReview资产验证1通过、0错误、0警告。
- [ ] 玩家在原图进入游戏，观察双方待命，向蓝方开火确认受击、伤害与销毁表现；向友军观察不会显示敌方红色轮廓。

静态代码、编译和地图实体检查分别记录，不能替代玩家效果确认。
