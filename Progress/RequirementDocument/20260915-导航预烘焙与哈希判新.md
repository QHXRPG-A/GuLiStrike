# 导航预烘焙与哈希判新

## 背景与目标

历史诊断的导航等待为 117.939–122.120 秒。正式改动前三轮双客户端、500 士兵的实测主机开局中位数为 124.080 秒，第二客户端为 126.098 秒。优化必须计入点击播放后的预检、烘焙和保存，不能只缩短 PIE 内部日志区间。

## 已确认需求

- PIE 前和打包准备阶段比较版本化导航源签名。数据有效且签名相同即复用；过期、缺失、损坏则重建。
- 地面瓦片沿用 UE 地图内序列化；空中图沿用 GuLiFlightNavigation 数据资产。
- 哈希覆盖导航相关碰撞、变换、实例、地形高度与洞口、代理与生成设置、Modifier 与 Link；排除烘焙产物和无关视觉变化。
- 成功后自动保存地图和导航资产；失败或取消阻止开局及打包。
- 地面保留 Dynamic 和当前两种代理，资源生成、建筑增删、矿簇耗尽及坡道变化按脏区更新。
- 保留导航全部就绪后才开放输入、经济交易和士兵生成的条件。
- 空中图此次增加编辑器与打包准备的自动判新，不新增正式游戏内的空中烘焙器。

## 验收标准

- [x] 改动前三轮同配置启动基线，核对真实 PID、地图、双客户端和 500 士兵。
- [x] 连续启动与重启编辑器后命中；原生全图重建审计为 0。
- [x] 移动、碰撞、实例、地形高度、洞口及导航参数变化使旧记录失效；视觉变更保持命中。
- [x] 矿簇耗尽、建筑阻断与拆除、坡道增删以及空中墙体变化后的可达性正确。
- [x] 改动后三轮主端 22.443 秒 / 客端 24.449 秒；首次全量准备、PIE 失效重建和重启命中单列，完整计入前置耗时。
- [x] 四图准备、重新加载和 Cook 通过；跳过准备的过期测试图 Cook 失败；源码版 Editor/Game 构建成功且 BuildId 一致。

## 验收结果与边界

最终自动化 11 通过、0 失败、0 未运行；重启后的首次 PIE 为主端 27.940 / 客端 29.930 秒，地面和空中均无重建及保存。输入、交易和士兵继续受导航就绪门禁控制。

首次全量导航准备约 434.775 秒，仍有重烘焙和大地图保存成本。前后基线存在闲置编辑器数量的差别，详见报告；Cook 验收使用单包模式，不代表完整发布包已验证。当前入口明确拒绝 World Partition 和未完整加载的子关卡；未注入磁盘写入失败或中途取消故障。
