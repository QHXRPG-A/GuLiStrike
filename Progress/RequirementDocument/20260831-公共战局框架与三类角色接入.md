# 公共战局框架与三类角色接入

## 背景
指挥官原型已承担整个 5v5 战局的席位和身份管理。后续飞船和战争机器需要共用同一场战斗，不能复制三套登录、阵营、复活或胜负入口。

## 需求描述
1. 提取公共 GameMode、GameState、PlayerState、PlayerController 与连接握手。
2. 保留指挥官命令和 Mass 数据链，将世界发布调度移至专门组件。
3. Ground 做可操控占位；Air 接现有飞船，保留惯性手感、热换装和现有射击。
4. 公共就绪、士兵名册就绪、飞船配置就绪独立；服务器拥有身份、移动判定、换装和出弹权限。
5. 冷编译、已有自动化、Listen Server 与独立服务器双客户端实测；更新中文教材和正式归档。

## 边界
- 不新增地图、正式模型、动画或测试文件；占位角色可新增原生 C++ 类。
- Ground 不射击。飞船不新增跨 Mass/载具伤害、护盾、弹药或完整死亡规则。
- 不自行设计胜负条件；不擅自改变全局默认地图。
- 不创建临时备份、校验脚本或散落报告，保留用户现有改动。
- 旧反射类、枚举、Getter、默认子对象路径尽量兼容；不承诺旧客户端二进制兼容。

## 验收标准
- [ ] 公共身份在选 Pawn 前确定，重连/无缝切图/复活不重复占席。
- [ ] Ground/Air 不因无士兵名册而卡住公共登录。
- [ ] 姿态与指挥权限保留独立名册门，指挥官网络回归通过。
- [ ] Ground 两端可见移动并可统一复活，无开火能力。
- [ ] 飞船惯性、预测纠正、版本切换、热换装和服务器弹丸实测通过。
- [ ] 三种角色同场共享身份/席位和士兵世界。
- [ ] 教材贴合实际源码；实测与静态推导明确区分。
