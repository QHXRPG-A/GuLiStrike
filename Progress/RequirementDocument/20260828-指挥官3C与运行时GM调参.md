# 指挥官 3C、Soldier 数据化与运行时 GM 调参

- 适用地图：`/Game/Maps/LVL_CommanderMassPrototype`，飞船调参同时适用于现有飞船地图

## 1. 背景

2026-08-27 已完成 500 名独立 Soldier、动态 ControlCohort、服务端权威移动、网络平滑与指挥官 UI 的首版。第二轮打磨聚焦三个问题：兵种参数仍散落在代码中、远距点选与移动终点体验不稳定、小地图没有跟随玩家朝向；同时需要一套仅在当前 World 会话生效的 GM 指令，用于运行中快速试验 Soldier 与飞船数值。

## 2. Soldier 数据化

- 复用现有 Excel → JSON/CSV → UE DataTable 管线，新增 `GuLiStrikeCommander.xlsx / Soldiers`。
- 当前只定义一个静态模型兵种 `DefaultSoldier`：
  - 移速 `3600cm/s`。
  - 最大生命 `100`。
  - 模型 `/Game/Commander/Units/SM_CommanderFourFRobot`。
  - 攻击力、防御力、攻击范围初值均为 `0`。
- 表格必须承载移速、最大生命、模型、攻击力、防御力和攻击范围；运行时每个 World 只解析一次，不得在 Tick 中查表。
- 模型字段在生成代码中使用软对象引用；运行时只接受 `UStaticMesh`。缺表、缺行、非法数值或错误模型类型按字段回退安全默认值，并且同类 Warning 只记录一次。
- 服务端出生时把有效数值写入权威 Soldier/Mass 状态；客户端表现从同一行取得模型。
- 现有 `uint8 Health` 网络合同保持不变，因此最大生命有效范围为 `1..255`。
- 攻击力、防御力和攻击范围本轮只建立数据承载与权威 Stats，不新增攻击 AI、目标选择或伤害公式。
- 预测最大距离由“有效移速 × 0.25 秒”推导；默认值为 `900cm`，不得继续维护独立的 `450cm` 常量。

## 3. 指挥官 3C

### 3.1 远距地面点选

- 鼠标地面射线长度为 `600000cm`，使用显式反投影与 `ECC_Visibility`。
- 一次解析最多跳过 16 个非 Landscape 阻挡物，最终只接受 `ALandscapeProxy` 命中。
- Soldier 模型和脚环 ISM 保持 `NoCollision`。
- LMB 选择、RMB 移动和选区预览必须调用同一地面解析函数，避免不同输入得到不同落点。

### 3.2 移动目标与松散到达

- 同一次命令中所有已接受 Cohort 共用同一个 NavMesh 投影目标；投影的水平修正不能超过 Soldier `AgentRadius`。
- 删除多 Cohort 的目标网格偏移、终点完整 5×5 足迹验证与最终方阵展开。
- 途中继续使用共享路径和 1–5 列弹性队形；真正进入最后接近阶段后取消槽位修正，让 Mass Avoidance/分离力在目标域内自然铺开。
- 到达域按本批命令初始接受的唯一 Soldier 数量 `N` 缓存。取最小整数 `k` 满足 `1 + 3k(k + 1) >= N`，半径为 `2 × AgentRadius × k + 500cm`。
- 同一批次只有在引导点到达、尾兵越过末弯，并且所有仍存活且仍跟随该订单的成员进入到达域后才能统一完成；死亡或已被新订单覆盖的 Soldier 不阻塞。
- 目标无法在一个 AgentRadius 内投影时返回 `InvalidTarget`；路径无效或 Partial 时返回 `PathFailed`。

### 3.3 Heading-up 小地图

- Panel、背景、边框、标题、提示文字和 HitBox 固定不转。
- 地形、坐标轴、兵点和相机视野框以世界边界中心为轴，相对玩家摄像机反向旋转，使摄像机前方始终对应小地图上方。
- 地形对现有 20×20 高度缓存做逆旋转采样；动态图元使用同一变换并裁切到 Panel。
- 点击聚焦执行严格逆变换；旋转后落在战场范围外的空角不得跳转。

## 4. 运行时 GM 调参

- 新增 World 会话级白名单注册表；优先级固定为 `C++/蓝图兜底 < DataTable 基线 < 当前 World GM Override`。
- 指令仅在非 Shipping 构建注册：
  - `gs.GM.List [prefix]`
  - `gs.GM.Get <key>`
  - `gs.GM.Set <key> <value>`
  - `gs.GM.Reset <key|all>`
- 首批 key：
  - `soldier.move_speed_cm_s`
  - `soldier.max_health`
  - `soldier.attack_power`
  - `soldier.defense`
  - `soldier.attack_range_cm`
  - `ship.max_speed_multiplier`
  - `ship.acceleration_multiplier`
- 缺参、额外参数、未知 key、尾随字符、NaN、Inf、非整数生命和越界值必须拒绝，不得静默钳制。
- 日志回显 baseline、旧/新 effective、来源与影响实例数。
- Soldier 移速在下一次 30Hz 权威步生效，同时更新活动 MoveTarget、速度和 Mass shared movement parameters；GameState 只复制一份有效速度与 revision，客户端据此预测。
- 修改最大生命时，存活单位按原生命比例换算，死亡单位保持 `0`；战斗 Stats 立即更新。
- 飞船使用保留的 `GM.Runtime` 修饰层并调用唯一重算入口；现存与后续出生飞船都继承当前 World 的有效倍率，Reset 不影响其他 Gameplay Modifier。
- `Set/Reset` 只允许 Standalone、Listen Server 和 Dedicated Server；纯客户端必须拒绝。
- Override 随 World 销毁，不写 Excel、DataTable、CDO、ini 或磁盘；本轮不支持 GM 热切换 Soldier 模型。

## 5. 公共合同与兼容性

- 新增生成行 `FGuLiStrikeCommanderSoldiersRow` 和校验后的 `FGuLiSoldierDefinition`。
- 新增 Authority 的 baseline/effective 查询与批量应用接口、Ship 的 GM 倍率设置/清除接口，以及结构化 GM 操作结果。
- 保持现有 SoldierId、命令 RPC、PoseChunk 和 `uint8 Health` wire contract；只增加 GameState 级有效 Soldier 移速和 tuning revision。

## 6. 验收标准

- 数据导出可重复执行且结果稳定；UE DataTable 能回读唯一 `DefaultSoldier` 行，模型确认为 `UStaticMesh`。
- 500 名 Soldier 出生时使用表内基线，默认有效移速为 `3600cm/s`，预测距离为 `900cm`。
- 自动化覆盖 resolver、移动/到达、heading-up 变换、GM 注册与解析、生命比例、客户端权限和预测距离。
- 真实 World 中 `List/Get/Set/Reset` 可工作，Soldier 调参报告 500 个实例，移速在下一个 30Hz 边界完成 Mass 更新；飞船倍率能更新现存实例。
- 编辑器目标和非编辑器 Game 目标均可完整编译。
- 远距点选四档高度、复杂路径/窄口以及 Q/E 连续旋转手感仍需可视 PIE 人工验收，自动化结果不能替代这部分体验验证。

## 7. 本轮不做

- 多兵种混编、骨骼动画和 Soldier 模型 GM 热切换。
- 攻击 AI、目标选择、命中判定和伤害公式。
- 万人规模、正式 Dedicated Server 打包与完整性能 Gate。
