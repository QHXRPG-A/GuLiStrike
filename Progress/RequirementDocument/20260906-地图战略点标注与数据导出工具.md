# 地图战略点标注与数据导出工具

## 背景

GuLiStrike 的大地图需要持续布置资源点、据点等战略位置，并编辑它们的作用范围。直接把坐标手填进 Excel 缺乏地图上的视觉参照，使用通用 Trigger/Volume 又没有稳定 ID、类型约束和可重现导出。需要一个项目内自给自足的地图标注工具，让设计者在 UE 视口中完成空间布局，再导出人和自动化都能读取的数据，供后续回填 Excel/DataTable。

## 需求描述

1. 在当前已保存地图的视口内新建、选中、移动和删除地图标记。
2. 交付嵌入 UE5 编辑器的项目插件，首批预设包含资源点、据点和通用标记。新增类型、显示名称、颜色、默认区域及字段通过类型配置资产完成，不依赖修改类型枚举或购买商城插件。
3. 每个标记具有稳定业务 ID、显示名、类型/子类型、启用状态、标签和备注；业务 ID 不从 Actor 名或坐标推导。
4. 位置通过 Actor Transform 编辑；点标记可以没有区域。同一标记支持多个命名区域，例如 Capture、Build、Influence；各区域独立编辑偏移、旋转、形状和尺寸。首版包含圆形加高度（圆柱）、球体、方框和不规则闭合多边形加高度，支持凹多边形，暂不支持洞、自交或样条路径。
5. 提供标记列表、类型筛选、一键定位、批量校验和导出入口。
6. 导出前校验地图已保存、ID 非空且唯一、类型合法、范围为正值；错误必须指向具体 Actor 和字段。
7. 同时导出 UTF-8 JSON 和扁平 CSV，按业务 ID 稳定排序，便于人读、Git diff 和后续自动填表。
8. 导出包含格式版本、地图资产路径、稳定 GUID、可读业务键、类型及字段定义、世界坐标、旋转、命名区域、范围形状/尺寸、完整多边形顶点、扩展字段、标签和备注。空间量统一以 cm 保存、角度以 degree 保存；CSV 在列名标明单位，面板可显示 m，不维护两份独立可编辑坐标。
9. 空间布局及地图实例字段以地图标记为唯一编辑源；类型定义资产负责字段结构与默认值。Excel 后续补充玩法数值时，应明确字段归属，不反向覆盖地图负责的字段。
10. 编辑面板和现有 UnrealMCP/Python 通道共用创建、读取、修改、校验及导出接口。首版交付到 JSON/CSV，之后再按用户要求接入 Excel→DataTable 管线。
11. 扩展字段具有稳定字段 ID；增加字段或重命名时保留已有值。删除字段或修改字段类型不得静默覆盖旧数据，需显示冲突并提供可撤销的显式升级操作。
12. 特殊范围形状、类型校验和导出格式具有 C++ 注册接口；后续扩展可由附加编辑器模块提供。

## 边界

- 首版不处理地形、植被、美术资产摆放、光照或 PCG。
- 首版不自动计算地面可达性、导航路径、阵营平衡、资源收益或据点占领规则。
- 首版不提供样条路径、多边形内孔、曲线边界、触发条件/事件执行图、运行时地图编辑或比赛规则执行。
- 不用 Actor Scale 隐式表示范围，避免非均匀缩放和单位误解；范围由 Radius/Extent 等明确字段表示。
- 不把 JSON/CSV 设为第二个手工编辑源；它们是可重建导出物。
- 本轮交付开发规划文档；插件实施时再创建原生代码、类型资产和测试。第一版不制作 Excel 工作簿，不接入 GameMode，不生成游戏运行时配置资产。

## 已确认选择与默认值

- 2026-09-06 用户明确选择：配置式类型和字段；首版包含不规则区域；只交付插件和 JSON/CSV；同一标记可拥有多个命名区域。
- 工具基于当前编辑器的已保存地图工作，不硬编码地图名。核对 `Config/DefaultEngine.ini` 后，项目启动地图实际为 `/Game/Maps/LVL_CommanderMassPrototype`；旧草案的 `LVL_Main` 假设取消。
- 2026-09-06 实时探测时编辑器世界为 `/Temp/Untitled_0.Untitled`；这不是可稳定导出的正式地图，实施验收前需打开或保存目标地图。
- 首版按几十至几百个战略标记设计；标记放在当前世界的持久关卡。兼容 World Partition 时需核对标记描述符，避免只导出视口附近加载的标记。子关卡独立布局、Level Instance 布局复用和千级性能优化留作后续。
- 最终 Excel 工作簿的名称与表结构属于后续填表任务，不作为本插件首版的前置条件。
- 用户已明确允许新增聚焦自动化测试，限定为新插件 `GuLiMapAuthoringEditor/Private/Tests/GuLiMapAuthoringTests.cpp`，覆盖配置类型/字段扩展、ID 与撤销、区域几何、保存回读及 JSON/CSV 一致性；另做视口人工验收。

## 验收标准

- [ ] 用户能在 UE 视口中放置一个资源点和一个据点，拖动位置并直观看到各自范围。
- [ ] 面板可列出、筛选并定位所有标记，且地图重新打开后数据仍保留。
- [ ] 同一据点可同时保存两个不同形状的命名区域；凹多边形可增删、拖动顶点并显示高度范围。
- [ ] 仅新建类型配置资产即可加入一个新类型及其自定义字段，能够放置、保存、重开并导出，无需改 C++。
- [ ] 增加/重命名字段保留实例旧值；不兼容变更明确提示，用户处理前不丢数据、不导出错误结果。
- [ ] 重复 ID、空 ID、无效范围或未保存地图会阻止导出并给出可定位错误。
- [ ] 相同地图数据连续导出产生字节级稳定的 JSON/CSV，修改一个标记时 diff 只体现相关记录。
- [ ] JSON/CSV 可被 Codex 直接读取，多个区域、多边形顶点和扩展字段均完整，能够供后续填表使用，不需要解析 `.umap` 二进制。
- [ ] 导出中的地图路径、坐标、旋转、各形状尺寸和世界空间顶点与视口属性回读一致。
- [ ] 复制标记生成新身份，撤销/重做恢复原操作身份；标记只用于编辑器，不参与碰撞、导航或游戏逻辑。
