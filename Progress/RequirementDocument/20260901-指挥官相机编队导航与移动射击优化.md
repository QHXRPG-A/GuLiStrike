# 指挥官相机、编队导航与移动射击优化

## 背景

当前指挥官原型在起伏地形和大规模编队移动中存在四类直接影响可玩性的故障：相机经过坡地会突然跳高或越出地图；单位经过高差道路时可能卡住并持续抽搐；多个单位共用宽松目标区后会长期互相避让、难以彻底停下；原“移动命令期间停火”规则又会让持续运动的部队长期无法普攻。红蓝双方当前部署距离也过远，不利于快速验证移动交火。

现象诊断确认，抽搐由多项移动规则叠加造成：个体沿整体引导方向切弯、导航约束仅每200ms发生一次、约束失败后仍继续发布速度、到达单位继续接受避让推动，以及单个失效成员拖住整批命令。需要把长程寻路、个体贴NavMesh移动、局部避让和终点编队分工明确，并让无法恢复的单兵稳定退出命令。

本需求只增量修改指挥官相机、出生部署、Mass移动和扫射行为。已经完成的扫射技能、指挥官GAS军队桥接、多兵种配置、技能替换与数值修改、浮点生命和协议v5继续沿用，不重写公共技能桥接。

## 需求描述

1. 增加共享Landscape查询能力，缓存Landscape Proxy与真实边界。相机、HUD和小地图统一使用真实Landscape边界；单位、建筑等Visibility命中不能作为地面高度回退。
2. 关闭SpringArm碰撞收缩和内置Camera Lag，使用显式姿态求解稳定相机。相机以不大于1/60秒的子步更新，每帧最多8步；沿摇臂每不超过10000cm采样一次地形，保证枢轴、摇臂、相机分别至少离地150、200、500cm。
3. 相机抬升与下降限速为30000cm/s和15000cm/s。候选平移、旋转或缩放无法安全抬升时，对本步操作做8次二分缩减，禁止穿地、突然缩臂或因单次错误命中跳变。
4. 根据实际宽高比、FOV、俯角和臂长计算完整视锥的落地范围，使整个画面保持在Landscape边界内并保留5000cm边距；最大缩放无法容纳时限制实际臂长。`JumpToWorldLocation`使用同一边界与净空求解并清理旧平滑状态。
5. 边缘滚屏使用16个DPI逻辑像素和SmoothStep强度，仅在游戏视口聚焦且鼠标位于视口内时生效。
6. 红方出生中心改为`(-10000, 127500, 0)`，蓝方改为`(110000, 37500, 0)`，平面距离150000cm。每个出生方阵朝向敌方中心。
7. 创建Mass实体前原子验证全部500个出生槽。任何槽投影失败、XY修正超过750cm、重复或槽间距低于1600cm时整批不生成并报告错误；禁止用未投影的请求坐标继续出生。
8. 移动命令先完成规划再修改单位状态。以选中单位质心到点击点确定朝向；零长度时依次使用平均朝向和世界+X。
9. 每25人cohort拥有固定5×5终点块，槽间距1800cm，块中心间距9000cm。cohort和单位均按稳定ID排序，通过确定性匈牙利匹配分别分配块与槽，减少交叉穿插和终点争抢。
10. 每个实际终点槽都必须投影到CommanderSoldier NavMesh，XY修正不超过750cm、槽间与同队现有静止/活动终点间距不低于1600cm，并通过短程可达检查。敌军不参与终点预约，允许向敌军附近下令。
11. 槽、共享路径和预约先暂存，成功cohort一次性提交；失败cohort返回`PathFailed`并保留旧命令。允许既有`PartiallyAccepted`语义，但任何cohort内部不得留下半套新状态。
12. 同一OrderId内终点槽固定，成员死亡留下空位，只有新命令才重排。途中列宽可以由5列缩到1列，终局保持5列。末段触发半径按“最远槽半径＋一步距离”计算，旧全批人数宽松到达圈不再决定完成。
13. 每个单位保存完整`FNavLocation LastValidNavLocation`，并在出生、调试生成、新命令和NavMesh重建时初始化。每个30Hz权威步骤均通过`FindMoveAlongSurface`约束候选位置；只有成功结果才能提交并更新NodeRef，单步Z变化超过250cm视为失败。
14. 普通行进方向由70%个体路径Lane Waypoint和30%终点槽纠偏组成；共享Guide沿路径XYZ插值。Mass Avoidance继续负责主要局部避让，手工分离只处理仍在移动且实际重叠的单位。到达、空闲和Blocked单位不再接受推动，但继续作为静态障碍供移动单位避让。
15. 距槽不超过`max(100cm, 速度×固定步长)`时验证最后一段导航并吸附剩余距离。完成后速度和力归零、Mass切换为`Stand`、清除该兵`ActiveOrderId`，并保证后续避让不会让其重新挪动。
16. 动态列宽收窄立即生效；扩宽需要连续15个成功步骤，且每0.5秒最多重排一次，避免窄路边界反复切换。
17. 卡住恢复采用`Normal → CenterlineRecovery → PersonalPathRecovery → Blocked`。路径游标推进或距当前Waypoint改善至少30cm才算进展；连续2次表面移动失败或1秒无进展时进入中心线恢复；再1秒无进展或累计6次失败时排队计算个人短路径。
18. 个人短路径按SoldierId排序限流，每个固定步最多4次查询。个人路径2秒无进展时只重寻一次，再失败2秒进入Blocked。
19. Blocked单位停在最后合法Nav点，切换`Stand`，清除`ActiveOrderId`并增加`StateRevision`，同时保留失败OrderId、最终槽、失败原因、次数和时间。Blocked单位不能传送、抽搐或拖住其他成员。
20. 选择摘要忽略已到达和Blocked成员的零OrderId，从仍执行的成员中计算共同非零OrderId；不存在执行者或存在两个不同非零命令时返回0。
21. NavMesh重建只刷新仍合法终点槽的Z，并按SoldierId修复失效槽，不移动其他预约。无法修复的成员进入Blocked，已经完成的旧命令不得复活。
22. “扫射”删除移动停火门。移动、恢复和到达转换不清目标、不刷新冷却，保持完整伤害、射速与射程；继续使用200ms分批索敌、开火前复核、三维距离、每步最多一发、无补射、统一伤害结算和同归于尽。
23. 固定步顺序为“移动及到达更新 → 攻击采样 → 统一伤害结算”，射程使用本步移动后的权威位置。兼容保留`Moving`停火枚举，但扫射不再产生该原因；GM分别展示导航状态与实际停火原因。
24. 增加服务器只读导航状态、单兵诊断与聚合统计接口，以及非Shipping命令`gs.GM.Commander.Nav.Soldier <SoldierId>`、`gs.GM.Commander.Nav.Stats`、`gs.GM.Commander.Camera.Debug <0|1>`。

## 边界

- 不设计或开发科技树、卡牌、火炮、附加效果、正式特效、动画、音效；不改现有技能桥接公共接口。
- 不在本期引入完整DetourCrowd、ORCA或流场移动。现有流场接口保留但继续关闭。
- 不修改协议v5的快照线形和ACK；Blocked只通过服务器日志与GM观察。本期不增加客户端可靠失败事件或协议v6。
- 不把敌军加入友军终点预约；本期不解决双方终点互占所需的战术站位规则。
- 万人移动只采样并记录结果，不承诺达标；500兵移动交火以权威30Hz步骤P95低于33.3ms为本期性能目标。
- 不修改旧扫射需求和既有归档的历史原文。

## 验收标准

- [ ] 30/60/120fps、16:9和超宽屏下，相机经过起伏地形、地图四角和最大缩放时无穿地、突然缩臂、跳出Landscape边界；失焦不触发边缘滚屏，小地图跳转稳定。
- [ ] 红蓝出生中心平面距离为150000cm；双方各250个出生槽全部投影成功、XY唯一、最小间距至少1600cm，任一非法槽都能阻止整批创建。
- [ ] 25、250、500兵移动命令得到稳定唯一的固定终点；友军预约、部分接受原子性、死亡留空、新命令重排和选择摘要符合规则。
- [ ] 起伏坡面连续移动无200ms高度阶梯，90度路径不切角，任何单位不离开Commander NavMesh；跨层单步Z变化被拒绝。
- [ ] 当前`OrderId=19`基线路线修复后全员结束，`Blocked=0`；到达成员连续2秒位置与速度不变。
- [ ] 人工不可达成员按阈值进入中心线恢复、个人恢复和Blocked，不抽搐、不传送、不拖住同批其他成员；个人查询每步不超过4次。
- [ ] 扫射在移动与恢复期间维持完整射速、目标和连续冷却；仍满足无补射、每步最多一发和同归于尽。
- [ ] GM能查询单兵导航状态、失败上下文和聚合统计，并能独立开启相机调试；Shipping不暴露这些命令。
- [ ] Editor与Server构建通过，全量`GuLiStrike`自动化及已有技能桥接回归通过。
- [ ] Dedicated Server加双客户端验证协议v5、移动射击、浮点生命、死亡与姿态一致，客户端不重复结算战斗。
- [ ] 500兵移动交火的权威30Hz步骤P95低于33.3ms并记录终点规划耗时；万人移动仅留存采样数据与限制说明。
- [x] 实现后更新`战斗.md`、`指挥官.md`和Mass移动说明，并新增只增不改的验证归档。
