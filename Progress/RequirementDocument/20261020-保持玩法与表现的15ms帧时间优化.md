# 保持玩法与表现的15ms帧时间优化

## 目标与基线

用户要求：读取 [ADAC6F2F 报告](D:/UE5.7/PerformanceCaptures/GuLiStrike/20261020-115158-ADAC6F2F/report.md)，在不改变玩法和表现的情况下优化到 15ms。

- 平台：源码 UE5.7.4，Win64 Development Editor。
- 地图：`/Game/Maps/LVL_CommanderMassPrototype`。
- 基线：5.032 秒，192 个完整 Tick 帧；平均帧间隔 25.929ms，P95 46.133ms。
- 负载：600 存活战斗单位，其中渲染客户端本地模拟 300、对端模拟 300；矿车和工程车各 16；建筑 32。据点、资源节点与逻辑更新频率均保持。
- 视口：1600×1104，嵌入式 PIE；全部前台，独立逻辑客户端和 Coordinator。
- 15ms 暂按平均完整帧时间验收，同时保留 P95、峰值、前后台和实际负载。不能把平均达标写成每帧均低于 15ms。

## 边界与验收

- [x] 同等相机、分辨率、画质、单位和建筑负载下，重复短窗平均完整帧时间不超过 15ms。
- [x] 不降低模拟频率，不暂停生产、采矿、冷却、避障和网络业务，不减少单位或特效。
- [x] 不调整阴影、光照、分辨率、LOD 或功能开关换取成绩。
- [x] 分开报告诊断采样期间和日常运行帧时间；编辑器开销和采样观察开销均明确披露。
- [x] 采样优化继续保留 CPU 细分、原生负载与队列、Slate 归属有效性和可用的 RenderDoc 截帧。
- [ ] 保留前后证据及配置，人工操作与视觉一致性由玩家确认。

现有地图直接复用，不添加与性能目标无关的测试 Actor，不改写玩法文档或美术资产。

## 自动复测结果

[最终证据报告](D:/UE5.7/PerformanceCaptures/GuLiStrike/optimization-15ms-20261020/report.md)：基线 25.929ms，最终两次完整 CPU 窗口 13.567ms / 13.586ms，按帧数加权 13.577ms，降低 47.64%。正常无文件 Trace 的 8 秒窗口为 13.076ms。两次 P95 为 19.320ms / 19.233ms，峰值约 27.5ms，不代表每帧低于 15ms。

全部原生样本核对 600 战斗单位、32 建筑、矿车/工程车各 16、资源簇 240、领地 49；实际逻辑频率约 60Hz。相机和画质读回一致，玩法模块身份与原报告一致。普通启动不自动附加 RenderDoc；显式 `-AttachRenderDoc` 启动保留 GPU 截帧，并已完成最终回归。

场景已保存并完成实体核对，编辑器保持打开；人工复核仍待玩家确认。长局负载增长、其他硬件及 GPU 调试启动不包含在本次短窗达标结论中。
