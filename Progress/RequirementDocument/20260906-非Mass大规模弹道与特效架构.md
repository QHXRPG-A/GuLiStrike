# 非 Mass 大规模弹道与特效架构

## 背景

项目需要在大量单位同时交火时呈现爆炸、激光、曳光弹、普通弹道和少量高价值导弹，但不希望为了这些短生命周期对象引入逐实体 Mass Fragment、Processor、Representation 与同步成本。

现有 `UGuLiCombatEffectRuntimeSubsystem`、`UGuLiCombatEffectPresentationSubsystem`、`UGuLiCombatEffectReplicationComponent`、Damage Ledger 和枪火 Niagara Data Channel 已形成非 Mass 基础链路。本需求在这条链路上扩展，不另建一套互相竞争的战斗结算系统。

### 假设

- “不用 Mass”指弹道、爆炸、激光和对应客户端表现不依赖 Mass；不代表本次移除 Commander 单位移动、选敌等已有 Mass 实现。
- 继续保持服务器权威伤害，Niagara 只负责可重建表现。
- 第一阶段以项目已有 500 单位交火场景为规模参考；最终目标平台、分辨率和硬性帧预算仍待确认。

## 需求描述

1. 所有新增弹道/特效公共协议只使用稳定目标句柄、Guid、数值和软资产引用，不暴露 Mass Entity、Fragment 或 Processor 类型。
2. 不为每颗普通子弹、每束激光段或每次短爆炸创建 Actor；服务器用世界子系统批量推进逻辑，客户端用共享 Niagara System、Data Channel 或受控组件池重建表现。
3. 建立三类表现通道：
   - 瞬时批量通道：枪口、曳光、命中火花和高频小爆炸。
   - 持续流通道：持续激光、批量可见弹体和长弹道端点。
   - 英雄特效通道：需要独立停止、修正或消散的导弹、大爆炸和持续法术场。
4. 爆炸的范围查询和伤害只执行一次权威结算；火花、烟、碎片、灯光、贴花均为可裁剪装饰层。
5. 激光只同步起点、终点、状态和时间；命中由服务器 Trace/目标查询决定，不以 Beam/Ribbon 粒子碰撞决定结果。
6. 普通弹道优先使用 Hitscan 或解析轨迹；确需飞行过程的逻辑弹丸由定频批处理器推进，客户端预测并接收低频校正。
7. 客户端必须按重要度、距离、可见性和当前预算降级；过载时先移除灯光、折射、碎屑、次级烟和 Ribbon 细分，保留攻击来源、方向、命中位置、阵营颜色和时序。
8. 网络只复制紧凑语义事件。瞬时表现允许不可靠丢弃；长生命周期效果可靠创建/终止并提供活动快照；Dedicated Server 不创建纯表现组件。
9. 所有效果必须具有确定的生命周期、Bounds、池回收和换局清理策略；禁止热路径同步加载资产。
10. 提供服务器逻辑、客户端表现、网络和 Niagara 成本计数器，并在固定场景中记录优化前后 p50/p95，而不是依据单帧或粒子数量判断完成。

## 边界

- 本需求不迁移或删除 Commander 单位系统中的 Mass，也不修改其移动、编队、选敌和 LOD。
- 首阶段不合并现有僚机 `UGuLiLogicalMissileSubsystem`，只保证新协议可在后续适配；避免一次性重写已工作的战斗路径。
- 不让 Niagara、材质或客户端 RPC 成为伤害、冷却、命中或目标选择的权威来源。
- 不引入新运行时插件，不修改引擎或商城资产；继续使用项目已有 Niagara 依赖和项目自有资产目录。
- 本轮只输出方案和任务清单，不修改 C++、蓝图或资产。
- 未经用户单独授权，不新增或扩充自动化测试、测试角色或性能测试矩阵。

## 验收标准

- [ ] `Gameplay/CombatEffects` 的新增公共接口和实现无 Mass 头文件、类型或反向依赖。
- [ ] 高频枪火、激光和普通弹道不存在逐发 Actor/逐段组件路径；同类数据可批量提交。
- [ ] 服务器关闭纯表现后，伤害、命中、冷却和终止结果保持一致；丢失不可靠表现事件不会丢失伤害。
- [ ] Dedicated Server 的 Niagara/纯表现组件数量保持为 0；客户端仍能重建必要表现。
- [ ] 爆炸、激光和弹道分别验证正常、重复触发、离屏、超距、拥塞、换局和所有者销毁后的清理行为。
- [ ] 最低画质仍能看清攻击来源、方向和命中位置，次级烟、火花、灯光、折射等按既定顺序降级。
- [ ] Niagara System 零编译错误；开始、峰值、消散和池复用均有回读及视觉证据。
- [ ] 在确定目标平台和帧预算后，以固定地图、镜头、分辨率、网络模式和采样时长记录 p50/p95；结果达到批准预算且无可靠队列持续增长。
- [ ] 若进入 C++ 实施，最终通过源码版 UE5.7 的 Editor 构建与 BuildId 门禁；需要 Game/打包验收时追加对应目标。
