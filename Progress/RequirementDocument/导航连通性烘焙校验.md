# 导航连通性烘焙校验

## 背景与目标

指挥官海岛已经出现山脚和高台分别可投影到导航、二者之间却只能得到部分路径的情况。此前对据点的寻路抽查不能证明整张导航图连通。新目标是提供确定的两点连通判断，并在烘焙阶段拒绝存在孤立可行走地块的地图。

## 需求描述

- 指定地图 `/Game/Maps/LVL_CommanderMassPrototype` 的整个 CommanderSoldier 可行走导航表面必须属于一个双向连通区域。没有导航的海域、陡壁不属于可行走地块。
- 沿用项目 CommanderSoldier 代理配置、Recast 默认查询过滤器和有效特殊链接规则。其他代理不能替代它。
- 两点查询分别返回正向和反向是否可达；区分连接、单向、断开、起终点未覆盖及依赖错误。投影偏移不得超出调用方明确提供的范围。
- 检查整张导航图，不只据点或基地；不使用部分路径成功、不依赖 A* 搜索节点上限、不忽略小孤岛。
- 原生导航烘焙返回失败，并报告各连通区域的位置、范围、面积和多边形数量。缓存命中也必须执行检查；PIE 许可检查和 Cook 校验复用同一结果。
- 校验在编辑器模块执行。运行时 Mass 移动、占领、运输及资源规则不改变。

## 边界

本次实现包括离线图分析、两点查询入口、现有 GuLi 导航烘焙集成、指定地图配置和验证点。UE 自带 Build Paths 生成数据仍由引擎负责；GuLi 的 Prepare/Validate 对结果进行认证。不开新通用测试图，不修改地形，不新增自动化测试，不自动开始 PIE、无头验收或打包。编译遵循项目单独授权规则。

## 验收标准

- [ ] 完整指挥官导航图仅有一个双向连通区域时，Prepare/Validate 可以成功；多于一个区域或依赖缺失时失败。
- [ ] 当前山脚→高台断开例子返回断开，同一山脚区域的两点返回双向连接。
- [ ] 两点未被导航覆盖时给出对应状态，不将附近其他区域投影当作原点。
- [ ] 原生烘焙失败不提交新的成功元数据、不保存本次烘焙输出；命令行烘焙保留非零退出码。
- [ ] 错误输出能够定位区域，且完整结果可由 Python/Blueprint 读取。
- [ ] 在指定地图保存验证标记并核对实体；玩家在加载本次代码后通过真实烘焙和只读查询验收。
