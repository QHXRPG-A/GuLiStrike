# 指挥官 UI 与小兵血条视觉设计

> 日期：2026-08-29  
> 状态：已确认并完成视觉实现，等待视觉审核  
> 类型：纯表现 / UMG 静态视觉稿

## 背景

为指挥官模式建立第一版可审核的 RTS HUD 视觉语言。本轮只解决信息层级、空间布局、色彩、图标与小兵血条状态，不接入任何玩法数据或运行时入口。结构参考 Iron Harvest 的底部指挥区组织方式，风格参考 StarCraft II 的科幻宇宙感；参考图只用于分析，不导入或复用其中素材。

## 目标

- 在 `/Game/Commander/UI` 建立顶中战况、左下战术地图、底部指挥坞组成的“三岛式”静态 HUD。
- 提供独立小兵血条视觉组件与包含四种血条状态、三种按钮状态的审核板。
- 生成六枚统一风格、透明底的 RTS 命令图标：移动、攻击、停止、坚守、巡逻、集结。
- 在 1920×1080、1280×720、2560×1080 三种画幅下保留信息层级和安全间距。

## 静态视觉合同

| 区域 | 设计尺寸 / 内容 |
|---|---|
| 顶中战况条 | 420×64；目标“轨道控制”；比分 `02:02`；时间 `08:42` |
| 左下战术地图 | 276×276；纯 UMG 网格、阵营点、路径与视野框 |
| 底部指挥坞 | 1120×204；6 张编队卡、指挥官核心、资源条、5×3 命令矩阵 |
| 小兵血条 | 84×12 @1080p；2px 黑框；红色连续填充；25%/50%/75% 分隔；默认 75% |
| 审核板 | 明示“视觉稿 / 未接逻辑”；满血、受伤、选中、危急；默认、悬停、禁用 |

统一样例值：战术点 `1280`、编制 `75/100`。主色为 `#050A12`、`#0B1622`、`#18D7FF`、`#D1AF86`、`#EDF8FF`、`#E44758`。

## 边界

- 不自动加入视口，不新增或修改 Blueprint 函数、事件、绑定、Tick、复制字段或玩法数据读取。
- 不修改 C++、Config、地图、Mass、Navigation、单位表现、Soldier Resolver/DataTable 或 `M_CommanderUnitRing`。
- 不制作逐兵 `WidgetComponent`，不启动 PIE，不切换地图，不改变运行时入口。
- 本需求通过视觉审核后，下一轮才讨论 HUD 接入、数据绑定、输入保护与批量世界空间血条。

## 验收标准

- 三份 WBP 可由 WidgetService 完整回读、校验、编译并分别保存。
- 三份 WBP 均无属性委托、动画、MVVM、用户函数、Event Tick 或其他图表节点。
- 六枚图标保留透明 Alpha，使用 UI 纹理组、无 mip、最大尺寸 256，并由 UMG 负责状态着色。
- 标准、窄屏、超宽和组件近景截图可人工检查中文、透明边缘、重叠、安全区与最小文字。
- 本轮变更只包含新 UI 资产、图标源图、审核截图和独立 Progress 文档；既存性能优化改动保持原样。
