# GuLiStrike 美术规范

本文件是项目美术方向与制作验收的统一入口，由 `gulistrike-progress` 维护。所有 GuLiStrike 视觉资源制作前必须读取；模型、特效、地编、UI与卡牌技能统一执行第11节色库及相应资产规则。具体参考图、资产例外和已过审版本要随任务核对，不能只记住“低模”或“三渲二”两个标签。

优先次序：用户当前明确指示 → 已确认的资产专属设计与例外 → 本规范默认规则 → 技能中的通用制作经验。新默认规则不自动改写已有资产；本次建立文档不触发全项目重做。

## 1. 总体方向

**动漫机械科幻：清楚的剪影、完整的机械设计、干净的大色块、适度低模、线稿与分档光影。新模型默认同时制作线稿和三渲二。**

- 与 Ship 统一的是造型、色块、线条和光影语言。不同兵种、建筑可以有各自配色；今后的基础配色从第11节统一色库选择，不能把“同风格”理解为全部涂成 Ship 的蓝白色。
- 低模是实现和预算选择。已审参考中的比例、装甲弧度、层叠关系、武器、支座、轮毂、悬浮盘等识别特征必须保留，不能为了少面数变成粗糙方块或低龄玩具造型。
- 表面平整光顺，机械边缘有控制地切角、倒角；设计要求的凸曲面和圆周必须保留。禁止生成网格式波浪、融化、随机鼓包和模糊涂装。
- 细节以中尺度、可解释的机械结构为主，主次有序。简约贴图不等于删空结构，也不等于完全不允许动画贴图、遮罩或图集。
- 美术制作不擅改伤害、攻击数量、节奏、兵种 ID、碰撞和已有挂点契约。

## 2. 制作与审核流程

模型严格按以下顺序推进：**用户需求 → 参考图 → 用户审核 A → Blender 一比一还原 → 用户审核 B → 导出并导入 UE → 引擎内验证。**

| 阶段 | 应交付的可审核内容 | 放行条件 |
|---|---|---|
| 参考设计 | 按需求制作的效果图、正/侧/背三视图；说明尺寸、功能、活动件、配色和特殊结构。设计图之间应一致。 | 用户明确通过具体版本，记录原话/消息依据和对应文件。 |
| Blender 还原 | 按已审图制作完整模型，包含默认线稿和三渲二；提供与参考同视角对照、三视角成品及必要的灰模/活动件演示。 | 用户审核实际 Blender 成品并通过该版本。参考图过审不能代替此审核。 |
| UE 交付 | 通过 B 的源文件、FBX、纹理和 UE 对应材质；导入后的真实游戏距离截图、尺寸/挂点/碰撞/LOD读回。 | 技术检查与视觉一致性通过；若 UE 出现外观差异，修复并提交差异复核。 |

“一比一”指忠实还原设计的轮廓、比例、曲面、厚度、分件、装配、色块和主要细节，不要求照抄图中的透视错误或画笔噪点。三视图冲突时，以用户已确认的文字和最新指定版本为准；无法判断的关键设计须在 A 阶段解决，不能建模时自行改造。

已明确过审的参考可以复用，不重复索要同一阶段批准。用户明确指定当前可见成品版本导入或明确免除某阶段审核时，记录其授权范围；笼统的“开始制作”不能被记成尚未展示成品的 B 审核通过。未获得所需审核时，先完成可审核产物并等待，不提前导入或覆盖正式资产。暂停审核须链接触发它的技能/本规范并说明这是用户规定的流程。

保持可编辑 Blender 分件与版本，当前路线为 Blender 手工/程序化规则几何建模，不再使用 Tripo 生成网格作为模型交付。AI 可用于前期二维参考；只有实际需要出图时调用图像制作技能。概念图不能冒充三维成品截图。

**特效与地编的适用方式：** 专用模型依然走上述 Blender 双审；纯 Niagara、材质动画和场景灯光在 UE 隔离预览副本中制作。特效先提交参考/时序分镜审核，再提交可播放候选审核，通过后接入正式战斗引用；不能以截图已通过代替动画审核。仅布置已审资产不要求重新建模。已有明确授权与过审记录延续有效，不增加重复审批。

## 4. 造型、材质与线稿

### 4.1 造型还原

- 先按三视图确定长宽高、剪影和大结构，再做装甲厚度、关节与中尺度细节。对称件共用参数镜像；偏移必须来自明确设计。
- 圆轮、轴承与悬浮盘保持规则圆周；装甲凸面用规则截面构建。不能用整体平滑掩盖坏拓扑，也不能靠重着色解决几何失真。
- 减面优先删不可见内部面、重复面和不影响剪影的小细节，随后生成距离 LOD。需要露出、运动、毁坏或透过间隙看到的内部结构不得直接清空。
- 面数目标按资产用途、屏幕大小和并发数量确定，区分主体、描边、各LOD及实际材质槽。预算不达标要如实记录，不得用未经审核的造型简化换取“通过”。

### 4.2 材质与三渲二

- 默认三档明暗：亮部、中间色、阴影；使用有限且清楚的色阶，允许为保持弧面阅读设置适度过渡。不能把每个三角形都染成不同色块。
- 大面积干净主色，辅色用于分件，少量功能色用于灯、武器口及识别。装甲低反射，暗部带色相且可读；避免油亮塑料、写实污渍、随机划痕和密集凹凸。
- 色块边界、遮罩和 UV 必须清楚，不能拉伸、漏色、发糊；不要把展示场景的阴影或高光烘进 BaseColor。
- 允许固定艺术光向或受场景光影响的三渲二方案，按审核结果选用并说明限制。Blender 的 Shader to RGB 节点不会自动成为 UE 材质，必须在 UE 重建等效结果；普通 PBR 自动导入成功不算风格交付。

### 4.3 线稿默认与资产例外

线稿包含主要装甲分界、凹槽和外轮廓，**不是三角拓扑线框**。外轮廓略重、内部线更细；使用深蓝灰等与配色相容的暗色，避免近景糊边、远景黑团、双重描边或所有棱边等粗。

内部结构线优先烘焙为独立灰度遮罩，方便调强度和关闭；不把所有内线做成额外几何。自由视角的外剪影默认独立轮廓壳或等效可靠方案，不能指望贴在表面的线条覆盖所有视角。轮廓不投影、不碰撞；实例规模大时评估壳成本与远景淡出，不能自行取消已审线条效果。

### 4.4 指挥官模型 LOD

指挥官 Soldiers 六种单位的模型**总共三档：LOD0 近景、LOD1 中景、LOD2 远景**。范围为先驱号 ID1、重防号 WM01／ID2、电磁矿车 ID3、建造车 ID4、扫荡者 ID5、彼之矛 ID6；玩家 Ground 席位不纳入本规则。镜头的三档距离策略、模型 LOD 和三档明暗分别维护，不能互相推导档数。

- 保留已审 LOD0 的几何、尺寸、UV、挂点及材质。预算按资产已有约束记录，超预算保留差额；不会为了统一档数再次压缩近景。
- 保留所选中远景的既有屏幕尺寸。新补齐档位使用 Crowd 默认 `1.0 / 0.056 / 0.028`，继续使用既有距离、屏幕占比和滞回显示策略。

## 5. 灯光、场景与游戏距离

- 默认画面明亮、色块清楚，单位与爆炸在指挥官视角能从背景中读出；阴影保留结构。气氛可以变化，但不能依靠压黑全画面制造质感。

## 6. 动漫爆炸的风格与特色

### 6.1 视觉目标

用户第二张图是主要目标：**奶黄色亮核、橙红热边、浅灰粉块状烟团、少量亮点/短条火星、清楚的外扩薄环。** 第一张战斗场景参考帮助检查密集交战时的层次与遮挡。

![爆炸主参考：奶黄火核、热边与块状烟团](D:/UE5.7/test1/ArtSource/ArtDirection/References/Explosion_Target_Main.png)

[战斗场景参考](../../ArtSource/ArtDirection/References/Explosion_Target_Context.png)显示烟团、热区和径向动势的关系。借鉴视觉语言，不复制来源游戏的模型或完整效果资产。

| 层次 | 形态与颜色 | 动作与辨识要求 |
|---|---|---|
| 起爆闪光 | 小面积奶白/奶黄，短促高亮 | 迅速建立命中感，不能长时间覆盖模型和地面 |
| 火球主体 | 奶黄内核、橙红热边；主次团块组成不规则整体 | 快速扩张，局部火区迁移、分裂与续燃；火焰和烟团有重叠阶段 |
| 烟团 | 圆润但分块明确，浅灰粉为主；摧毁型允许少量可读的深灰/灰紫 | 大小、年龄和相位错开，翻卷、上升、边缘破碎后消散；不是八个同龄球同步改色 |
| 火星/碎屑 | 少量黄白亮点或短条，辅助暗色小碎片 | 径向爆发与少量弧线，迅速衰减；数量和亮度不抢火球主体 |
| 冲击波 | 干净的薄环，有明确外扩边缘，中心不铺满不透明色 | 先快后缓地扩张淡出；地面型贴合落点/斜坡，空中型从常用镜头可见 |

整体要有“猛地炸开 → 局部燃烧与烟团涌出 → 烟边消散”的连续形态变化。单纯球体膨胀、统一年龄混色、硬折面岩石感、密集裂纹、纯黑烟饼、纯白发光团都不能替代这种动画。

普通中型爆炸可从短闪光约0–0.1秒、冲击环约0.05–0.55秒、火星主段约0.65秒开始调节；这些是既有方案的起步节奏，不是所有效果的寿命上限。完整火烟消散以已审动画为准，回收不得切断尾段。早期四发射器/22粒子/1.8秒烟尾的试作方案不作为全项目固定标准。

### 6.2 制作手段与性能边界

- 先拆解参考的轮廓、内部燃烧、相位、颜色与遮挡，再选择低模Mesh烟团、Flipbook或混合方案。材质动态阈值、受控顶点运动和通道动画是可用手段，不能把“简约贴图”误读成“禁止贴图动画”。
- 火烟轮廓优先由遮罩、色阶和贴图通道构成，不默认增加独立几何描边壳。发光/Bloom仅增强热感，不能代替内部形态；动态灯、碰撞和物理碎片不作为默认成本。
- 冲击环默认不依赖场景折射；确有已审热浪需求才单独评估。普通爆炸的环峰值外径以主火球约1.5倍为初始美术目标，按固定机位实际校准，不能反复叠加第二套波环或重复组件缩放。
- 先保住主火球、烟火转换和命中反馈，再减少次要火星/烟尾、透明覆盖与材料开销。CPU/GPU模拟、发射器数和粒子数不能单独证明性能；按预期并发在相同条件下测量，收益要超过采样波动。
- 不改变玩法半径与伤害。范围参数与粒子数解耦，缩放只施加一次；生命周期、裁剪、回池和客户端/专用服务器职责沿用项目已有接口。

[参考资源拆解记录](../../ArtSource/FX/WingmanGroundExplosion_Toon/reference-audit/分析.md)明确记录了早期试作为什么失去动画层次；作为制作经验读取，不把失败试作视为已通过的风格样板。

## 10. 模型目录与区域材质接口（v1.7，2026-10-08）

### 11.2 制作时的使用方式

- 每项资源从统一色库选择主色、辅色和点缀色，允许跨图组合；不要求用齐22色或整套照搬，不设全游戏固定面积比例。主次色块与实际游戏镜头的可读性仍按本规范和已审设计检查。
- 基础配色从色库选取。三渲二明暗、渐变、透明和发光允许基于选色派生，光照与色调映射造成的显示变化不要求逐像素等于基色；不能借派生另引入无关的装饰色系。材质或UI采用线性值时按其既有管线转换sRGB，不改色值含义。
- 现有红蓝阵营、血量、合法性、文字高亮等功能色保留已确定的含义和值，作为明确例外；例如卡牌关键词黄色继续由既有文本样式源表维护。不能为了套色卡让敌我、状态或增益提示失去辨识度。
- 新建资源和明确要求重新设计配色的任务执行本色库；已审资产、冻结参考和原始prompt沿用具体版本。技术修复、拆层或导入不会自动触发重染，复用已审模型身份配色时保留其资产专属依据。
- 第9节十四模型的固定区、浅深队色、顶部队色灯、乳白面积及暗部提亮，第10节模型区域接口继续按其具体范围执行；这些资产规则不扩展为全游戏固定比例或统一参数。扫荡者无线稿等既有例外仍有效。
- 参考、制作和交付记录注明所选主／辅／点缀色、功能色或资产例外及对应规范版本。新prompt只读取所需色值，不覆盖冻结历史prompt；配色审核仍按相应资产流程执行。
