# 客户端视野裁剪与特效三档LOD优化

## 2026-10-10 正式应用与验收安排

用户已要求应用所有新变更，正式代码、资源和数据管线已接入；对应开发文档为当前实施状态入口。当前剩余活动步骤为玩家PIE效果验收；FPS对照按用户最新指示暂缓。下文仅文档登记的范围描述保留为原方案历史。

## 背景与目标

600移动单位、500弹丸目标的同进程一专服双客户端压力场景已测得约15.55FPS，游戏线程平均64.34ms、GPU平均16.22ms。机枪命中特效游戏线程平均独占约8.17ms，真实P95附近帧达17.39ms；双客户端弹丸预测合计约0.50ms/引擎帧。上述数字来自[既有截帧报告](../../outputs/performance/20261009-stress-frame-analysis/report.md)，不是本轮新增测量，也不是可直接全部节省的屏外耗时。

既有版本已包含采矿／建造激光屏外暂停、枪口／机枪命中生成前范围裁剪，以及飞行批次可见性判断。尚需补齐已生成命中特效的离屏回收、普通单位屏外呈现降频、弹丸屏外网格提交停止和相关特效细节分级。本需求是在这些已交付行为上追加方案，不将既有优化标记为未实施。

目标是降低客户端屏外表现成本，并补齐本次性能相关特效的完整、简化、最简三档。性能目标以相同负载下的实测结果为准；收益超过重复采样波动才记为有效，不预先承诺达到30FPS。

## 本轮交付与实施边界

本轮只完成分析、需求讨论、需求文档、同名开发文档、原四份文档关联和Progress索引检查。开发方案中的代码、资源、配置、Excel修改及所有功能／视觉／性能验证均属于未来实施，不在本轮执行。

不修改源码、Niagara、材质、蓝图、地图或运行配置，不执行编译、PIE、压力测试或场景搭建。已有归档和既有实施／验收状态保留；需求确认与未来候选的视觉审核分别记录。

未来实施的范围限定为：

- 首批新增细节分级围绕机枪命中ID5、地面／机械枪口ID52、采矿ID36、建造ID45，以及飞行光束ID4、38的附属表现。
- 其他飞行表现接入屏外提交控制；重防号现有导弹尾迹三档资源和预算继续沿用。
- 普通单位客户端呈现姿态、机械表现及提交纳入屏外5Hz；本地玩家、武器与摄像机必要挂载保留原频率。
- 单位摧毁爆炸、升级光效等不扩入本轮新增LOD范围。服务器Ship集中销毁／补建热点另列后续事项。

## 已确认需求

### 特效显示与三档细节

| 对象 | 完整档LOD0 | 简化档LOD1 | 最简档LOD2 |
|---|---|---|---|
| 枪口／机枪命中 | 保留当前六层表现 | 保留主体与核心尾迹，火花、碎屑数量约减半 | 保留主闪光、发光和核心轮廓，关闭外围尾迹、火花及碎屑 |
| 采矿／建造光束主体 | 当前8节点 | 保持8节点 | 保持8节点 |
| 采矿／建造端点火花 | 当前数量 | 数量约减半 | 停止生成 |
| 飞行光束／弹体 | 保留主体、尺寸和逐帧运动 | 保留主体，仅减少已有附属细节 | 保留主体，关闭可分离的附属细节 |
| 已有导弹尾迹 | 沿用现有三档资源及预算 | 沿用现有三档资源及预算 | 沿用现有三档资源及预算 |

采矿保持7.5cm、建造保持12cm，均保留当前绿色／紫色、不透明材质、宽度曲线、组件基础缩放和停止收束。各档不重新配色或改变主体尺寸；没有可分离附属细节的飞行资源只做可见性门控，不凭空增加新的简化层。

沿用现有指挥官镜头档位以及其他视角的距离、投影尺寸和档位切换缓冲规则，不新增统一距离截断。指挥官前两档继续按既有规则忽略旧独立视觉距离限制；总览继续关闭相关世界特效，保留既有地图与UI提示。其他仍准入的远处视角可以使用最简档，最简档不代表总览重新显示特效。

同一客户端World中，任一合格本地视图可见即准入，质量满足这些视图中的最高需求；不同客户端根据各自视图独立处理，并保留总览的按视图隐藏规则。

### 离屏、停止与回屏恢复

- 本次纳入的一次性特效生成前检查完整范围，禁止只按起点裁剪。已生成特效的完整范围持续完全离屏0.15秒后结束并回池，在宽限到期后的首次检查执行回收；回屏不重播旧事件。
- 持续采矿／建造光束屏外暂停，恢复时读取最新任务及扫描时间，不从旧目标或开始时刻重播。独立轻量检查周期为0.05秒。
- 光束中段、端点、弹体、当前尾迹及仍存活的历史尾迹属于可见范围；主体离屏但尾迹仍可见时不能整条停止。
- 弹丸回屏使用当前预测位置，从当前位置生成新尾迹，不补生成屏外历史粒子。仍在画面中的旧尾迹允许自然结束。
- 可见性恢复不依赖已经停止的蓝图Tick或网格变换；回屏恢复不能等待普通单位下一次0.2秒更新。

### 更新频率与例外

| 内容 | 画面内 | 屏外 |
|---|---|---|
| 普通单位呈现姿态、机械表现及提交 | 逐帧 | 5Hz，即每0.2秒 |
| 本地玩家、武器及摄像机必要挂载 | 保持原频率 | 保持原频率 |
| 弹丸预测、反弹及期限推进 | 保持现有逻辑 | 保持现有逻辑 |
| 弹丸网格变换、Niagara表现提交 | 逐帧 | 完整表现范围离屏后停止 |
| 持续特效可见性检查 | 独立轻量检查 | 0.05秒周期 |

普通单位仅因被选中不会获得全频例外。选择、血量、归属、面板数据、网络状态及必要期限继续正常处理，不能通过隐藏单位使面板数据停更。

5Hz只减少昂贵的客户端呈现更新。网络样本接收、时间推进和状态事件保留；弹丸追踪目标与历史枪口查询按需使用最新样本，不能读取滞后0.2秒的渲染变换。死亡、停止、过期、去重、墓碑、Generation和Epoch处理不等待降频周期。

### 玩法与兼容合同

服务器移动、寻路、避障、碰撞、伤害及采矿／建造进度保持原合同，不按某个客户端摄像机关闭。保持单一GuLiStrike模块、既有效果ID、可靠创建／结束协议和每批16条／1000字节限制；本地表现状态不加入网络协议。

本轮不改变弹丸预测时间步、反弹路径、服务器命中顺序、攻击数量、寿命或人口。地面机甲Ground席位与重防号WM01兵种保持独立路由。

## 未来验收标准——本轮均未执行

- [ ] LOD0与当前正式版本对照，主体颜色、宽度、尺寸、时序和停止行为保持；LOD1/2符合上表，事件依赖无断链。
- [ ] 光束起点屏外但中段可见、弹体离屏但尾迹可见，以及近裁剪面和屏幕边缘均正确显示。
- [ ] 快速转镜头、切换三档及总览切回，持续光束恢复最新任务，一次性特效不重播。
- [ ] 普通单位屏外5Hz、回屏即时恢复；屏外死亡／改令、大量选兵及本地玩家挂载符合频率与例外规则。
- [ ] 双枪历史姿态、追踪目标、反弹、停止、槽位复用、晚加入及Epoch切换保留既有合同。
- [ ] 混合批次中的屏外槽位停止表现提交，旧粒子、灯光和数据退出正确，逻辑槽位仍正常存活。
- [ ] 同负载对照分别报告整帧、GT、GPU、平均FPS、P95、内存、实例创建／回收、表现提交和按需姿态补算成本。
- [ ] 技术、性能和用户视觉验收分别记录；收益未超过采样波动时记为未证实，不用本轮文档检查替代运行验收。

未来性能对照使用源码UE5.7，同进程一专服两客户端，地图`/Game/Maps/LVL_CommanderMassPrototype`，600移动单位和500弹丸目标。固定视口、质量、人口及生产入口，记录实际活跃量和事件吞吐，不恢复旧代码。

分别比较当前行为、仅新增屏外优化、仅新增LOD及组合版本；覆盖全部可见、混合可见、主要屏外三种镜头，记录实际屏内外占比。每项采用3对样本、热身10秒、有效采样30秒。15.55FPS是既有压力报告参考值，正式对照仍需同场景重新取得当前行为样本。
