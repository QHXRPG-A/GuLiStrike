# Ship僚机俯冲轰炸门槛简化

## 背景与目标

现有僚机已能获得有效地面目标，但大量成员长期停留在 `Ingress/Lineup`：进入 `Dive` 必须同时命中纵向 6.8 米窗口、横向 5 米、机头 6°和速度 ±5% 四个条件，现场连续 20～44 秒可出现零发射。目标是把投弹资格简化为“僚机存活、已完成安全进场并进入俯冲、该机武器冷却结束”。

## 需求描述

1. 合法地面目标和地形安全航线仍按既有流程生成；僚机到达 `Lineup` 后，不再等待精确位置、横向误差、机头误差或速度误差收敛。
2. 武器冷却完成时直接进入 `Dive` 并发射首枚；一轮内仍按现有配置在 1.5 秒内发射 10 枚，首枚开始计算每机 8 秒冷却。
3. `Dive` 期间不再因相对冻结航线的位置误差或机头误差取消剩余投弹。
4. 僚机死亡、武器配置失效、目标/租约/权威状态失效、非法地形航线、射程与发射序列异常仍按既有安全规则拒绝。

## 边界

- 不修改导弹数量、俯冲时长、伤害、爆炸半径或冷却数值。
- 不取消服务器对存活成员、合法目标、配置版本、顺序、冷却和射程的校验。
- 不新增或扩充测试用例；只运行既有 Wingman Attack 自动化与当前空战原型 PIE。

## 验收标准

- [x] `Lineup` 不再读取纵向/横向/机头/速度阈值，冷却完成后直接进入 `Dive`。
- [x] `Dive` 投弹不再因冻结航线位置误差或机头误差被客户端取消或服务器吞掉。
- [x] 既有 Wingman Attack 自动化全部通过。
- [x] 当前空战原型连续采样中不再长期滞留 `Lineup`，导弹计数持续增长且能观察到 `Dive/PullUp/Climb`。
