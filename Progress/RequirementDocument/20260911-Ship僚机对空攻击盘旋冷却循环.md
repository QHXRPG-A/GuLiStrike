# Ship 僚机对空攻击—盘旋冷却循环

## 背景与目标

旧对空流程以随机脱离转向、冻结远离点和随机折返制造往返缠斗，状态与开火门槛过多。新流程需要形成清晰可读的“攻击一轮—返舰盘旋—再次攻击”节奏，同时让服务器继续权威结算伤害、客户端只同步低频持续射击状态。

## 行为规则

1. `AirSeparate`：目标中心距离严格小于100米时，僚机直接背离目标飞行；达到或超过100米后进入攻击。
2. `AirApproachFire`：朝实时目标中心直飞并持续开火；50–100米继续开火，严格小于50米或本轮持续满5秒时结束。
3. `AirReturnToOrbit`：结束当前持续射击，关闭攻击引导，交还现有编队逻辑返回己方Ship。
4. `AirOrbitCooldown`：只有进入编队 `OuterSoftRadius=520米` 后才开始计时；盘旋满3秒后，按当时目标距离重新进入 `AirSeparate` 或 `AirApproachFire`。
5. 对空开始开火只判断：存在当前获授权且存活的目标、僚机自身存活、目标中心距离大于等于100米。最大射程、射界角、LOS、飞行模式、避障阻塞和随机机动结果不得成为对空开火条件。
6. 目标切换、目标消失或死亡时结束当前射击；僚机死亡立即清理对空状态。FlightNav、碰撞、编队和避障继续约束运动，但不约束对空射击资格。

## 数据与网络语义

- `AirDogfight` 更名为保留枚举序号的 `AirBurstOrbit`，删除旧转向计划、随机候选点、远离点和对应运行时字段。
- 表驱动参数为：开始距离10000cm、停止距离5000cm、持续5秒、盘旋冷却3秒。
- `CooldownSeconds=0.2` 是逻辑射击间隔，即5Hz；允许的最短间隔为 `1/30s`，更短或其他非法频率直接使配置无效，不进行钳制或兜底。
- 客户端每轮只上传一次“射击段开始”，协议升至v14。持续射击使用 `SustainedHitscan` 活跃效果状态同步，不逐发上传或逐发广播。
- 服务端按30Hz效果Tick，从 `t=0` 开始在半开区间 `[0,5s)` 结算；5Hz完整一轮25发/250伤害，30Hz完整一轮150发/1500伤害。同Tick到期射击可聚合为一次伤害提交，但逻辑发数和确定性伤害ID保持可审计。

## 边界

- 目标分配、1500米获取/1800米释放、编队和对地俯冲/导弹逻辑不变。
- 协议层继续验证版本、会话/租约、配置、成员、目标授权、记录结构和重复提交；这些结构验证不得扩展成新的对空战术门槛。
- 运行时距离一律使用僚机与目标Actor中心位置。

## 验收标准

- [x] 机尾朝向目标、超过旧射程、无LOS、非旧允许飞行模式和避障阻塞不再阻止合法对空射击段开始。
- [x] 目标丢失/死亡/切换和僚机死亡会结束持续射击；地面攻击测试保持通过。
