# 飞船与场景模型尺寸归一

## 背景
当前场景中的 Dreadnought、无人机和 cannon_war_machine 依赖 Actor Transform Scale 才达到已确认的视觉尺寸；玩家飞船还额外继承了父蓝图根组件 0.3 倍缩放。这使资源尺寸、关卡实例尺寸与运行时尺寸不一致，不利于后续批量摆放、碰撞、相机与挂点调校。

## 需求描述
- 将场景实例上已确认的统一缩放烘焙进对应模型资源：Dreadnought ×0.5、无人机 ×2、cannon_war_machine ×30。
- 资源尺寸更新后，目标关卡实例统一回归 Scale 1，且世界空间中的外观尺寸、位置与旋转不变。
- 仅在 `BP_CombatAvatarFly01` 覆盖继承的 `CollisionCylinder` Scale 为 1，不改变父蓝图及其他子船。
- Dreadnought 资源缩小后同步修正舰体居中偏移，并按新旧运行尺寸比 5/3 放大相机及避障距离。
- 若根碰撞放大后原出生点不再可用，只调整 `LVL_Main` 的 PlayerStart 高度，保证舰体不穿地；不改变其 X/Y 与朝向。

## 边界
- 不处理天空盒、Landscape 或基础 Plane 的场景缩放。
- 不改动公开 C++/Blueprint 接口、表结构、飞行性能数值或非目标关卡资产。
- 不清理或覆盖工作区中已有的无关改动。

## 验收标准
- [x] 三项资源包围盒分别为原资源的 0.5、2、30 倍。
- [x] `LVL_Main` 中目标实例数仍为 2/1/128，Scale 全部为 1，世界包围盒与摆放不变。
- [x] 机器人保留现有 Skeleton、16 个材质槽，无骨骼或材质丢失。
- [x] 父蓝图根 Scale 仍为 0.3，`BP_CombatAvatarFly01` 根 Scale 为 1，舰体居中。
- [x] PIE 中默认机位、运行相机参数、舰体居中与出生位置正常，无相关日志错误。
