# 数据管线：Excel 配置飞船数值

- 类型：技术架构
- 日期：2026-08-21
- 状态：已确认

## 背景

飞船部件与整机数值目前全部硬编码在蓝图部件 CDO 的 `EditDefaultsOnly` 属性上（引擎推力、武器伤害/射速、飞船 20 项 Stats/Handling 调参）。策划改数值必须进 UE 编辑器开蓝图细节面板，逐个找属性，无法批量调参、无法 diff、无法留数值变更记录。希望引入"策划写 Excel → 管线转换 → 游戏运行时加载"的数值生产流。

## 需求描述

1. 策划在 Excel 中编辑飞船数值（部件表 + 整机调参表），Excel 是唯一数值编辑入口。
2. 管线把 Excel 转成 JSON 中间产物（入库、可 diff），再导入为 UE DataTable 资产。
3. 游戏运行时从 DataTable 加载数值：部件安装时按行覆盖部件数值，飞船出生时按预设行覆盖整机调参。
4. 导出脚本带校验：列名/数值范围/必填项错误时报出具体 sheet 与单元格位置。
5. 全流程可一条命令跑通（编辑器开着时）。
6. 向后兼容：未配表或行缺失时，沿用蓝图默认值并给出 Warning，不炸游戏。

## 边界

- 首版只做两张表：部件数值表（引擎/武器）、飞船调参表（Stats+Handling）。投射物表、出生配装表列为后续。
- 部件网格、挂接变换（`PartRelativeTransform`）、槽位兼容性（`CompatibleSockets`）仍配在蓝图 CDO——它们与舰体 socket 结构耦合，且热切换过滤读 CDO，v1 不动。
- 运行时状态（冷却时间戳、推力聚合值等）与输入资产绑定不进表。
- 不做 Excel 在线协同、不做运行时热重载（PIE 中改表需重跑管线）。
- 不引入新插件；编辑器需保持开启才能执行导入步骤（commandlet 导入列为后续项）。

## 验收标准

- [x] Excel 改一个引擎推力值（600→200），跑全管线后 PIE 中飞船总推力/极速相应变化，有日志或读数证据。（实测：总推力 1400、总质量 160、极速 1750、引擎实例推力 200）
- [x] Excel 填越界值（如 MaxBankAngle>45）时导出脚本报错并指出单元格位置，管线中断。（`Tuning!N2: 50.0 超过上限 45`，exit 1，不产 JSON）
- [x] 不挂任何 DataTable 时，飞船/部件行为与现状完全一致（蓝图默认值兜底）。（接入前多次 PIE 实测数值=蓝图默认，无表时 ApplyPartRow/ApplyTuningRow 静默跳过）
- [x] 生成的 JSON 与 DataTable 资产均入 git，可 diff 可回溯。
