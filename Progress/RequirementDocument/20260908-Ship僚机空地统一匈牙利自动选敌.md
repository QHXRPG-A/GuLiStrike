# Ship 僚机空地统一匈牙利自动选敌

## 背景与目标

需求提出时，每艘 Ship 默认拥有 25 架僚机，但攻击状态只发布一个整组共享目标。服务器优先指定目标，否则保留当前目标，再按目标到 Ship 的距离选择敌人；逐架攻击状态机读取同一个目标，容易使整组集中攻击一个单位。

本需求让自动攻击同时分散到多个空中和地面敌人。分配规则保持统一：只使用匈牙利算法决定每架攻击谁，继续使用现有对空机枪与对地俯冲轰炸。

来源：[IDEA-202609-002](../Backlog/2026-09.md)。用户已确认空地统一、手动索敌独立，并选择“定期匹配，偏好原目标”；多轮分配与 100 米换敌惩罚随本次文档计划一并确认。

## 已确认规则

### R1：每艘 Ship 的统一分配池

- 每艘 Ship 独立为自己的僚机组进行分配，参与者为全部存活、具备有效状态和相应攻击能力的可用僚机。
- 所有可攻击的空中、地面敌人放进同一个候选池，不按空地拆分匹配，不以“只取最近若干个目标”截断范围内的合法候选。
- 同一目标按完整目标身份去重。友军、死亡、失效目标以及无法形成合法攻击任务的目标不参与。
- 获取与释放沿用现有范围：新目标在 Ship 的获取范围内进入候选；处于获取范围外、释放范围内的已有目标，只可由原持有者继续保留。

### R2：统一匈牙利匹配

- 每轮每架僚机最多得到一个目标，每个目标最多接收本轮一架僚机。
- 优先最大化本轮合法匹配数量，再在这些匹配中最小化总代价。没有合法配对时允许未分配，不能为填满矩阵强制配对。
- 代价为“僚机到目标的三维距离 + 换目标惩罚”。原自动目标仍合法且改配其他目标时，加 100 米等价距离；首次分配或原目标已经失效时不加惩罚。
- 相同输入及相同代价按稳定成员、目标身份排序，结果可复现。100 米是初始调参值，尚未通过玩法或性能验证。

### R3：数量不相等时的多轮分配

对尚未分配的僚机继续运行匈牙利，每轮重新开放同一个目标池，直到僚机分完或本轮没有合法匹配。全流程只使用这一种匹配算法。

以下分配结果以全部配对合法、僚机均可开始新任务为前提：

| 僚机数 | 空地目标总数 | 分配结果 |
|---:|---:|---|
| 25 | 25 | 每个目标一架，直接覆盖 25 个不同目标 |
| 25 | 8 | 三轮各 8 架，末轮 1 架；7 个目标各 3 架、1 个目标 4 架 |
| 25 | 100 | 从全部候选中选择 25 个不同目标，其余本轮未分配 |
| 25 | 1 | 全部 25 架分配给该目标 |
| 25 | 0 | 没有自动攻击目标，沿用跟随或已有归队流程 |

合法配对受武器与状态限制时，以合法匹配结果为准，不要求所有目标数量均衡。目标多于僚机时不承诺定时轮换或每个目标最终都会被选中；多轮算法也不承诺所有轮次合起来具有最小总距离。

### R4：每 0.2 秒重匹配

- 自动模式沿用 0.2 秒扫描间隔，更新目标位置并重新计算分配；新敌人出现、成员补充或位置变化均可改变结果。
- 原目标偏好通过换敌惩罚表达，不把“目标仍活着”作为永久不重新分配的条件。
- 只有配对关系变化才改变该成员的目标分配版本；单纯位置和时间刷新不应反复重置攻击状态。

### R5：手动指定目标独立

- 有效手动目标存在时完全跳过自动匈牙利求解，沿用现有指定目标攻击流程，自动结果不能覆盖手动目标。
- 手动取消或目标死亡、失效后进入自动流程；手动目标超出释放范围时仍遵守原有归队门。
- 本需求不改变手动目标选择接口、命中方式或玩家输入操作。

### R6：按目标类型沿用现有攻击方式

- 自动分到空中目标的僚机使用现有对空攻击；分到地面目标的僚机使用现有俯冲轰炸。同组可同时执行两种攻击。
- 分配只负责确定攻击对象。真正开火仍检查僚机自身射程、射界、LOS、冷却及当前武器配置，允许正常接近与转向。
- 已进入地面 Dive/PullUp/Climb 的僚机完成当前冻结轮后，再读取新分配或手动目标；死亡、紧急恢复、租约或配置失效仍可按原规则中断。
- 分配表中的下一目标与冻结轮正在执行的目标可暂时不同。分配数量不代表同一瞬间实际命中数量。

### R7：目标释放、成员变化与归队

- 单个自动目标死亡、失效或超出释放范围时移除对应分配；其余有效分配继续参与自动匹配，不因一个目标丢失让整组停火。
- 只有扫描开始前存在自动分配、且这些目标全部因超出释放范围丢失时，才触发原有整组自动索敌锁和归队门；达到归队条件后恢复分配。
- 目标全部死亡、普通无候选或暂时无法配对不额外触发超距归队锁。已有锁仍必须通过原有条件解除。
- 僚机死亡或被移除时清除其自动分配；补充成员以新身份在下一次可用扫描中参加，不能继承被替换成员的目标授权。

### R8：联网权威边界

服务器负责自动分配与开火验证，客户端继续负责僚机运动模拟。可靠状态携带逐成员目标，模拟拥有者交接后可恢复；开火必须能证明目标在对应时间和版本确实分配给该成员。其他成员曾经获准攻击同一目标不能代替本成员的授权。

### R9：攻击参与和索敌范围反馈

- 获得自动目标的可用成员都应消费自己的分配并尝试建立攻击轮。对地成员从自身来向开始，按稳定顺序最多尝试8个进场方向；没有合法FlightNav、物理碰撞和地面净空路径时仍保持安全失败，不强制穿越世界。
- “全部僚机参与自动攻击”不表示同一帧齐射。进场、对线、俯冲、拉起、冷却、避障恢复及冻结轮会让各成员自然错开；验收关注每个已分配成员能够进入攻击轮，而非任一瞬间全部处于开火阶段。
- 本地玩家控制的Ship显示青色三维线框球，半径读取与服务器自动选敌相同的获取范围。远端Ship和服务器不创建可见结果；蓝图可通过 `bShowWingmanTargetingRange` 关闭显示。

## 数值与边界

| 项目 | 数值或规则 | 来源 |
|---|---|---|
| 当前编制 | 每组 25 架 | 现有编制，不增加 |
| 自动扫描间隔 | 0.2 秒 | 沿用现有 Targeting 配置 |
| 新目标获取半径 | 1500 米 | 现有默认值，继续由原配置提供 |
| 原目标释放半径 | 1800 米 | 现有默认值，继续由原配置提供 |
| 换目标惩罚 | 100 米等价距离，即 10000 厘米 | 本需求初值，待实测 |
| 归队门 | 沿用当前 80% 比例、Formation 距离及 1 秒姿态时效 | 不新增另一套归队规则 |

本版不增加血量或在途伤害预算、AOE 区域聚类、其他分配算法、威胁评分及跨 Ship 协调。允许轰炸范围重叠和过量伤害，以分散目标和降低规则复杂度为目标。全部合法目标进入候选池，但不承诺无限规模的实时性能；实际性能尚未测量。

## 验收标准

以下验收条件已由关联开发案中的定向自动化、源码构建和 BuildId 门禁覆盖：

- [x] 配对全部合法时，25 对 25、25 对 8、25 对 1 的结果符合 R3。
- [x] 25 对 100 从全部候选中选择 25 个不同目标，没有近邻截断；非法配对不会被强制填满。
- [x] 同组同时分配空中与地面目标，并分别执行现有机枪与轰炸方式。
- [x] 相同静止输入重复扫描结果稳定；位置、新目标或可用成员变化时，每 0.2 秒允许重新匹配，并体现 100 米换敌惩罚。
- [x] 单个目标死亡或超距只影响相关分配；全部原自动目标因超距丢失时正确进入并退出原归队门。
- [x] 成员死亡、补充和身份换代后没有残留分配或串用旧成员授权。
- [x] 手动目标有效时不运行自动求解且不被自动结果覆盖；取消或失效后按 R5 恢复。
- [x] 已开始的俯冲仍完成冻结轮；新分配不会改写当前冻结条带或重复发射。
- [x] 可靠同步与租约交接保留逐成员目标；成员、目标或版本不相符的开火记录被拒绝，合法迟到和冻结轮仍可按原规则处理。
- [x] 完成关联开发案规定的既有回归和源码版构建门禁，并分别记录实际结果及未验证边界。
- [x] 同一空战原型图中25架均有自动目标时，25/25成员都至少进入一次攻击轮；轮次错开不被误判为分配缺失。
- [x] 本地Ship显示实际获取半径的青色三维索敌范围线框，远端和服务器不显示。

验收证据汇总见[开发案](../DevelopmentDocumentation/20260908-Ship僚机空地统一匈牙利自动选敌.md)、[原实施归档](../Archive/20260908-Ship僚机空地统一匈牙利自动选敌.md)和[全员参战修正归档](../Archive/20260909-Ship僚机全员参战与索敌范围显示.md)。原27项定向自动化零失败；本次复跑11项攻击测试与1项逐成员Mass测试均通过。同一空战原型图修正后在60.8秒与153.5秒两次采样均为25条自动分配、25/25成员已进入攻击轮，后一次有22架处于攻击引导。本次验证确认功能契约，不把100米初值或25×100输入规模写成长期玩法、压力或帧耗时结论。
