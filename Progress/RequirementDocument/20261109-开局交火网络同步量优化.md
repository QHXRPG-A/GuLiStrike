# 开局交火网络同步量优化

用户目标为“优化网络同步量，目标：当前PIE开局前的那一波交火，压缩至1MB/s”。指标取本机成功发送和收到的 P2P UDP 载荷字节，包含应用包头、确认、分片与重传，除以墙钟时间。阈值为 1,000,000 B/s。

场景为 `/Game/Maps/LVL_CommanderMassPrototype` 的 `HybridNetworkReview` 正式本地联机入口，600 单位配置、一个独立逻辑对端、本机约 300 名模拟士兵。以逻辑步约 211 开始的五秒开局交火作对照，保留当前发射、伤害、退役、据点与资源业务。

2026-11-09 新基线采集为 `20261109-120315-4136AD17`。逻辑步 216–518，存活弹丸 744–843，发送 2,455.08 KB/s、接收 342.54 KB/s，合计 2,797.63 KB/s。五个完整约一秒区间最高为 3,266.46 KB/s，重传、解码失败和接收溢出均为零。

该窗口内可靠控制发送队列从 43.13 KB 增长到 1,987.86 KB，最老消息等待从 7.69 ms 增长到 670.02 ms。每个完整区间都有发射、结束与伤害结算进展；后续需同时比较业务计数与队列，避免将延迟发送误判为流量优化。

- [x] 三间独立房间同负载复采，每间五秒平均收发合计和完整约一秒区间均不超过 1,000 KB/s。
- [x] 采样过程中原有业务正常推进，队列年龄与字节无持续增长，可靠重传、解码失败与接收溢出分别记录。
- [x] 字节计数覆盖整条连接，并记录压缩 CPU 成本。
- [x] 保存原地图验证入口并回读相关实体数据，玩家动作与表现核验另行记录。

实施见[开发记录](../DevelopmentDocumentation/20261109-开局交火网络同步量优化.md)。

用户补充授权：允许编译两端并完成定向复测；不限修改范围，可扩展到网络同步规则和数据结构。实测仍需保留原业务负载与完整字节口径。

验收结果：协议 44 三间独立房间五秒平均 869.44、881.96、894.31 KB/s，完整区间最高 921.36 KB/s；加权平均相对当前基线下降 68.48%。构建、定向恢复与场景数据检查通过，玩家表现验收单列。[验收证据](../Evidence/20261109-NetworkBudget/acceptance.json)
