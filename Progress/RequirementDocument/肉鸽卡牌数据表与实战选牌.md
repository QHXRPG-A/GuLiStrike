# 肉鸽卡牌数据表与实战选牌

## 数据与效果

- 新建 `data/Excel/GuLiStrikeRogueCards.xlsx / Cards`，前三行为字段名、类型、必要性，第四行起为数据；`_说明` 不参与导出。
- 字段：文本 `id`、稳定行名 `name`、策划介绍 `Note`、`Type`、固定两项 `TextIds`、`ImplementationClass`、`UnitTypeId`、`BonusPercent`、`FrontMaterial`。ID 为卡族.两位等级，保留前导零和 `01.10`；重复取得不改变等级。
- 类型 1 指挥官部队、2 Ship、3 地面机甲、4 建筑。首批三卡为 Type=1、战争机器 WM01、UnitTypeId=2。
- `01.01` 增加射速 +20%；`02.01` 极速机动 +50%；`03.01` 增加导弹伤害 +20%。己方本局现有及后续生成的战争机器受益，换任指挥官保留，新战局清空。
- 每次取得使用独立来源逐次乘算；同一确认不重复取得。攻速只影响 BasicAttack，不影响主动导弹冷却。导弹伤害进入真实爆炸结算，已经发射的导弹保持旧快照。移速同时更新速度、加速度和 Mass 参数，不改敌方或其他兵种。
- TextIds 是 JSON 字符串列表，index 0 卡名、index 1 说明。标题和参数化说明在公共游戏文本 Excel 中维护；由公共源表生成 StringTable，通过稳定键取得 FText。说明中的 {0} 由 BonusPercent 计算。本轮不制作翻译。

## 交互与显示

- `/Game/Maps/LVL_CommanderMassPrototype` 的指挥官按 F4 打开，固定左射速、中导弹、右机动；忽略重复开启。无经验、随机权重或费用系统。
- 战场继续运行，原相机保持；取消未完成拖选、建造预览、技能瞄准，隐藏指挥官 HUD，锁定本地战场操作。
- UMG BackgroundBlur 强度默认 8，开关各淡变 0.2 秒，可编辑。只捕获卡牌的透明 SceneCapture 叠在模糊背景上方，卡框、文字和闪光保持清晰；捕获只在选牌期间运行。
- 保留六层视差 ×4、整牌 ±16°、面积与厚度各 ×2；依次飞入、第一次点击翻背、第二次确认、成功闪光、三牌退场。
- 客户端只提交候选会话和卡牌 ID。服务器检查指挥官身份、阵营、战局、候选归属、目标及数值上限；固定步提交成功后才播放成功闪光。失败保留旧数值并提示。
- 提交前 Esc 可取消，提交中锁定重复操作。结束、取消、角色切换、离开世界均清理捕获/卡牌/遮罩，恢复当前角色 HUD、输入及焦点。
- 保留 StartPresentation / OnPresentationFinished(SelectedIndex)，增加确认请求与继续播放入口；评审地图保留重播。

## 资产目录补充决定

- `/Game/GuLiStrike/Cards/<类型>/<单位（如适用）>/<效果>`；本批为 `Commander/WM01/FireRate`、`Commander/WM01/MissileDamage`、`Commander/WM01/MoveSpeed`。
- 共用表现、卡背、HUD、材质基类与评审地图集中到 `/Game/GuLiStrike/CardSystem`。商城资产继续只引用。
- 使用 UE AssetTools 迁移资产并保存引用，保留 UE 按引用需要创建的旧路径重定向器；同步 Excel 和当前制作脚本。不得直接搬动或读取 UE 二进制文件内容。

## 2026-09-28 修订：白模修复与批量升级特效

本轮用户明确要求实施包含原生编译、实战回归和100/500/1000单位性能比较的方案；该指定范围沿用本轮授权。画面仍由用户核验，不读取过程图片，不把技术结果作为美术通过。

- 解除F4的引擎 `viewmode lit_detaillighting` 调试绑定，保留选牌；正常/取消/异常退出共享幂等清理，模糊归零后移除界面并释放捕获。
- 以 `P_UpgradeGlow04_Converted` 为参考，制作 `/Game/GuLiStrike/FX/RogueCards/NS_RogueUpgrade_Lite`。两个GPU发射器，每单位1辉光网格、1光圈和最多6光粒；按1024单位块合批、池化、可见性裁剪，持续约1秒。
- Cards增加 `UpgradeVfx:softobject`、`UpgradeVfxScale:float`、`UpgradeVfxColor:str`；默认缩放1、原主要光圈线性HDR色 `(R=20,G=6.930114,B=0.933554,A=1)`。
- 成功结算时冻结当前存活受益单位；选牌和模糊退出后广播一次。后续新生单位继承属性但不补播；特效失败不撤销属性。
- 用户明确选择所有能看到单位的玩家都可看到升级特效；随后明确“敌方的特效统一为红色”。每个客户端按本地阵营判断，己方读表色，敌方显示红色，遵守单位可见性。
- 验证重复关闭、取消、异常退出、角色切换、重复网络回执、新局复位、双方颜色及原版/新版性能。美术验收待用户确认。

### 玩家可见性反馈修订

用户反馈战争机器看不见升级特效。正式模型实战宽约12.5米、高约7.5米；原基础特效尺寸过小。首批三张战争机器卡的 `UpgradeVfxScale` 当前从1调整为6，其余颜色、时长、粒子数量和效果规则保持原配置。尺寸合适与否继续由用户复核；缩放1的既有性能数据不作为缩放6的性能验收。

随后用户提供截图，要求“这些细线改成短又多的发光粒子”。将原6条次级光线表现调整为最多18个柔光短点，沿用6个GPU面片承载，每个面片3点；主体光圈、上升辉光、颜色规则与统一缩放6不变。短点表现待用户验收。

最新截图反馈“太规整了，一簇一簇的，我想要那种杂乱随机的”。当前要求取消重复三点簇及等角度排布，使用18个独立光粒，分别打散位置、尺寸、出现时刻、速度和淡出；中/低质量为6/0个。保留主光圈、辉光、缩放6和敌我颜色。每块粒子容量增至20480，组件继续合批；编译与实战清理可独立核对，随机视觉由用户验收，新版性能不沿用旧测量结论。
