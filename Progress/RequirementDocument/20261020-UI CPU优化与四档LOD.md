# UI CPU优化与四档LOD

UI 保持当前外观、绘制顺序、交互响应与动态内容。完整圆环维持64段、128个三角形，使用128个共享顶点。几何缓存命中时复用批次容量并跳过重复准备；相机、视口、来源、选择、阵营和开关变化必须使对应缓存失效。

指挥官运行档位以相机**目标高度**划分，统一覆盖兵种、建筑、玩家地面机甲与飞船，以及装配、受击、施工和残骸副本。

| 运行档位 | 条件 | 网格与表现 |
|---|---|---|
| LOD0 | 35 ≤ 高度 <100m | 全量表现，自动网格选档，保留模型描边 |
| LOD1 | 100 ≤ 高度 <300m | 最高网格精度限制为MeshLOD1，允许自动选择更低精度，去掉模型描边；其余采用全量表现 |
| LOD2 | 300–700m | 战术表现，保持MeshLOD1精度上限，去掉模型描边 |
| LOD3 | 总览模式 | 图标与模型隐藏策略，总览特效策略 |

运行档位、相机模式和资源索引分别表达。相机仍为近景、战术、总览三种模式；特效资源质量映射为Full / Full / Reduced / Minimal；MeshLOD0/1/2表示模型内资源索引。

100m门槛由LOD配置维护，300m与700m读取相机配置。最高精度限制不强制固定到MeshLOD1。缺少MeshLOD1保留原网格；Nanite维持现有机制。本次不生成减面资源，不改写已审网格、动画频率、VAT相位、机械姿态、主体阴影或玩法逻辑。

用户补充要求：除LOD0外去掉模型描边。运行策略抑制独立描边材质和模型轮廓合成，覆盖没有MeshLOD1的模型、装配与表现副本，回到LOD0或关闭策略时恢复。主体材质中的结构线、选择圈、血条和操作指示保持。

组件通过生成、替换、装配、池复用和销毁入口注册/注销；稳态不增加全世界遍历。同World多视图采用最高精度需求，不同World独立。退出指挥官、关闭网格策略或注销时恢复组件设置，使用现有最短驻留时间抑制切档。

## 验收

- UI和网格策略分别有回退开关，并提供顶点、索引、批次、缓存命中/重建及网格回退诊断。
- 共享顶点几何等价验证检查三角形、位置、UV、颜色和裁剪；动态检查覆盖移动、选择、血条、建筑预览、HUD开关及视口缩放。
- 检查99.9、100、299.9、300、700m和总览往返；包含缺失MeshLOD1、装配、受击副本、残骸、出生和销毁。
- `/Game/Maps/LVL_CommanderMassPrototype`固定2359×1748前台视口、镜头、可见对象、人口与画质。基线、仅UI、UI加四档分别三轮配对，热身10s、记录30s；计时期间不截图、不枚举对象。
- 三轮最终平均帧间隔均≤15ms，合并P95不高于配对基线。分别报告游戏线程、UI、GPU队列与整帧；GPU队列重叠区间不得相加。
- `Slate.EnableGlobalInvalidation`须另做三轮配对并通过动态UI检查，才可修改默认值；否则保持原值。
- 保存地图中的默认停用验证入口；性能事实与玩家视觉验收分别记录。代码注释和文档只保留当前运行档位定义，资产索引明确标注MeshLOD。
