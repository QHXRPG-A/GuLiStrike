# 指挥官 WM01 第二兵种与多 ISM 表现

## 背景

指挥官当前虽然已有 `UnitTypeId=1/2`、分兵种生命与基础攻击数据，但客户端把全部 500 名士兵画进同一个 StaticMesh ISM，因此两个兵种共用 FourFRobot Crowd 外观。WM01 原始资源是 SkeletalMesh，也不能直接填入当前只接受 `UStaticMesh` 的 Soldiers 模型字段。

## 需求描述

- 将 WM01 的战斗待机动画中点冻结并烘焙为低成本 StaticMesh Crowd 代理。
- 客户端表现层按 `UnitTypeId` 建立独立 ISM 批次；当前 ID1 使用 FourFRobot、ID2 使用 WM01。
- 保持总计 500 人、每队 125 名 ID1 与 125 名 ID2，保持现有网络同步、选兵、移动与战斗权威链路。
- 把 Soldiers 的 ID2 从测试兵种正式化为 WM01，沿用 300.5 生命与现有默认扫射参数作为未平衡集成值。
- 对齐 GAS 语义：指挥官 ASC 只拥有一个军队技能命令桥；武器是 `UnitTypeId + SlotId + SkillId` 的数据配置，每个兵种当前只有一个生效的 `BasicAttack`。

## 边界

- 首版代理不播放行走、开火或受击动画；不启用 AnimToTexture，只保留未来接入位置。
- 不增加逐兵 Actor、SkeletalMeshComponent、ASC 或 GameplayAbility。
- 不增加第二兵种 HUD 卡，不调整出生比例、全局移动速度或正式平衡数值。
- 同槽替换武器暂不切换代理中的武器外观。
- 不新增、修改或运行与本需求无关的测试。

## 验收标准

- [ ] WM01 Crowd 代理为单材质、单 Section、三 LOD，满足 20k/6k/1.5k 三角上限与轻量渲染契约。
- [ ] 500 人表现产生两个单位 ISM 批次，ID1/ID2 各 250 个稳定槽，选择圈仍为一个共享 ISM。
- [ ] 类型变化会迁移单位批次并回收旧槽；未知类型只警告一次并使用默认代理。
- [ ] 血条高度按兵种模型 Bounds 计算，选择、移动、攻击、死亡与双端同步保持正常。
- [ ] ID2 数据解析为 WM01、300.5 生命、7.5 伤害、4 次/秒、15000 cm 射程。
- [ ] 每名指挥官仍只有一个 `UGuLiArmySkillAbility`；ID1/ID2 各解析一个默认 `BasicAttack` Profile。
