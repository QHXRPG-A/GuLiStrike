# Mass权威数据迁移与千单位对比

当前重复发布方案是本轮基线，不能使用上一轮历史数据代替。权威记录移入 Mass Fragment，移除副本同步。保留原主动侧绕、0.5 秒让路、同命令不让、只向同等或较大单位让路、下步传递请求、按 SoldierId 顺序即时更新圆索引。既有 NavMesh 修正及时间预算保留，不启用官方 Mass 避障。

## 实施与测量

- [x] 500、1000 移动单位；对穿与静止人墙；每组 3 次 30 秒。
- [x] 基线采完后迁移权威记录；核对导航、侧绕、让路函数及提交先后。
- [x] 源码版 GuLiStrikeEditor Win64 Development 构建，重跑同一快照。
- [x] 报告逻辑步均值、P95/P99、活动单位成本、实际活动数量、侧绕/让路工作量及轨迹差异。
- [x] 保存 `/Game/Maps/LVL_CommanderMassPrototype` 玩家入口并读取实体数据；视觉和手感由玩家判断。

大数量负载通过一次性 PIE 准备入口生成，保留原 632 单位开局。新增单位在当前进程本地模拟，走正式实体初始化、寻路规划、侧绕、让路与位移提交；新增负载不参与 Hybrid 网络分发，因此比较限定为移动 CPU 数据管线，不用于推断千单位网络吞吐。计时窗口外准备与预热，冻结位置、ID、命令与画质。

无零穿透门槛。耗时是否改善根据同版重复波动判断，不能把未移动或停住计作优化。时间预算导致的规划完成步变化与算法变化区分记录，不因函数文本一致宣称轨迹完全相同。
