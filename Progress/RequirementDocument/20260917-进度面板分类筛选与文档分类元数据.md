# 进度面板分类筛选与文档分类元数据

## 背景与目标

进度面板（`Tools/ProgressDashboard`，http://127.0.0.1:4317）的归档、需求、开发三个视图此前只能按关键词筛选，无法按工作性质（美术 / 玩法 / 性能优化）快速切片。`areas` 模块词表过细（commander/network/ship 等 29 种），不能直接充当粗分类。

目标：分类写入 Markdown front matter（唯一事实源），索引、快照与前端读同一份数据，不做纯前端启发式。

## 需求描述

1. 新增可选多值元数据字段 `categories`，取值 `art / gameplay / performance`，空数组表示不属于三类。
2. 归档、需求、开发三类文档全部填写；同一 `work_id` 的需求与开发保持一致，拆分子页继承父文档，归档取关联工作项与自身 `areas` 推导结果的并集。
3. 进度面板「需求」「开发」表格与「归档时间线」视图提供分类筛选：可多选、并集语义、显示各分类计数、可一键清除；文档条目上展示分类标签。
4. `progress_docs.py check` 校验取值并对三类根文档缺失分类给出提示；`build` 生成的 `catalog.jsonl` 带出该字段。

## 边界

- 不改动 `areas` 词表与既有语义；`categories` 是与其互补的粗分类。
- 玩法模块、月度 Backlog、参考文档不强制填写，也不在本次筛选范围内。
- 纯前端关键词推断不可接受；分类必须可从元数据直接读出。
- 不触发源码版编译门禁（本次仅涉及 Python/TypeScript 工具链，无原生模块改动）。

## 验收标准

- [x] 273 篇归档/需求/开发文档（含拆分子页）front matter 均含 `categories`，取值合法。
- [x] `progress_docs.py check` 0 错误，且无缺失分类提示。
- [x] `/api/snapshot` 与 `_Index/catalog.jsonl` 均下发 `categories`。
- [x] 需求/开发表格与归档时间线可多选筛选（并集），计数、清除、按压态可用。
- [x] 前端 `npm run check`、`npm run lint`、`npm run build` 全部通过。
