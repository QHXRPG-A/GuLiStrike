# 移动命令自由扩散与静态寻路线

- 类型：gameplay / UI / 技术架构
- 日期：2026-09-01
- 状态：已确认

## 背景

当前移动命令把每个 `ControlCohort` 的终点硬性限制为固定 5×5 方阵。点击点附近只要存在地形边缘、导航孔洞、友军旧预约或任一不可达槽，就可能让整个 cohort 原子失败，并统一输出 `fixed destination, reservation, or shared path validation failed`。同一批命令中的其他 cohort 还可能用旧位置或旧终点互相阻挡，使结果受 CohortId 处理顺序影响。

玩家的实际意图是“让所选单位移动到点击点附近可站立的位置”，并不要求抵达后保持 5×5 阵型。终点应从点击点向外扩散寻找，单兵能找到合法位置就执行；确实无法落位的单位保留原指令并退出当前选择。为了让大批量规划不阻塞游戏线程，候选投影和寻路还必须按帧限流。

## 需求描述

1. 取消固定 5×5 终点作为接令前提。`ControlCohort`继续用于内部路由、批次管理和回执归属，不再约束最终阵型与朝向。
2. 以点击点为中心生成世界轴固定的六角候选格，格距1800cm，按原始二维距离和六角坐标稳定排序，由中心向外搜索至最大45000cm。
3. 候选使用Landscape高度作为Z种子，再投影到`CommanderSoldier` NavMesh。投影XY修正不得超过750cm，投影结果仍须位于450m搜索半径内。
4. 投影结果去重；新终点之间以及与未参与本次命令的同队硬预约之间保持至少1600cm。敌军不参与终点预约。
5. 点击点或原固定块中心不可走时继续搜索外圈，不因中心失败直接拒绝整个cohort。
6. 规划开始时，在scratch预约表中释放本次全部可规划单位的旧位置或旧终点，避免同一批命令互相阻挡。最终失败单位恢复旧预约；由此产生冲突时重新向外分配受影响的新槽。
7. 保留9000cm间距的内部软锚点帮助同一cohort获得相对集中的候选，但软锚只参与分配成本，不参与合法性裁决。
8. 候选优先级先保证接近玩家点击点，再由cohort软锚和成员到槽位的匈牙利匹配减少穿插。输入顺序变化不得改变最终结果。
9. 路由优先使用同cohort共享长路径；共享路由失败时按终点包围盒最长轴稳定二分为多个内部Formation，最终允许降级为单兵完整路径。
10. 单兵与候选组合寻路失败后应黑名单该配对并继续尝试更外候选；只有候选耗尽后才拒绝该单位。
11. 同一cohort允许单兵部分接受。成功单位使用共同的非零`BatchOrderId`执行新命令；失败单位完整保留旧指令，并从权威选择中移除。
12. 全部规划在scratch状态完成，准备完成后于下一次30Hz权威固定步统一提交。Pending期间单位继续执行旧命令。
13. 规划拆分为候选投影、分配、路由、预约协调和提交阶段；每个World帧最多执行64次候选投影和4次路径查询，不使用墙钟超时。
14. 路由阶段及提交前重新读取权威起点。成员状态、权限、战局或导航代次失效时重算或取消，不能提交基于过期位置或旧NavMesh的结果。
15. 相同命令重复发送只关联既有规划任务，不重复建任务或重复下令；最终可靠ACK重放必须保持相同掩码和批次号。
16. 指挥官协议由v5升级为v6。`FGuLiCohortCommandAck`增加`MemberCount`、`EligibleMemberMask`和`AcceptedMemberMask`，位序对应发令时冻结的`MemberIds`。
17. 至少一名Eligible成员成功时生成非零`BatchOrderId`。全员成功为`Accepted`，部分成功为`PartiallyAccepted`，Eligible存在但无人成功为`PathFailed`，没有Eligible成员为`NoSelection`。
18. 提交后一次性更新选择：失败成员移除，成功成员保持原cohort ID和相对顺序，空cohort删除，整次命令最多推进一次`SelectionRevision`。全部规划失败时选择变空；整单系统错误不修改选择。
19. 新增OwnerOnly移动终点FastArray，按Soldier复制`ActiveOrderId`、权威提交起点、实际最终槽和版本。改令、到达、Blocked、死亡或换局时清理，Bootstrap时可重建当前活动终点。
20. 移动反馈保留橙色Pending和全失败时短暂红色提示。成功后按单兵绘制“权威提交起点→实际最终槽”的1px静态绿色直线，不使用流动、箭头、脉冲、标签或淡入淡出。
21. 静态绿线只显示给当前仍选中、存活且执行对应`ActiveOrderId`的单位；到达、失败、Blocked、死亡、改令、取消选择或网络状态重置时立即隐藏，并执行视锥、投影与最短2px剔除。
22. 拒绝诊断使用结构化失败阶段，覆盖成员失效、起点非法、候选投影、间距、友军预约、恢复预约、共享路径、连接段、个人路径和候选耗尽；候选级失败只聚合统计，不逐条刷屏。
23. 增加非Shipping命令`gs.GM.Commander.Nav.LastMove [CohortId]`，并扩充`Nav.Stats`的待规划任务、投影/路径查询、部分接受和失败原因统计。

## 边界

- 本需求只调整指挥官移动终点、规划调度、移动回执、选择收敛、终点复制与命令线表现；不修改扫射、GAS军队桥接、科技树或卡牌规则。
- 不要求终点保持5×5、固定朝向或其他可见阵型；9000cm软锚不构成玩法承诺。
- 不引入完整DetourCrowd、ORCA或默认开启流场；继续使用现有NavMesh、Mass Avoidance和权威30Hz移动框架。
- 不把敌军变为友军终点硬预约，也不加入传送式脱困。
- 当前Launcher版UE5.7不支持本项目Server Target；Dedicated Server验证留待源码引擎环境，不以Standalone替代其通过结论。
- 旧需求和既有Archive保持历史原文，不回写尚未发生的实现或验证结果。

## 验收标准

- [ ] 六角候选在1800cm格距、45000cm圆形范围内稳定产生2263个理论位置，中心优先且输入顺序不影响结果。
- [ ] 中心不可走、NavMesh边缘、地形孔洞和友军密集区会向外扩散落位，不再因固定5×5中的单槽失败拒绝整个cohort。
- [ ] 投影后槽位无重复、XY修正不超过750cm、间距不低于1600cm，且不超过450m搜索半径。
- [ ] 同批旧预约全部释放，未选友军预约继续生效，敌军不阻挡；失败单位恢复旧预约后，冲突的新槽能确定性重配。
- [ ] 共享路径失败可稳定拆组并最终降级到单兵路径；无路配对会换槽，候选耗尽才拒绝单兵。
- [ ] 同一cohort混合成功时，成功单位执行同一新批次，失败单位保留旧指令并自动取消选取；选择版本最多增加一次。
- [ ] 全部失败时`BatchOrderId=0`且选择变空；Unauthorized、Stale和无导航系统等整单错误不改变选择。
- [ ] v6握手、两类掩码净化、快速请求/可靠重发、Pending去重、ACK与SelectionState乱序、预测单兵回滚和重连终点恢复均符合定义。
- [ ] 静态绿色寻路线为1px、无任何动画，只在对应单位满足显示条件时存在；500条线经过剔除后无明显表现层尖峰。
- [ ] GM能读取最近一次规划的候选、掩码、冲突、拆分、查询和失败阶段，正常失败不再只输出无法定位的泛化警告。
- [ ] 25/250/500兵在空地和复杂地形完成PIE验证，权威固定步P95继续低于33.3ms，并记录规划帧数及最坏查询量。
- [ ] Editor、Game及全量`GuLiStrike`自动化通过；Standalone/双客户端完成本环境可执行的联机验证，Dedicated Server明确标注环境限制。
