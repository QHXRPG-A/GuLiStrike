# GuLiStrike：5v5 大战场玩法策划草案

- 版本：v0.2
- 目标引擎：Unreal Engine 5.7
- 目标模式：5v5 非对称角色、混乱壮观、允许较大随机性的娱乐 PvP
- 目标局长：约 30 分钟

## 0. 文档约定

本文把规则分成三类：

- **已确认**：用户已明确提出或确认的设计方向。
- **建议初值**：用于首轮原型的可调假设，不代表最终平衡。
- **待确认**：会明显改变体验或实现范围，进入开发前必须定稿。

本文的目标是固化当前玩法设想、暴露关键风险并给出首个可玩版本，不证明玩法已经平衡或有趣；最终结论必须来自真实联机试玩。

## 1. 游戏定位

### 1.1 一句话概念

在一场 5v5 的超大规模战争中，一名指挥官从上帝视角调度海量小型单位、据点与战略支援，四名操作者驾驶巨型地面战争机器或大气层飞船撕开局部战线；操作者创造突破，指挥官将突破转化为领土、资源与最终的大本营攻势。

### 1.2 玩家承诺

玩家应当获得以下感受：

1. 自己正在参与一场拥有上万单位、前线持续变化的巨大战役。
2. 每个玩家既有独立操作空间，又能明确看到自己的行动如何帮助全队。
3. 战局会因能力牌、指挥官支援、据点易手和大型单位复活产生戏剧性逆转。

### 1.3 核心设计支柱

#### 支柱 A：宏观指挥与微观突破互相兑现

- 正向测试：操作者制造的局部优势可以被指挥官转化为据点和资源；指挥官的部署能为操作者创造目标、掩护和撤退窗口。
- 反例：操作者只是在清理背景杂兵，或指挥官不依赖操作者就能自动滚平地图。

#### 支柱 B：壮观但可读的万军战场

- 正向测试：玩家能识别主战线、侧翼、危险区域、支援技能预警和据点状态。
- 反例：单位很多，但玩家无法理解自己为何获胜、死亡或失去据点。

#### 支柱 C：允许强随机，但保留选择与反制

- 正向测试：随机能力牌提供新的战术难题，玩家通过三选一、组件槽位和临场协作形成构筑。
- 反例：某队只因随机获得唯一可用的反空或反装甲能力而直接获胜。

### 1.4 当前非目标

- 不以严格电竞公平性为第一目标，但仍需保证重大事件可预警、可理解并存在反制。
- 不要求指挥官逐个选择或微操上万名小兵。
- 首个玩法原型不直接制作完整一万单位、完整建筑树和完整能力牌池。
- 首发地图不采用球面、左右循环或进入战区后加载独立战斗地图的结构。
- 本文不直接确定最终 UE 类结构、网络架构或资产制作清单。

## 2. 队伍组成与角色职责

每队固定五名玩家：一名指挥官、两名地面操作者、两名飞船操作者。

| 角色 | 数量 | 视角与载体 | 核心职责 | 不可替代价值 |
|---|---:|---|---|---|
| 指挥官 | 1 | 上帝视角战略地图 | 调度兵团、修改据点进攻目标、配置建筑、使用战略支援、批准紧急复活 | 将局部战果转化为战线、领土与资源 |
| 地面操作者 | 2 | 巨型地面战争机器 | 突破工事、掩护小兵、进入据点核心区、承受正面火力 | 直接参与据点占领，每台等价 20 个小型单位 |
| 飞船操作者 | 2 | 机动性较低的大气层大型飞船 | 地面打击、空中拦截、僚机与激光火力、快速响应重要战区 | 改变战区火力结构，但不能直接占领据点 |

### 2.1 角色协作闭环

`指挥官发现薄弱战线 → 操作者制造局部突破 → 小型单位进入据点 → 据点易手并清场 → 新资源与兵力形成 → 指挥官选择下一条战线`

操作者负责“质量优势”，指挥官负责把质量优势转化为“数量与领土优势”。

## 3. 胜利条件与战役结构

### 3.1 胜利条件

- **已确认**：双方开局各拥有一个大本营。
- **已确认**：摧毁敌方大本营的一方立即获胜。
- **已确认**：地图据点本质上是通往最终胜利的资源，而不是独立积分胜利条件。

### 3.2 据点与大本营的建议关系

为避免飞船或传送门绕过整张地图直接偷家，建议采用以下两阶段关系：

1. 所有据点持续为本方大本营提供护盾再生、防御单位或防御建筑容量。
2. 当敌方持续控制多数关键据点时，大本营停止护盾再生，并开启 60～90 秒攻城窗口。
3. 攻城窗口内可以把传送门部署到基地外圈；护盾存在时不能把传送门目标放入大本营核心区。
4. 攻城窗口结束而核心未被摧毁时，护盾逐步恢复，但已造成的本体伤害是否恢复仍待确认。

> **待确认**：大本营是否始终可受少量伤害，还是只有攻城窗口内才能受伤。

## 4. 核心循环

### 4.1 全队循环

`争夺资源与外围据点 → 形成局部兵力优势 → 操作者突破 → 指挥官投入兵团 → 占领据点并触发冲击波 → 获得生产、建筑与经验优势 → 解锁能力牌和战略支援 → 进攻大本营`

### 4.2 指挥官循环

`观察战线 → 选择主攻/佯攻/防守目标 → 配置兵团和据点目标 → 分配蓝色资源与建筑 → 使用战略支援 → 评估战果并重设战线`

### 4.3 操作者循环

`接收或判断目标 → 驾驶战争机器战斗 → 击毁高价值单位/建筑/敌方操作者 → 获取团队与个人经验 → 三选一能力牌 → 安装组件并形成构筑 → 进入下一场关键战斗`

## 5. 地图与据点系统

### 5.1 地图结构

- **已确认**：采用单张连续的平面大战场，不采用球面地图。
- **已确认**：战场位于巨型陨石坑内部，环形山、断崖和不可通行山体构成地面单位可见、可理解的实体边界，不设置透明空气墙。
- **已确认**：环形山上方、外侧以及战区最高高度以上属于轨道封锁区，用可见的轨道监视、锁定和拦截处理飞船越界。
- 地图包含双方大本营、多个可占领据点、蓝色资源区和绿色资源区。
- 据点之间形成可读的环状进攻网络；小型单位按据点目标沿战线推进。
- 地图必须同时提供中央主战线、至少两条侧翼路线和可重新汇合的外围机动路线，使超大兵团推进承担丢失其他区域的机会成本。
- 建议使用近似圆形或椭圆形的可玩区而非矩形，减少角落龟缩和贴边防守。
- **待确认**：据点总数、关键据点数量、资源点是否与兵营据点重合。

#### 5.1.1 分层边界规则

边界不是一套同时作用于所有对象的碰撞墙，而是按对象类型分别处理。

| 对象 | 边界规则 | 首轮表现与恢复 |
|---|---|---|
| 小型地面单位 | 环形山外不生成导航和战略路径；兵团目标验证时拒绝不可达区域 | 在接近山脚前重新寻路，不允许持续撞墙或堆积 |
| 地面战争机器 | 由真实山体、断崖、深沟和废墟阻挡 | 卡入不可达区域时回收至最近合法地面点，不因透明碰撞突然停下 |
| 大型飞船 | 可以飞越坑内普通地形，但进入环形山上方、山外或超过高度上限后触发轨道封锁状态 | 预警 → 干扰/锁定 → 轨道拦截或强制返航 |
| 指挥官镜头 | 可以看见环形山外的远景，但不能选择、建造或下达地图外目标 | 接近操作边界时减速并弹性回拉，可一键返回己方战区 |
| 建筑、传送与支援 | 只能把有效目标放在合法战区和允许高度内 | 非法预览明确变色并说明原因，不扣资源、不进入冷却 |

飞船轨道封锁采用建议初值：

1. 接近封锁区时，根据当前速度预测越界并提前约 5～10 秒发出方向性警报。
2. 越界后 0～5 秒进入“轨道锁定”：雷达和画面受干扰，HUD 指示最近安全方向，飞船仍可主动返航。
3. 越界后 5～12 秒进入“封锁压制”：停止主动锁定和释放战略级武器，护盾或能源持续损耗；飞船仍然可以被敌方正常攻击。
4. 越界超过约 12 秒后触发轨道拦截和紧急返航；是否允许玩家继续控制但承受致命伤害，留待飞行原型决定。
5. 越界标记在返回安全区后保留建议 5 秒，避免玩家反复进出边界规避锁定和伤害。
6. 在封锁区死亡的操作者不能使用原地紧急重构，重生/重构位置改为最近的己方合法撤离点。

以上秒数均为**建议初值**。封锁的目标是明确战区、阻止边界利用并保留恢复机会，而不是以不可见规则突然处决玩家。

#### 5.1.2 陨石坑布局原则

- 双方大本营向可玩区内部缩进建议 15%～20% 地图直径，基地后方仍保留可被空袭、传送或地面绕行的作战空间。
- 中央区域可以设置陨石坑中央隆起或破碎高地作为视觉地标，但不能成为双方唯一必经路线。
- 据点图优先形成环路和交叉连接，不采用单条从己方基地直通敌方基地的线性兵线。
- 环形山内缘可以承载外围机动走廊、隐蔽资源或高风险捷径，但不放置可长期无代价防守的地图角落。
- 轨道封锁、环形山轮廓、中央地标和双方基地应从多个主要战区可见，帮助操作者判断方位。
- 地图外继续表现山体、云层、轨道火力和远景地貌，使世界在视觉上延续；地图外不承载常规资源、占领或战斗目标。

### 5.2 占领权重

| 单位 | 占领权重 | 状态 |
|---|---:|---|
| 小型单位 | 1 | 已确认 |
| 地面战争机器 | 20 | 已确认 |
| 大型飞船 | 0 | 已确认，不能参与占领 |

占领基本规则：

1. 当一方有效占领权重高于对方时，该方开始推动占领。
2. 权重差越大，占领越快。
3. 建议对占领速度采用递减收益和上限，避免数千单位在线性公式下瞬间占领。
4. 建议据点核心区只接纳约 100～200 份有效占领权重；外围单位仍参与战斗，但不继续线性提高占领速度。

建议公式形态：

```text
权重差 = max(己方有效权重 - 敌方有效权重, 0)
占领速度 = 基础速度 × 递减函数(权重差)
占领速度受最小值和最大值钳制
```

具体函数、基础占领时长与上限均待原型测试。

### 5.3 据点战势 Buff

- **已确认**：人数/权重占优的一方每 10 秒获得 1 层 Buff。
- **已确认**：最多 5 层。
- **已确认**：当人数/权重被反超后，每 5 秒失去 1 层。
- **已确认**：Buff 提高单位攻击力和血量。

建议把 Buff 表现为单一的“据点战势”刻度：红方 5 层至蓝方 5 层。进攻方反超后先削减守方层数，守方归零后才开始积累进攻方层数，避免双方同时拥有满层 Buff。

#### 建议初值

| 参数 | 建议初值 | 说明 |
|---|---:|---|
| 小型单位每层攻击增幅 | 3%～5% | 五层后攻击 +15%～25% |
| 小型单位每层生存增幅 | 4%～6% 临时护盾 | 优先使用护盾，避免最大生命变化导致血量跳变 |
| 地面操作者 Buff 系数 | 小兵效果的 25%～40% | 防止占点机器成为无法击穿的堡垒 |
| 飞船 Buff 系数 | 0 | 飞船不参与占领 |

> **待确认**：Buff 是只影响据点核心区内单位，还是影响据点附近一定半径内的所有单位；单位离开区域后是否立刻失效。

### 5.4 占领冲击波

- **已确认**：据点占领成功后释放强烈冲击波。
- **已确认**：冲击波摧毁据点内及附近的敌方小型单位。
- **已确认**：地面操作者会受到一定比例伤害，但不会直接被摧毁。
- **待确认**：冲击波是否影响空中的大型飞船、敌方建筑和未完成的传送门。

建议表现与反制：

- 占领即将完成前提供 8～10 秒的光柱、警报、地图提示和扩散范围预览。
- 地面战争机器建议受到最大生命 20%～30% 的伤害并被击退或短暂瘫痪，作为首轮测试值。
- 在冲击波触发前重新夺回人数优势，可暂停或逆转最终占领阶段。

## 6. 小型单位与兵团控制

### 6.1 已确认行为

1. 据点持续生成大量小型单位。
2. 新生成单位默认向距离生成据点最近的其他据点发动进攻。
3. 指挥官可以修改某个据点的进攻目标。
4. 小型单位 5 秒未被指挥时，会自行前往最近据点。
5. 单局目标规模最高约一万单位。

### 6.2 建议的指挥粒度

- 指挥官以班组、连队、兵团、据点驻军或战线为单位下达命令，不直接微操单兵。
- 直接命令建议持续到目标完成、目标失效或指挥官主动取消。
- “5 秒后前往最近据点”建议只作用于真正无任务的单位，避免命令自动失效造成重复操作。
- 据点保存进攻目标、集结点和兵种编制，新生成单位自动继承。

建议基础命令集：

- 进攻目标据点
- 驻守/固守
- 集结
- 护送地面操作者
- 跟随战线
- 撤退/重新部署

### 6.3 兵种体系

当前尚未定义小型单位的兵种和克制关系。首轮完整玩法至少需要少量清晰职能，例如：

- 占领/线列单位
- 反装甲单位
- 反空单位
- 工程/建筑单位
- 侦察单位

能力牌不能成为唯一反空或反装甲来源；基础单位和建筑必须提供弱但稳定的反制。

## 7. 资源与建筑系统

### 7.1 资源类型

| 资源 | 已确认作用 | 仍需定义 |
|---|---|---|
| 蓝色资源 | 提高已占据点造兵速度；提高防御塔、围墙、陷阱等功能建筑的可建造数量 | 获取方式、存储方式、是否消耗、生产加速曲线、建筑费用、紧急复活是否消耗该资源 |
| 绿色资源 | 增加全队经验，推动操作者获得能力牌机会 | 是持续收入还是一次拾取、经验曲线、是否存在上限或溢出用途 |

建议蓝色资源主要提供“选择和容量”，避免无限线性强化：

- 解锁据点生产路线或兵种编制。
- 提供建筑槽位和建筑维护容量。
- 在有限范围内提升生产速度，采用递减收益或硬上限。
- 支付紧急战场重构等高价值战略行为。

### 7.2 功能性建筑

当前候选包括防御塔、围墙和陷阱。为控制指挥官操作负担，建议优先采用据点插槽、预设阵地或工程单位施工，而不是完全自由摆放。

> **待确认**：建筑由指挥官直接放置、工程单位执行，还是两者结合；建筑是否会被据点冲击波摧毁或转化所有权。

### 7.3 弱势方抢点奖励

- **已确认方向**：弱势方占领强势方据点时，额外获得与强势方据点数量相关的资源。
- 当前概念公式：额外获得强势方 `1 / 强势方占领据点数` 的资源。

为避免交换据点刷资源，建议首轮改写为：

```text
额外战利品 = 被占据点最近 60 秒基础产出 × 劣势系数
```

约束建议：

- 不直接扣除对方已存资源，而是额外生成战利品。
- 同一据点易手后的 90～120 秒内不重复产生额外战利品。
- 只有据点落后达到阈值并持续 20～30 秒后，队伍才进入弱势状态。
- UI提前显示本次占领可获得的额外奖励。

> **待确认**：“强势方资源”原本是指当前库存、资源总产量、单个据点产量，还是另一种定义。

## 8. 指挥官系统

### 8.1 战略职责

- 观察完整战场态势。
- 设置据点进攻目标和兵团任务。
- 调整主攻、侧翼、驻防和撤退战线。
- 分配蓝色资源和建筑容量。
- 使用战略支援技能。
- 决定是否为死亡操作者支付紧急原地重生费用。

### 8.2 战略支援技能

| 支援 | 已确认用途 | 建议反制与限制 |
|---|---|---|
| 大范围杀伤武器 | 清除密集兵团，打破死亡大兵团 | 明显预警；可疏散或用屏障抵挡；不应无提示秒杀操作者 |
| 无敌屏障 | 保护兵团、据点或攻城部队 | 固定范围和持续时间；与轰炸共享战略能量；不能覆盖整张战线 |
| 传送门 | 将己方操作者直接送到敌方重要目标附近或上空 | 需要己方视野/信标；8～10 秒预警；护盾存在时不能部署到大本营核心区；不能以轨道封锁区、地图外或非法高度为目标；可被干扰或拦截 |
| 紧急战场重构 | 在操作者死亡地点原地复活 | 见第 10 节；占用大量资源或战略能量；存在独立冷却 |

### 8.3 充能与翻盘建议

- **已确认**：指挥官随时间获得强力支援技能。
- 建议所有强力支援共享“战略支援能量”，迫使指挥官在轰炸、屏障、传送和复活之间选择。
- 建议双方都有基础充能速度，弱势方根据公开的劣势等级获得轻度充能加速。

建议公式形态：

```text
支援充能速度 = 基础速度 ×（1 + 15% × 劣势等级）
```

具体比例必须通过试玩验证，避免落后方故意控分或优势方感觉获胜受到惩罚。

## 9. 操作者载具与能力牌

### 9.1 地面战争机器

- 可以进入据点并参与占领，每台等价 20 个小型单位。
- 主要职责是突破防御、保护占领部队、吸收正面火力和摧毁建筑。
- 据点冲击波造成比例伤害而非直接摧毁。
- **待确认**：两台地面战争机器是否拥有不同基础定位，例如重装攻坚与机动支援。

### 9.2 大气层大型飞船

- 机动性较差，定位为移动火力平台而非高速战斗机。
- 不能参与据点占领。
- 在陨石坑内部的受控大气层空域活动，可以越过坑内山地和地面战线，但不能借环形山脱离战场。
- 环形山上方、外侧和最大飞行高度以上属于轨道封锁区，以预警、干扰、拦截和紧急返航构成软边界，不使用透明碰撞墙。
- 通过能力牌形成两条主要路线：
  - 地面打击：大范围对地武器、轰炸、攻城火力。
  - 空中优势：生成僚机、空中激光武器、击落敌方飞船和空中单位。
- 基础反空能力必须在能力牌之外存在，能力牌只负责强化和改变打法。
- 现有 [飞船玩法册](../Gameplay/飞船.md) 和 [DIY 飞船需求](./20260820-DIY飞船.md) 可作为模块化组件基础，但当前实现偏太空 6DOF；正式大战场版本需要另立“大气层大型飞船操控”需求，重新确认升降、转向、高度层和飞行边界。

### 9.3 能力牌与组件构筑

- **已确认**：四名操作者随总经验成长，总经验由团队经验和个人经验共同构成。
- **已确认**：达到条件后获得抽取能力牌的机会。
- **已确认**：能力牌主要提供足以改变战局的强力武器，并以组件形式安装在地面战争机器或飞船上。
- **已确认定位**：允许较大随机性，强调混乱壮观的娱乐 PvP。

建议使用“先随机、后决策”的输入随机：

1. 每次从同等级池中随机展示三个选项。
2. 操作者选择一个并安装到有限槽位。
3. 重量、能量、散热或插槽类型限制全能构筑。
4. 敌方可以识别关键组件，并在下一次选择或战术部署中进行反制。
5. 团队等级负责同步开启抽牌阶段；个人经验优先用于刷新、升级或专精，避免击杀领先者提前跨越完整强度档位。

> **待确认**：抽牌次数、时间点、卡牌稀有度、组件槽位数、能否更换/拆除、死亡后是否保留全部组件。

## 10. 死亡、重生与紧急重构

### 10.1 普通重生

- **已确认**：操作者载具被摧毁后读秒重生。
- **待确认**：基础复活时间、复活地点、是否随比赛时间或连续死亡变化。

建议首轮使用 30～45 秒普通重生，并随比赛阶段轻度增长，避免早期一次死亡导致长时间无法参与。

### 10.2 指挥官紧急原地重生

- **已确认**：指挥官可以消耗约四分之一资源，让操作者在死亡位置原地重生。
- **已确认**：优势方使用该能力的代价更高。

建议做成具有预警的“紧急战场重构”：

1. 指挥官接受操作者请求并确认支付。
2. 死亡地点出现持续 5～8 秒的大型重构信标。
3. 敌方能够看到信标并选择撤退、埋伏或尝试破坏。
4. 操作者以 40%～60%生命重生，获得短暂减伤，但不能立即释放最高级武器。
5. 每名操作者拥有独立的紧急重构冷却。
6. 若死亡位置位于轨道封锁区、地图外或其他非法区域，原地重构自动改为最近己方合法撤离点，并在确认支付前明确告知指挥官与操作者。

费用不建议使用“当前库存的 25%”，否则先花光资源会让复活变得异常便宜。建议从以下方案二选一：

- 团队蓝色资源容量的 25%，再按据点领先增加附加费。
- 固定蓝色资源费用，加上每领先一个据点的额外费用。

## 11. 翻盘系统

已确认的翻盘来源：

1. 指挥官随时间获得的大范围杀伤、无敌屏障和传送门。
2. 弱势方夺取强势方据点时获得额外资源。
3. 指挥官支付资源让操作者原地重生，且优势方代价更高。

为避免三套翻盘机制叠加后造成无法理解的巨大摆动，建议统一使用公开的“劣势等级”：

- 主要由据点差决定。
- 状态持续 20～30 秒才更新。
- 最多分为 3 级。
- 支援充能、抢点战利品和紧急重构费用都读取同一等级，但各自有独立上限，不能继续乘法叠加。

## 12. 死亡大兵团与空间反制

目标不是禁止超大兵团，而是让它成为高收益、高风险的战略选择。

- 大兵团拥有极强正面战斗力。
- 据点占领速度存在软上限，额外兵力主要负责外围战斗。
- 兵力过度集中会放弃其他据点和资源路线。
- 大范围杀伤、飞船轰炸、陷阱和炮塔对密集阵型效率较高。
- 无敌屏障、分散移动、侦察和提前撤退提供反制。

不建议第一版加入不可解释的“单位越密集越脆弱”隐藏惩罚。

## 13. 30 分钟对局节奏

| 时间 | 战役阶段 | 主要体验 |
|---|---|---|
| 0～5 分钟 | 展开 | 占领外围据点、建立进攻方向、学习本局地形和资源分布 |
| 5～12 分钟 | 第一次分化 | 首次能力牌、一级战略支援、中央资源争夺 |
| 12～20 分钟 | 全面战争 | 建筑与构筑路线分化、超大兵团成形、首次基地外围进攻 |
| 20～26 分钟 | 攻城准备 | 高级支援、传送门、大型空袭、反复争夺攻城窗口 |
| 26～30 分钟 | 战争升级 | 资源和支援节奏加快、大本营防御下降、推动决胜 |
| 30 分钟后 | 加时 | 使用明确的护盾衰减、资源升级或终局事件避免无限拖延 |

时间节点均为建议初值。绿资源和据点数量应当改变能力牌与支援到达时间，但不能让领先方提前跨越完整阶段。

## 14. 信息与交互需求

### 14.1 指挥官需要看到

- 据点所有权、战势层数、占领进度和冲击波倒计时。
- 各兵团规模、兵种构成、当前命令、预计到达时间和路径拥堵。
- 操作者位置、生命、构筑、死亡读秒和复活请求。
- 蓝绿资源流、建筑容量、战略支援能量和劣势等级。
- 大本营护盾、攻城窗口和高威胁传送门/轰炸预警。
- 合法战区、轨道封锁投影范围、飞船越界状态和预计被拦截时间。
- 镜头可以观察环形山外远景，但地图外选择框、建造和目标指令必须被明确拒绝。

### 14.2 操作者需要看到

- 当前主目标和指挥官意图，但不强制剥夺自主行动。
- 自己对据点提供的占领权重和局部兵力差。
- 敌我战略支援预警、飞船/地面高价值目标和安全撤退方向。
- 飞船接近或进入轨道封锁区时的状态阶段、返航方向、剩余宽限时间和能力限制。
- 团队经验、个人经验、下一次抽牌进度和组件状态。
- 申请支援、请求护送、请求紧急重构和建议目标的快捷沟通。

语音沟通可以提升体验，但核心指令、请求、确认和危险信息不能只依赖语音。

## 15. 主要风险与验证方式

| 优先级 | 风险 | 可能表现 | 最小验证 |
|---|---|---|---|
| 高 | 据点攻血 Buff 乘法过强 | 满层守军无法被普通增援反推 | 固定兵力差对战，测试 3%、5%、8% 每层组合 |
| 高 | 多层正反馈滚雪球 | 领先方同时拥有更多兵、更强 Buff、更早卡牌与基地压力 | 记录 5/10/15 分钟据点差与最终胜负相关性 |
| 高 | 翻盘机制叠加过度 | 击杀和占领成果频繁被瞬间抹除 | 分别开启支援、战利品、紧急复活，再测试组合版本 |
| 高 | 指挥官操作过载 | 大量时间用于重复下令和寻找闲置兵 | 统计每分钟重复命令数及无任务单位比例 |
| 高 | 传送门绕过地图 | 最优策略变成固定偷家 | 测试视野、信标、护盾区和预警限制 |
| 高 | 一万实体性能/网络风险 | 服务器帧率、寻路、复制或客户端表现崩溃 | 独立进行无美术 Mass 压力测试 |
| 高 | 飞船蹭边规避战斗 | 反复越界断锁、躲避火力或拖延追击 | 测试状态残留、越界仍可受击、武器限制和强制返航时序 |
| 中 | 环形山产生安全后方 | 基地贴山、边缘据点或外围路线只需防守一个方向 | 基地内缩；检查每个关键目标是否至少有两条地面接近路线或一条地面加一条空中接近路线 |
| 中 | 飞船随机构筑无解 | 一方抽不到基础反空能力 | 确保基础反空存在，卡牌只强化路线 |
| 中 | 地面操作者 20 权重失去意义 | 据点常驻上千小兵时，操作者无法改变占领 | 限制核心区有效权重并记录操作者贡献占比 |
| 中 | 原地复活否定击杀 | 对方完成高难击杀却无战果 | 测试重构预警、部分生命和冷却方案 |

## 16. 首个可玩版本

### 16.1 阶段 A：核心协作原型

建议先做 3v3：每队一名指挥官、一名地面操作者和一名飞船操作者。该阶段用于验证角色依赖，不代表修改最终 5v5 定位。

- 一张单层连续、近似椭圆形的陨石坑对称灰盒地图；用灰盒环形山和断崖形成真实地面边界。
- 一套简化轨道封锁软边界：接近预警、越界计时、能力限制和安全返航；不制作最终轨道美术。
- 三个据点和两个资源类型。
- 每方约 200～500 个可见小型单位。
- 一种基础小兵，可增加简化的反装甲/反空单位。
- 一种功能建筑。
- 一次三选一能力牌。
- 一种大范围支援和一种屏障支援。
- 普通重生和一次紧急战场重构。
- 简化大本营护盾与攻城窗口。

### 16.2 阶段 B：5v5 角色原型

- 扩展为一名指挥官、两名地面操作者和两名飞船操作者。
- 验证同类型操作者之间是协作、分工还是功能重复。
- 增加飞船地面打击和空中优势两条构筑路线。
- 增加传送门、抢点战利品和公开劣势等级。

### 16.3 独立技术原型

玩法原型之外，单独进行一万单位压力测试：

- 使用 Mass Entity 或等价的数据导向实体模拟。
- 小兵不设计为一万个完整复制的 Character/Actor。
- 兵团共享战略意图，个体只执行局部移动和战斗。
- 使用表现层 LOD、实例化渲染、分层更新频率和批量寻路/流场。
- 服务器权威计算占领、伤害、资源、支援和胜负；客户端接收聚合状态与必要表现。

现有 [Mass 框架预研](../DevelopmentDocumentation/20260824-Mass框架启用与源码导读.md) 可作为技术起点。

## 17. 首轮验收标准

- [ ] 操作者能够说明自己至少一次如何制造了可被指挥官兑现的突破。
- [ ] 指挥官能够在不逐个选择小兵的情况下改变主战线和侧翼目标。
- [ ] 直接命令不会因 5 秒自动行为而被无意覆盖。
- [ ] 玩家能够在冲击波发生前识别范围、倒计时和撤退机会。
- [ ] 大兵团拥有正面优势，但至少存在两种可执行的空间或支援反制。
- [ ] 飞船不能占点，但能通过地面打击或空中优势明确改变战区结果。
- [ ] 传送门无法无预警地跳过据点和大本营防御体系。
- [ ] 原地重构具有明显代价和预警，不会让击杀完全失去意义。
- [ ] 一局能够在约 25～35 分钟内自然结束。
- [ ] 弱势方至少能识别两条现实可行的翻盘路线，优势方也能识别并反制。
- [ ] 地面单位不会持续撞击或堆积在环形山边界，玩家能仅凭地形判断不可通行区域。
- [ ] 飞船轻微误入封锁区后有机会返航，但不能通过反复越界获得脱锁、免伤或传送优势。
- [ ] 双方大本营和关键据点不因贴近环形山而获得无法绕行的安全后方。

## 18. 建议埋点

- 据点进入争夺、占领权重变化、战势层数变化、占领完成、冲击波击杀/伤害。
- 各据点每分钟生成单位数、有效占领单位数和外围单位数。
- 指挥官命令类型、重复下令次数、命令持续时间、无任务单位比例。
- 蓝绿资源来源、消耗、库存、建筑与生产投入。
- 能力牌候选、选择、安装、替换、击杀和对建筑/操作者伤害贡献。
- 战略支援选择、目标、预警时长、击杀、保护量、传送人数和反制结果。
- 操作者死亡、普通重生、紧急重构请求/批准/取消/失败/成功。
- 飞船接近封锁、越界、进入压制、触发拦截、主动返航和强制返航；记录越界持续时间及越界期间承受/造成伤害。
- 地面单位寻路触及环形山禁行区、重新寻路、卡住回收；记录边界附近的单位密度和停留时间。
- 每 5 分钟据点差、经验差、资源差、大本营护盾与最终胜负。

## 19. UE5 数据与系统边界建议

- 所有占领权重、Buff、资源、卡牌、支援和重生数值进入现有 Excel → DataTable 管线，不散落在蓝图默认值或 C++ 常量中。现有管线见 [数据管线需求](./20260821-数据管线Excel配置.md)。
- 比赛规则、公开据点状态和大本营状态由服务器权威持有并复制。
- 小型单位定义、能力牌、组件、支援技能和建筑适合采用稳定 ID 加 Data Asset/Data Table 定义。
- 环形山禁行区、合法作战区、飞船预警区、轨道压制区和高度上限应由服务器权威的显式区域数据定义；视觉山体和远景不能成为唯一判定来源。
- 地面 Mass 导航在生成阶段排除环形山禁行区；飞船轨道封锁状态由服务器按位置、高度和越界时间判定并复制。
- 指挥官 UI 和操作者 HUD 通过语义事件刷新，不逐帧查询上万单位。
- 大规模单位表现、寻路和网络验证必须与最终美术资产解耦。
- 现有模块化飞船组件可以承接能力牌“作为组件安装”的方向，但大气层飞行手感、多人复制和战场角色仍需单独设计与验证。

## 20. 待确认问题
