# 指挥官相机稳定巡航

## 背景

指挥官相机原显式地形求解器把“本子步能够抬升到安全高度”作为整段平移、旋转和缩放的通过条件。默认臂长下，相机平移速度约为91750cm/s，而上升限速为30000cm/s，可持续通过的地形坡度只有`atan(30000 / 91750) ≈ 18.1°`；地图中央坡道实测约18.5°，因此正常移动也会触发二分缩短。最大臂长时阈值进一步降到约8.3°。

同一求解器又把每帧完整摇臂净空要求直接作用到枢轴Z，只做很高的升降速率钳制，没有舒适高度保持、提前预测或小起伏过滤。因此相机会随地表上下起伏；越过高地后下降与下一次上坡限速还会形成明显的速度脉冲。

本需求将“完整平面巡航”和“垂直净空安全”解耦：有效地形上的平移不再为抬升预算让步，垂直方向则通过前视、平滑抬升、高度保持和硬净空兜底保证安全。

## 需求描述

1. 有效Landscape与合法视锥范围内始终完整应用本步XY、Yaw和缩放，不再因为所需Z超过本步上升预算而缩短输入。
2. 继续使用真实Landscape边界和完整视锥约束。地图边界造成的停止、视锥无法容纳时的臂长限制，以及缩放改变基础移动速度仍是预期行为。
3. 保留当前姿态的完整硬净空检查：枢轴、摇臂和镜头最低离地分别为150、200、500cm，摇臂采样间隔不超过10000cm。
4. 二分搜索只在Landscape查询失败或候选姿态无效时寻找最后有效位置；不能带着未知高度继续移动。
5. 按本步实际平面速度，在未来0.25、0.50、0.75秒的枢轴位置各做一次地形高度查询。预测只采枢轴，不重复扫描整条摇臂。
6. 巡航目标为“当前完整硬净空要求”和“三个预测枢轴高度要求”的最大值，再增加1000cm舒适余量。
7. 普通巡航只在目标高于当前保持高度300cm以上时开始抬升；使用0.20秒半衰期，最大上升速度30000cm/s。
8. 最终Z不得低于当前姿态的完整硬净空底线。普通抬升来不及时立即补足差值并计为应急抬升；应急抬升不得影响XY、Yaw或臂长。
9. 普通平移、停止与Q/E旋转不降低已经保持的巡航海拔。越过高地后保持当前高度，不自动贴回低地。
10. 仅当有效滚轮输入实际改变目标臂长时进入高度重锚。重锚期间每个子步按当前地形、摇臂和预测重算目标；向下使用0.35秒半衰期、最大15000cm/s，误差小于50cm后恢复高度保持。
11. 初始化和`JumpToWorldLocation()`立即设置为目标姿态完整硬净空高度加1000cm，并清除旧高度保持、重锚和待处理输入，避免跳转后二次漂移。
12. SpringArm碰撞、内置Camera Lag、Blueprint输入接口、复制、Controller与Landscape查询子系统保持不变。
13. 继续复用`gs.GM.Commander.Camera.Debug`。非Shipping快照增加请求/实际平移比例、硬净空Z、预测巡航Z、保持Z、重锚状态、本帧应急抬升量和累计应急次数，并明确候选姿态查询是否有效。
14. 参数先作为相机实现内部常量落地，不新增Config、蓝图参数或GM调参命令。

## 边界

- 不删除整条摇臂净空检查，不改成只检查枢轴或相机两点。
- 不启用SpringArm自动碰撞收缩，不通过提高上升限速掩盖求解策略问题。
- 极端陡坡预测不足时允许一次明显上抬；恒定平面移动和绝不穿地优先于垂直观感。
- “保持至操作”解释为平移、停下和旋转不触发下降；只有实际滚轮缩放和小地图跳转能够重新锚定高度。
- 不新增或修改自动化测试源码；只运行现有测试并通过调试快照与人工PIE矩阵验收运行行为。
- 不改写2026-09-01已确认需求与历史归档原文，本需求作为增量规则覆盖相机的旧升降预算行为。

- [ ] 中央18.5°坡道上下行远离边界时，平移应用比例保持99.5%～100%，固定时长位移的帧率差异不超过1%，且不触发应急抬升。
- [ ] 未缩放或跳转时，下坡和返回低地不自动降低Z。
- [ ] 50.5°坑壁允许应急抬升，但平移不减速，枢轴/摇臂/镜头净空不低于150/200/500cm。
- [ ] 山脊附近Q/E、连续滚轮和边缘滚屏符合恒速巡航与平滑重锚规则，不突然缩臂。
- [ ] 地图四角和小地图跳转继续保持完整视锥边界，跳转后无二次漂移。
- [ ] Landscape查询失败时保持最后有效姿态，调试信息明确标记无效，不能继续未知高度移动。
