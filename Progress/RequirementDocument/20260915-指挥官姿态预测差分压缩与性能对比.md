# 指挥官姿态预测差分压缩与性能对比

## 已确认需求

- XY采用1m步长、Z采用10cm步长、速度XYZ采用1m/s步长、机身朝向采用8位。
- 仅网络量化改变，服务器模拟保持10Hz，客户端逐帧插值。
- 用客户端已确认的量化基线预测位置，再发送残差与发生变化的字段；解码结果须准确还原量化整数。
- 保留不可靠姿态块独立接收、已有三相发送及距离降频；增加有界确认和历史缓存。
- 丢包、乱序、基线过期、传送、重连和单位回收均有明确处理；不增加通用重试或静默修复。
- 直接修改GuLiStrike正式网络代码，本次不接入Oodle/rANS、不改导航或人口上限。
- 2026-09-15追加：清除正式源码中被v9替代的旧姿态协议结构、入口和处理逻辑；压测基线源码与历史证据保留用于复现。

## 验收

- [x] 位置XY每轴误差不超过50cm，Z不超过5cm，速度每轴不超过0.5m/s，朝向不超过0.703125度。
- [x] 差分往返无额外精度损失；字段省略仍重建当前模拟步的样本。
- [x] 已确认基线、512位接收位图及2048块历史上限生效，重连/换局/回收清理完成。
- [x] 前后各三轮1200单位、一服务端两客户端有效负载，比较共同30秒窗口的上下行、CPU、内存。
- [x] 报告包括新增ACK上行、缓存内存、编码/解码耗时及所有回退，不用单项带宽下降替代完整结果。
- [x] 源码版Editor/Game构建、BuildId、相关既有与获准新增测试、文档索引检查完成。

## 实测结果与边界

三轮中位数：服务端两连接合计下行375.09→134.46KB/s（−64.15%）；客户端分别187.39→67.31和187.74→67.12KB/s。新增ACK约0.8KB/s/客户端。CPU平均核心当量变化为服务端−0.69%、客户端1+3.43%、客户端2−1.82%，不能认定整体CPU下降；新增缓存峰值服务端合计4.35MiB、每客户端2.06MiB。工作集、私有提交、P95与逐函数数据见[完整报告](../../TestResults/CommanderPoseCompression/REPORT.md)。

六轮均为1200存活单位；优化后第3轮移动人数P05为1199/1200/1199，其余轮次P05均为1200，分位数差异1人（0.083%）。逐帧极值另列：基线第3轮客户端1最低1160，其余轮次各端最低1198–1200，不能把P05当作最小值。服务端共同30秒约10Hz、0丢步，客户端0解码失败；单兵有效姿态约7.46–7.51Hz，保留近10Hz/远5Hz规则。源码版双目标构建和65项自动化通过；真实公网劣网与跨机容量不在本次测量中。
