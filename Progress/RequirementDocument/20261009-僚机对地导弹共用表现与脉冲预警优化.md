# 僚机对地导弹共用表现与脉冲预警优化

## 2026-10-10 正式应用与验收安排

用户已要求应用所有新变更，正式代码、资源和数据管线已接入；对应开发文档为当前实施状态入口。当前剩余活动步骤为玩家PIE效果验收；FPS对照按用户最新指示暂缓。下文仅文档登记的范围描述保留为原方案历史。

## 2026-10-09 实施确认补充

僚机尾迹完整范围完全离屏后停止尾迹生成并清理隐藏历史；逻辑预测继续。回屏使用原发射时间的当前脉冲相位，从当前位置重新增长，不补画屏外轨迹。仍可见的尾迹中段和消散段继续参与范围判断。

## 本轮交付与需求依据

本轮只保存需求及配套开发方案，并检查文档结构、关联和索引。下文的资源制作、原生开发、构建、运行对照和地图交付均为后续任务，不能据此认定已实施。

用户要求深入分析“僚机对地导弹这一套是否能走重防号的导弹那一套”，并确认将当前导弹替换为周期 0.5 秒的脉冲发光点、10–50 米拖尾和地面红圈预警，光点与拖尾均使用不透明材质。需求和方案已确认；新资源的可播放视觉审核另行记录。

## 背景与目标

僚机与重防号已经使用公共 CombatEffects 服务器运行服务。当前差异主要在玩法请求构造和客户端表现：僚机仍逐枚使用旧飞行 Niagara，重防号已有批次槽位、Generation、组件池、Bounds、LOD 和上传缓存。复用这些管理能力，减少僚机逐枚组件及重复提交，同时保持俯冲投弹、固定条带落点和权威命中。

红圈采用既有通用预警服务，提示每枚导弹冻结的实际爆炸范围。新增预警有独立成本，性能验收须区分飞行表现节省与红圈开销。

此前 600 移动单位、500 弹丸场景约 15.55 FPS 是四来源混合负载的观测。[截帧记录](../Archive/20261009-600移动单位500弹丸PIE截帧耗时分析.md)中的 `BP_ShipProjectile` 集中到期、销毁补建及物理移动属于 Ship 舰载炮路径。本项不会将该热点归为僚机对地导弹，也不承诺单独解决整个压力场景的帧率。

## 当前基线与玩法边界

以下资源事实沿用前序只读核对，数值由本轮导出数据复核；不构成本项新实现的运行验收。

| 投弹节奏 | 当前源表每轮 10 枚、1.5 秒，冷却 8 秒；条带长度 2400 cm。保持实际运行配置及升级后的冻结值 |
| 导弹运动 | 基础速度 1200 cm/s、寿命 8 秒、Sweep 半径 6 cm；不改轨迹、碰撞或落点冻结规则 |

## 视觉需求

| 项目 | 已确认规则 |
|---|---|
| 主体 | 用立体球形网格发光点替换旧导弹主体，任意观察方向保持体积感 |
| 光点与尾迹材质 | **Opaque + Unlit**，正常深度遮挡；不添加逐枚动态灯 |
| 脉冲周期 | 每 0.5 秒完成一次完整呼吸，尺寸与发光同步平滑变化 |
| 光点尺寸 | 旧主体横向实宽 `W₀` 为直径基准，范围 **1.5W₀–2.5W₀**，不以导弹全长为基准 |
| 发光 | 初始发光倍率 1–4；最终曝光下可读性由可播放候选审核确认 |
| 尾迹长度 | 从零沿已飞过的轨迹自然增长；最大长度配置范围 10–50 米，默认上限 50 米；短航程只显示实际飞过长度 |
| 尾迹宽度 | 头部初值 0.35W₀，沿尾迹收细至尾端零宽 |
| 结束 | 光点随逻辑结束移除；尾迹在 0.55 秒内收细至零，不留下静止线段 |
| 光点基色 | 奶油白 `#FEE4D9` |
| 尾迹基色 | 暖橙 `#EE9D58` |
| 预警颜色 | 沿用现有功能红，双方均可见 |

配色依据为[《GuLiStrike 美术规范》](GuLiStrike美术规范.md)第 11 节统一色库及功能色例外；HEX 表示 sRGB 基色，按既有材质管线转换为线性值。规范维护色库，本项只记录资产所选颜色。

脉冲的统一规则：

```text
Age = max(0, 当前服务器时钟 - 发射时间)
u = (1 - cos(2π × Age / 0.5)) / 2
Diameter = W₀ × (1.5 + u)
EmissionMultiplier = 1 + 3 × u
```

发射时为尺寸与亮度谷值，0.25 秒到达峰值，0.5 秒回到谷值。不同客户端、屏外恢复和晚加入均使用原发射时间，不重新起算脉冲相位。当前基础速度下，约 0.83 秒达到 10 米尾迹，4.17 秒达到 50 米；路径修正时按累计弧长计算。

制作前必须读回旧主体网格、粒子缩放、VFX 登记缩放和组件变换，冻结最终 `W₀`。网格原始尺寸或单个缩放值不能单独当作实宽。制作脚本写入最终绝对尺寸，重跑不叠乘。

## 地面红圈规则

1. 发射成功后，从该枚导弹的冻结落点开始显示；发射失败不产生预警。
2. 每个圈半径等于该枚冻结爆炸场的实际半径。基础值为 8 米，升级或其他合法修饰后的值以冻结载荷为准，不另写一套预警半径。
3. 仅显示实际落点 AOE；不将整轮条带或整个投弹编队合成一个范围圈。
4. 保留已有外圈、浅底色及 0.8 秒波纹周期，复用 `/Game/GuLiStrike/FX/GroundWarning/DA_GroundWarning_Red`。
5. 同位置、半径、样式及既有合并键相同的来源共享贴花；每枚导弹独立登记、结束与过期，新增来源不重置已有圆的波纹。
6. 命中、提前碰撞、取消、超时、换局均清理该枚预警。提前撞障碍后原目标圈立即结束，爆炸使用服务器实际碰撞位置，不延长到尾迹消散结束。
7. 冻结落点不因目标移动或死亡而移动；晚加入恢复仍有效的圈，已经结束的导弹不重放；专服不创建表现组件。

重防号 Q 的整次引导批次、共享配额和 `GuidanceBatchId` 属于其玩法合同。本项复用通用预警服务和样式，不将这些规则转成僚机投弹行为。

## 接入与兼容需求

新增可选飞行表现配置，仅在僚机对地导弹 Definition 上接入。未配置的导弹保持既有行为，重防号的运行配置和共享 ID 2 保留。新资源使用独立项目名称，经 VFX Excel 管线登记，并在写入时核对未占用 ID。

表现资源暂不可用时回退到旧飞行表现，记录一次诊断；预警仍按独立生命周期处理。保持单一 `GuLiStrike` Runtime 模块、可靠创建/结束协议及每批 16 条/1000 字节限制，本地批次和池句柄不进入网络。

新视觉先交付开始、脉冲峰值、长尾迹、命中和消散的可播放对照。视觉审核后切换僚机正式表现配置；技术检查、性能结果和用户视觉决定分别记录，需求确认不能代替新候选审核。流程依据为 [VFX 技能](../../.agents/skills/ue5-vfx-production/SKILL.md)及[美术规范](GuLiStrike美术规范.md)。
