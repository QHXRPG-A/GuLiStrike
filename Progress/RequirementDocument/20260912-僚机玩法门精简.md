# 僚机玩法门精简

## 现场事实

- 删除表现距离/数量门后，现场仍复现Client1的24个存活Remote代理在6秒内全部位移为0，而同客户端Owner仍在移动。
- 服务端已累计数千发逻辑射击；每发非致死伤害都增加HealthRevision并调度六Scope可靠Bootstrap。这使可靠通道长期堆积，同时客户端每次都释放整组Remote Pawn、丢弃插值历史。
- 修复后普通受伤只更新服务端权威血量；只有真正死亡/补员改变成员时才发布新切片，且未变槽位沿用Pawn、展示Transform和Pose历史。

## 需求

- 活着且已收到首个Accepted Pose的Remote僚机始终分配Actor，不因观察距离、全局Actor数量或Remote数量预算而回收。
- Remote继续使用0.2秒回看和 `RetainLastPose`；无新快照时停在最后姿态，不淡出、不隐藏。
- Owner逻辑根继续30Hz确定推进，但移动只执行请求速度、加减速、转向上限和真实碰撞滑移。
- Owner普通飞行不再使用FlightNav前瞻否决、多方向探针选择、0.5秒恢复迟滞、候选安全点或自动Rebase。这些机制不得再使存活僚机等待或取消攻击。
- 服务器继续保留协议版本、连接代、epoch/lease、成员身份、存活状态、帧/序列和记录格式校验；不恢复服务器二次飞行模拟或空间门。
- 死亡仍是唯一允许已显示僚机消失的玩法状态；本工作不改死亡伤害、补员或死亡VFX。
- 非致死血量变化不得触发整组可靠Bootstrap；真正成员切片必须保留所有未变存活成员的表现连续性。
- 在线组不再依赖心跳或静默超时看门狗；真实Logout、死亡和成员合法性仍直接清理状态。
- 不增加重试、自适应阈值、静默修正或替代路径。

## 验收标准

- [x] 存活Owner在无真实碰撞时持续执行30Hz逻辑位移，不进入技术恢复等待。
- [x] 远端存活轨道不因3km距离或Actor预算被释放。
- [x] 没有新快照时保留最后姿态，不淡出或隐藏。
- [x] 非致死伤害不再发布整组可靠快照，死亡/补员不清空未变成员的插值。
- [x] 攻击、碰撞、Candidate与死亡仍使用Owner的30Hz逻辑根。
- [x] Presentation定向7/7、Editor构建与同图Dedicated双客户端采样完成；完整Wingman套件的3项旧预期失败已单独记录。
