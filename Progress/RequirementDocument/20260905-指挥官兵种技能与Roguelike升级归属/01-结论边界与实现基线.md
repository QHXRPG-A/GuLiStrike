# 指挥官兵种技能、Ship 武器通道与 Roguelike 升级归属 · 结论、边界与实现基线

<!-- guli-progress:split-content -->

- 版本：v0.3（合并地空武器通道；补充可扩展与局内动态更换要求）
- 核对范围：v0.2 的陆军与 UE 5.7 GAS 源码分析；本轮补充核对当前工作区 Ship Ability、Wingman 战斗、飞船部件武器与相关玩法记录。包含未提交修改，未做运行或资产验证
- 文件沿用原名；本轮只更新本需求草案，后续技术方案仍与本文件同名配对

## 1. 合并结论与技能计数口径

可以把兵种 A 的 x 个生效武器、兵种 B 的 y 个生效武器，做成指挥官拥有的 x+y 个兵种技能；也可以在同一个指挥官 ASC 上实际授予 x+y 个 `GameplayAbilitySpec`。这些 Spec 可以复用少量 GA 类，不要求写 x+y 个类，更不意味着每名士兵建 ASC、每发子弹激活一次 GA。

沿用 v0.2 对早期“只有主动输入能力才做 GA”表述的修正：GAS 也适合自动触发、事件触发和被动能力。是否使用 GA，取决于是否需要它管理激活、阻塞、取消、费用与能力生命周期，而不是技能是否手动释放。

本项目推荐：**稳定武器通道绑定 + 局内升级记录 + 最终 Profile + 各自的战斗执行层，按需要接入 GA。** 陆军沿用服务器 Mass 战斗，僚机沿用 Wingman Simulation / Relay / Combat，飞船本体武器沿用 WeaponPart 与服务器弹丸。共享装备、成长、参数解析和展示规则，各执行层消费适合自己的最终配置。

关键不是“是不是 GA”，而是：升级改哪个绑定、谁保存最终参数、每名士兵如何执行，以及冷却作用于谁。单纯授予 x+y 个 GA，不能自动解决这些问题。

本稿把“一武器一技能”明确为：**一个可独立装备、替换、解锁和升级的武器通道，对玩家算一个武器技能条目。** 同一通道的多架执行单位、多个枪口、一次齐射的多发弹丸，以及附加燃烧词条，均不增加技能条目。两个槽即使装同一武器，或显式共用冷却组，也仍是两个装备/成长绑定。

| 例子 | 武器技能数 | 说明 |
|---|---|---|
| 陆军 A 有 2 个已装备槽、WM01 有 3 个 | 5 | 指挥官军队的 x+y；同槽候选、锁定槽不计入 |
| 25 架同型僚机共用基础自动武器与导弹齐射两个槽 | 2 | 每架自动射击各自运行；齐射仍是一个通道的一次指令 |
| 僚机基础槽从机枪换成激光炮 | 不变 | 原槽换装；激光炮仅为设计举例，不代表已有执行器 |
| 僚机解锁另一个并行副武器槽 | 增加 1 | 新增独立绑定与执行状态 |
| Ship 的 SwarmOrbit 编队能力 | 不计入武器技能 | 仍是有效的 GAS 能力，单列为编队能力 |

军队、僚机、飞船本体可以采用一致的技能视图，但保留各自所有者与操作权限。`Army ASC` 和 `Ship ASC` 继续分开，不能把这三类条目数相加后当成当前指挥官 ASC 的 Spec 数量。

## 2. 用户需求、建议假设与边界

已知需求：

- 指挥官拥有多个兵种，WM01 作为第二兵种。
- 后续 Roguelike 成长能够改变某个兵种的某个技能，而非只能强化整个指挥官。
- 僚机需要沿用武器通道思路，支持同槽换武器、独立升级和后续并行副武器；把这部分与原有陆军方案合并规划。
- **可扩展：能够持续新增兵种和武器。** 已有行为范围内应由配置和资源接入完成，不为每个新 UnitTypeId / SkillId 修改核心分支；新增攻击行为允许通过明确的执行器接口开发。
- **局内动态更换：对局运行中能够切换已解锁的武器与配装，服务器提交后作用于现存单位，后续生成/补充单位继承当前配装，不要求重开对局或重生。** 兵种的动态编成/类型切换也纳入扩展合同；是否将现存单位立即改成另一兵种的具体规则，见 8.5 和第 12 节。
- 本轮更新原草案，不实施代码、数据表、资产或 UI。测试内容须先与用户确认，不进行无关测试。

用于本稿的建议假设，尚不代表用户已确认：

- 沿用当前每队一个指挥官的结构，军队成长归 `Team`；换任指挥官继承本队本局成长，新对局清空。暂不增加私人军队所有权。
- x、y 指已解锁、已装备的并行槽位数量；同槽的候选技能不计入当前数量。若采用二选一武器，属于同槽替换，而非增加并行槽。
- 一次针对兵种的升级影响本队该兵种所有现存及后续生成的士兵，不只影响当前选中部队。该兵种暂时没有存活单位时，已获得的技能和升级仍保留。
- 空中成长建议归当前玩家的本局空中配装，影响该配装下指定僚机类型的所有现存及后续补充成员。同队另一名 Air 玩家默认有独立配装和成长，暂不推导成“全队僚机一起强化”。
- 同一玩家的 Ship 重生保留空中配装和成长记录，重建 Pawn、ASC 和成员运行状态；退出 Air 角色时暂停使用，返回本队 Air 时恢复。跨队、换人、断线重连继承另行确认，首版不承诺跨新会话恢复。
- 当前 Ship 讨论重点是僚机武器；飞船本体挂载武器同时纳入通道身份与接入规划，安排为独立阶段。不给当前舰体新增 socket、默认部件或武器资产。
- 首版只设计单局成长；随机池、稀有度、商店、奖励频率、跨局养成及存档另行确定。

## 3. 当前代码究竟做到哪里

### 3.1 陆军侧（延续 v0.2 核对）

| 环节 | 源码核对结果 | 对本需求的影响 |
|---|---|---|
| 军队 GAS 入口 | `BattlePlayerState` 初始化军队 ASC/AbilityActorInfo，授予一个通用 `UGuLiArmySkillAbility`；命令执行时校验当前指挥官权限。并未按武器表授予 x+y 个 Spec | 当前 GA 是军队配置命令桥，不是每种武器的执行技能。不能把本结论扩展成所有角色总共只有一个 GA |
| 技能定义与绑定 | 已有 `SkillDefinition`、`UnitSkillConfig`、`Team + UnitTypeId + SlotId` 的 `ResolvedSkillProfile` | 已有按兵种/槽位解析的基础，不必推倒重做 |
| 修改与替换 | 支持伤害、攻速、射程的固定值/百分比来源；先选同槽替换，再按最终 SkillId/Tags 过滤数值修改 | 可以复用为成长解析层，但还没有完整的奖励、等级、解锁模型 |
| 多槽配置 | 每个配置过的兵种/槽位要求恰好一个默认技能；解析器会生成这些槽位的 Profile，没有锁定/启用状态 | 表里有多个 SlotId，不等于已支持解锁，也不等于士兵会同时使用它们 |
| 实际攻击 | `FSoldierRuntime` 只有一个 `CombatProfile` 和一个 `Attack`；提交时只查默认 `BasicAttack`，每兵生成一个战斗 Sample | **多武器并行不能只填表，必须改运行状态和攻击遍历** |
| 目标选择器 | 现有选择器必须指定一个 SlotId；可以选全部/指定兵种，再限定 SkillId/Tags | “全队所有槽位的火焰技能”尚不是任意标签查询，需要扩展跨槽选择或显式展开目标 |
| 行为扩展 | 当前只注册 `DirectSingleTarget`；EffectHook 有接口，但现有伤害结算路径未调用 | 燃烧、分裂等不是现成功能，不能通过填一个新 ExecutorId 就获得行为 |
| 提交与同步 | 已有候选解析、固定步提交、逐 Profile Revision 和最终配置复制 | 还缺奖励联合事务、槽位移除、完整 Loadout 版本及奖励/UI说明同步 |

### 3.2 Ship、僚机与飞船本体武器（本轮补充）

| 环节 | 源码核对结果 | 对本需求的影响 |
|---|---|---|
| Ship GAS | `AGuLiStrikeShip` 自有 ASC；当前 V2 选择 SwarmOrbit、Basic Auto、Missile Salvo。前两者常驻，导弹按输入触发 | 已有能力生命周期，不需要先撤掉这套 GAS；Formation 不属于武器通道 |
| 能力槽与索引 | `EGuLiShipAbilitySlot` 固定为 Formation / BasicWeapon / Missile，授予映射按 AbilityId；换 AbilitySet 会清理并重授整套 Spec | 尚非任意多武器槽；同 AbilityId 多绑定需要改索引，单槽升级不能依靠重建整套能力 |
| 组配置 | `FGuLiGroupAbilityConfigSnapshot` 固定包含 BasicWeaponRuntime 与 MissileRuntime；有效组配置要求编队与两种武器全部存在 | 需要改为通道集合及逐通道可用性，支持副槽未解锁、武器卸下后编队仍有效 |
| 僚机自动武器 | Simulation / Relay 生成并提交自动开火意图；服务端按 `WingmanHandle` 记录下一次射击时间，从 ASC 对应 WeaponDefinition 读取最终用于校验/结算的参数 | 缺武器 SlotId；多槽要改本地运行状态、服务端冷却键、请求身份与最终参数读取 |
| 导弹齐射 | Ship 输入和 GA 授权；服务端选择目标与一个 Flight，由其最多 5 架合法成员发射逻辑导弹。共享冷却当前由 Ship ASC 的标签、计时器和预留状态维护 | 保留主动技能体验；将具体通道、共享组和请求版本显式化，不能自动改成每架独立手动冷却 |
| 生命周期 | PlayerState 保存稳定 AbilityId 配装；Ship 重生创建新 ASC，旧 Spec、临时效果和冷却丢弃 | 已有配装恢复基础，尚无空中 Roguelike 成长账本；成长和运行身份必须分开 |
| 飞船本体武器 | `FireInstalledWeapons` 遍历已装部件，`UGuLiStrikeWeaponPart` 自管 FireRate / LastFireTime 并生成服务器复制弹丸 | 可以在部件前接通道配置适配；不需要逐发改成 GA，也不能与僚机 BasicWeapon 混为一个槽 |
| 当前可见反馈 | Ship HUD 显示 Basic / Missile 可用与冷却状态；基础自动武器主要直接记入伤害账本，导弹有逻辑弹丸表现链 | 尚无按类型/通道的换装、成长说明界面；新行为的视觉表现需单列交付 |

已有[飞船玩法记录](../../Gameplay/飞船.md)说明，当前公共 Air 无畏舰为空舰体、没有默认部件武器；本轮未重新审计这些二进制资产。具备 WeaponPart 代码不等于当前默认舰体已经安装了本体武器。

以上结论基于源码和既有记录，不是对运行结果、性能、当前资产配装或 WM01 烘焙状态的验收。
