# 指挥官兵种技能、Ship 武器通道与 Roguelike 升级归属 · 同步、验收与关联

<!-- guli-progress:split-content -->
## 10. 展示、同步与填表边界

- UI按兵种分组展示已装备槽位，标明自动/主动类型、当前技能及成长说明。仅统计本队已拥有兵种的已装备槽位，不把整个配置库、未解锁槽位或对方军队算进来。x+y 是武器技能条目数，不等于所有 GAS Spec 总数，也不等于全都占用快捷键。
- 同一视图合同按“军队 / 僚机 / 飞船本体”分组；Air HUD 显示自己的空中配装，指挥官查看全队信息时也必须标注所属玩家与权限。Formation 独立展示，技能列表不直接枚举所有 ASC Spec。
- 奖励卡明确写出兵种、槽位/武器限制、替换后是否继续有效，并基于相同解析规则展示预期变化。候选预览不修改权威账本。
- 同一兵种各士兵的射击冷却不同；不要展示一个假定全兵同步的机枪倒计时。只有全队共享的战术冷却才可自然展示为单一倒计时。
- 僚机自动武器显示已装备/可用/暂停和成长说明；导弹齐射可显示当前共享冷却。临时冷却或缴械不减少已装备技能数量；未解锁、空槽、换装准备中和缺少合法目标应有可区分状态。
- 现有 ArmySkillReplicationActor 向相关客户端发布双方最终 Profile，不复制完整成长账本。草案沿用战斗结果配置同步；奖励选项、可领取状态与成长说明需设计对应的拥有者/队伍可见视图，不能顺便把私有选项塞进全局快照。
- 空中执行者通过可靠通道快照获得必要的模拟参数，观察者获得所需表现信息；私有奖励候选和完整成长账本按所有者可见性分发。角色权限、配装版本或目标变化后，旧升级预览必须重新校验。
- 基础改造完成后，相同行为类型下的新兵种基础数值、候选武器、升级目标、解锁和叠加规则应尽量配置化；新增执行行为、弹道、目标规则、持续效果仍需要实现。
- 僚机现有基础攻击是逻辑伤害，导弹有独立表现链；同槽替换必须更新显示名、参数及该行为需要的表现引用。通道适配本身不等于已交付激光、散射或燃烧特效。Ship 本体接入也不自动补齐当前舰体的武器挂点资产。
- WM01 StaticMesh Crowd 烘焙和按 UnitTypeId 分 ISM 批次只解决资产/表现问题，与技能归属解耦；它们既不要求 x+y 个 GA，也不会替代多槽攻击改造。本轮不处理其资产完成状态。

## 11. 建议推进顺序与验收口径

以下仅为草案中的后续范围，不代表本轮授权实施或新增测试：

### 11.1 分阶段产出

| 阶段 | 产出与完成判据 | 主要涉及位置 |
|---|---|---|
| P0 归属与合同 | 确认第 12 节关键默认值；固定地空绑定、SkillId、触发/冷却字段、单位、版本及奖励范围；形成同名开发文档 | 当前草案及后续同名技术方案 |
| P1 通道配置核心 | 复用现有选择器/修饰规则，增加 Owner/Domain、类型/武器注册、通道模板、兼容校验、启用集合、LoadoutRevision 和最小技能视图；新增内容不依赖 ID 特判 | `Gameplay/Skills`，Ship 静态配置适配 |
| P2 陆军多槽 | 每兵多槽执行、目标实体去重、逐槽升级/换装迁移；现有 BasicAttack 兼容；槽位移除完整提交 | `Commander/Mass`，ArmySkillSubsystem/ReplicationActor |
| P3 Ship 僚机通道 | 默认 BasicWeapon/Missile 接入绑定；按绑定授予/路由；多槽执行、Profile 结算、可靠协议和恢复；编队不因换武器重置 | `Gameplay/Ship/Abilities`、`Gameplay/Wingman`、`Battle/Contracts`、Relay、Combat |
| P4 地空局内成长与动态换装 | 按 Owner 保存奖励/装备/解锁记录；对局中请求、候选准备、联合提交、幂等和冲突处理；现存与后续单位一致使用新配装；按确认范围支持兵种编成切换及重生恢复 | 成长记录、PlayerState 适配、Army/Ship 配装提交、对应 HUD 视图 |
| P5 Ship 本体适配 | 以已有可用挂载部件接入；挂点 Profile 驱动服务器开火，换装保留冷却，旧弹丸保留发射快照；本阶段独立验收 | `GuLiStrikeShip`、`GuLiStrikeWeaponPart`、弹丸/伤害适配 |

P1 是共用基础；P2 与 P3 分别迁移各自执行层，P4 连接两边的成长流程，P5 独立安排。每阶段的测试文件、场景与运行范围在执行前单独确认。新增具体激光/燃烧/分裂行为，以及陆军全量 GA 入口，按实际内容需求另列后续任务。

最小内容切片沿用现有行为，减少内容依赖：

- 陆军：兵种 1 和 WM01 各有 BasicAttack，WM01 另有初始锁定的 SecondaryWeapon；强化 WM01 主槽、同槽替换一个现有执行器的参数变体、再解锁副槽。
- 僚机：一种 WingmanType，保留 BasicWeapon 与 Missile；同槽替换已有 Basic 自动行为的参数变体，再解锁复用该行为的 SecondaryWeapon。25 架成员应得到 3 个共享配置绑定和各自需要的自动执行状态。
- 飞船本体：仅在 P5 使用已有合法挂点配装，验证挂点通道；当前空舰体不额外增加部件，不把本体武器资产制作作为前置交付。

参数变体只用于证明配置替换，不冒充已完成不同弹道或特殊词条的新武器。

### 11.2 候选验收结果（未批准、未执行）

- [ ] A 装备 2 槽、B 装备 3 槽时，得到 5 个带兵种/槽位归属的已装备技能；同槽候选不多算。
- [ ] 两个兵种使用相同 SkillId，或同兵种两槽使用相同 GA 类时，定向升级、激活和撤销仍不串槽。
- [ ] 每兵多槽有独立目标/冷却；目标网格仍每兵一项，一槽换装不重置另一槽。
- [ ] 同卡重复获得按配置叠加，重复提交同一领取不叠加；非法组合整笔拒绝且不消费奖励。
- [ ] 替换后，槽位型奖励继续有效，技能限定型奖励按最终技能生效；撤销来源可重算恢复。
- [ ] 解锁/锁回引起 Loadout 版本变化，服务端、运行状态与客户端视图一致，不残留旧武器。
- [ ] 指挥官换任、当前兵种暂时无存活单位时成长按 Team 保留；新局不继承旧局来源。
- [ ] 采用 GA 入口时，独立/共享冷却符合声明规则，不因复用类、事件或标签意外全体触发/阻塞。
- [ ] 没有新增逐兵 ASC、逐发 GA 调用，也没有把行为未实现的词条展示为已支持。
- [ ] 同型 25 架僚机装备两槽显示为 2 个武器技能；解锁副槽后变为 3 个；Formation 仍单列为编队能力。
- [ ] 空中同类型/同槽升级只影响指定所有者；同队其他 Air 玩家、陆军和 Ship 本体武器不受串改。
- [ ] 僚机同槽换装/解锁不重置其他武器、导弹共享冷却、成员身份或编队状态；卸下所有武器仍可保持合法编队。
- [ ] 自动武器每成员每槽按最终 Profile 运行；右键仍只触发明确绑定的导弹齐射，最多使用所选 Flight 的合法成员，并按共享组消费一次冷却。
- [ ] 旧通道/旧代际请求不会套用新伤害；新通道快照在拥有者、备份执行者和服务器一致，迟到、重复请求不会多结算。
- [ ] 僚机补充读取当前配置；同玩家 Ship 重生按已确认策略恢复成长/配装，运行代际和旧请求失效；模拟租约接管不转移升级权限。
- [ ] 已发出的逻辑导弹/本体弹丸保留发射时来源与参数；换装后的新攻击使用新版本。
- [ ] P5 接入后，本体同挂点换装不增加技能数，其他挂点不重置；服务器部件与 HUD 使用一致的最终武器配置。
- [ ] 复用已有行为时，新增一个兵种/僚机类型或新武器只需内容配置、资源及已有管线导入，核心代码没有为新 ID 增加特判；新增通道可被运行层、复制与 UI 自动识别。
- [ ] 对局不中断、不重生即可更换兼容且已解锁的武器；提交前完整使用旧配置，提交后现存及后续生成/补充单位使用新配装，重复请求不会重复换装或叠加奖励。
- [ ] 不兼容/未解锁候选、未注册执行器、准备失败或过期版本不会破坏旧配装；快速连续更换的迟到回调不覆盖更新结果。
- [ ] 动态加入或重新启用兵种按已确认应用范围生效，原兵种成长保留，新兵种按自身绑定解析；武器更换不暗中改变单位兵种或生命身份。

## 12. 尚需产品确认的选择

这些选择尚未获用户确认；本稿用推荐值使方案可讨论，不将其写成既定玩法。

| 选择 | 本稿建议 | 对实施的影响 |
|---|---|---|
| 空中成长归谁 | 陆军归 Team；僚机与本体武器归本队内该 Air 玩家配装 | 若改成全队空中成长，OwnerKey、可领取对象与权限一起调整；备份模拟者始终不自动获得权限 |
| 技能槽数量与候选 | 首个切片沿用默认槽并预留一个锁定副槽；具体最大并行数/候选另定 | 决定内容配置、通道上限及 UI；同槽替换不增加数量 |
| 动态更换的兵种应用范围 | 武器明确支持局内立即提交生效；兵种可先切换生成/补充编成，现存单位是否即时换型待确认 | 即时换型需要生命、身份、编队和表现迁移事务；不会阻塞已明确的武器动态换装 |
| GAS 粒度 | 陆军先 A；僚机保留现有两个武器 GA 并按绑定扩展；Ship 本体先部件适配 | 决定 Spec 映射和输入路由工作量，不改变成长身份模型 |
| 同局继承 | 指挥官换任继承本队陆军；同玩家 Ship 重生/回到同队 Air 保留空中成长 | 跨玩家接手、跨队和断线新会话的继承政策另定 |
| Ship 重生的战斗冷却 | 首轮保留当前重生清冷却行为；同生命换装保留，避免换装刷新 | 若要求重生/切角色也保留齐射剩余时间，需要 Pawn 外的运行冷却记录 |
| 换装与首次就绪 | 槽位奖励随换装；武器限定奖励暂存；新解锁等待完整间隔/冷却 | 迁移已有默认武器保持现有首次就绪；是否改变出生体验需明确 |
| 本体武器接入时机 | 同一草案规划，P5 独立交付，不绑定当前舰体资产制作 | 先完成陆军/僚机通道，再接已有挂点部件 |
| 第一批肉鸽内容 | 先定向伤害/射速/射程、同槽替换与解锁；齐射冷却独立配置 | 稀有度、奖池、上限、叠加组、火控共享和特殊词条另定，不编造平衡参数 |

实施前优先确定空中成长归属、Ship 重生冷却政策，以及兵种动态切换是否立即影响在场单位。最小验证切片已在 11.1 列出，测试候选在 11.3 列出，均待用户确认后执行。
