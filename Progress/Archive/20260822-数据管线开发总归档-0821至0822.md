## 做了什么（按阶段）

### 阶段一（08-21）：MVP——Excel→JSON→DataTable→运行时

管线形态：**Excel →（系统 Python + openpyxl 校验导出）→ JSON（入库）→（编辑器 Python 经 UnrealMCPython TCP 12029）→ DataTable 资产 → 运行时 InstallPart/BeginPlay 查行应用**。

踩坑与解法（按时间线，均已验证）：

1. **Live Coding 半应用**：新增 USTRUCT 注册成功，但给已有类（Ship/PartComponent）新增 UPROPERTY 的反射未生效。解法：退出编辑器 → Build.bat 全量构建 → 重启编辑器。LC 只用于函数体级改动（最后的 CDO 兜底补丁即用 LC）。
2. **UE5.7 编辑器 Python API 差异**：`Class.is_child_of`/`is_a` 不存在 → 改用 CDO 的 `isinstance`；布尔属性 `bOrientToMovement` 的 python 名是 `orient_to_movement`（去 b 前缀）。
3. **JSON→DataTable 导入三连坑**：① AssetImportTask 不挂 factory 时 UE 自选 ReimportDataTableFactory 但无行结构而失败；② 挂 `DataTableFactory` 后报"未知扩展名 json"（该工厂 CanImport 只认 csv）；③ `fill_data_table_from_csv_string/json` 的导入本身能完成，但**收尾路径必挂游戏线程**（复现两次，连带编辑器卡死重启多次）。最终解法：读引擎头文件 `CSVImportFactory.h` 发现官方自动导入通道——**`CSVImportFactory` + `AutomatedImportSettings(ImportRowStruct, ImportType)`**，JSON 数据在脚本内转 CSV 侧车（向量列用带括号 ImportText 格式 `(X=..,Y=..,Z=..)`），经 AssetImportTask 导入，全程无挂死。
4. **编辑器内禁用 `delete_asset`**：会弹引用对话框卡死游戏线程。改用"复用资产 + replace_existing 整表替换"。
5. **MCPython TCP 是排队异步执行**：连接立即关闭、脚本稍后在游戏线程跑；"空回显"≠失败，须轮询结果文件 mtime。
6. **python 直改蓝图 CDO 后 `save_loaded_asset` 默认 `only_if_is_dirty=True` 静默跳过保存**（包未标脏）→ 磁盘上 BP 一直没挂表。解法：`asset.modify()` 标脏 + `save_loaded_asset(asset, False)` 强制保存，并 grep uasset 验证引用落盘。
7. **PIE 实例上 `part_data_table` 为 NULL 而类 CDO 有值**（根因未明，怀疑与 python 设值的 CDO 经 PIE 重实例化/序列化路径有关）：无任何 FindRow/ApplyPartRow 警告（静默走"无表"分支，蓝图默认值兜底，行为与旧版一致）。解法：BeginPlay 里实例表指针为空时从类 CDO 回退取值。**已固化规避，根因留档待查**。

### 阶段二（08-22）：表名由 Excel 派生 + 脚本通用化

- **命名规则**：表名 = `DT_{Excel文件名主干}_{sheet名}`（GuLiStrikeShip.xlsx 的 Parts → `DT_GuLiStrikeShip_Parts`）。名字源头是策划看得见的文件；改 xlsx 文件名即改资产名（旧资产变孤儿，导入脚本警告、不自动删）。
- **脚本改名与职责重划**：`export_ship_tables.py` → `export_data_from_excel.py`，`import_ship_data.py` → `import_data_to_engine.py`；表清单/行结构/接线全部收敛到 tables.json。
- **资产迁移**：`rename_asset` 把旧 DT_ShipParts/DT_ShipTuning 改到新名。坑：**第二个参数必须传完整目标路径**，传裸名字报 "destination asset path not valid"。改完后 BP 直连新资产并保存，旧路径零残留、无重定向器遗留。
- 全量构建前需删 `Intermediate/.../LiveCodingInfo.json` 解除 LC 构建锁。

### 阶段三（08-22）：校验规则配置化（脚本去字段知识）

- 删除脚本内硬编码的 `PARTS_SCHEMA`/`TUNING_SCHEMA` 字段清单与表专属导出函数，改为单一通用规则引擎，参数化于 tables.json 的数据。
- 实施中处理的三个"Excel 世界 ↔ C++ 世界"映射细节（均为配置能力）：
  1. **JSON 键名必须等于 C++ 行结构属性名**——Excel 列 `DisplayName` 对应属性 `PartDisplayName`，schema 第 4 元素做列名映射；
  2. **Type 列不能进 JSON**（行结构无该属性）——aux 类型：参与枚举校验与 required_by 判定，但不导出；
  3. **向量属性名 ≠ Excel 列前缀**——`MuzzleOffset` 在 Excel 里叫 MuzzleX/Y/Z，vector 第 4 元素指定前缀。
- **新增一张游戏表的完整清单：C++ 加 FTableRowBase 行结构 + tables.json 登记一段配置，脚本零改动。**

## 验证

- 全量构建通过（初始版本 + CDO 兜底版本）；导入回环比对：DT 导出 JSON 与源 JSON 全字段一致（含中文 FText、向量、软类引用、布尔）。
- **端到端**：Excel 改 Engine_Standard 推力 600→200 → 全管线 → PIE 实测总推力 1400、总质量 160、极速 1750、引擎实例推力 200，与手算一致；恢复 600 再走管线 ALL OK（可逆）。
- **校验路径**：越界 `Tuning!N2: 50.0 超过上限 45`、条件必填 `Parts!F4: Damage 为必填项（Type=Weapon 行）`，均 exit 1 且不产出 JSON（在 xlsx 副本上测试）。
- **配置化重构等价性**：重构前后导出 JSON 归一化数值后逐行语义相同；导入 ALL OK、无孤儿。
- 无表兼容：表指针空时飞船数值=蓝图默认（2200/160/2400），行为与改造前完全一致。
- BP CDO 实读指向 `/Game/GuLiStrike/Data/DT_GuLiStrikeShip_*`；uasset 二进制 grep 到新名引用；Content/GuLiStrike/Data/ 只剩两个新名 uasset。

## 日常使用

```
1. 编辑 Data/Excel/GuLiStrikeShip.xlsx（Parts = 部件，Tuning = 整机手感）
2. python Tools/DataPipeline/export_data_from_excel.py          # 校验+导出（有错指出单元格）

```

## 遗留问题

- PIE 实例表指针为空的根因未查清（已用 CDO 兜底规避）；若在其它 EditDefaultsOnly 指针属性上复现值得深挖。
- FText 经 CSV 导入为 NSLOCTEXT 包装的文化不变文本；接正式本地化管线时需迁移。
- schema（含 Clamp 范围）需人工对照 C++ 头文件维护在 tables.json；编辑器 Python 读不到 UPROPERTY meta（ClampMin/ClampMax），自动生成 schema 需走 C++ 侧，暂缓。
- 改 xlsx 文件名导致的孤儿资产需手动删（delete_asset 有卡死前科，不自动化）。
- 导入需编辑器开着；命令行 commandlet 导入、一键 run_all 包装（导出+导入+报告汇总）未做。
- Excel 文件被 Excel 程序占用时导出脚本可读不可写（预期行为）。
- 通用推断路径的向量合并按列名前缀约定，复杂结构（嵌套/数组）未支持——需要时应登记 schema。
