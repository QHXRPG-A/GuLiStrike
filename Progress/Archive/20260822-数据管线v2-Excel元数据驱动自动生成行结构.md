# 2026-08-22 解决了：数据管线 v2 —— Excel 三行元数据驱动，自动生成 C++ 行结构

- 对应开发文档：20260821-数据管线Excel配置.md（v2 演进，schema 配置化方案被本方案取代）
- 变更类型：C++ | 工具脚本 | 内容资产（DataTable 重建）

## 背景与决策

用户把表格式改成三行元数据（第 1 行列名 / 第 2 行类型 int|float|bool|str|softclass / 第 3 行必要性
Necessary|Optional，数据从第 4 行起；每表必有标准三列 id/name/Note），要求消灭手写的
`GuLiStrikeShipData.h` 与 `Tools/DataPipeline/tables.json`。

两个方案抉择（用户拍板）：
1. **代码生成（采纳）**：导表器从元数据自动生成 C++ 行结构到 `Generated/` 目录，保留强类型与蓝图暴露；表结构变更需重编译，改数值不用。
2. 通用动态行结构（id/name/Note + 字符串字典）：永不碰 C++ 但失去类型安全，弃。

RowName 规则（用户拍板）：**name 列**（如 '重型引擎'/'Default'），全表唯一由导表器校验。
Parts 表按 PartId 列遍历匹配行（原 FindRow(PartId) 直查不再适用）。

## 类型映射约定（写死在导表器）

id→`int32 Id`；name→行名（不生成属性）；Note→`FString Note`；int→int32；float→float；
bool→bool；str→FString；softclass→`TSoftClassPtr<UObject>`；PrefixX/Y/Z 三列→`FVector Prefix`。
结构命名 `F{Excel主干}{sheet}Row`；表名 `DT_{Excel主干}_{sheet}`。

## 新工作流

- **改数值**：`python Tools/DataPipeline/export_data_from_excel.py` → `python Scripts/ue_exec.py Scripts/import_data_to_engine.py`。不碰 C++。
- **加列/新表/改结构**：导出（自动重生成 .h，输出 `GEN` 提示需重编译）→ UBT 重编译 → 导入。
- 新游戏系统接线：在 `import_data_to_engine.py` 的 `WIRING` 字典加一行。

## 验证

- UBT 编译 `GuLiStrikeEditor Win64 Development` Result: Succeeded（修 GetRowNames 签名后）。
- 导入 report：两表 imported=True，回读全量比对 row_checks 全过，ship_assigned 两表，无孤儿资产。
- DT 结构检查：两 DT 的 row_struct 分别为 `/Script/GuLiStrike.GuLiStrikeShipPartsRow` / `…TuningRow`，行名 = name 列值。
- PIE 冒烟（编辑器临时生成 BP_GuLiStrikeShip 后开 PIE）：Tuning 全部应用（hull_mass=100、base_max_speed=1200、yaw_rate=40、orient_to_movement=False、hull_mesh_offset=(0,0,700)）；4 部件（标准引擎×2/重型引擎/激光炮）part_mass/thrust/damage/fire_rate/muzzle_offset/projectile_class 全部与 Excel 一致；部件显示名（标准引擎/重型引擎/激光炮）证明 name→RowName→PartDisplayName 链路通；日志无 ApplyPartRow/ApplyTuningRow 警告。验证后临时飞船已删、关卡已存盘还原。

## 遗留问题

- 旧 tables.json 的 required_by（Engine⇒Thrust）、compare（Max≥Min）、Clamp 范围校验在新格式无载体，已丢失；将来可在类型行扩展语法（如 `float[0,45]`）补回。
- Optional 空值落到 C++ 默认值（数值 0），如 PartMass 标 Optional 的行不填则为 0。
- 换表结构（如改列名）时游戏侧引用旧字段名的代码要同步改——消费代码（ApplyPartRow 等）仍是手写 gameplay 逻辑。
- 编辑器当前开着（本会话启动），如后续要改表结构记得先关编辑器再重编译。
