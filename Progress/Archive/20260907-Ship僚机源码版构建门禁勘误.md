# 2026-09-07 勘误：Ship僚机最终构建恢复源码版 UE5.7 门禁

- 被勘误归档：[Ship僚机三维往返缠斗与随机转向](20260907-Ship僚机三维往返缠斗与随机转向.md)
- 当前开发记录：[技术方案与验证](../DevelopmentDocumentation/20260907-Ship僚机三维往返缠斗与随机转向.md)

## 旧结论哪里不准确

原归档引用的 `build-editor-dogfight-final.log`、`build-game-dogfight-final.log` 和 `AutomationDogfightFinal` 来自 `C:\Program Files\Epic Games\UE_5.7`。该 Launcher 引擎的 Changelist 为51494982，而项目正式源码版 `D:\UnrealEngine-5.7` 的 Changelist 为0。两套引擎会覆盖同一项目的 `Binaries`，因此源码版 Editor 随后读取到 Launcher BuildId 时弹出“Missing GuLiStrike Modules / built with a different engine version”。

## 修复

- 将 `GuLiStrike.uproject` 的 `EngineAssociation` 恢复为 `{CD3BD5BF-4DAC-F6BF-194B-18AD041E3961}`；本机注册表将该 ID 映射到 `D:\UnrealEngine-5.7`。
- 使用源码版 `Build.bat` 重编 `GuLiStrikeEditor Win64 Development`。261个动作完成，主项目及弹窗列出的所有项目插件都重新链接。
- 使用同一工具链构建 `GuLiStrike Win64 Development`。首次完整 Game 目标补齐817个动作并生成 `GuLiStrike.exe`。
- 本次没有无故重编整个 `UnrealEditor` 引擎目标；准确结论是“使用源码版引擎工具链构建项目、插件和 Game 目标所需模块”。

## 仍然有效的结论与边界

三维往返状态机、数据部署、Dedicated Server + 两客户端采样和玩法结论不因这次 BuildId 勘误而改变；源码版重新编译和7项专项再次覆盖了本次功能代码。整个 `GuLiStrike.Wingman` 历史集合仍不是通过状态：旧 protocol-v7 夹具先被当前v11校验拒绝，随后既有 registry 用例在空夹具上解引用并使命令进程以退出码3终止：[日志](../../TestResults/WingmanAttack/wingman-regression-source-engine-final.log)。
