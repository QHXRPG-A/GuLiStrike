# 2026-11-03：修复 Ground 席位启动

用户反馈PIE一直进不去机甲席位。复现场景是正式地图选择Ground；预期控制正式Ground角色，实际在`Ground mobility configuration differs from the network manifest`后等待120秒并自动退出。原失败日志在修复前保留，编辑器与地图没有未保存改动。

## 首个失败点与勘误

旧归档ARC-20261103-003关于“图标修改不需要网络清单同步”的结论错误。`FGuLiGroundMechConfiguration::Load`把Skills完整行文本写入指纹，包含IconId；RocketJump.IconId由7改1后，制作脚本的`GULI_SKIP_MECH_POST_IMPORT=True`使清单仍持有旧指纹。Ground网络适配器的配置校验先失败，120秒超时是下游结果。图标素材、资源引用、构建和原地图保存回读的旧证据仍有效。

该假设由明确错误、源码指纹组成和新旧清单值共同证实；连接或席位权限并非本次首个失败点，无需修改其逻辑。未扩大到战斗回归或视觉测试。

## 修复

- `Scripts/GroundMech/author_ground_toon_icons.py`移除跳过Mech后处理，校验后处理成功并输出200/600清单。图标修改仍不重制弹道特效。
- 正常重新导入Skills，通过既有`sync_mobility_assets`导出正式`Config/Hybrid/RuntimeManifest-200.json`和`RuntimeManifest-600.json`，不手改生成指纹。
- 指纹由`16b5fc96a49190de10713b293cc1f608`更新为`86fdae12c2b21c458c80844f33a1ad9f`，引擎清单校验均成功；动作签名未变化，没有重烘步态或接地曲线。
- 没有原生代码变更，本次未编译。沿用上一轮已加载的源码版Editor产物。
