# 2026-10-02：山脚与高台当前导航不可达

承接[上一轮部分路径诊断](20261001-Mass编译后高处部分路径诊断.md)，用户进一步要求确认导航是否断开。本次将“搜索上限导致部分路径”与“目标不在可达导航区域”分开检查。

## 原生可达性证据

当前世界为 `/Game/Maps/UEDPIE_0_LVL_CommanderMassPrototype.LVL_CommanderMassPrototype`。选中单位135、138、141、142，前后选择版本5、命令确认号25均不变。所有查询位于帧85870、导航版本249内，没有混用导航更新前后的状态。

| 查询 | 完整路径 | 原生搜索耗尽 |
|---|---|---|
| 四个当前单位山脚→各自高台槽位 | 均否；有效部分路径 | 均否 |
| 135高台槽位→山脚 | 否；有效部分路径 | 否 |
| 135山脚→138山脚 | 是 | 否 |
| 135高台槽位→138高台槽位 | 是 | 否 |
| 存储关卡四个同坐标查询 | 均否；有效部分路径 | 本项未读取 |

两端均能精确投影到 `RecastNavMesh-CommanderSoldier`。查询半径150厘米、高度28.8厘米，实际NavData通过原生 `getall NavigationTestingActor MyNavData` 日志确认。普通与层级搜索上限仍为16384，没有修改设置。`NavigationTestingActor` 的标志来自本地UE5.7 `Result.Path->DidSearchReachedLimit()`；关闭详细搜索过程收集，使用默认过滤器和默认无限成本上限。

因此当前CommanderSoldier无法从这些山脚位置走到目标高台；部分路径不是这次查询耗尽搜索节点的结果。这里验证实际可达性，没有声称已导出并遍历全图全部导航多边形。

## 坡面辅助定位与遗留项

135脚下约19米，目标约75米。二者连线的41点地形剖面在XY约−321～−331米、+680～+672米的一段采到44.3～46.3°坡度，超过当前44°上限，这些样本没有精确导航覆盖。坡度由存储Landscape的1米中心差分估算，属于辅助证据；这段坡面不通行，整个导航缺口的缓坡、台阶、净空、区域过滤原因尚未逐项隔离。

需要先接通符合代理要求的实际步行通道，再构建导航，并以两方向完整路径核对。与此同时，上一轮确认的共享部分末端、停滞状态与不可达反馈缺陷仍未修复；不能把导航目标不可达与单位一直保留Normal状态混成一个问题。
