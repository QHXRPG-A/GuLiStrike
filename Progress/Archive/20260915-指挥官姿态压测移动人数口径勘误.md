# 指挥官姿态压测移动人数口径勘误

[前一归档](20260915-指挥官姿态协议9压缩与六轮对比.md)将P05差异写成“最大1人”，范围过强。P05无法代表逐帧最低值，收尾检查原始`frames.csv`时发现基线第3轮客户端1存在短时下降。保留旧正文，明确以本勘误和更新后的[完整报告](../../TestResults/CommanderPoseCompression/REPORT.md)为准。

按相同QPC共同30秒窗口重新汇总，仅增加分析字段，没有删除样本或修改实验。以下每格为逐帧“平均 / 最低”；所有轮次存活人数都是1200。

| 组/轮 | 服务端 | 客户端1 | 客户端2 |
|---|---:|---:|---:|
| 基线1 | 1200.000 / 1200 | 1199.961 / 1198 | 1199.962 / 1198 |
| 基线2 | 1199.983 / 1199 | 1199.984 / 1199 | 1199.981 / 1199 |
| 基线3 | 1200.000 / 1200 | 1199.238 / 1160 | 1199.981 / 1199 |
| 优化1 | 1199.983 / 1199 | 1199.962 / 1199 | 1199.943 / 1198 |
| 优化2 | 1199.950 / 1198 | 1199.965 / 1199 | 1199.951 / 1198 |
| 优化3 | 1199.949 / 1199 | 1199.948 / 1198 | 1199.889 / 1198 |

移动人数P05依然是优化3的1199/1200/1199、其余三端均1200；1人（0.083%）只描述这一分位数差异。最大逐帧偏离出现在基线3客户端1，为40人（3.33%），该客户端窗口平均1199.238，未丢弃低点。比较体现约1200单位的持续移动负载，不声明每个渲染帧恰好1200单位移动。

此前服务器9.997–10.000Hz取自完整50秒采集汇总；现改用共同30秒实际固定步数，六轮均300步，即10.000Hz。全采集Hz仍保留为`full_capture_sim_hz`，全采集及共同窗口均无丢步。有效性检查另显式要求解码失败数为0，六轮仍通过。

网络字节、CPU、内存及其百分比未变：服务端合计下行−64.15%，整进程CPU变化混合，新增缓存服务端合计4.35MiB/每客2.06MiB。原始数据、18份正式CPU截帧、前后源码、源码版双目标成功与65/65自动化均未变化，沿用[前一归档的证据链接](20260915-指挥官姿态协议9压缩与六轮对比.md)。

变更仅涉及[分析脚本](../../Scripts/analyze_commander_pose_compression.py)、[报告生成器](../../Scripts/report_commander_pose_compression.py)、报告与需求/开发记录。更新索引`build`和全量`check`，0错误、11项既有提示；[结果](../../TestResults/CommanderPoseCompression/progress-final-check.json)。跨机、公网劣网和部署容量仍未测。
