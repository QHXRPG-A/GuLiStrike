## 做了什么

1. 回读材质与 ISM 数据合同，确认 `PerInstanceCustomData[0/1/2]` 仍分别承载生命比例、选中和可见性；问题不是 C++ 数据被错误染色，而是低亮度世界 Emissive 经预曝光、Local Exposure 与 Film Tonemapper 后变暗。
2. 将材质输出改为 `Custom RGB → EyeAdaptationInverse → EmissiveColor`，保持 `PerInstanceCustomData[2] → OpacityMask` 不变。
3. 将生命色锁定为 `float3(2.0, 0.02, 0.03)`。1.0 档仍偏暗，4.0 档进入 Film Shoulder 后出现去饱和珊瑚色；2.0 是当前场景直接截图的实测鲜红档。
4. 没有在最终颜色上整体乘亮度，因此 `Track = float3(0, 0, 0)`、四分位分隔线和 75% 未填充段仍保持黑色。
5. 保留 Surface / Masked / Unlit、Two Sided、原生深度测试、单 ISM、三项 PerInstanceCustomData 和现有显隐策略；没有增加材质实例、逐兵 Widget、Actor、Tick 或 Draw Batch。
6. 只编译并单独保存目标材质，没有 Save All；未修改 C++、Config、地图、单位资产或并行性能优化文件。

## 验证

- 材质回读：共 6 个 Expression；`EmissiveColor` 输入为 `MaterialExpressionEyeAdaptationInverse_0.EyeAdaptationInverse`，`OpacityMask` 仍为 `MaterialExpressionPerInstanceCustomData_2`。
- HLSL 回读：`Track = float3(0.0, 0.0, 0.0)`，`HealthColor = float3(2.0, 0.02, 0.03)`；材质仍为 Surface / Masked / Unlit，`DisableDepthTest=false`，`UsedWithInstancedStaticMeshes=true`。
- 运行验证：`gs.DamageSelected 25` 对 25 名选中小兵生效；截图中每条血条为 75% 填充，最后 25% 和三条分隔线为黑色。
- 直接场景像素采样：鲜红填充核心约 `RGB(255, 0, 26)`（`#FF001A`）；黑色轨道样点约 `RGB(0, 1, 7)`（`#000107`）。后者的极低蓝量来自 TAA、青色选中边缘和场景后处理邻域采样，材质 Track 常量仍为精确零。
- 资产保存触发内容验证并通过；最终日志没有 `Failed to compile Material`，材质 dirty package 为空。
- 最终编辑器状态：PIE=false，dirty package 为空。
- 资产边界：未修改 `GuLiCommanderPresentationActor.*`、HealthBar Renderer C++、Mass/Navigation、DataTable、`Content/Commander/Units/**`、地图、Config 或 Gameplay 文档。
