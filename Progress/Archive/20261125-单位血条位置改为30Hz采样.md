# 单位血条位置改为 30 Hz 采样

巡天、游骑兵、指挥官近景与总览共用每个本地视口的 30 Hz 世界锚点采样时钟。两次采样之间持有上次的世界坐标，绘制时使用当帧相机重新投影并筛选密度。生命、护盾与上次受击时间在独立的 10 Hz 时钟发布。单帧错过多个采样点时只读一次最新姿态。新对象、换代及回到候选集的对象重新取样，普通角色血条会在席位模型报告死亡或失去显示资格时撤下。小兵离散位移可提前更新锚点。[位置缓存](../../Source/GuLiStrike/Commander/UI/GuLiHealthBarLayout.cpp) [实际采样入口](../../Source/GuLiStrike/Commander/UI/GuLiCommanderHealthBarRenderer.cpp)

普通视角在取样帧才读取受击 Actor 的模型包围盒和小兵显示姿态。游骑兵描边及指挥官总览图标本身需要当帧姿态，血条复用其位置来源并独立采样。正式菜单中的僚机对地、僚机综合、Ground 与指挥官入口均使用这一版本。[视口接入](../../Source/GuLiStrike/Commander/UI/GuLiSceneUIWidget.cpp)

## 跟随误差

在对地试玩中跟拍一架正常飞行的僚机，测试相机相对机身偏移约 13.5 米，视口为 2034 × 1257。切换测试相机后先经过 36 帧，再连续读取 240 帧。在 2.521 秒的实测窗口中，位置采样为 29.75 Hz，信息发布为 9.92 Hz。每一采样帧的锚点与独立计算的网格顶部中心误差小于 0.001 厘米。其余 164 个帧间隔世界锚点保持不动，屏幕矩形都随镜头移动。

本次飞行平均速度 19.78 m/s，样本内最高速度 22.94 m/s。世界位置偏差均值 22.48 厘米，P95 为 55.14 厘米，最大 66.29 厘米。上述近距机位对应的屏幕偏差 P95 为 27.37 像素，最大 37.79 像素。实际摄像机投影与本次绘制矩形的差异小于 0.001 像素。屏幕偏差随相机距离、视场和单位运动方向变化。

首次探针对测试相机切换后立即采样，第 3 帧的诊断矩形仍与前一帧相同，与相机投影相差 13.81 像素。为此另开独立试玩，经切镜预热后重新采集，并记录每帧实际世界 UI 绘制计数。两个原始窗口分别保留。

## 性能对照

复用[逐帧版实测基线](20261125-单位血条逐帧跟随与屏幕密度.md)。两个版本均使用相同的地图、席位、分辨率和受击反馈频率，每个场景各采三段 180 帧，合计每版每场景 540 帧。总览加入 96 个密集的临时 Pawn。整帧 P95 按各组 540 帧取最近秩，CPU 更新均值覆盖整个本地 SceneUI 更新，包含候选收集与缓存维护。

| 场景 | 整帧均值，逐帧 → 30 Hz | 整帧 P95，逐帧 → 30 Hz | 场景 UI 更新 CPU 均值，逐帧 → 30 Hz |
| --- | --- | --- | --- |
| 对地，25 架僚机与 6 个地面目标 | 10.50 → 11.01 ms | 14.19 → 14.63 ms | 0.2360 → 0.2457 ms |
| 综合，50 架僚机与 36 个地面单位 | 11.60 → 12.64 ms | 14.16 → 16.24 ms | 0.2580 → 0.2675 ms |
| 指挥官密集总览 | 18.43 → 18.27 ms | 28.22 → 26.93 ms | 0.1885 → 0.1915 ms |

50 架僚机时，单看世界血条收集的 CPU 均值从 0.0418 变为 0.0407 ms。三种场景的整帧变化方向不一致，当前测量未显示稳定的帧率收益。默认飞行镜头在计时采样点显示 0–2 条血条，总览显示 6–10 条。展开密度布局的单独验证在总览和战术相机均达到 36 条。Ground 席位在实际交战的 360 帧中有 359 帧显示敌方受击血条。

已用本次血条对照授权安全重启编辑器，在 `D:/UnrealEngine-5.7` 构建 `GuLiStrikeEditor Win64 Development`，退出码 0，引擎和项目 BuildId 一致。八项原生回归通过，覆盖 120 FPS 下的 30 Hz 位置与 10 Hz 信息、逐帧相机投影、复用及可见性。地图 `/Game/Maps/LVL_CommanderMassPrototype` 已确认可进入。玩家视觉体验及打包版本未在本次采样范围。
