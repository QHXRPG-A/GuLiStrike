## 做了什么

### 复现上下文与定位证据

用户在正式地图 `/Game/Maps/LVL_CommanderMassPrototype` 的“地图标注”面板中选中 Generic 标记，点击“删除”后出现 Fatal error。截图中的业务键为 `Generic_1E058BA042E28910A9D69D870503F146`。本次没有在正式地图中重试删除，也没有改写该地图、恢复自动保存或操作其他任务打开的编辑器。

原始进程为源码版 `D:/UnrealEngine-5.7/Engine/Binaries/Win64/UnrealEditor.exe`，PID 72468。崩溃 GUID：`UECC-Windows-27D2824E4C4ED71C23A3D2AB3BDACF08_0000`。

`OriginalCrash.log` 的 UTC 时间 `2026.09.07-00.44.45`（本地 08:44:45）先记录 `Deleted Actor: GuLiMapMarker` 和 `Deleted 1 Actors (0.081 secs)`。CrashContext 记录 `EXCEPTION_ACCESS_VIOLATION reading address 0x00000000000000d8`，崩溃线程为 GameThread。

使用 Visual Studio 自带 `llvm-symbolizer.exe --relative-address`，在覆盖旧 DLL/PDB 前解析 CrashContext 的模块偏移：

```text
UnrealEditor-GuLiMapAuthoringEditor + 0x264e0
  FGuLiMapVisualizer::DrawVisualization
  GuLiMapViewport.cpp:124（修复前）
UnrealEditor-UnrealEd + 0x1250d10
  UUnrealEdEngine::DrawComponentVisualizers
  UnrealEdEngine.cpp:1497
UnrealEditor-UnrealEd + 0xc9a541
  FLevelEditorViewportClient::Draw
  LevelEditorViewport.cpp:5048
```

UE 的 `DrawComponentVisualizers` 直接把缓存选择的 `ComponentPropertyPath.GetComponent()` 传给可视化器。该路径在 Actor 删除及 GC 后允许返回 nullptr；插件原来无条件执行 `C->GetOwner()`，因此在绘制控制柄之前就崩溃。不是 JSON/CSV 导出错误，也不能据此认定地图损坏。原先怀疑的 Details 刷新并非本次堆栈落点，未对其作无证据改动。

### 最小修复

1. 绘制入口遇到空或无效组件直接返回，Owner 必须是有效 Marker 才继续绘制。
2. 控制柄点击入口先解析 HitProxy 的弱组件引用并检查 Owner，忽略删除后尚未刷新的过期点击数据。
3. 未修改 UE 源码、面板删除事务、业务 GUID、持久化格式或其他玩法模块；未增加对外 API。
