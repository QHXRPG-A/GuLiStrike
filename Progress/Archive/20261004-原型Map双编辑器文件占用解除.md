# 2026-10-04：解除原型Map的双编辑器文件占用

用户反馈“开不了pie”，日志中Ground/Flight导航缓存均通过；最早异常为保存`/Game/Maps/LVL_CommanderMassPrototype`时移动原文件失败，Windows错误32。导航插件随后报告Navigation save failed并取消PIE。[原失败日志](../../outputs/commander-green-guide-line-20261004/pie-start-recovery/player-pie-start-failure.log)

系统同时存在任务在构建后重开的PID38128，以及用户后来打开的PID19868。对`D:\UE5.7\test1\Content\Maps\LVL_CommanderMassPrototype.umap`执行Windows Restart Manager只读锁查询，确认唯一占用者为38128；没有读取或改写二进制资产。通过该实例的编辑器API确认没有游戏世界、未保存地图或内容后，正常调用QuitEditor退出。

退出后锁查询为空，只有用户PID19868保留；该实例的GuLiStrike DLL路径和修改时间与本次构建相符。未修改导航、地图内容、源码或配置，未重编或启动PIE。此为编辑器会话维护，无新增功能或场景，不需另建无关验证Map。
