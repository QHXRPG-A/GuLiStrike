# 2026-09-14：法术场配置归并到单一入口

## 变更

- `GuLiStrikeSpellFields.xlsx/Fields`接收原`WeaponFields`的`WM01_MissileExplosion`（id=1）和`WingmanGroundMissile`（id=2），同时保留4条传送配置（1001–1004）。所有ID、行名、伤害、范围和时序均保持。
- `GuLiStrikeSecondaryWeapons.xlsx`删除`WeaponFields`；`Skills/H`和`WingmanWeapons/Z`将原字符串EffectConfigId维护列改为中文“产生的法术场”，类型为可空整数，引用Fields.id。
- DataPipeline校验唯一法术场来源与引用有效性后，将数字ID解析为已有UE行名属性EffectConfigId。manifest的Fields只有SpellFields一个来源。错误配置在任何生成物写入前失败。
- 次级武器导入先导入Fields，再导入6张武器相关表；历史拆表脚本识别新格式后退出。
- 法术场运行层优先使用武器上下文的引用。普通弹体查询该引用的全局配置；点目标弹体核对上下文与冻结配置的一致性。特效资产的ConfigId仅作为无武器引用时的默认值，表现资产连接继续保留。
- 既有公开API、反射属性布局、服务器权限、伤害修饰、来源租约与已发射效果生命周期不变。
