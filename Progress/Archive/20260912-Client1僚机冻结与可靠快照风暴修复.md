# 2026-09-12：Client1僚机冻结与可靠快照风暴修复

## 变更清单

| 文件/模块 | 变更 |
|---|---|
| `FGuLiWingmanRelayServer::SetWingmanHealthPermille` | 非致死伤害只更新权威血量，不再建立整组可靠切片 |
| `AGuLiWingmanPresentationActor::ApplyBootstrap` | 同handle存活槽位继承Remote Pawn、已展示Transform、插值样本和服务端时钟 |
| 租约/位姿传输 | 删除运行时静默看门狗和心跳RPC，活跃Flight持续10Hz上传 |
| 客户端表现分配 | 已删除距离、组数、总Actor和Remote Actor预算门；陈旧姿态保留最后位置 |

## 决策与实现

现场的非对称冻结不是30Hz逻辑未运行，而是Client1的公共远端位姿长期得不到处理。修复前6秒采样中，Client1的24个可见Remote全部位移为0；同时Owner仍在运行，证明问题位于公共同步/表现链。

根因是对空逻辑射击的每发非致死伤害都调用 `HandleActiveRosterRevision`：高射速下持续生成包含Roster、AuthorityMap、Health、Dead、AcceptedSnapshot和AbilityConfig的可靠Bootstrap。它既挤压不可靠位姿，又让客户端反复释放整组Remote Pawn并清空插值队列。

现在血量在服务端按发结算，但非致死变化不发布成员切片；真正死亡/补员仍可靠同步。新切片到达时，未变存活成员不重建Actor，并保留较新插值历史和已推进服务端时钟。本改动不改Owner 30Hz逻辑根、碰撞、攻击坐标或伤害结算。
