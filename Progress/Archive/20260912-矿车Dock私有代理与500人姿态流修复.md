# 2026-09-12：矿车 Dock、队伍私有代理与 500 人姿态流修复

## 结果

- 矿车不再把工厂中心当成返厂点。每座工厂在地图内侧 4000cm 处生成并复制 DockPoint，位于 2500cm 工厂障碍外；矿车保持普通碰撞和导航限制，没有对工厂开穿越特例。
- AI MoveTo 的 600cm 接受距离会再计入 750cm 矿车导航半径，因此服务器停靠判定与导航成功语义统一为 1350cm。双方矿车均实际跑通“采 10 → 返 Dock → 停 1s → 卸货 → FIFO 加工 → 再出发”。
- 库存、工厂 FIFO 队列与本队所有矿车的货仓/控制/任务状态改为一份带 Revision 的队伍快照，由 Commander Resource Adapter 组装并写入每个同队 PlayerState 的 OwnerOnly 属性。资源 Actor 不再动态切换 Owner，也不复制上述私有字段。
- 工厂消失是表现复制缺口：客户端有工厂业务 Actor，但未收到 `UChildActorComponent` 需要的表现类。现在 `FactoryPresentationClass` 使用 InitialOnly 复制，服务器和 OnRep 共用同一设置路径，三个 PIE World 中红蓝工厂都有可见的 `BP_ResourceProcessingFactory` 子 Actor 与网格。
- 500 人姿态流固定为 `SoldierId % 3` 发送相位；近距离移动保持 10Hz，远距离移动与静止都降到 5Hz。连接定位基于实际 PlayerViewPoint，传送标记始终不被降频过滤。
- 插值基线从 0.10s 改为 0.12s，大于 10Hz 的一个采样周期；每名单位按收包间隔 EWMA 和抖动单独计算缓冲，上限 0.35s，状态切换时清除旧频率样本。

## 实测与门禁

- 实际 D3D SM6、Dedicated Server + 2 Client 的 500 人 PIE，配置 100ms RTT、30ms 抖动、5% 丢包与重排；读取真实 `UNetConnection::InBytesPerSecond`，而非按协议字段估算。
- 连接预算 `250000 B/s`；入站平均 `56920 B/s`，P95 `59818 B/s`（约 0.455/0.479 Mbps），对应使用预算约 22.8%/23.9%。
- 门禁通过：70 个新鲜姿态帧，种子单位最大收包间隔 400.7ms，163 个表现步长样本、行进 1706.1cm、步长 P95 44.6cm，未标记硬瞬移 0，命令 ACK 平均/P95 46.9/65.3ms。
- 资源双客户端验收 16/16；最终 Resources 6/6、Commander Network 19/19、Commander Presentation 13/13，共38/38，测试用例未修改。
- `GuLiStrikeEditor`、`GuLiStrike`、`GuLiStrikeServer` Win64 Development 构建均成功。项目与引擎 `UnrealEditor.modules` BuildId 同为 `ca32e40e-6f35-4046-b75e-aeb3f6da9927`。

## TaskGraph 断言处置

`TaskGraph.cpp:689` 的 `RecursionGuard` 断言堆栈从自动化关闭逻辑进入 `KismetSystemLibrary::QuitEditor → EndPlayMap → CollectGarbage → AudioDevice::Teardown → ProcessTasksUntilIdle`。根因是在 PIE 拆卸回调中同步关闭 Editor，使 Named Task Queue 重入，与采矿车、矿厂、Mass 处理器或姿态发送逻辑无关。

资源 PIE 运行器现在分三步：请求 End PIE，在后续 Slate tick 中确认 PIE 已结束，再调用 `QuitEditor`。修改后以同一用例重跑资源双客户端验收，16/16、errors=0，Editor 正常自行退出，Windows 应用日志无新的 UnrealEditor 崩溃事件。验收断言和步骤未变。
