# 2026-09-13：僚机Big17爆炸范围缩放修正

## 原因

此前爆炸场的参考半径和权威AOE半径均为4000cm，公共表现公式得到 `FieldScale=4000/4000=1`，Variant也为1倍，因此组件最终只按1倍播放。运行时代码虽然写入`User.Radius=4000`，但Big_17实际只暴露`User.CameraDepthFafe`、`User.Color`、`User.Depth Fade`、`User.Emissive`和`User.LifetimeMult`，没有`User.Radius`，该值不会改变粒子尺寸。

Niagara读回显示主火球的`Uniform Sprite Size`为2500–2600cm。3.1倍后为7750–8060cm直径，约等于40米半径对应的80米直径，因此选择3.1而不是沿用明显超出范围的5倍。

## 变更

- `/Game/GuLiStrike/FX/WingmanWeapons/DA_WingmanGroundExplosion`：唯一视觉Variant的Scale由1改为3.1。
- `Scripts/deploy_wingman_attack_assets.py`：新增3.1倍常量；允许安全迁移已知1倍旧合同；Variant浮点读回使用0.001容差，避免UE将3.1保存为3.0999999时误报。
- 权威伤害半径仍为4000cm，Field参考半径仍为4000cm，Big_17系统本体、随机Yaw、3秒MaximumLifetime与Commander引用均未改。

## 验证

- 冷重启后部署回读：Variant Scale=`3.0999999046325684`、RandomYaw=true、MaximumLifetime=3秒、DissipationSeconds=3秒；源/副本Niagara均11个Emitter、0错误、0警告。修正脚本幂等复跑成功且保存列表为空。
- `/Game/Maps/LVL_ShipWingmanAirCombatPrototype` 的Dedicated Server+双客户端PIE真实轰炸中，先后捕获21与172个活动Big_17组件；所有活动组件世界Scale均为`(3.1,3.1,3.1)`，Pitch/Roll为0，Yaw保持逐事件随机且同一事件双端一致。
- 峰值画面保存在 `TestResults/WingmanAttack/Big17_scale31_active_client1.png` 与 `Big17_scale31_active_client2.png`，可见放大后的连续轰炸火团。切换为空中目标停止新对地轮次并经过弹体/表现清理窗口后，64个池对象全部为非活动状态；收尾停止PIE，内容和地图脏包均为0。

## 边界

3.1倍按主火球尺寸对齐AOE直径；烟雾、火花和冲击波各层的边缘不保证与伤害球严格重合。Big_17含GPU发射器，密集轰炸时观察到172个并发活动组件；本轮只完成设计与功能读回，未测目标硬件GPU时间。
