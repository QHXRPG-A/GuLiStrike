# 2026-09-13：僚机对地轰炸Big17爆炸特效

用户指定 `/Game/AllExplosions/Niagara/Big/NS_Explosion_Big_17` 作为僚机对地轰炸爆炸，并要求每次随机朝向、播放3秒后销毁。实现把市场资源复制到项目自有目录，避免直接把Gameplay定义绑定在外部包路径上。

## 变更

- 新增项目副本 `/Game/GuLiStrike/FX/WingmanWeapons/NS_WingmanGroundExplosion_Big_17` 与独立爆炸场 `/Game/GuLiStrike/FX/WingmanWeapons/DA_WingmanGroundExplosion`；僚机专用 `DA_WingmanGroundMissile` 改指向该爆炸场。
- 飞行Niagara仍复用Commander的WM01资源，僚机导弹2倍飞行表现不变。Commander的 `DA_WM01_Missile` 及 `DA_WM01_MissileExplosion` 引用未修改。
- `FGuLiEffectVisualVariant` 增加 `bRandomYaw`。表现层使用复制状态中的 `RandomSeed` 派生 `[-180°, 180°]` Yaw；Pitch/Roll为0，因此同一事件在不同客户端方向一致，不同爆炸仍逐次变化。
- 爆炸场参考半径设为4000cm，与权威AOE半径一致，Big_17按1倍组件Scale播放；`DissipationSeconds=3`、`MaximumLifetime=3`，到期执行立即停用并释放回Niagara池。
- `Scripts/deploy_wingman_attack_assets.py` 增加源/副本Niagara编译、Emitter对照、旧资产契约保护和只保存显式脏目标的幂等部署。

## 验证事实

- 指定源Niagara和项目副本均编译为0错误、0警告，Emitter列表完全一致，共11个：`refr_sprite`、`refr_mesh`、`main`、`spark`、`impact`、`spark_l`、`smoke_shockwave`、`smoke_after`、`parts`、`spark001`、`spark002`。
- 首次部署只保存3个Wingman专用资产；第二次运行保存列表为空。回读为4000cm参考半径、3秒消散、随机Yaw=true、3秒MaximumLifetime，Commander ImpactField仍为原路径。
- 源码引擎 `D:\UnrealEngine-5.7` 的 `GuLiStrikeEditor Win64 Development` 与 `GuLiStrike Win64 Development` 均构建成功；Editor构建后引擎/项目BuildId均为 `26d441ba-b96a-4e7b-b104-c2c6cd3e663c`。
- `/Game/Maps/LVL_ShipWingmanAirCombatPrototype` 普通Dedicated Server+双客户端PIE产生真实对地轰炸。客户端曾同时观察到25/42个活动Big_17组件，Yaw样本包含 `-154.822°`、`-70.679°`、`1.521°`、`73.056°`、`177.828°` 等，覆盖正负方向；样本Pitch/Roll均为0，并在两客户端观察到相同Yaw值。
- 切换为空中目标停止新对地轮次后，Big_17活动组件由20降为0；池对象保留但全部为非活动状态。资产与运行时双重3秒上限负责硬清理，收尾时PIE已停止且内容/地图脏包均为0。

## 边界

Big_17含GPU发射器；本轮覆盖了普通双客户端多实例生成、随机朝向和回池，没有执行打包运行或目标硬件的同屏峰值GPU分析。现有旧验证脚本仍断言僚机与Commander共享ImpactField，属于本次需求改变后的待授权测试维护项，不作为本轮失败。
