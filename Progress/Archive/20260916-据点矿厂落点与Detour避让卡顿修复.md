# 2026-09-16：据点矿厂落点与 Detour 避让卡顿修复

## 根因

- 崩溃来自已有赠品生成与坡道的地面契约不一致。R3C4 西向入口比中心高 1190.606 cm，旧射线从中心上方 500 cm 向下，起点已在地面内；失败触发运行时 `checkf`。相关实现于 9 月 14 日存在，早于本轮导航预烘焙；实际失败使用物理射线而非 NavMesh。
- 旧压测中两套导航剩余瓦片任务均为 0。所谓约 487 ms/帧的 `NavigationBuild` 几乎全部来自 CrowdManager；Insights 中 99.7% CrowdManager 时间位于 `Step: proximity`。Mass 被动障碍的查询半径为 0，仍反复创建并线性查找不能复用的墙体边界样本。

## 实施

- 建筑生成前采样完整占地，校验地面、坡度、高差与占位；读取实际矿厂蓝图坡道模板，验证入口中点与两侧。
- 预检与运行时坡道共用解析函数。地面不合格时记录原因，禁用该坡道碰撞、可见性与导航相关性；有效地面恢复后可重新拟合，不再致命断言。
- 按用户选择，先试原槽位，再在据点附近 70–210 m 候选范围内搜索，尝试四种朝向。每槽单次至多四个候选，跨 tick 继续；失败保留待发奖励，换主不重复发放。
- 修改源码引擎 `DetourCrowd.cpp`：先将全部障碍加入空间索引，再跳过查询半径非正的被动障碍自身邻域查询。工程车仍可查询和避让这些障碍；人口、NavMesh 参数及运行时 Dynamic 模式保留。
- 可重复安装的补丁与说明保留在 [Scripts/EnginePatches](../../Scripts/EnginePatches/README.md)，反向只读应用检查确认当前引擎已安装。

## 验证结果

### 崩溃与导航行为

- 原编辑器 PID 43932：全部 25 个据点成功发放 75 栋奖励建筑；主客端各 27 座矿厂（含两座初始矿厂）坡道有效。R3C4 自动选择 `(126000,0,-7151.611)` 朝东落位，红转蓝后实例不变。
- 最终源码编辑器 PID 39244 再次验证同一 R3C4 落位，主客端坡道有效，局部导航任务随后完成。最终重开后的地面、空中缓存均命中，重烘焙及保存为 0，输入与士兵门禁顺序正确。
- 最终 53 项导航、放置与资源自动化成功，零警告、零失败。新增坡道回归处于用户已授权的建筑/坡道导航回归范围。
- 复用既有工程车绕静止 Mass 士兵场景：11.02 秒到达 500 cm 目标容差；士兵漂移 0，最小中心距 1896.07 cm，车辆观察到一个邻居，管理器保留 597 个 Mass 障碍。

### 1200 人持续移动

沿用原采集脚本、1920×1080 Epic、固定相机、8 秒往返及共同 30 秒窗口。单客、双客各三轮，采样期间没有本轮编辑器、构建或其他验证任务干扰。

| 指标 | 结果 |
|---|---|
| 九份客户端采样移动人数 P05 | 1199–1200，全部超过 1140 门槛 |
| 单客帧 P95 三轮中位数 | 10.75 ms，预算 16.67 ms |
| 双客帧 P95 三轮中位数 | 客端 1 为 18.66 ms，客端 2 为 18.57 ms，预算 33.33 ms |
| 六轮客户端零移动帧 | 全部为 0 |
| 六轮服务端模拟掉步 | 全部为 0 |
| 单客 CrowdManager 每帧均值的三轮中位数 | 487.15 → 1.84 ms |
| 六轮两套 NavData 采样期剩余任务 | 均为 0 |

单客 Insights 相同 30 秒窗口的 proximity 每次平均耗时由 495.858 ms 降至 0.111 ms。当前完整负载达到原验收门槛；旧客户端优化前后负载均不足，不能用本表声称其独立收益已经证明。
