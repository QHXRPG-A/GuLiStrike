# 2026-09-23：Mass验证场景PIE阻塞修复

用户在源码版编辑器点击Play，连续被`Could not hash GuLiMapAuthoring output`取消。当前为源码版Editor进程13356，地图`/Game/Maps/LVL_CommanderMassPrototype`，无游戏世界；初始地图无未保存修改。`LogUMGEditor`多窗口Post Buffer提示不是本次取消原因。

## 根因与勘误

`FGuLiStrikeEditorModule::RequestPIEPermission`首先调用`ValidateCurrentBake`，其资源哈希还包含`FGuLiInitialArmyAuthoring::Build`的出生数据。后者明确拒绝任何`GuLiCommanderDeploymentPoint`。前次助手添加的25个专项部署Actor触发这一规则，具体错误被`HashAuthoringFiles`包装成通用哈希失败。直接调用初始军队预览后日志读到了`Canonical 500-unit resource authoring requires default deployment; remove the overriding deployment point.`。

移除专项部署后，哈希恢复原值，但出生检查在第76名（team=1 formation=3 slot=0 type=2）失败。实际出生坐标约(6140,61710)，处于专项通道墙体附近；另有墙角及封闭区墙体接触其他出生槽位。此前仅核对Actor已保存及矿体避让，遗漏默认军队和PIE前置检查，不能据此认定可玩。前次“25/500/2000/10000人口档位已交付”结论撤回，仍是待完成范围。

本记录只更正前次归档的场景交付结论；预算规划、绿线与避障源码变更以及后续[成功编译](20260923-Mass分帧寻路与基础避障编译交付.md)事实保留，不代表其运行效果已经通过。

## 已实施修复

- 备份原地图文件和25个部署Actor配置，只删除带`MassNavigationReview20260923`标签的专项部署。恢复红蓝各250名默认混合兵种，保留原资源定义和240矿簇。
- 以真实出生预览的615个军队/设施预约及240矿簇共855项空间约束检查墙体，并保留250cm额外净距。8面验证墙体整体沿Y移动6500cm，800cm通道宽度不变，同步移动对应观察说明点。
- 墙角主要位置为(11200,70500)/(12600,71500)，通道为(5200,69000)/(6200,69000)，封闭区中心为(16500,67000)。原105个Actor变换保持。
- `Scripts/author_mass_navigation_scene.py`默认只接受profile 0，其他人口覆盖值在改图前拒绝；删除不兼容的专项部署生成功能，加入真实军队/设施净距检查、导航准备和资源/出生校验。当前场景14个验证Actor已保存。
- 通过现有编辑器导航准备API重建2套地面导航和1套飞行导航并保存，耗时22.27秒；未改NavMesh代理尺寸、单位半径、资源布局或PIE校验规则。
