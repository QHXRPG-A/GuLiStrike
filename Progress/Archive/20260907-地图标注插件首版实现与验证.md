## 做了什么

1. 按可扩展合同拆分 Core/Editor。普通玩法类型由 DataAsset 定义，参数用 FInstancedPropertyBag，区域用 FInstancedStruct，不用 Resource/Outpost 固定枚举驱动业务。
2. 字段按 GUID 迁移。新增/改名保留兼容值；删除/改类型不静默覆盖，必须修回定义或显式升级重置冲突，且能撤销。复制/粘贴产生新 Marker/Region GUID 与业务键；位置/保存/重开/Undo 不重生成身份。
3. 增加 Slate 面板、当前地图服务与持久关卡标记。每个 Marker 可以有多个独立命名区域，Actor 世界变换与区域相对变换分开，Scale 固定 1。
4. 四类几何使用相同注册接口。多边形拒绝自交/退化/非相邻接触/重叠边，凹形用 GeometryCore 三角化；至少 3、最多 4096 顶点，无内孔。
5. 场景代理负责未选中时也可见的轮廓和填充；Visualizer 负责控制柄。拖动暂存整条记录，提交校验失败回滚并取消事务；关闭、换图、PIE、Esc 清理未提交状态。
6. UpdateMarker 先在副本解析、检查所有字段/身份/几何，再校验全图并一次事务应用；成功后广播属性变更以刷新面板。无头保存使用 UE 无对话框保存 API，普通编辑器仍使用正常保存/签出流程。
7. 导出从同一完整快照生产 layout.json 和五张 CSV，写同级 staging 后整目录切换，保留 previous。UTF-8 无 BOM、LF、固定排序、double 往返精度，扩展形状原始参数在 JSON/properties.csv 中保留。
8. WP 扫描 Actor Descriptor，临时强引用按需加载 Marker，并核对实际 ActorGuid 集合。不支持空间加载、Data Layer、子关卡/嵌套容器时明确失败，不把可见列表当全图。

### 实际视口发现并修正的渲染问题

首次截图只有控制柄清晰：轮廓原先按世界空间 2cm 线宽，远景只剩零星像素；同时 UE5.7 的 DynamicEditorMeshElements 路径过滤半透明网格。

最终采用屏幕空间 2px 轮廓，场景代理使用普通渲染路径，并读取 DebugMeshMaterial 实际 MaterialRelevance。此材质为 After DOF，不能只硬编码 bNormalTranslucency。修复后取得四形状实际填充、凹多边形缺口和未选中常驻图像；Actor/组件仍是 EditorOnly，无碰撞、导航、Tick 和阴影。

后台 UE 会停更视口，部分早期截图是旧帧。只在隔离验收进程暂时关闭 bThrottleCPUWhenNotForeground 后取得更新图像；结束已恢复为 true。Windows 输入接口仍不能激活窗口，因此没有把 API 放置/选择或截图当作实际鼠标操作验收。

## 遗留问题

1. 鼠标交互矩阵未验收：实际点表面/工作平面放置、Alt/相机输入、四形状拖拽、区域移动/旋转、插删多边形点/高度、临时红色无效轮廓和失败回滚、一次拖拽一次 Undo/Redo、拖动时关闭面板/换图/进入 PIE。实现已编译，但原生 API 与无头测试不能替代这些操作。
2. WP 真正未加载 Marker 恢复及无法取得完整集合时的端到端失败分支未验证；当前仅证实描述符清点及近远标记正常导出。现有自动化未模拟磁盘满/目录被占用等所有 OS 发布失败情形。
3. 验证脚本初稿曾在 Python 全局变量持有 duplicate_asset 返回的 World，切换地图触发 UE WorldMemoryLeaks 检查；隔离进程重启后恢复，最终脚本改为函数局部引用并在换图前释放。不是用删除数据绕过检查，原正式地图未受影响。使用说明已提醒此现有 Python 通道陷阱。
4. 新插件只面向编辑器。Excel 映射/填表、运行时消费、GameMode、事件编排、样条和多边形内孔未做；不承诺这些布局 CSV 能直接进入现有 DataTable 导入器。
5. 旧编辑器进程不自动载入新 DLL。使用者应先保存自己的工作，再用源码版 Editor 重启项目打开插件；本次没有关闭用户原有编辑器会话。

接续验收时先打开隔离地图，按插件 README 操作四类区域，记录操作前后快照和单次 Undo 结果，再补齐上列勾选项。没有这些实际证据前，开发文档中 M2/M3/M4 的完整验收保持未完成。
