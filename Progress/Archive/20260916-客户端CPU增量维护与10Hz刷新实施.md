# 2026-09-16：客户端CPU增量维护与10Hz刷新

## 变更与决策

| 模块 | 变更 |
|---|---|
| Commander/Network | 本地名册ID值缓存、FastArray批量增删改事件；不增加协议字段 |
| Commander/Presentation | 事件驱动槽位维护、持久变换缓冲、原生ISM提交、10Hz Mass位置批次及安全代次隔离 |
| Commander/UI、CombatEffects | 小地图两个Slate缓存层；血条活动集合、槽位回收与空闲休眠 |
| 原有四份测试文件 | 名册、实例池、调度、Mass生命周期、血条、小地图缓存及原生渲染更新回归 |

移动插值与位置提交保持每帧；常规低频工作统一0.1秒，卡顿不补跑。选择、受击、生命和位移变化及时更新。失败槽位独立10Hz重试，不回到每帧全员扫描。

实施中通过实际失败修正了预留Mass实体的批量销毁路径，以及普通朝向错误触发可靠快照更新的问题。错误采集轮完整保留并排除。

## 验证

- 引擎 `D:/UnrealEngine-5.7`；GuLiStrikeEditor Win64 Development、GuLiStrike Win64 Development最终退出码均0。最后日志为editor-build-9、game-build-6。
- 引擎、项目、GuLiFlightNavigation的BuildId均为`26d441ba-b96a-4e7b-b104-c2c6cd3e663c`。
- Automation-5：42成功、0失败、0未运行。仅扩充用户已授权的四份现有测试文件。
- 前后单客/双客各三轮。九份修改后客户端共同30秒窗口：Mass位置批次和小地图采样各300次；空闲血条逐帧更新和池全量校准0次。
- 双客Client1局部计时中位数：表现主循环1.317→0.569ms/帧，Mass延迟执行0.216→0.029ms/帧；全场景Recreate每30秒3143～3206→67～75次。实际负载未达门槛，不能推导整帧收益。
- 明确埋点的缓存容器高水位相加约872KiB，未包含全部引擎、Slate及GPU分配。
- 原Slate鼠标流程确认3条移动被服务端接受并呈现起步、改向、停止；旧脚本依赖已关闭的位移预测入口而报告失败，该判据未改写为通过。
- 血条选择、受击、死亡、过期休眠及小地图旋转/重新显示/两种窗口缩放的点击检查完成；最终PIE正常结束，编辑器原地图无脏包。

## 未通过与遗留

**整体性能验收未通过。** 前后每轮客户端的实际移动人数P05均低于1140，修改后单客三轮为0；首轮服务端导航构建平均487.168ms/帧，存在明显掉步。即使观测帧时间P95低于数值预算，也不算持续移动目标通过。

两次长PIE运行触发现有建筑坡道入口地面断言（GuLiGroundAccessRampComponent.cpp:37），本轮未修改该文件；采用短窗口完成UI补验，保留原始中断日志，不宣称长期运行稳定性通过。

六轮修改后计时中，小地图原静态计时标签合并了两个缓存层；最终仅拆开标签，并重做双目标构建与42项测试。原六轮按子层合计解释，不作为地形单层次数。
