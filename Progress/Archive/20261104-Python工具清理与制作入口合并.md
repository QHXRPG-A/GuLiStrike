# Python 工具清理与制作入口合并

按用户“应删尽删”的指令审查 GitHub 当时的 1,124 个 Python 文件。核对范围包括仓库脚本、启动与配置、制作说明，以及本地尚未发布的调用方。最终删除 185 个，保留 939 个。每个已删除文件的旧路径、Git blob 和归类依据均可追溯。[逐文件清单](../Evidence/20261104-PythonCleanup/retired.json)

删除范围包括三档 LOD 已退役的兼容入口、旧地图尺寸迁移、旧卡面写入及预览、一次性文档改写和专用于旧版本的诊断。保留了 2.3 km 地形读取的原始地形导出器，以及独立机体和武器所需的制作、导入与回读。SpiderMech 的导入和摆放仅操作自身资源。旧文档中可点击的历史脚本链接指向清理前的 Git 版本。[基准提交](https://github.com/QHXRPG-A/GuLiStrike/commit/c7974fb6a44b0dda05913318ff47f6506098dc55)

游骑兵机动区统一由一个入口维护原地图的 10 个对象，包括平台、坡台、台阶、左右标靶和入口。新的相机采集使用独立文件。源表恢复从当前已发布的三张文本表取数，正式导入负责动画接线与清单同步。[游骑兵制作步骤](../../Scripts/GroundMech/MechaDestroyer/README.md)

剩余 939 个 Python 文件均通过语法检查。已核对直接导入、脚本路径、同名模块所在目录及被继承的着色器常量和写表函数。机动区数值与既有场景读回相符。使用正式工作簿的临时副本验证了错误数值可恢复、重复恢复无需写回、显式选择相机采集生效。UE 游戏运行和画面沿用此前交付的验证状态。
