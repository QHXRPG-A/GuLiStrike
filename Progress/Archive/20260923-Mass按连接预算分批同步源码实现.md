# 2026-09-23：Mass按连接预算分批同步源码实现

用户确认实施名册、终点和位置队列联合调度；明确本轮不改120Hz补额限制、战斗特效、建筑复制、单位数值与三倍纠偏，不新增自动化用例或运行PIE/压测。

## 变更与合同

| 位置 | 实现 |
|---|---|
| `Commander/Network/GuLiCommanderStateStream.h/.cpp` | 每连接已发布值、最新待发值、固定初始ID集合及最多4个未确认批次；字段掩码增量，单批编码含长度最多1000字节、最多256条记录。 |
| `Commander/Framework/GuLiCommanderStateDispatch.cpp` | 每Tick按连接预算调度可靠事实与不可靠位置；默认位置预留50%，紧急状态→位置→普通状态，空闲额度释放。 |
| `GuLiCommanderNetSyncComponent.h/.cpp` | `ClientReceiveStateBatch`、可靠累计应用ACK、完成数量/ID哈希/批次屏障；同步代次、连接关闭及换局清理，异常接收或同代次身份重置请求新基线。 |
| `GuLiSoldierStateReplicator.h/.cpp` | 保留服务器完整对账与本地查询/事件；停止直接网络发布FastArray与全局版本，客户端只增量合并及显式移除。 |
| `GuLiCommanderPoseCodec.h/.cpp` | 增加无副作用Prepare及准入后Commit，未获额度不增加序号、不存发送历史。保留原Encode便利接口。 |
| `GuLiCommanderWorldReplicationComponent.h/.cpp` | 10Hz采样脱离全局三相排空条件；近远/静止降频仍保留，各连接仅排队最新单兵样本。 |
| `GuLiBattleAuthoritySubsystem.h/.cpp` | 回收残骸前发出最终权威状态通知，确保排队死亡不会被最终移除覆盖。 |
| `Battle/Network/GuLiBattleTypes.h` | 公共/指挥官协议18→19，拒绝旧客户端混用。 |

状态以连接、战局、SoldierId隔离，最新待发值覆盖旧值，首次等待时间保留；相对最近已交给UE可靠通道的值编码，可靠传输重试完全由UE负责。死亡/移除最高，其次停止、传送、控制限制，其余按等待时间；普通状态等满1秒提升一级，不超过死亡。删除通知在未确认批次中保留至应用ACK。残骸回收可能早于下一次10Hz名册采样，短暂回收标记会压制这份旧采样，防止重建已移除单位。

命令与终点按ActiveOrderId合并，停止清除终点；源终点比名册新时暂缓发布。出生、换令、传送、死亡与控制变化设置位置流应用屏障，避免不可靠位置抢在其可靠身份/命令基线前；普通掉血不重复关闭位置门。对外仍是公共名册、所属指挥官的终点；Listen Server不重复应用远端批次到权威读模型。

每连接按`-(QueuedBits + SendBuffer位数)`的实际信用判断额度；每次RPC预留128字节保守封装余量，发送后核对这些原生计数的增量，只额外保留尚未体现的估算部分，不重复扣费、不虚增UE信用。这是本发送器的准入，不能约束其他复制系统稍后占用连接。没有连接的远程Controller不会被当成本地无预算连接。

位置保持原量化精度、10Hz捕获及近远策略。只留每名士兵最新未发送值和原采样时间，同一块只含相同采样帧/时间；预算不足原地留队。出生/命令/传送屏障未确认时亦保留最新值。移除时清理发送、接收待消费位置及编码历史；传送淘汰旧位置。

首次同步从开始时固定的ID集合推进；其后新增不加入该待覆盖集合。完成批次记录实际已发布集合的数量、按升序ID计算的64位FNV-1a校验值及连续批次号。服务器在完成确认前暂缓后续状态发布，客户端核对后才开放选择、命令和位置；零成员完成也合法。全局SnapshotRevision不再作为就绪证明。客户端增量中未出现的ID不会被删，首次见到死亡也可直接应用。
