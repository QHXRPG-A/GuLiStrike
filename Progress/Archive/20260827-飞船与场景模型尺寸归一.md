# 2026-08-27 解决了：飞船与场景模型尺寸归一

## 结果

场景中三组已人工标定的实例缩放已烘焙到模型资源，关卡 Actor Scale 全部归一为 1；当前玩家飞船仅在子蓝图取消根组件 0.3 倍缩放，父蓝图保持不变。运行时飞船使用缩小为原资源 0.5 的 Dreadnought 舰体，因此最终尺寸为改动前的 5/3，并同步更新舰体偏移、相机参数和出生高度。

## 验证

- 资源：三项包围盒精确符合 0.5/2/30 倍；Dreadnought 与无人机碰撞模式保持；机器人 Skeleton 路径、16 个材质槽顺序和材质资产逐项一致。
- 关卡：目标数量仍为 2/1/128，全部 Scale 1；逐 Actor 对照变更前基线，Location、Rotation、世界包围盒无差异。
- 蓝图：父 `CollisionCylinder` Scale 0.3；子 Scale 1；胶囊半径 800、半高 2000；Hull Mesh Scale 1、Yaw -90°、位置 `(-7081,0,-464.5)`。
- 数据：Dreadnought 相机值为 Default Arm 25000、Step 6666.667、Min 13333.333、Max 83333.333、Probe 3333.333、Min Arm 833.333；三表全行回读通过，生成头文件未变化。
- PIE：Player 0 为 `BP_CombatAvatarFly01_C`；舰体本地尺寸 `19378.039×45023.203×6984.660 cm`，舰体中心与根误差约 0.29 cm；从 PlayerStart 正常出生，舰底距 Landscape 200 cm、无初始重叠，实际相机臂长 25000。
- 截图：`Saved/Screenshots/SizeNormalization/01_top_view.png`、`02_perspective_view.png`、`03_player_view.png` 均已回读检查。
- 日志：最终重导入与终检窗口未出现蓝图、DataTable、资源重导或引用错误。

## 踩坑与处理

- SkeletalMesh 的 Interchange 导入若从 UnrealMCPython 游戏线程回调触发，会命中 TaskGraph 递归断言；改为正常 `UnrealEditor -ExecutePythonScript` 独立进程执行。
- UE 5.7 将 `AssetImportTask.result`、Blueprint `status/generated_class` 等属性改为受保护；改用确定性目标路径与 `EditorAssetLibrary.load_blueprint_class()` 回读。
- `Rotator` 位置参数顺序容易把 Yaw 写成 Pitch；最终统一使用命名参数并做 CDO 回读。
- 根碰撞放大后，旧 PlayerStart 距地仅约 98 cm，被 GameMode 判为不可用并回退世界原点；按新舰体半高抬升后通过磁盘重载 PIE。
