# 约200单位移动交火与场景UI性能截帧

用户先要求在约200单位、约100红色描边及双方持续开火的情况下采样截帧，后续以“差不多就好了”接受近似数量，再明确“不能禁止单位的移动，这也是需要采样的点”。本轮补采采用双方经正常客户端任务入口下达、服务器已接收的移动指令，保留移动、避障、碰撞、姿态、开火与自然战斗停步。完整数据、脚本和验证边界见[本轮报告](../../outputs/performance/20261010-dense200-moving/report.md)。

## 样本和结论

使用当前 `/Game/Maps/LVL_CommanderMassPrototype`、源码引擎 `D:/UnrealEngine-5.7`、同进程专服和双客户端。Client1为1505×1115，Client2为640×484，当前质量和正式优化开关保持。热身10秒，采样30秒；741个CSV帧，按QPC排除起止桥接后有738个完整CPU帧。截图、盘点、ProfileGPU及离线导出均在测量窗口外。

| 范围 | 平均 | P95或单帧 |
|---|---:|---:|
| 整帧，整个编辑器进程 | 40.61 ms，约24.62 FPS | P95 57.05 ms |
| GameThread CSV | 40.62 ms | P95 55.71 ms |
| GPU CSV | 16.31 ms | P95 17.54 ms |
| Client1完整场景Widget Tick＋Paint | 1.626 ms | P95 1.960 ms |
| Client1原生场景UI Update／Paint | 0.293／1.293 ms | 活动帧P95 0.489／1.534 ms |
| 全窗口Slate Tick | 8.353 ms | P95 10.056 ms |
| 编辑器窗口DrawWindow | 1.237 ms | P95 1.864 ms |
| Client1描边捕获GPU | 不按30秒平均报告 | 单帧2.224 ms |

全窗口Slate包含三个窗口及游戏UI，不能全部称为编辑器UI。窗口归属使用GameInstance_10/11对应的真实Widget路径；本次Client1为独立窗口。全窗口Prepass2.126 ms尚未进一步按窗归属，之前Live Coding诊断回调在本次重启会话中未加载，不能套用旧布局数字。

游戏线程仍为瓶颈。双客户端集中战斗表现更新平均5.333 ms，部分包含Niagara子调用；机枪枪口相关系统GT自身耗时平均3.607 ms。最差完整GT帧69.69 ms，其中集中表现更新26.32 ms、枪口系统自身13.87 ms，主要落在表现集中更新、帧尾Niagara提交及Tick完成任务路径。父子范围不能叠加。Client1单位呈现0.439 ms，服务器避障查询0.252 ms、建网格0.069 ms、求解0.013 ms；当前移动及避障不是主要长帧来源。

## 实际负载与证据

- 原生人口快照开始196存活、106移动，结束195存活、65移动。双方实例位置前后回读有变化；正常到达、战斗停步与死亡不阻止。
- Client1可见单位中心179→178，其中敌方地面单位中心79；UI准备脚环230、活动血条128→132，准备数包含视口外来源。未冒充精确100个可见描边或200个始终移动单位。
- 每客户端收到10488条射击事件、接纳7452次目录命中。命中批量组件1个、回退0；结束时847条飞行数据记录、飞行Actor0。没有叠加额外500枚生产器。
- 为人口稳定，只在测试World临时暂停建筑生产及据点夺取，并为生成单位应用血量50000；武器射速、伤害和射程保留。旧停止指令不作为本轮移动负载；采样前正常移动请求接收数为101和80，拒绝0。
- [帧数据与Trace](../../outputs/performance/20261010-dense200-moving/result.json)、[最差帧](../../outputs/performance/20261010-dense200-moving/selected-frames/worst-analysis.json)、[窗口分析](../../outputs/performance/20261010-dense200-moving/slate-analysis.json)、[GPU原始帧](../../outputs/performance/20261010-dense200-moving/gpu-profile-frame.log)。
- 指定Client1的ReadPixels只记录场景像素；SHOWUI全局请求实际捕获Client2，已按蓝方HUD核对并正确标记。不把不同客户端截图、事后GPU帧或不同计时定义混为同步证据。

## 验证和恢复

本轮为用户明确要求的运行时性能诊断。没有新增生产代码、资源或构建，没有执行整版三轮配对收益验证；测试场景仅使用当前地图的运行时生成，未作为新地图内容保存。准备期失败、人口漂移及移动负载不足的旧窗口均排除。本轮40.61 ms与早期42.55 ms不构成优化收益配对。

结束测试PIE后，[恢复回读](../../outputs/performance/20261010-dense200-moving/cleanup.json)确认World数0、CaptureSeconds20、TeamUnitCap300、移动诊断0；采集用GPU参数已恢复。运行时血量、生产暂停、移动订单、镜头及捕获标签随PIE销毁。早期编辑器部署点改动已精确还原，不保存正式资源。这里只交付具体负载的耗时证据，不改动此前计划的用户视觉验收或FPS矩阵状态。
