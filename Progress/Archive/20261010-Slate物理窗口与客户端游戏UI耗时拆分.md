# Slate物理窗口与客户端游戏UI耗时拆分

用户要求进一步拆分编辑器、Client1、Client2的Slate耗时。本轮实时Python桥核对PIE已经结束，因此复用原先同进程专服加双客户端的30秒Trace，不重新启动游玩、改动地图或套用新的负载。

采样时有两个实际Slate窗口：编辑器主窗口内嵌Client1（GameInstance_1），以及独立Client2 PIE窗口（GameInstance_2）。每个`Slate::DrawWindow`使用真实子树的SLevelEditor/SPIEViewport和UObject路径识别；902帧均验证每窗口只包含一个游戏实例。原按World的场景UI计时与两个实例的Tick/Paint包装Scope交叉核对相符。身份归属没有使用窗口调用顺序或仅凭耗时大小猜测，也不改变原CPU World Tick的客户端A/B归属边界。

| 互不重叠的分类 | 平均ms/引擎帧 | 独立P95 ms |
|---|---:|---:|
| 编辑器主窗口其余绘制，扣除Client1视口，含窗口处理 | 1.138 | 1.497 |
| Client1游戏UI更新与绘制 | 0.965 | 1.552 |
| Client2游戏UI更新与绘制 | 0.690 | 1.164 |
| 全部窗口布局预计算Prepass，尚未分窗 | 1.962 | 2.184 |
| 游戏视口、窗口壳及其余公共Slate处理 | 0.500 | 0.641 |
| Slate合计 | 5.255 | 6.595 |

逐帧验证五项之和等于该帧Slate总时长且没有负项；各P95不是同一帧，不能相加。编辑器主窗口整个绘制平均2.141ms，其中Client1视口1.003ms、游戏UI0.965ms；独立Client2窗口平均0.773ms，其中游戏UI0.690ms。不能将编辑器主窗口全部2.141ms算作编辑器UI。

Client1游戏UI包含場景UI包装Tick/Paint约0.301/0.420ms和Commander HUD Paint约0.221ms；Client2分别约0.323/0.151ms和0.194ms。小地图Paint约0.060/0.059ms已包含在Commander HUD Paint内，不另加。原先0.70ms的Client1场景UI原生计时仅是局部，不代表全部游戏HUD。

已有证据确认编辑器主窗口其余绘制占Slate总量约21.6%，两个客户端游戏UI合计约31.5%，未知分窗布局占37.3%。因此不能认定“大部分Slate耗时都是编辑器UI”。UE5.7的DrawPrepass仅在遍历全部窗口外层记录一个Slate::Prepass，原捕获也未启用Slate Channel；已有Trace没有可用于恢复每窗口完整Prepass的边界与身份，不能事后将1.962ms估算为编辑器。完整布局归属仍需同场景补采逐窗口Prepass诊断标记。

本轮严格902完整帧的Slate平均为5.255ms，原窗口计时汇总包含一个边界Slate调用得到5.262ms，差约0.007ms是筛选差异，不是优化收益。原30.11FPS、GT/GPU、服务器和两个客户端World Tick的瓶颈结论不变。

本轮只新增离线导出、分析、报告脚本与证据；没有修改生产代码、正式资源、质量或地图，没有编译或启动新的PIE/压力入口。场景搭建与玩家功能验收不适用于本次纯诊断；原三项优化的玩家验收及暂缓整版FPS矩阵状态保持。
