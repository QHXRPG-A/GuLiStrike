## 做了什么
1. 目标是给指挥官玩法 UI 找设计参考。先尝试图片搜索工具（SC2/AoE4/CoH3 等查询），得到零散结果且部分查询服务端报错。
2. 改用 Steam 商店 API 作为主数据源：`storesearch` 解析 26 款经典 RTS 的 appid → `appdetails?filters=screenshots` 拉取全部官方截图（每款≤16 张，共 293 张下载到会话临时池 `/tmp/rts_pool`）。
3. 关键发现：Steam 商店前 1~2 张截图多为去 HUD 的宣传图，盲选命中率极低（抽查 10 张仅 1 张带 UI）。
4. 用 Python+Pillow 生成"HUD 联络表"批量审核：每张图只裁顶部资源条+底部小地图/指令面板两条带，30 张一屏共 10 张联络表，逐张标注带 UI 的截图（命中 81 张）。
5. 商店图库覆盖弱的游戏（AoE4/CoH2/SupCom/WC3）用图片搜索补充 23 张候选，联络表确认 9 张可用。
6. 按"每游戏 1~4 张、实战 HUD 优先于菜单"精选 50 张（36 张来自 Steam 官方截图、14 张来自搜索补充），以 `编号_游戏名_序号` 重命名（编号保证按游戏交错排序）。
7. 生成最终 50 张全图联络表逐张验收：全部含可见 UI（小地图/指令面板/建造菜单/科技树/资源栏等）。

### 过程中的坑（复现时注意）
- 截图 URL 尾部带 `?t=` 时间戳，若整个当扩展名会因 Windows 文件名禁用 `?` 导致 curl 全部写盘失败。
- Steam `appdetails` 有速率限制，26 款连续调用会 NODATA，需 2s 间隔+3 次重试。
- 社区域名 `steamcommunity.com` 当前网络不可达（000），但图片 CDN `steamuserimages`/`shared.akamai` 可用；商店 API `store.steampowered.com/api/` 可用。
