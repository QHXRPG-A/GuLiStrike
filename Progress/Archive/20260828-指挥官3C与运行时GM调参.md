## 一、交付结论

本轮把 Commander 原型从“代码常量 + 终点恢复方阵 + 固定朝向小地图”推进为“单兵种表驱动 + 共享目标松散到达 + heading-up 小地图”，并补上当前 World 会话级 `gs.GM.*` 调参系统。

| 交付面 | 最终结果 |
|---|---|
| Soldier 数据 | `DefaultSoldier` 唯一行；移速 3600cm/s、最大生命 100、FourFRobot 静态模型、攻/防/射程 0；每个 World 解析一次 |
| 权威与表现 | 500 个 Soldier 出生时使用同一有效定义；服务端写 Health/Stats/Mass，客户端从同一表取模型；预测默认 900cm |
| 远距点选 | 600000cm Visibility 反投影射线，最多跳过 16 个非 Landscape 阻挡物，只接受 Landscape；LMB/RMB/预览共用入口 |
| 移动目标 | 同批所有 Cohort 使用同一投影目标；途中 1–5 列，近目标后取消槽位；不再验证或恢复终点 5×5 |
| 到达规则 | 按批次初始唯一人数计算松散到达域；完成判定聚合同一 BatchOrderId 的全部 Formation，死亡/改令不阻塞 |
| 小地图 | Panel/UI 固定，地形、坐标轴、兵点和相机框 heading-up 旋转；严格逆点击拒绝战场外空角，地形格严格裁切到 Panel |
| GM 调参 | 7 个白名单 key，严格解析、服务端权限、World 隔离、不落盘；Soldier/Ship 现存和后续实例均可应用 |
| 联网一致性 | Soldier 速度只在 30Hz Mass shared 参数提交成功后发布 GameState；Ship 以单一 RepNotify struct 原子复制 GM 倍率和 revision |

## 二、Soldier 数据链

- 新增 `data/Excel/GuLiStrikeCommander.xlsx / Soldiers`、JSON、manifest 与生成行 `FGuLiStrikeCommanderSoldiersRow`。
- 导出器新增 `softobject → TSoftObjectPtr<UObject>`。
- `UGuLiCommanderDataSettings` 在 `DefaultGame.ini` 指向 `/Game/GuLiStrike/Data/DT_GuLiStrikeCommander_Soldiers` 和 `DefaultSoldier`。
- `UGuLiCommanderDataSubsystem` 只在 Game/PIE World 创建并加载一次。
- `FGuLiCommanderSoldierResolver` 校验数值与模型类型；无效字段回退，不允许最大生命突破现有 `uint8` wire contract。
- DataTable 和 `/Game/Commander/Units` 被列入 AlwaysCook。
- UE 回读结果记录在 `Progress/CommanderSoldierDataValidation.json`：表、行结构、唯一行、六项数值、模型引用及 `UStaticMesh` 类型全部为 `true`。

## 三、移动与 3C 修复

### 3.1 地面解析

`AGuLiCommanderPlayerController::TraceGroundUnderCursor` 统一服务选区预览、LMB 选择和 RMB 移动。单位与脚环 ISM 保持 `NoCollision`，射线不会再被 500 个表现实例挡住。

### 3.2 共享目标与松散到达

- 目标只做一次 CommanderSoldier NavMesh 投影，二维修正上限为 750cm AgentRadius。
- 每个 Formation 仍独立共享一条路径，但同批目标锚点完全相同；无效/Partial Path 返回 `PathFailed`，近距投影失败返回 `InvalidTarget`。
- 两点直线路径不会从起点就错误进入终段：Guide 必须位于最后路径点阶段且进入 `ArrivalRadius + WaypointTolerance`，才取消槽位修正。
- 25/50/100 人到达半径分别为 5000/6500/9500cm。
- 同一 `BatchOrderId` 的 Formation 聚合完成；先到的 Cohort 不会让其余 Cohort 的订单提前结束。

### 3.3 Heading-up 小地图

新增可逆 `FHeadingUpTransform`。世界到屏幕、屏幕到世界、兵点、坐标轴、相机框和地形逆采样使用同一旋转中心与方向。20×20 地形缓存继续复用；最后一个栅格的 `+0.5px` 缝隙覆盖也会裁切到 Panel，不再越界。

## 四、运行时 GM 系统

### 4.1 命令与 key

```text
gs.GM.List [prefix]
gs.GM.Get <key>
gs.GM.Set <key> <value>
gs.GM.Reset <key|all>
```

白名单为：

- `soldier.move_speed_cm_s`
- `soldier.max_health`
- `soldier.attack_power`
- `soldier.defense`
- `soldier.attack_range_cm`
- `ship.max_speed_multiplier`
- `ship.acceleration_multiplier`

命令仅在非 Shipping 构建注册。Registry 拒绝未知 key、错误参数数量、尾随字符、NaN、Inf、非整数生命和越界值，不做静默 Clamp。

### 4.2 Soldier 应用

- 移速写入 pending，在下一次 30Hz Authority Tick 成功迁移 Mass shared movement parameters、活动 MoveTarget 和 Velocity 后，才更新 committed speed、GameState revision 与客户端预测。
- 同帧 `Set 7200 → Reset` 会取消旧 pending，不会在下一 Tick 错误提交 7200。
- 最大生命按比例换算；死亡保持 0。攻击、防御和射程即时写入权威 runtime 与 Mass Stats。

### 4.3 Ship 应用

- `GM.Runtime` 是保留层；普通 `AddStatModifier/RemoveStatModifier` 不能操作该名称，重复保留项会被清理，其他 Gameplay Modifier 保持不变。
- `FGuLiShipGMRuntimeReplicatedState` 以一个 RepNotify 属性同步 active、两项倍率和 revision；客户端不会混读不同 revision 的速度/加速度。
- 服务器更新现存 Ship，后续出生 Ship 在 BeginPlay 继承当前 World Registry；客户端只消费服务器复制状态。

## 六、已知外部问题与后续人工验收

- 既有 `Content/GuLiStrike/Blueprints/BP_GuLiStrikeGameMode.uasset` 的包头无效，AssetRegistry 固定记录 `Invalid value for PACKAGE_FILE_TAG`。因此 Python commandlet 虽明确输出“script executed successfully”并产生全通过 JSON，进程仍返回 1。本轮没有擅自覆盖该既有资产。
- Epic Launcher 发行版不支持 Server target，`GuLiStrikeServer` 构建会直接报告 engine distribution 不支持；正式 Dedicated Server 二进制需在源码版/Server-capable Engine 中验证。
- 尚需有画面的人工 PIE：20,000/80,000/111,392/180,000cm 四档相机高度的中心/边缘/四角点选；25/50/100 人窄口、L 弯、NavMesh 边缘和中途改令；Q/E 连续旋转与小地图连续点击手感。
