# 单位血条仅数值变化时全量显示

玩家提出取消血条重叠计算，只有生命与护盾信息发生变化才显示。本版撤下每屏 36 条、视口间距检查和优先级排序，屏内有效的矩形逐条绘制。3 秒保持与 0.5 秒淡出从最近一次真实变化起算。世界锚点按 30 Hz 采样，镜头每帧重新投影，生命与护盾按 10 Hz 发布。指挥官近景、总览、巡天与游骑兵共用屏幕布局。游骑兵沿用敌方准入，普通视角沿用距离规则。[布局实现](../../Source/GuLiStrike/Commander/UI/GuLiHealthBarLayout.cpp) [上一版屏幕策略](20261125-单位血条逐帧跟随与屏幕密度.md) [30 Hz 采样对照](20261125-单位血条位置改为30Hz采样.md)

Actor 与游骑兵敌方视图比对当前值及上限，指挥官士兵读取名册中的生命和上限变化。首次同步包括残血入场，均建立基准。伤害、治疗、回盾和容量变化触发血条，选中、检视、重复同步、仅播放命中闪光均不会点亮或续期。死亡、失去资格或换代移除旧条。指挥官总览图标保持原有选中和点选入口。[Actor 数值入口](../../Source/GuLiStrike/Gameplay/CombatEffects/GuLiUnitFeedbackComponent.cpp) [士兵名册](../../Source/GuLiStrike/Commander/Network/GuLiSoldierStateReplicator.cpp) [总览入口](../../Source/GuLiStrike/Commander/UI/GuLiCommanderOverviewOverlay.cpp)

## 正式地图验证

在 `/Game/Maps/LVL_CommanderMassPrototype` 以 2034 × 1257 的独立 PIE 视口测试。指挥官总览中临时改变测试世界的士兵生命上限，读回 590 名士兵的新上限。加上同场普通战斗事件，峰值一帧收到 601 条候选，绘出 601 条。对已绘矩形单独统计，发现 4,769 对相交。试玩结束前复位运行时参数。游骑兵用正常攻击输入交战，在 360 帧中有 358 帧显示敌方血条。

巡天综合试玩有 50 架僚机。480 帧内按固定间隔读回生命组件和血条列表，38 架僚机的数值发生过变化，37 架在采样时也出现在候选里，原始飞行镜头中读到 2 架的屏幕血条。一架由 1000 生命降至 990 时进入了候选。

## 性能

指挥官战术视角在相同地图、镜头焦点和分辨率下各采三段 180 帧。单位按正常玩法交战，两版同时受击数随战况变化。表中均为整个采样窗口的逐帧均值。

| 战术镜头 | 旧版 | 本版 |
| --- | ---: | ---: |
| 每帧绘制血条 | 8.50 | 11.01 |
| 每帧矩形间比较次数 | 51.97 | 0 |
| 血条屏幕投影与筛选 CPU | 0.00401 ms | 0.00126 ms |
| 血条信息发布 CPU | 0.00139 ms | 0.00103 ms |
| 整帧均值 | 16.65 ms | 17.15 ms |
| 整帧 P95 | 24.50 ms | 25.07 ms |

另开总览，在同一镜头测一次 120 帧普通交战和两次 120 帧集体上限变化。计时期间逐条矩形导出关闭。两次高密度窗口里共有 221 帧绘制至少 500 条，平均每帧 593 条。该组屏幕投影与裁剪平均 0.0114 ms，P95 为 0.0146 ms，信息发布平均 0.0189 ms。两项都是游戏线程子项。整帧还包含 Slate 绘制与游戏模拟，普通战斗对照没有测出整局帧率提升。

## 构建与回归

`GuLiStrikeEditor Win64 Development` 构建成功，项目和引擎模块 BuildId 一致。8 项原生测试通过，覆盖 96 条完全重合的带盾血条、超出视口、两个本地视口、生命代次、30 Hz 世界锚点、10 Hz 信息、真实生命组件的掉盾与恢复，以及场景 UI 几何。首次连续复测发现清理已失去 World 的反馈组件时会崩溃，已防护该销毁路径并让测试显式销毁临时单位。重开同一地图后原生回归和连续进入、退出试玩均通过。
