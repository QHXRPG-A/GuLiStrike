# 指挥官相机、编队导航与移动射击优化 — 技术方案

- 对应需求：[指挥官相机、编队导航与移动射击优化](../RequirementDocument/20260901-指挥官相机编队导航与移动射击优化.md)

> 后续增量（2026-09-01）：现场出现`Move cohort 11 rejected atomically`后，用户确认终点不再要求固定5×5，并要求cohort内单兵部分接受、协议v6及1px无动画静态绿线。新方案见[移动命令自由扩散与静态寻路线](20260901-移动命令自由扩散与静态寻路线.md)。本文的固定5×5、cohort级原子接受、协议v5和Accepted流水反馈保留为该阶段历史基线，不是新方案的最终规则；新方案仍在实施和验证。

## 技术选型

本期采用“共享长路径 → 每兵路径游标 → 每步NavMesh表面移动 → Mass局部避让 → 固定终点槽 → 限流个人恢复路径”。每25兵继续共享一条长路径，避免为500兵持续计算完整独立路径；每兵保留自己的路径游标和最后合法`FNavLocation`，每个30Hz步骤通过[`FindMoveAlongSurface`](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/NavigationSystem/ANavigationData/FindMoveAlongSurface)推进并更新PolyRef。该API面向导航表面上的连续小步移动，适合替换当前每200ms一次投影、其余步骤无约束积分的做法。

恢复过程借鉴[Detour Path Corridor](https://github.com/recastnavigation/recastnavigation/blob/main/DetourCrowd/Source/DetourPathCorridor.cpp#L1674-L1699)的小步推进与走廊失效重寻思路，但不引入完整DetourCrowd。项目仍以共享长路径承担大尺度导航，只在个体确认卡住后限流计算一次短路径，控制查询尖峰。

终点分配采用固定5×5块与确定性匈牙利匹配，借鉴[Recoil/Beyond All Reason的先生成移动点再匹配单位](https://github.com/beyond-all-reason/RecoilEngine/blob/master/rts/Game/SelectedUnitsAI.cpp#L453-L475)方式。相比所有单位追同一目标或用随人数扩大的宽松到达圈，固定终点能消除末段争抢，死亡留空也不会触发全队重排。

局部避让继续使用UE5.7 Mass Avoidance，不新增ORCA。根据[Mass Avoidance对Moving与Standing的处理](https://dev.epicgames.com/documentation/en-us/unreal-engine/mass-avoidance-overview-in-unreal-engine?application_version=5.7)，已到达、空闲和Blocked成员切换为Stand并只作为障碍，不接受避让或手工分离推力。单纯RVO可能将单位推离NavMesh，且共享目标拥堵需要更高层目标分配；Epic论坛的[相关说明](https://forums.unrealengine.com/t/rvo-avoidance-causing-ai-to-get-stuck-and-pushing-them-out-of-navmeshes-issue/313611)与本项目现场故障一致，因此最终候选位置仍由NavMesh表面移动做硬约束。

相机侧使用共享Landscape查询子系统、真实Landscape边界和显式姿态求解。关闭SpringArm碰撞缩臂与内置Lag，消除建筑/单位Visibility误命中和多套平滑器互相叠加造成的跳变。视锥约束基于实际画幅和FOV，而不是继续在相机、HUD和小地图各自维护`±380000cm`常量。

扫射只删除移动停火门，不改变技能桥接、索敌和伤害管线。权威固定步先提交经过NavMesh约束的位置，再采样攻击，确保射程使用本步最终位置；协议、快照和ACK保持v5。

不采用完整DetourCrowd，因为现有共享路径、Mass实体和网络表现管线已形成稳定边界，整体替换会扩大验证面；不采用ORCA，因为本期的核心故障包含导航表面约束和终点争抢，单换避让算法不能解决；不启用现有流场，因为当前接口尚未达到生产验证条件，且本轮可通过固定槽和受限恢复完成闭环。

## 运行时规则

### 相机求解

- `UGuLiCommanderLandscapeQuerySubsystem`只接受Landscape Proxy，缓存真实XY边界并提供严格高度查询；查询失败不能回退到任意Visibility命中。
- 每帧按最大1/60秒、最多8个子步求解。沿摇臂按不超过10000cm间隔采样，最低净空为枢轴150cm、摇臂200cm、相机500cm。
- 上升/下降分别限速30000/15000cm每秒。候选姿态不安全时对本步平移、旋转或缩放执行8次二分，不通过突然缩短摇臂绕过障碍。
- 用实际宽高比、垂直/水平FOV、俯角和臂长求四角射线的Landscape落点包围范围，保留5000cm边界余量；无法容纳完整视锥时限制实际臂长。
- `JumpToWorldLocation`复用同一求解器并清除速度、Lag和二分残留。边缘滚屏按16个DPI逻辑像素计算SmoothStep，只有视口聚焦且鼠标在视口内才注入移动。

### 出生与固定终点

- Game配置保存红方`(-10000,127500,0)`和蓝方`(110000,37500,0)`，方阵朝敌方出生中心。
- 出生阶段先构建并验证500个`FNavLocation`，再创建任何Mass实体。出生投影专用垂直范围`SpawnProjectionVerticalExtentCentimeters`为50000cm，用于覆盖出生配置Z与地图Nav面的高差；XY修正仍限制为750cm，并继续要求无重复、最小间距1600cm。失败时整批退出并输出可定位的槽与原因。
- `IssueMove`先对cohort和成员按稳定ID排序。移动朝向优先取“选择质心→点击点”，零长度依次退化为平均朝向和世界+X。
- 终点由5×5块组成：槽距1800cm，块中心距9000cm。匈牙利第一层匹配cohort与块，第二层匹配单位与槽；成本与遍历顺序保持确定性。
- 实际使用槽需满足CommanderSoldier NavMesh投影、XY修正不超过750cm、短程可达和同队预约间距至少1600cm。忽略敌军预约；被本次成功替换的旧预约只在提交阶段释放。
- 每个cohort先暂存槽、共享路径和预约。成功后一次提交；失败保持原OrderId、路径和终点不变。多个cohort时可返回`PartiallyAccepted`，但单个cohort不可部分写入。
- 同一OrderId的槽不重排，死亡只留下空位。途中可以收窄列数，终点仍为5列；末段半径为该块最远槽半径加一步距离。

### 逐步移动、到达与恢复

- 每兵保存`LastValidNavLocation`、最终槽、路径游标、状态、进展基线和失败上下文；出生、调试生成、新命令和NavMesh重建负责初始化。
- 普通行进以70%个体Lane Waypoint方向与30%最终槽纠偏混合；Guide按共享路径XYZ插值。收窄立即生效，扩宽需连续15个成功步骤，且0.5秒内最多重新布局一次。
- 每个30Hz步骤将Mass避让和仅限移动重叠单位的手工分离合并为候选速度，再调用`FindMoveAlongSurface(LastValidNavLocation, Candidate)`。只提交成功且单步Z变化不超过250cm的结果；失败时位置退回最后合法Nav点并清零速度。
- 距最终槽不超过`max(100cm, Speed×FixedStep)`时验证最后一段，成功后吸附到槽、速度/力归零、Mass切换Stand并清除该成员`ActiveOrderId`。
- 路径游标推进，或距当前Waypoint比既有最好值改善至少30cm，才重置无进展计时。恢复状态固定为：

  `Normal → CenterlineRecovery → PersonalPathRecovery → Blocked`

- Normal连续2次表面失败或1秒无进展时进入CenterlineRecovery，取消Lane偏移和避让；再1秒无进展或累计6次失败时按SoldierId进入个人路径队列。
- 每个固定步最多处理4个个人短路径查询。个人路径2秒无进展时只重寻一次，再2秒失败后进入Blocked。
- Blocked停在最后合法Nav点、Stand、速度/力归零、`ActiveOrderId=0`并增加`StateRevision`；保留`LastFailedOrderId`、最终槽、原因、次数和时间。它不再接收推力，也不妨碍其他成员完成命令。
- 选择摘要只聚合仍执行成员的非零OrderId。无执行者或发现两个不同非零命令时返回0。
- NavMesh重建只刷新合法终点的Z，按SoldierId依次修复失效槽；不能修复则Blocked。完成成员的零OrderId不会被旧Formation状态重新激活。

### 移动射击与诊断

- `GuLiSoldierCombat`不再因`bHasMoveOrder`产生`Moving`停火。移动状态变化不清目标、不重置或推进额外冷却；其余200ms分批索敌、开火复核、3D射程、每步最多一发、无补射和统一结算规则保持不变。
- 权威顺序固定为移动/到达、攻击采样、伤害结算。`Moving`枚举只为兼容旧诊断保留。
- 只读接口提供`EGuLiSoldierNavigationState`、`FGuLiSoldierNavigationDebug`、`FGuLiNavigationStats`、`TryGetSoldierNavigationDebug`和聚合统计查询。统计活动、到达、两级恢复、Blocked、Surface调用/失败、路径查询、终点规划耗时和最慢单位。
- 非Shipping GM命令为`gs.GM.Commander.Nav.Soldier <SoldierId>`、`gs.GM.Commander.Nav.Stats`、`gs.GM.Commander.Camera.Debug <0|1>`。导航状态与真正停火原因分栏输出。
