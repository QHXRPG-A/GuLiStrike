## 技术路线与接入边界

采用**专用 Niagara Data Channel + 每World共享消费系统 + C++命中状态槽位**。项目现有枪火已经使用Data Channel，无需新增引擎插件、修改引擎或拆分运行模块。Epic也将大量命中共享模拟列为该功能的典型用途。[UE5.7官方说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/niagara-data-channels-overview?application_version=5.7)

新增模块内部对象 `UGuLiImpactBatchPresentation`，由现有 `UGuLiCombatEffectPresentationSubsystem` 持有；负责队列、槽位、共享组件、资源缓存及诊断。

接入现有 `PlayMachineGunImpact` 路径，覆盖普通Linear终止及逻辑Projectile转换后的目录命中。其他自定义 `ImpactVfxId`、爆炸和枪口路径保持原职责，不顺带迁移。

现有证据不支持命中入口必然重复播放；新增去重用于防止批量消费引入重复，不将其描述为已确认旧缺陷。

## 数据流与接口合同

数据流固定为：

**终止事件验证 → 命中记录接纳 → 独立槽位分配 → 帧F批量发布 → F+1读取上一帧数据 → 粒子出生并复制参数 → 独立生命周期清理。**

模块内部接口提供：

```cpp
void Enqueue(const FGuLiImpactEvent& Event);
void BeginFrame(uint64 FrameNumber, double LocalWorldSeconds);
void PublishFrame(uint64 FrameNumber);
void Reset(uint32 MatchEpoch);
```

`FGuLiImpactEvent` 保存现有终止身份与呈现参数。去重键包含 `Epoch、EffectId、终止Sequence、表现用途`，不按位置去重，不依赖终止记录可能已经缺失的来源Actor。

新鲜度沿用现有0.5秒条件，在接纳时判断；已接纳事件不因明确的一帧缓冲而再次按网络年龄淘汰。Epoch切换及关闭表现仍清空待消费输入。

### Data Channel v1

使用专用Global Channel，与现有Gunfire Channel分开。数据存储由客户端World隔离，同World的多个LocalPlayer不重复发布命中。

| 字段 | 类型及用途 |
|---|---|
| Slot、Generation、Epoch | Int，关联独立命中状态，防止旧粒子绑定复用槽位 |
| PublishFrame、LOD | Int，限定消费帧及对应档位 |
| RandomSeed | Int，传递现有视觉随机输入；不修改玩法随机 |
| Position | Niagara Position，支持世界坐标 |
| Rotation | Quaternion，保留当前调用的旋转 |
| Scale | Vector3，传递已解析基础缩放，避免组件与粒子重复缩放 |
| Tint | Color，每命中独立颜色 |
| Radius、LifetimeCap | Float，保留现有参数及释放上限 |

资源在粒子出生时复制该行参数；后续更新使用粒子自身属性及槽位控制数据，不能继续读取已经过期的事件行。

读取器必须嵌入Niagara图并保留编译期访问信息；不能仅在运行时设置一个User Data Interface。该约束已由项目现有作者工具源码核实。

所有消费副本启用上一帧读取；每个发射器每帧只消费一次符合自身档位的记录。拖尾关联键包含槽位及代次，不能将不同命中的点连成一条Ribbon。

## 共享系统、槽位与生命周期

- 每客户端World按实际解析后的档位资源建立消费组；正常配置最多三个批量组件。多个档位回退到同一资源时合并消费组。
- 组件使用单位变换；事件位置、旋转和缩放由粒子参数承担。目录命中原来的零旋转继续保留，不擅自改成命中法线方向。
- C++状态池初始512槽、每次增长256槽；这是容量策略，不是命中数量上限。工作数组保留容量，不每帧重建。
- 槽位保留完整包络、开始时间、期限、首次离屏时间及身份。资源提供认证寿命包络，生命周期取其与原释放上限的较小值。
- 通过整数数组 `ActiveGenerations` 控制粒子有效性：槽位值必须与粒子保存的Generation一致；退出置零，复用改变代次。数组只在修订变化时提交。
- 活跃槽位使用紧凑索引管理；不扫描整个World寻找命中组件。
- 完成、期限及离屏处理只失效对应槽位。批次范围是未结束命中完整包络的并集，保留仍可见的尾迹。
- 没有待消费及存活命中后停止共享模拟，组件留作World内复用；再次唤醒不得消费旧数据。World结束时注销并释放引用。

Epoch切换清理本对象的队列、状态及共享模拟，并更新消费Epoch；不得修改网络Epoch产生方式或将本地槽位作为网络身份。

## 对照开关与诊断

规划 `gs.Impacts.BatchMode` 三种模式：

| 模式 | 行为 |
|---|---|
| 0 | 当前即时单次播放，用于原行为回退 |
| 1 | 延后一帧，仍逐次播放，用于隔离缓冲影响 |
| 2 | 延后一帧，由Data Channel共享承载 |

纯批量收益以**模式1对模式2**比较，避免把延迟变化当作批量收益。模式0对模式2另作最终行为对照。开关在World初始化或新采样前设置，不在有效采样中混用路径。

按World记录接收、接纳、重复、过期、裁剪、提交、回退、活跃槽位、组件激活／复用、发布批次、控制数组提交和消费延迟。

CPU计量覆盖收集、解析、发布、生命周期、Niagara模拟及渲染数据提交。旧单次资源与新批量资源的计时统一归类；整进程GT不重复累加嵌套Scope或工作线程时间。额外日志默认关闭。
