# CS-P2P实现与本地PIE交付

## 直接使用

1. 使用源码版UE5.7打开项目，进入 `/Game/Maps/LVL_CommanderMassPrototype`。
2. 项目设置 → GuLiStrike → GuLi Local PIE，Main Role默认Commander，可在开局前改为Ground或Air；Coordinator Port默认18787（本机8787已被其他进程占用）。
3. 点击普通PIE。编辑器内为红方渲染客户端，蓝方Commander逻辑端和Coordinator自动以独立进程启动；其他职责空席，不另起客户端。
4. 正常试玩保留600单位，资源和血量使用正式清单，额外飞行物只由真实玩法生成。停止PIE后两个子进程退出，再次点击会创建新房间。

Coordinator可执行文件保留在项目Tools/GuLiCoordinator的Release构建目录。端口占用会明确报错，关闭占用者或在设置中换端口即可；不会自动停止不属于本次会话的进程。

## 实现边界

编辑器模块的GuLiLocalPIESubsystem管理播放设置、预检、房间身份、两个子进程及Windows作业对象。初始化时安全查询已存在的编辑器世界，地图打开后配置一个Standalone PIE世界，并校正当次复制的播放设置。

运行时配置解析支持Resolve(World)，未注册覆盖时保持原命令行行为；编辑器提供的覆盖只匹配本次目标PIE世界。Actor、飞行物和场效果读取同一世界配置，运行时模块不依赖编辑器模块。默认服务预期红蓝各1人，逻辑端使用NullRHI；不传入GuLiAcceptanceRun等验收参数。

原Hybrid客户端模拟、资源组、能力与工作交接、数值和回执逻辑保留。先前已应用的离席接收端准入、有效矿位准备读回及原生自动交付识别等修复已纳入Git快照。协议31、清单24、交接2和原5/15秒期限保持。
