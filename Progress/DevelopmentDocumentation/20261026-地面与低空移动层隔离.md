# 地面与低空移动层隔离 — 实施与交付

## 实现与范围

新增 `EGuLiUnitMovementLayer`，只含Ground与LowAir。低空使用原地面NavMesh与地形约束，导航点为实际根位置减去配置高度；提交实际位置时只加一次高度。渲染、命中及同步继续接收真实世界位置。悬浮盘的局部姿态和模型缩放保持。

| 变更点 | 实施 |
|---|---|
| 配表 | `data/Excel/GuLiStrikeCommander.xlsx` 的Soldiers表新增MovementLayer、AltitudeMeters；WM01=1、30，其余五行=0、0。单位为米，运行时转换为厘米。 |
| 数据检查 | Excel导出器及原生Resolver拒绝非法层级、高度越界与非有限值；生成的Row和Definition携带分层、高度。 |
| 导航与移动 | `GuLiBattleAuthoritySubsystem` 保持地面路线、脚下投影、坡地约束和导航恢复；实际提交、召唤、外部位移恢复按高度还原。 |
| 避障与碰撞 | 手动碰撞、预测避障、环境候选与游骑兵接触按层过滤；同层低空按2D处理，工程车同类互通例外保持。共享几何缓存同时比较层级及绑定状态。 |
| 站位与占地 | 方格站位按尺寸及层级分桶；旧环形站位按层保存进度。网格实际占用、落点预占和许可携带MovementLayer。 |
| 出生与传送 | 兵种出生、生产、召唤、强制落点使用目标层；只忽略已明确绑定到另一地面/低空层的单位，真实环境和未绑定飞行体保留原响应。 |
| 网络与恢复 | Mass对象/系统状态版本5，GroundGridTraffic状态与数据包版本3；保存分层、高度和站位分层进度，恢复检查目录定义一致性。 |
| 初始军阵 | 保留既有军阵XY布置，只按兵种高度抬升实际出生位置。初始军阵中心被玩家出生点复用，因此不能顺带重排军阵。 |

飞船和僚机没有接入本枚举；共享传送入口只对明确绑定到Ground/LowAir的对象启用分层分支。没有修改Ship/Wingman移动源文件或飞行表。战斗目标类别、飞船最低高度及高空侵入低空的现有能力不在本轮改动范围。

## PIE启动拦截修复（2026-10-26）

玩家报告无法启动PIE。首个失败阶段发生在复制PIE世界之前：日志两次记录 `Play-In-Editor canceled by plugin`，原因是 `GuLiMapAuthoring source changed after the last resource bake; rebake before PIE.`，尚未进入游戏运行阶段。

新增的初始军阵预览字段 `movement_layer`、`altitude_cm` 被整段JSON带入矿区烘焙源哈希，虽然地面占地、初始XY和资源排除范围未变，也会令原烘焙被判定过期。`FGuLiInitialArmyAuthoring::ToJson`增加默认开启的移动元数据选项，资源哈希调用显式关闭这两个字段；普通预览继续输出层级和高度，地图、地形、地面军阵及占地仍参与原哈希检查，未跳过资源校验或重生成矿区。

修复编译并重启空闲编辑器后，资源检查恢复通过。随后只读导航检查暴露第二个问题：新建的五个核验圆环在地图重载后从临时NoCollision恢复为Custom/QueryAndPhysics，导致飞行导航静态几何指纹过期。交付脚本改用完整的 `NoCollision` 碰撞配置并标记组件修改，仍关闭导航影响与重叠事件。仅修复这五个圆环并保存，实际卸载、重载原地图后再次读取确认配置持久化；未重烘焙飞行导航。

本次验证：

- 同一授权下完成 `GuLiStrikeEditor Win64 Development` 编译，退出码0，重启前确认无PIE及未保存内容。
- `ValidateCurrentBake`通过；source/layout哈希与原烘焙相同，已验证11个地图作者配置的初始样本位置。该11个样本不是正常600兵运行清单的兵数。
- `ValidateWorldNavigation`通过：两组Ground与一组Flight均为Hit，地面/飞行重建次数均为0。
- 重载后14个核验实体仍在，五个圆环均为NoCollision且不参与导航；地图和内容无未保存修改。
- 200/600兵清单SHA-256与本轮原交付一致；飞船、僚机行为和飞行数据未修改。部署脚本补充资源及导航烘焙检查，后续失败会明确停止交付成功标记。
- 修复验证仅使用编译、日志和编辑器结构化检查，未启动PIE/Standalone、未读图。玩家可重新点击原图播放，实际进入对局及运动效果仍待确认。
