# 次级单位武器独立Excel维护 — 技术方案

## 技术选型与边界

依赖方向：Excel → 既有 DataPipeline → 稳定 DataTable/USTRUCT → 运行时解析 → 服务器伤害及复制表现。全部位于现有 GuLiStrike 模块，无新增模块、插件或循环依赖。

| 层 | 责任 | API/生命周期 |
|---|---|---|
| Excel/DataPipeline | 武器与全局法术场分别维护；数字ID引用解析为稳定UE行名 | 导出先全量校验，再写JSON、头文件和manifest |
| Commander/Ship数据适配 | 保留现有技能槽、授权、DataTableRowHandle和原生结构身份 | 世界初始化/技能快照时读取；服务器权威 |
| CombatEffects | WM01导弹在发射时解析并冻结表中Motion | ResolveMotionSettings；既有复制状态携带完整Motion |
| Wingman武器定义 | 所有四个武器从表格构建RuntimeConfig；资源也按表解析 | GetResolvedWeaponConfig、ResolveAttackProjectile |
| 导入脚本 | 先导入全局Fields，再按manifest导入武器表；绑定资产并原生回读 | 停止PIE后执行，只保存明确目标资产 |

## 工作表

`Skills`、`UnitSkills`、`WeaponMounts`、`WingmanWeapons`、`WingmanTargeting`、`Projectiles`，附 `_Guide` 使用说明。所有Combat与Teleport行统一维护在 `GuLiStrikeSpellFields.xlsx / Fields`，次级武器表不再保留WeaponFields。

Skills/H与WingmanWeapons/Z的“产生的法术场”列是可空整数，引用Fields.id。导出器在全量读取后解析为该行name，继续生成既有FString EffectConfigId属性，无新增公开API、反射布局或复制协议。WM01与僚机对地分别引用1和2；已有法术场ID、行名和数值均保持。

运行时ResolveFieldConfig优先读取武器上下文EffectConfigId，特效资产只为没有武器引用的直接调用提供默认配置；点目标导弹核对权威上下文与冻结法术场的一致性。服务器权限、来源租约、伤害修饰和已发射效果的冻结生命周期沿用现有实现。导入仍校验弹体有表现资产，但不要求表现资产的默认ConfigId覆盖武器所选配置。

已有DataTable及UScriptStruct身份由导出器显式迁移映射保留，避免破坏蓝图及历史资源；manifest的`sources`记录所有真实来源。新Projectiles使用中立名称。每个配置行只能有一个源。
