# 编辑器窗口开销与交火基准

承接[根开发记录](20261020-Hybrid交火CPU与追帧优化.md)。用户指出此前已报约17ms，随后又报24.26降至22.32ms。本次核对历史数据并控制窗口条件，避免把不同环境的整帧值直接归因于代码。

## 历史口径

`diag-16-layout/r1-candidate`的17.679ms确实是整帧均值，P95为29.332ms；与单例模型提交17.971ms是不同证据。该历史采集只检查进程前台，没有当前游戏预览的原生逐帧前台记录，也未记录编辑器主窗口最小化状态。它与build-27的模块版本、移动推进策略均有变化，不能直接将17.679至22.323的4.644ms全归因于代码退化。

重新按相同分析范围计算，全进程Slate布局/绘制联合范围从历史0.875ms变为build-27的4.630ms，差3.755ms。这解释了差额的主要组成，但单凭历史记录不能证明当时具体窗口状态。证据：`window-state-28/historical-17ms-comparison.json`。

build-27同构建完整避让/活动端点查询24.258至22.323ms仍保留为该组单轮事实；其约1.935ms改善不能拿来说明与更早17ms的相对表现。后续由统一窗口条件的新配对判断优化收益。

## 本次实现

`Source/GuLiStrike/Gameplay/Performance/GuLiPerformanceSubsystem.cpp`在显式采样期间直接取得编辑器主窗口原生状态，记录`Capture.EditorRootUnavailableFrames`、`VisibleFrames`、`MinimizedFrames`、`HiddenFrames`。查询已知根窗口，不新增对象或窗口遍历；继续独立记录实际游戏预览的逐帧前台状态。

采集JSON提供`editor_window_state`及`editor_window_basis=native_editor_root_window_v1`。`Scripts/Performance/capture_hybrid_cpu.py`在准备结束及计时前检查要求状态，计时后要求全窗口帧计数一致。默认`--editor-window-state minimized`；显式`visible`可做独立受控对照。`any`仅生成诊断证据，标为`uncontrolled_window_diagnostic`，不具备验收资格。脚本不擅自操作窗口，切换在计时外完成。

## 同构建窗口对照

证据根目录：`D:/UE5.7/PerformanceCaptures/GuLiStrike/hybrid-cpu-20261020`。

- 可见组：`env-33-editor-visible/r1-candidate`。
- 最小化组：`env-34-editor-minimized/r1-candidate`。
- 配对核对：`window-state-28/environment-comparison.json`，明确`purpose=environment_comparison`、`code_optimization_gain=false`。

两组均build-28，同模块、地图元数据、全部开关、冻结交火输入和前后相机；2359×1748、133.4m、600初始单位，预热至少10秒后记录30秒。游戏预览分别1301/1737帧前台，后台均0；编辑器状态分别所有1301帧可见、所有1737帧最小化。各48项移动记录完整。逻辑分别推进1801/1800步，末端一步差来自实际30秒结束时刻。两轮原生采样期间没有截图、读图、对象枚举或离线分析。

| 指标，ms | 编辑器可见 | 编辑器最小化 |
|---|---:|---:|
| 整帧平均 | 23.071 | 17.277 |
| 整帧P95 | 39.910 | 30.089 |
| GT平均 | 23.070 | 17.276 |
| 全进程Slate布局/绘制联合范围 | 4.631 | 1.218 |
| 游戏UI绘制子项 | 0.808 | 0.810 |
| GPU Graphics队列Frame平均 / P95 | 17.413 / 24.547 | 15.245 / 21.215 |
| GPU Compute队列Frame平均 / P95 | 18.623 / 33.732 | 14.667 / 22.542 |

仅改变窗口状态，整帧相差5.794ms；全进程Slate相差3.413ms，而游戏UI绘制子项近似不变。这次已复现编辑器窗口带来的额外负担，并在当前程序重新得到约17ms。该差值是环境影响，不能登记为新代码优化收益，也不能反推出历史17.679ms时的确切窗口状态。

GPU Frame包含队列等待和空隙，Graphics/Compute会重叠，不能相加，也不等于着色器纯忙时。Graphics的SceneRender包含范围两组约12.124/12.084ms，不能仅从队列Frame降低推断绘制工作减少了同等时间。CPU固定频率逻辑在不同数量的引擎帧中分摊，每帧均值变化也不全部代表删除了工作；全进程Slate每墙钟秒约200.741至70.526ms更能说明该部分实际工作减少。

最小化组GT独占分组为模拟4.707、其他Hybrid2.074、主线程应用1.460、表现1.368、Slate1.304、引擎及其他6.150ms/帧，另有少量HUD和等待。布局/绘制联合范围已包含在这些分组中，不重复相加。完整游戏窗口Slate归因仍未覆盖，0.810ms只用于同子项对照，不代表完整游戏UI成本。

最小化组两条最终回执29.787/44.540ms，48项保留2cm观察35.505至84.056ms；该观察包含权威写入后的探针调度，不能当作OS点击到屏幕或1cm首次模型提交。完整20ms响应目标仍未通过。

## 构建与交付

沿用已授权源码`D:/UnrealEngine-5.7`、`GuLiStrikeEditor Win64 Development`。build-28首编因Viewport指针误加const失败（退出6）；改为非const指针后`build-28-retry1.log`成功（退出0、6.39秒）。失败后误启动的旧模块编辑器未采样，已退出；两组有效窗口都来自成功重编后的PID36032。引擎、项目、GuLiFrameProfiler的BuildId均`dd3ee083-a0fd-45c8-814e-67fe5ef95e31`。最终编译源码清单为`build-28-source-manifest.json`，采样所用脚本另留`window-state-28/capture_hybrid_cpu.sampled.py`。

Python语法、改动差异与模块身份核对；采集结束后所属PIE和逻辑/协调子进程正常退出，开关恢复，编辑器主窗口恢复。没有改动玩法、质量、资源或表现。

`/Game/Maps/LVL_CommanderMassPrototype`的默认停用入口`PerfHybridCPU_Entry`补充窗口条件、最新数据及独立配对说明，由`Scripts/Performance/author_hybrid_cpu_review_entry.py`保存并通过`review-entry-28.json`回读；仍为`PersistentLevel.Note_72`、EditorOnly，位置cm `(10139.4321,-55434.2764,1101.7791)`。玩家可按入口固定窗口条件后执行三轮脚本，并自行检查移动、绿线及特效；助手不做读图测试。

当前17.277ms是单轮受控结果，尚高于15ms，P95与完整指令响应也需按目标继续验收。三轮最终验收和用户视觉核验均保持未完成。
