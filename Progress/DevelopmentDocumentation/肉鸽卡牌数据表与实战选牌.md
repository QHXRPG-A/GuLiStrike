# 肉鸽卡牌数据表与实战选牌 — 技术方案

## 实现边界

代码位于 `Source/GuLiStrike/Gameplay/Cards`；复用当前模块、Commander NetSync、ArmySkill 与现有卡牌蓝图。新增 DeveloperSettings 模块依赖，用项目设置维护表/材质/候选/模糊参数。客户端界面不写战斗属性。

| 层 | 实现 |
|---|---|
| 数据 | Excelize 创建源表，导出器支持 str[]、字符串 ID 和跨表引用校验；通过原导入器生成 DataTable |
| 文本 | 公共 GameTexts 源表导出 StringTable，保留稳定 namespace/key；原有文本表用户不改 |
| 效果 | GuLiRogueCardEffect 基类与 FireRate / MoveSpeed / MissileDamage 三个原生实现 |
| 会话 | GuLiRogueCardSubsystem 按世界保存候选和阵营取得记录，服务器核对拥有者、阵营、战局和候选 |
| 固定步 | BeginFixedStep→效果提交→ArmySkill CommitCombatProfiles→EndFixedStep 成功回执 |
| 移动 | 阵营+兵种来源账本，预检所有目标 Archetype 后迁移，更新速度/加速度/DesiredSpeed；后续生成读取相同倍率 |
| 展示 | Commander F4 Enhanced Input→本地组件→UMG BackgroundBlur＋透明 SceneCapture；只捕获卡牌组件 |
| 蓝图兼容 | 新增 ExternalConfirmation / AwaitingConfirmation / OnConfirmationRequested / CompleteConfirmation，默认仍为评审自动确认 |
| 清理 | Esc、成功退场、身份/阵营/战局变化和 EndPlay 清理；UIOnly 屏蔽战场输入，关闭恢复当前角色 |

攻速与导弹均复用独立 GUID 的 ArmySkill AddPercent 来源，服务器已有解析器负责限值校验。导弹沿用 `Weapon->Damage` 发射快照与 FrozenField，不改法术场源表。移动倍率账本不依附 PlayerState，角色换任不清除；战局 epoch 改变清除。

## 表格填写与后续扩展

一行数据定义一张卡；一个效果类可以被多张卡复用。例如新增 `01.02 / WM01_FireRate_Lv2`，仍引用 `GuLiRogueCardFireRateEffect`，仅改变 BonusPercent、文本键或材质。不同等级并不要求新增 C++ 类，新的行为逻辑才需要新的实现类。

`id` 保持文本格式；`BonusPercent=0.2` 显示为 20%，不用另写一份说明数值。`TextIds` 固定为标题、说明两项，分别写入现有 UMG 的 `CardTitle`、`CardDescription`。修改公共文本源表中的稳定键可继续接入 UE 本地化；当前仅有中文源文案。

填写后执行 Excel 导出，再在编辑器中导入两表并重建 StringTable。实战固定候选可在项目设置 `Rogue Cards` 的 Candidates 调整，首版要求恰好三项。当前仅启用类型 1 的部队效果，其他类型保留数据和目录约定。
