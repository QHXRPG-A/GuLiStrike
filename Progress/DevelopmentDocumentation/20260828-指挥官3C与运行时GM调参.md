# 指挥官 3C、Soldier 数据化与运行时 GM 调参 — 开发文档

- 对应需求：[指挥官 3C、Soldier 数据化与运行时 GM 调参](../RequirementDocument/20260828-指挥官3C与运行时GM调参.md)

## 1. 实现总览

本轮在现有 Commander Mass 架构上增加三条边界清晰的链路：静态兵种数据由 `UGuLiCommanderDataSubsystem` 在 World 初始化时解析并缓存；会话调参由 `UGuLiRuntimeTuningSubsystem` 持有显式白名单和 Override；服务端 Authority、客户端 Presentation、GameState 与 Ship 只消费已经验证的有效值。

```text
Excel Soldiers
  -> JSON / generated row / UE DataTable
  -> CommanderDataSubsystem (per World, load once)
  -> RuntimeTuningSubsystem (fallback < DataTable < GM Override)
     -> BattleAuthority / Mass shared params / Soldier Stats
     -> CommanderGameState replicated speed + revision
     -> Ship GM.Runtime modifier layer
```

## 2. 数据管线与兵种解析

- `data/Excel/GuLiStrikeCommander.xlsx` 新增 `Soldiers` sheet；导出结果为 `data/Json/DT_GuLiStrikeCommander_Soldiers.json`。
- `Tools/DataPipeline/export_data_from_excel.py` 支持元数据类型 `softobject`，生成 `TSoftObjectPtr<UObject>`。
- 生成头：`Source/GuLiStrike/Gameplay/Data/Generated/GuLiStrikeCommanderTableRows.h`。
- `UGuLiCommanderDataSettings` 通过 `DefaultGame.ini` 指向 Soldier DataTable 和 `DefaultSoldier`。
- `FGuLiCommanderSoldierResolver` 校验 `uint8` 生命边界、有限数值、移动速度的 Mass int16 表示范围以及 `UStaticMesh` 模型类型；失败逐字段回退并去重 Warning。
- `UGuLiCommanderDataSubsystem` 只在 Game/PIE World 创建，初始化时同步加载一次表与模型。
- Packaging Settings 将 Commander DataTable 和模型目录列入 AlwaysCook。

## 3. Authority、表现与复制

- `FGuLiMassSoldierStatsFragment` 承载最大生命、攻击力、防御力和攻击范围。
- Authority 出生时把有效定义写入 Soldier runtime、Health fragment 和 Stats fragment。
- 客户端 Presentation 在 BeginPlay 从同一 DataSubsystem 取得模型；非法模型保留现有 FourFRobot 静态代理。
- 预测距离调用 `CalculatePredictionDistance(effective speed, 0.25s, fallback)`；默认 `3600 × 0.25 = 900cm`。
- `AGuLiCommanderGameState` 新增一份复制的有效 Soldier 移速和 tuning revision；没有新增逐兵字段。

## 4. 移动与到达

- `ResolveSharedMoveTarget` 对整批命令只解析一次目标，限定二维修正不超过 `AgentRadius`。
- 每个已接受 Cohort 仍建立自己的共享路径，但目标锚点完全相同；无效/Partial 路径拒绝。
- 途中保留 1–5 列槽位；进入最后接近阶段后改为每兵沿共享路径跟随，不再追求终点方阵。
- 到达域半径由批次初始唯一成员数计算并缓存；25/50/100 人分别为 5000/6500/9500cm（当前 AgentRadius 750cm）。
- 完成判定按同一 `BatchOrderId` 聚合所有 Formation：引导点、末弯和仍有效成员必须共同满足；死亡和已改令成员会被过滤。

## 5. 远距射线与小地图

- `AGuLiCommanderPlayerController::TraceGroundUnderCursor` 成为选择、移动和预览的唯一落点入口。
- 显式 Deproject + 600000cm `ECC_Visibility` 射线，最多跳过 16 个非 Landscape blocking hit，只返回 Landscape。
- 小地图的 `FHeadingUpTransform` 统一负责世界 ↔ 屏幕、旋转、裁切和点击逆变换。
- 固定 UI 与旋转内容分层绘制；地形对 20×20 高度缓存做逆采样，兵点/坐标轴/相机框使用同一 heading-up 变换。

## 6. GM Runtime Tuning

- `FGuLiRuntimeTuningRegistry`：显式注册 7 个 key，负责排序、严格数字语法、范围与整数规则，并返回结构化结果。
- `UGuLiRuntimeTuningSubsystem`：每个 Game World 一份 registry；加载 DataTable baseline、执行 Authority/Ship 批量应用并发布 GameState revision。
- `GuLiRuntimeTuningCommands.cpp`：四个命令全部位于 `#if !UE_BUILD_SHIPPING`。
- Soldier speed 先进入 pending，在 `TickAuthority` 的下一次固定步切换 Mass shared fragment archetype，并同步活动 MoveTarget 与 Velocity。
- 最大生命按比例换算，死亡保持 0；战斗属性立即写入 Authority 与 Mass Stats。
- Ship 的 `GM.Runtime` 使用独立命名 modifier，设置或清除后只调用一次 `RecomputeStats()`；服务器 BeginPlay 会应用当前 World 值。
- Ship 的 active、两项倍率和 revision 使用单一 `FGuLiShipGMRuntimeReplicatedState` RepNotify 属性原子复制，客户端只消费服务器状态；通用 modifier API 拒绝保留名并清理重复项。
- GameState 不提前发布 Registry 中尚未提交的 Soldier speed；Authority 完成下一次 30Hz Mass archetype/shared-params 迁移后回调 TuningSubsystem，再推进 revision 与复制值。同帧 Set→Reset 会取消旧 pending。

## 9. 已知外部问题与验证边界

- 项目已有的 `Content/GuLiStrike/Blueprints/BP_GuLiStrikeGameMode.uasset` 包头无效。资产注册器会记录 `Invalid value for PACKAGE_FILE_TAG`；Python commandlet 因此返回 1，但本轮数据脚本自身成功、独立 JSON 校验全项通过。该资产不属于本需求，未擅自覆盖。
- Epic Launcher 发行版不支持构建 `GuLiStrikeServer` target；`GuLiStrikeEditor` 与非编辑器 `GuLiStrike` Development 均通过。正式 Dedicated Server 二进制需要源码版/Server-capable Engine 环境。
- 小地图地形来自 20×20 缓存，旋转边缘仍存在栅格级锯齿；点击逻辑按严格战场边界拒绝，不影响命令安全。
