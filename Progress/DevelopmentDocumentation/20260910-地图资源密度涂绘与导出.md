# 地图资源密度涂绘与导出 — 技术方案与实施记录

## 技术选型与边界

密度业务数据留在 `GuLiMapAuthoringCore`：世界 XY 用 `floor(WorldXY / CellSizeCm)` 映射为有符号格坐标，每层存稳定 GUID、ASCII `LayerKey` 和稀疏 `32×32` uint8 瓦片。Core 负责笔刷纯函数、验证、Territory 点归属、汇总和 JSON/CSV；不依赖 Slate、Landscape 或玩法模块。

`GuLiMapAuthoringEditor` 增加地图内单例 `AGuLiMapDensityMap`、代码 SceneProxy、Legacy EdMode 和 Slate 资源涂绘页。Actor 固定在 PersistentLevel、Identity Transform、非空间加载、无 Data Layer/碰撞/导航/Tick，并拒绝在非空数据上直接改 CellSize。SceneProxy 在游戏线程查询 Landscape 高度并缓存格角，失败时回退 Visibility/工作平面，渲染线程只读值副本。

没有修改 `Source/GuLiStrike`。以后运行时矿藏系统只消费导出合同，不能引用 Editor Actor 或插件 Editor 模块。

## 数据与行为决策

- `FGuLiMapSnapshot::DensityMap` 是可选值副本。Actor 不存在时 Core 不生成密度文件，旧地图和旧六文件合同保持不变。
- `BlueOre`、`RedOre` 只是预设；存储和序列化不以枚举写死图层。补齐预设不会覆盖现有层数据或元数据。
- 修改格值会即时回收零瓦片。修改分辨率只允许空图；面板提供带确认的“清空全部并应用”，不做隐式重采样。
- 每次拖拽保存完整前值，候选记录从前值重算整条路径。固定世界间距补点并取每格最大覆盖，使结果不随帧率或鼠标事件频率累加。
- Territory 只匹配密度 Actor 保存的 `TypeId=Outpost`、`RegionKey=Territory`。有效对象必须启用、为水平 `PolygonPrism`；倾斜/错误形状是 Error。
- 格中心严格落入多个 Territory 才是 overlap；只命中共享边界时，预排序的 MarkerKey/RegionId 决定唯一归属。未归属和重叠是 Warning，允许导出并输出异常格。
- 整个批次仍先内存生成，再 staging 写入并目录级替换；密度文件与原六文件一起成功或一起失败。

## 公开 API

```text
EnsureDensityMap(CellSizeCm=2500)
GetDensitySnapshot()
UpdateDensityCells(PatchJson)
```

`UpdateDensityCells` v1 只允许 `schema_version/layer_key/cells`；每格只允许 `cell_x/cell_y/density_u8`。所有坐标必须是 int32 整数、密度为 `0..255` 整数，同一补丁不得重复格。完整解析与候选整图验证成功后才以一次事务写回。

## 导出合同

密度 Actor 存在时总计九文件。新增文件：

- `density_layers.json`：独立 schema v1、格尺寸、图层元数据、排序非零格、Territory 汇总及 anomaly 明细。
- `density_cells.csv`：图层、格坐标、世界格中心、u8 和 0..1 权重。
- `density_territories.csv`：每图层的 territory/unassigned/overlap 行、格数、权重和加权面积。

`layout.json` 不嵌入密度字段，继续保持 schema v1。JSON canonical 化、CSV 转义、LF、UTF-8 无 BOM、double 往返精度和固定排序均沿用原合同。
