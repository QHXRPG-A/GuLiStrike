# 玩家地面机甲与Mass单位立体碰撞 — 技术方案与实施记录

## 技术选型与边界

每个Mass士兵保持数据实体。`UGuLiGroundMassContactSubsystem`以0.1秒周期从权威状态或客户端姿态流生成`FGuLiGroundMassBody`，再按1000cm网格索引。机甲每次扫掠只查询移动包围盒附近的桶，并把快照姿态最多外推0.1秒；查询、碰撞和平台支撑不写Mass位置。

机甲移动组件继承`UGuLiExternalCharacterMovementComponent`，保留原CharacterMovement预测、服务端校正和外部位移Revision。侧面求解使用机甲与单位的相对位移计算连续圆碰撞，最多三次接触并投影剩余位移实现滑动；初始重叠沿最短方向退嵌且单次调用最多50cm。顶部支撑使用专用Custom Movement Mode，支持玩家水平移动并排除当前支撑体的侧面碰撞。

友军退让位于服务器10Hz权威循环。普通地面行走机甲以稳定句柄更新带类型和阵营的动态障碍；飞行、下落或站在Mass顶部时注销。移动单位继续走现有避障，只有同阵营闲置/已到达单位进入局部退让，敌军位置不会被玩家碰撞直接修改。

## 实施结果

- [x] `FGuLiGroundMassBody`包含稳定ID、阵营、类型、位置、速度、半径与`BottomZ/TopZ`。模型边界无效时使用位置Z到`Max(200cm, 2×Radius)`。
- [x] 服务端调用`BuildGroundCollisionSnapshot`；客户端直接订阅NetSync解码姿态事件，结合士兵列表与定义构建快照，不读取Presentation姿态或消费其队列，不扩展网络DTO。
- [x] 世界索引10Hz重建；首次角色查询会惰性建表，避免Actor Tick早于子系统首Tick时出现空快照窗口。
- [x] 实现垂直分离、相对速度连续侧扫、滑动、有限退嵌、高速下落顶面检测和确定性支撑选择。
- [x] 实现`CMOVE_MassSupport`、平台平移/高度继承、水平移动、离开/失效/传送/飞行清理及owner-only支撑ID复制。
- [x] 实现机甲动态障碍稳定更新与友军16人上限、25%速度、1250cm锚点、0.5秒返回；新命令立即结束退让。
- [x] 友军候选选择先构建局部网格，并以固定16人有序缓冲保留最近单位；退让步进另构建一次当前位置网格，落点校验只访问可能相交的邻近桶，不执行机甲×全军或退让单位×全军扫描。
- [x] 非Shipping记录快照耗时、查询候选、侧面命中、支撑次数和退让数量。
- [x] 保持开火组件、动画、弹池、伤害账本、战斗网络类型、特效和数据表不变。

## 风险与备忘

- 客户端碰撞依据解码原始姿态，服务端依据权威姿态，二者使用服务器模拟时间域；真实网络持续校正观感仍需独立验收。
- 平台不继承单位旋转；当前Mass单位只维护Yaw且需求明确不继承朝向。
- 友军退让只检查每台机甲最近16个闲置单位，不恢复全军严格净距；没有NavMesh空间时单位保持原位并继续阻挡机甲。
- 未来飞行系统应使用`MOVE_Flying`；结束飞行切到`MOVE_Falling`后，现有顶面着陆会自动恢复。

### 修复实现与接口边界

- 公共碰撞体、空间索引、包围盒和几何求解移至Navigation；权威端和客户端复用同一包围盒函数，模型缩放只应用一次。客户端不依赖显示插值参数。
- 快照携带对局代次、姿态帧号、原始采样模拟时间和本地缓存代次。生命周期变化使用小型覆盖表发布新快照，历史移动仍持有原快照；重连/换局清除缓存与待回放移动。外推预算从原始样本累计100ms，超时静止。
- `PerformMovement`、SavedMove及服务器移动包使用显式移动时间；同一世界帧内多个服务器包依次消费时间。步内侧扫与滑动同时缩短剩余时间；高度调整、旋转、退嵌不重复推进Mass时间。
- 侧面求水平圆相交区间与垂直区间交集，与世界命中、顶面命中比较最早时间；带类型的接触进入CMC着陆流程，滑动后重新查询，余时交给新模式。保留三次接触和50cm退嵌预算，预算用完停止侵入。
- 平台先用上一参考姿态检验边缘，再携带并执行世界扫掠，最后检查走出顶部。顶部模式使用现有走速和制动数值。校正响应保存与确认时间戳对应的支撑基线；剩余移动从权威基线重放，平台位移只叠加一次。
- 外部位移SavedMove/响应抽取成可继承的私有网络实现，机甲扩展其支撑字段并复用`DisplacementRevision`。服务端独立判定支撑，身份不一致也校正；owner-only ID只做镜像。确认/回收移动时释放历史快照。
- 显示层在既有渲染预测偏移之后读取接触覆盖，位置/朝向对齐，保留缩放和动画；离开接触后200ms恢复正常插值。保持原有`TG_PostUpdateWork`顺序。
- `UpdateObstacle`明确返回Updated/Unchanged/NotFound/InvalidData；只有NotFound重建句柄。非法输入保留旧障碍，首次非法注册不插入。友军退让参数、静态资源注册接口未变。

私有CMC网络格式发生变化，客户端和服务端必须使用同批构建；战斗网络DTO没有调整。
