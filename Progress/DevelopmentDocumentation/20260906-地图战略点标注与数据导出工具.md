# 地图战略点标注与数据导出工具 — 技术方案

- 对应需求：[地图战略点标注与数据导出工具](../RequirementDocument/20260906-地图战略点标注与数据导出工具.md)

## 技术选型

建设项目插件 **GuLiMapAuthoring**，从 UE 菜单“工具 → GuLi → 地图标注”打开可停靠面板。用户在当前地图中编辑资源点、据点及以后新增的玩法标记，保存到地图，再导出供填表使用的 JSON/CSV。

已确认首版包含配置式类型与字段、多个命名区域、凹多边形区域，以及限定范围的自动化测试。游戏侧的数据加载、Excel 工作簿、占领/产出逻辑和事件编排属于后续任务。

| 选型 | 决定及原因 |
|---|---|
| C++ 项目插件＋原生 Slate 面板 | 与 UE 的停靠窗口、Details、选择、Undo/Redo、视口控制点统一；采用 Slate 实现此前设想的 Editor Utility 面板职责，无需额外搭建 UMG 蓝图。 |
| 类型配置 DataAsset＋FInstancedPropertyBag | 类型与自定义字段由数据定义；实例按固定字段结构编辑值。新增出生点、补给点等配置无需修改插件枚举。 |
| FInstancedStruct 形状数据＋处理器注册 | 圆柱、球、方框、多边形是首批形状；未来新增路径或特殊区域能注册独立实现。 |
| 完整 JSON＋分表 CSV | 保留多区域、多顶点、自定义字段；导出数据不依赖 UE 二进制或屏幕截图。 |
| 两个 Editor 模块 | 本期只提供编辑能力与文件导出，核心模型也仅在编辑器加载；未来游戏侧通过导出合同或既有 DataTable 管线消费，避免迁移地图里的 Marker 类。 |

本机源码版 UE5.7 已核对 `FInstancedPropertyBag`、`StructUtilsEditor` 和 `FComponentVisualizer` 接口。字段迁移可复用引擎按属性 ID 匹配的能力，新增字段使用定义中的默认值，见 [Epic 接口说明](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/CoreUObject/FInstancedPropertyBag/MigrateToNewBagInstance)。World Partition 导出需考虑编辑器未加载的 Actor，见 [Epic World Partition 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/world-partition-in-unreal-engine?application_version=5.7)。这些是选型依据，尚未构成插件运行验证。

## 涉及模块

插件根目录：`Plugins/GuLiMapAuthoring/`。依赖方向固定为 `GuLiMapAuthoringEditor → GuLiMapAuthoringCore → UE 基础模块`；插件不依赖 `GuLiStrike` 玩法模块。

| 模块/产物 | 职责与边界 | 类型 |
|---|---|---|
| GuLiMapAuthoringCore | 类型定义、记录/形状结构、纯数据校验、字段迁移、JSON/CSV 序列化、几何与导出注册接口；不包含 Slate 或编辑器世界操作 | Editor 模块 |
| GuLiMapAuthoringEditor | Marker Actor、区域可视化组件、视口交互、Slate/Details、类型资产创建、世界扫描、事务与自动化调用入口 | Editor 模块 |
| 类型资产 | 存于 `/Game/GuLiStrike/Editor/MapAuthoring/Types`，首批 Resource、Outpost、Generic 可直接编辑；以后在面板中创建新类型 | 编辑器 DataAsset |
| 导出目录 | `Data/MapAuthoring/<地图包路径去掉根斜杠>/`，保留挂载点及子路径，避免同名地图相互覆盖 | 生成数据 |

Core 的 Public 依赖为 `Core/CoreUObject/Engine`，Private 为 `Json/GeometryCore`。Editor 的 Public 依赖为 `Core/CoreUObject/Engine/EditorSubsystem/GuLiMapAuthoringCore`，Private 为 `UnrealEd/EditorFramework/Slate/SlateCore/InputCore/ToolMenus/LevelEditor/PropertyEditor/StructUtilsEditor/AssetRegistry/AssetTools/Projects/DeveloperSettings/RenderCore/RHI/Json`。两个模块均用 Default 加载；菜单和视口注册在编辑器就绪回调中完成。EditorFramework 提供 UE5.7 的 FEditorModeInfo；RenderCore/RHI 只服务于编辑器场景代理。

只把配置资产、记录类型和必要扩展接口放入 Public；界面、扫描、序列化实现和注册表内部放入 Private。`GuLiStrike.uproject` 启用插件；本期无须在 `GuLiStrike.Build.cs` 添加插件依赖。

## 配置与扩展合同

### 类型和实例

- `UGuLiMapTypeDefinition` 定义稳定 `TypeId`、中文名称、颜色/编辑器图标、默认命名区域、可用形状、字段结构、默认值及必填/数值范围约束。TypeId 用 FName，禁止以固定 C++ 类型枚举分派资源点/据点逻辑。
- 字段首版允许 bool、int32、double、Name/String、枚举资产、FVector、软对象/软类引用。允许通过配置增加字段；任意嵌套容器、任意 UObject 实例和可执行脚本不作为字段类型开放。
- 类型资产中使用可编辑结构的 `FInstancedPropertyBag`；Marker 中使用固定结构的实例值。字段的 GUID 负责迁移，字段键用合法标识符负责导出，显示名称可以中文。
- `AGuLiMapMarker` 持有 `FGuLiMapMarkerRecord`：稳定 GUID、地图内唯一的可读业务键、显示名、类型引用、Enabled、标签、备注、参数及命名区域列表。Actor Transform 是标记位置/旋转来源，不再保存第二份可编辑世界坐标。
- `FGuLiMapRegionRecord` 包含区域 GUID、标记内唯一的 RegionKey、区域显示名/启用状态、相对标记的平移/旋转和 `FInstancedStruct` 形状。每个区域可独立移动、旋转、改形状。
- 新建时产生 GUID 和默认业务键；复制、Alt 拖动复制、粘贴生成新 GUID/业务键，并重分配所复制区域的 GUID。移动、重命名 Actor Label、保存、加载和 Undo/Redo 不重生成身份。地图复制后通过“地图包路径＋GUID”区分布局。

### 字段变化

类型定义保存后，面板标出当前地图中需要更新的实例，并提供“同步类型定义”。新增字段填入默认值；同 GUID 同类型的字段保留实例值，重命名不丢值。默认值改动只影响新建实例和新字段，不自动改写既有实例数值。

删除字段或改变字段类型时，保留旧实例数据并显示差异，禁止静默导出。用户可修回类型定义，或执行“升级并重置冲突字段”；后者迁移兼容值、对冲突采用新版定义并进入 UE 事务，可撤销。缺失类型资产、重复 TypeId、未注册字段/形状处理器同样明确报错，不降级成空数据。

### 扩展接口

- Core 提供 `IGuLiMapGeometryHandler`：注册 ShapeType 与对应 UScriptStruct，负责形状校验、规范数据输出、边界/顶点提取；首版的四类区域也走注册接口。
- Editor 提供 `IGuLiMapGeometryEditor`：按 ShapeType 注册绘制、控制柄和编辑操作；以后增加样条路径时，可在附加编辑器模块中接入对应数据和交互。
- Core 提供类型附加校验与 `IGuLiMapExportProvider` 注册点。通用校验/默认导出始终执行，附加模块补充特殊规则或新输出格式；模块卸载时必须注销。
- 新增普通类型/字段只需类型资产；新增几何或特殊校验需要代码扩展。未来玩法的事件执行、网络状态和资源结算由游戏模块实现，编辑器仅生产其布局和配置。

## 面板与地图操作

- 面板顶部为当前地图、添加类型/标记、校验、保存并导出；左侧是类型/文本/启用状态筛选及标记列表，右侧使用 UE Details 编辑所选标记与区域，底部显示可点击定位的问题和导出结果。
- 列表与视口选择双向同步，支持双击/F 聚焦、批量删除/启用、复制及 Undo/Redo。筛选只控制插件的显示，不修改 Actor 或区域的业务 Enabled 值。
- 默认用类型预设新建 Marker。进入放置状态后单击场景表面放置；无表面时使用可设置高度的水平工作平面，默认 Z=0。提供“放到所选 Actor 原点”和“添加到世界原点”供精确起步；Esc 退出放置，Alt＋鼠标保留 UE 相机操作。
- 类型资产的创建/修改入口在面板内可达；用 AssetRegistry 在配置的类型目录按类查询，并监听增删改，无需文件系统遍历商城资产。
- 区域显示轮廓和淡色填充，选中区域显示控制柄；全部命名区域可同时显示，当前编辑区域突出。常驻显示由 UGuLiMapVisualizationComponent 的场景代理负责，FComponentVisualizer 只承担选中控制柄；避免未选中的区域消失。渲染线程只读构建好的网格快照，数据变化时重建；组件不 Tick，不参与碰撞、导航、阴影或游戏逻辑。轮廓采用屏幕空间 2px 线宽；UE5.7 的 DynamicEditorMeshElements 不接受半透明填充，故场景代理使用正常材质渲染路径，按 DebugMeshMaterial 的真实 MaterialRelevance（After DOF）设置通道，EditorOnly/视图门控仍生效。
- 面板/服务使用编辑器事件驱动刷新。关闭面板或切换地图时退出放置/顶点编辑，清理委托和失效对象引用；界面快捷键仅在相应控件或编辑状态拥有焦点时处理。
- 删除/GC 后，UE 缓存的选择组件路径和控制柄 HitProxy 可能失效。可视化器绘制与点击入口必须先检查组件及 Owner，有效对象才参与操作；不能假设退出编辑模式后 UE 就不再发出绘制回调。
- Marker 与类型配置资产声明 EditorOnly，Marker 设置 `IsEditorOnlyLoadedInPIE=false`，避免进入 PIE 或打包游戏。本期不添加 Runtime 模块。

## 范围编辑与空间约定

标记可以没有区域，表达单纯点位。所有尺寸显式存储，Actor/区域 Scale 固定为 1；原生位置/旋转工具编辑 Transform，尺寸通过属性或专用范围控制柄编辑。存储与导出空间量为 cm、角度为 degree；面板明确标注 cm 和 100cm=1m 的换算，避免单位误读。

| 形状 | 存储和交互 |
|---|---|
| Circle/Cylinder | Radius、MinZ、MaxZ；底面为区域局部 XY，沿局部 Z 表示高度范围；可拖半径和上下边界 |
| Sphere | Radius；拖动半径控制柄 |
| Box | 三轴 HalfExtents 按半尺寸编辑，完整宽/深/高为对应值 ×2；支持区域旋转和各轴尺寸控制柄 |
| PolygonPrism | 有序局部 XY 顶点、MinZ、MaxZ；直线闭合边界，支持凹多边形，沿局部 Z 挤出 |

多边形支持选中/拖动顶点、选中边后插入中点、删除顶点和方向统一；闭合关系隐含存储，不重复保存首顶点。至少三个有效顶点，首版防护上限 4096，拒绝零长度边、近零面积、自交和非相邻边接触；允许正常相邻边共享端点。一次视口拖动对应一次事务：临时无效轮廓标红、不生成填充，松开仍无效则恢复拖动前完整记录并取消事务；Esc、关闭面板、地图切换和 PIE 进入同样清理未提交输入。Details 可暂存无效输入，但不能导出。填充使用 GeometryCore 的实际凹多边形三角化，不以凸包或包围盒替代。首版不处理内孔或曲线边。

初始编辑尺寸统一采用半径 100m、Box 半尺寸 100m×100m×50m、多边形 200m 方形轮廓及 -50m～50m 高度；这是可修改的编辑占位值，不定义实际玩法平衡。Resource 默认提供 ResourceArea 圆柱，Outpost 默认提供 Capture 圆柱，Generic 默认为点；Build、Influence 等区域由用户按需新增或加入类型默认值。

## 地图保存与导出范围

- 每次操作从编辑器取得当前世界，显示其真实包路径，拒绝 PIE/SIE 世界。可以在未保存地图中编辑，导出要求地图已有正式路径并保存相关改动。
- 首版 Marker 统一创建在持久关卡，使用专用 Outliner 文件夹；不支持把标记放入子关卡或 Level Instance 作为独立布局。发现已加载的不支持位置时给出定位错误。
- World Partition 下 Marker 默认非空间加载且不加入流送 Data Layer；导出前按 Marker 类核对 Actor Descriptor 与实际记录，只按需加载 Marker。若仍有未解析标记则报告导出不完整并失败，不能把“已加载列表”冒充完整布局。
- UI 的“保存并导出”通过 UE 正常保存流程保存当前地图、相关外部 Actor 包和引用的类型定义，取消保存即停止。程序化 `ExportMap` 不自动保存；脏包、临时地图或不完整快照返回结构化错误。
- 导出按整张受支持地图的标记集执行，不受列表筛选或视口显隐影响。禁用标记/区域仍导出 Enabled 状态，保留策划意图。

## 导出数据和自动化接口

输出目录按完整地图包路径映射，例如 `/Game/Maps/LVL_CommanderMassPrototype` 对应 `Data/MapAuthoring/Game/Maps/LVL_CommanderMassPrototype/`。

| 文件 | 内容 |
|---|---|
| layout.json | 完整快照：格式版本、地图、坐标单位/坐标系、已使用的类型与字段定义、Marker、命名区域、形状原始参数、扩展字段、标签 |
| markers.csv | 每个标记一行：GUID、业务键、类型、显示名、启用状态、备注、世界位置与 Pitch/Yaw/Roll |
| regions.csv | 每个命名区域一行：MarkerId、RegionId/Key、启用状态、形状、相对及世界变换、半径/半尺寸/高度等显式参数 |
| vertices.csv | 多边形每个顶点一行：MarkerId、RegionId、顶点序号、局部 XY 和完整世界 XYZ |
| properties.csv | 自定义字段逐项展开：所属 Marker/区域、字段 GUID/键/类型、标量值或 Vector X/Y/Z；用于扩展形状的附加字段也使用此表 |
| tags.csv | 每个标记的每个标签一行，使用 MarkerId 关联，不把多值列表塞入一个单元格 |

JSON 保留局部几何与变换，CSV 提供世界坐标用于直接阅读，二者从同一快照计算。枚举导出稳定枚举项名，软引用导出完整资产/类路径，浮点数保留 double 精度，不按界面显示小数位截断。首版格式 `schema_version=1`，Type/Field/Shape 标识随快照导出，后续非兼容格式修改提升版本。

文件使用 UTF-8、固定列/键顺序、LF 换行，按业务键、区域键、字段键稳定排序；顶点保留轮廓次序。CSV 使用规范引号/换行转义。生成文件不含时间戳、临时 Actor 名或其他易变诊断字段。相同输入重复导出必须字节一致。

全部数据验证与序列化成功后，写入同级临时输出目录，再将整套输出替换为正式目录；保留一套 previous 成功输出，提交失败时恢复，不发布混合批次。诊断记录写入导出结果/验证证据，不污染规范数据。新增地图或类型不覆盖其他地图的输出。

`UGuLiMapAuthoringSubsystem` 作为统一 UEditorSubsystem，暴露 Blueprint/Python 可调用的 `ListTypes/CreateMarker/GetSnapshot/UpdateMarker/ValidateMap/ExportMap`。其中 UpdateMarker 使用带版本的 JSON 补丁按字段键/区域 GUID 更新，解析和校验通过后作为单个 UE 事务应用；未知键、错误类型或错误身份不修改实例。GetSnapshot 返回完整规范快照；ValidateMap/ExportMap 返回成功状态、问题列表及输出文件路径，问题包含 MarkerId、RegionId 和字段位置。

面板与现有 `Scripts/ue_exec.py` 通道调用相同服务，不另写一套 Python 导出逻辑，也不修改 MCP 服务端。首版不提供从外部 JSON/CSV 反向导入整张地图的功能。现有 Excel 管线要求数值 id、字符串 name 和三行元数据，因此这些 CSV 是供后续填表的布局数据，不能未经映射直接交给现有 DataTable 导入器。

## 验证与验收

用户已在本次规划中明确授权新增聚焦测试。唯一新增自动化测试文件限定为 `Plugins/GuLiMapAuthoring/Source/GuLiMapAuthoringEditor/Private/Tests/GuLiMapAuthoringTests.cpp`，测试前缀 `GuLi.MapAuthoring`；不扩展到其他玩法模块或新的性能矩阵。

自动化在源码版 Editor 的隔离临时测试世界/包中运行，覆盖：

1. 新配置类型可创建实例并保留字段；字段新增/重命名迁移保值，不兼容变化不静默丢值。
2. 新建、复制、粘贴的身份分配及 Undo/Redo；重复业务键/GUID 被拒绝。
3. 规则区域、多区域和区域相对变换；凹多边形有效，自交/退化形状无效；局部到世界坐标与导出一致。
4. 保存并重新加载后，身份、类型、区域、顶点和参数一致。
5. JSON 与 CSV 记录对应、中文/逗号/引号/换行正确、重复导出字节一致；不合法或未保存的输入不发布新快照。
6. 程序化更新与面板使用同一校验/事务服务，错误补丁不产生部分修改。

人工验收包括：打开/关闭/再次打开面板，列表与视口选择同步，相机输入不被吞，新建 Resource 与 Outpost，增加两个不同形状的命名区域，操作凹多边形控制点，保存重开，创建一个额外的配置类型并完整导出。World Partition 地图上验证远处 Marker 未因视口区域卸载而漏导；未取得对应地图证据前，不声明这部分通过。
