# 客户端 CPU 增量维护与 10Hz 刷新

## 2026-09-16 修复后独立复测：当前结论

本轮CPU子范围验收通过。用户确认相关问题修复后，重新构建源码双目标、运行既有42项回归，并独立采集1200单位单客／双客各三轮；本次未改生产源码。证据见[复测报告](../../TestResults/CommanderClientCpu-Retest-20260916/REPORT.md)和[本次归档](../Archive/20260916-客户端CPU修复后六轮复测验收.md)。

| 场景 | 三轮平均帧时间中位数 | 三轮P95中位数 | 三轮P99中位数 | 实际移动人数P05 |
|---|---:|---:|---:|---:|
| 单客 | 9.553ms | 10.897ms | 11.475ms | 1198～1200 |
| 双客Client1 | 16.320ms | 18.450ms | 19.323ms | 1199 |
| 双客Client2 | 16.426ms | 18.734ms | 19.633ms | 1199～1200 |

各轮分别通过单客P95≤16.67ms、双客P95≤33.33ms和移动人数P05≥1140门槛。六轮服务端各完成500模拟步，丢步0；全部角色零移动采样0。CrowdManager平均1.814～1.864ms；此前顶层NavigationBuild的主要阻塞已由[Detour修复任务](20260916-据点矿厂落点与大规模避让修复.md)定位为proximity查询，并非NavMesh重建。

九份共同30秒窗口内，完整池校准、结构增量处理、空闲血条实例更新及小地图地形重绘均0次；Mass位置采样／提交／执行、小地图采样／动态层绘制均300次。全场景Recreate仍有103～136次，不再逐帧出现；残余场景更新成本保留。明确计数的容器高水位合计872.46KiB，不是净增量。

源码引擎仍为`D:/UnrealEngine-5.7`；Editor与Game Win64 Development构建退出码均0，七份模块BuildId一致为`11b8900e-cd30-41cb-ad6b-96933e5d3584`。42项回归全部成功，15份运行日志没有Fatal、Assertion、Ensure或bunch超限标记，采集前后30份相关文件哈希一致。

本次采集关闭后台编辑器；旧CPU基线的后台编辑器和移动负载条件不同，不能计算五项CPU改动的独立收益百分比。双客尚未达到P95≤16.67ms。此前鼠标／血条／小地图人工回归沿用原证据，本次未重跑人工交互；旧预测派发判据限制保留。下文首次实施的未通过记录属于历史状态，当前结论以本节及元数据为准。

## 边界与调度

本开发记录承接[客户端性能需求](../RequirementDocument/20260915-客户端性能优化与压测问题记录.md)的本轮 CPU 子范围，保留当前工作区已有插值、协议及其他任务改动。服务端模拟、协议字段、画质、显示距离保持当前设置。

| 路径 | 实施方式 |
|---|---|
| 名册索引 | Replicator 本地 TMap 保存值，FastArray 接收结束通知增删改；SnapshotRevision 仍不是复制就绪证明 |
| 实例池 | 新增、移除、兵种迁移按 ID 合并；初始化/源切换完整校准一次；失败分配 10Hz 重试 |
| 变换 | 持久缓冲与变化槽位，ISM 原生实例数据更新，普通变换及颜色不完整重建代理 |
| Mass | 安全命令缓冲批量创建/销毁/更新；位置 10Hz，生命和代次事件及时更新；句柄和本地存活令牌隔离旧命令 |
| 小地图 | UMG 宿主保留，地形/动态标记分别使用 Slate 缓存子层；10Hz 采样，选中/死亡/阵营事件更新 |
| 血条 | 选中与受击有效期活动集合；槽位复用；空闲关闭 Tick，依赖/过期维护使用独立 0.1 秒定时器 |

移动插值、预测修正、模型提交及活动血条跟随/朝向/淡出保持每帧。低频维护不补跑过期周期，不增加姿态接收等待。

## 采集条件与已发现限制

证据根目录：[CommanderClientCpu-20260915](../../TestResults/CommanderClientCpu-20260915/)。使用源码引擎 Editor 的 `-game` 运行时，1200 人、单客/双客各三轮、1080p Epic、固定镜头、8 秒折返、客户端 40 秒/服务端 50 秒，中间共同 QPC 30 秒用于比较。修改前采集期间未编译。

首轮原参数因当前工程车避障工作的 GroundCrowd MaxAgents=1024 断言而无效；保留失败日志。正式本轮前后采集均使用启动参数临时覆盖 MaxAgents=2048，不修改项目配置。这一条件与早期历史压测不同，只在本轮内部比较。

六轮修改前采集完成，实际名册人数均为1200。客户端在共同窗口的实际位移人数 P05 为601～908，低于既有1140门槛；服务端P05为1184以上。这些数据可用于观察本轮机制和开销，不能直接宣称1200人持续移动性能验收通过。最终报告必须保留此限制，不用 requested_population 代替实测负载。

构建期间遇到页面文件不足及相机 TObjectPtr 类型推导错误，已修正并限制构建并发为3。最终 Editor build 9、Game build 6 均成功，引擎/项目/GuLiFlightNavigation BuildId 同为 `26d441ba-b96a-4e7b-b104-c2c6cd3e663c`。

早期两轮修改后采集因本轮错误的朝向比较触发可靠 bunch 超限而无效，已修复并补回归。预留 Mass 实体的取消销毁也由新增回归发现并修正。正式 final 六轮均完成；随后仅拆分了小地图计时标签，重新双构建并通过42项自动化。六轮原计时标签需解释为两个缓存层绘制合计，不能用来声称地形单层重绘频次。

## 首次实施验证结果（复测前历史）

详细数据与失败项见[本轮报告](../../TestResults/CommanderClientCpu-20260915/REPORT.md)。

| 项目 | 结果 |
|---|---|
| 名册与实例池机制 | 正常采样窗口全量池校准0次；普通状态通知不触发结构维护 |
| Mass / 小地图 | 九份客户端窗口内常规位置批次及小地图采样均300次/30秒，即10Hz |
| 空闲血条 | 逐帧实例更新0次；运行时选择20人后唤醒，受击提示结束后再次关闭Tick |
| 普通渲染更新 | 双客Client1的全场景Recreate从每30秒3143～3206次降到67～75次，残余场景更新未被宣称消失 |
| 局部CPU | 双客Client1表现主循环中位数1.317→0.569ms/帧，Mass延迟执行0.216→0.029ms/帧；不代表相同持续移动负载的整帧收益 |
| 明确计数的缓存 | 跨轮容器高水位相加约872KiB；不含全部引擎/Slate/GPU缓存，没有基线细分计数，不能当净增量 |
| 鼠标/UI | 三次真实Slate右键均被服务端接受，姿态有前进/反向/停止；血条生命变化、隐藏休眠、小地图旋转/重新显示及两种窗口缩放下点击已检查 |
| 原鼠标脚本判据 | 失败/不适用：已有控制器关闭位移预测，脚本仍要求BeginPredictedMove派发事件；未为使脚本通过而恢复旧预测 |
| 整体性能 | 未通过：前后各六轮实际移动人数P05均低于1140；修改后单客P05为0，服务端导航构建明显阻塞并掉步 |

整帧三轮中位数：单客P95 14.562→14.238ms；双客Client1 22.256→22.075ms、Client2 22.290→22.064ms。虽然观测P95低于数值预算，负载条件不成立，首次验收记录为 `verification: failed`，当时未标记开发完成；后续复测结论见本文首节。

两次长时间PIE检查遇到既有建筑入口坡道地面断言（GuLiGroundAccessRampComponent.cpp:37）；已保留日志。后续短窗口补验正常结束，编辑器恢复原地图，脏关卡/资产包为空。本轮没有修服务端导航或建筑地面问题。

关联需求已超过20KB，后续可按客户端CPU、持续移动压测和其他显示需求边界拆分；本轮不改写历史证据。

Progress索引已构建并核对，全量检查0错误、12条既有文档尺寸/任务数提示。构建与检查日志位于本轮证据目录。
