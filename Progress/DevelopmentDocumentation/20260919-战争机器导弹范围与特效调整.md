# 战争机器导弹范围与特效调整

## 初次实施：数值与资产

| 入口 | 原值 → 新值 |
|---|---|
| `GuLiStrikeSpellFields.xlsx / Fields / F4` | `RadiusCentimeters` 160 → 200 |
| `GuLiStrikeSecondaryUnitSkills.xlsx / Skills / R4` | `TargetAreaDiameterCentimeters` 800 → 1600 |
| 同表 `Skills / C4` | 说明同步为直径16米、爆炸与预警半径2米 |
| `DA_WM01_Missile.VisualScale` | 0.2 → 0.4，Core/Exhaust/Trail共用 |
| `DA_WM01_MissileExplosion.Radius` | 160 → 200，资产回退值与表一致 |
| `DA_WM01_MissileQ.TargetAreaDiameterCentimeters` | 800 → 1600 |

Excel通过项目xlsx CLI修改，逐单元格比对仅上述三处改变：[源表差异](../../outputs/wm01_missile_update_20260919/source-changes.json)。运行既有导出器并只重导入`DT_GuLiStrikeSpellFields_Fields`和`DT_GuLiStrikeSecondaryUnitSkills_Skills`；生成C++行结构未变。基础伤害30、每台6秒冷却、48米基础圆心射程和0.55秒尾迹退场时间不变。

用户指定的商城2A资源保持原样，派生项目资源`/Game/GuLiStrike/FX/CommanderWeapons/NS_WM01_Explosion_2A`，由`DA_WM01_MissileExplosion`唯一激活变体引用。原NS_WM01_Explosion_7/8/9资产保留，但不再参与此导弹随机爆炸。

原有效缩放为`1 × 160 / 800 = 0.2`。保留`VisualReferenceRadius=800`，新变体`Scale=1.6`，有效缩放为`1.6 × 200 / 800 = 0.4`。避免将伤害半径的1.25倍变化再次叠加到两倍视觉目标上。

## 指定资源的缩放适配

原始2A资源不提供统一缩放用户参数，实际播放发现组件比例不能统一改变主要粒子尺寸。因此项目副本添加`User.VisualScale`，各发射器在Spawn和Update阶段生成缩放后的渲染位置与精灵尺寸；Sprite Renderer读取这两项属性。局部空间围绕局部原点缩放，世界空间围绕`Engine.Owner.Position`缩放，保留原始动画、材质、粒子数量与模拟。

实现入口：[author_wm01_explosion_2a.py](../../Scripts/author_wm01_explosion_2a.py)。运行时通过已有`ScaleParameterName=User.VisualScale`传入0.4，组件本身比例保持1；没有新增运行时C++逻辑。

## 同日后续：爆炸在当前基础上再放大四倍

用户明确反馈“爆炸特效还是太小了，设置为现在的4倍”。本轮特效配置仅修改`/Game/GuLiStrike/FX/CommanderWeapons/DA_WM01_MissileExplosion`：激活变体`Scale`从1.6调至6.4，仍由已有`User.VisualScale`接口驱动2A项目副本。有效缩放`6.4 × 200 / 800 = 1.6`，是本次修改前0.4的四倍。伤害与预警半径200cm、Q直径1600cm、导弹/尾焰比例0.4均保持。

[保存回读](../../outputs/wm01_explosion_4x_20260919/saved-readback.json)记录倍率严格为4；引用的Niagara编译零错误、零警告。复用既有隔离播放流程对照0.4/1.6，在0.1、0.4、0.9、1.5、2.6秒取样，末帧无残留；[峰值对照](../../outputs/wm01_explosion_4x_20260919/preview/peak_040.png)左侧为修改前、右侧为本次放大版。没有修改Niagara图、材质、粒子数或新建测试。

复用已有Q入口进行单机PIE观察，19台成功施放并播放19次爆炸。运行时2A的`User.VisualScale=1.6`、导弹仍为0.4，参数均命中，组件比例均为1，观察错误为空：[实际施放读回](../../outputs/wm01_explosion_4x_20260919/runtime-after-navigation.json)。初次观察因启动导航重建超过45秒而超时；待编辑器既有启动流程重建并保存`LVL_CommanderMassPrototype`导航缓存后，在同一PIE中恢复观察并完成，随后结束PIE。本轮未改导航代码或手工调整地图布局。

本轮未进行性能压测。尺寸增大沿用现有池化、动态包围盒、可见距离和专服抑制机制；画面覆盖增加不等同粒子数量增加，也不能据此承诺性能不变。此次指令是对尺寸的明确修订授权，不补写用户对新版本完整播放的美术终验。
