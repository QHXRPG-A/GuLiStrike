# Ship僚机对地轰炸与对空盘旋攻击 — 技术方案

- 对应需求：[Ship僚机对地轰炸与对空盘旋攻击](../RequirementDocument/20260907-Ship僚机对地轰炸与对空盘旋攻击.md)

> 后续变更：本文件保留首版实现记录。当前对空行为以[三维往返缠斗技术方案](20260907-Ship僚机三维往返缠斗与随机转向.md)为准；对地俯冲、武器拆槽和公共结算仍沿用本实现。

## 技术选型

继续使用单一 GuLiStrike Runtime 模块、Ship GAS、Mass、FlightNav、ClientValidatedRelay 和公共 CombatEffects/DamageLedger。编队授权与武器执行分离；新增武器更换独立 SkillId/GA/执行器，不把激光等新行为压成旧机枪数值。每架仅增加攻击运行状态，仍由唯一 FlightIntegration 写入 Transform。

权威 Ship 维护自动/指定目标；租约拥有者根据可靠目标命令、武器数值快照与已确认目标观测导航/开火。服务器验证轨迹及同批开火记录，再启动公共弹体或提交机枪伤害，不替代客户端模拟僚机位姿。

新武器参数通过 Ship 源表 WingmanTargeting/WingmanWeapons 驱动，Definition 引用表行并发布冻结数值。公共 CombatEffects 增加固定落点直接发射入口和显式冻结爆炸参数，原 Commander 追踪弹逻辑保持兼容。僚机继续复用 WM01 飞行 Niagara，但命中改为项目内复制的 `NS_WingmanGroundExplosion_Big_17` 和独立 `DA_WingmanGroundExplosion`；Commander 的 Projectile/ImpactField 引用不变。

## 行为与初值

- 目标：三维半径150000cm，扫描0.2秒，有效指定优先、自动目标保持、失效后最近优先且稳定ID打破平局。
- 俯冲/接近/盘旋速度4500cm/s；拉起起始高度10000cm，硬范围5000–10000cm，转弯中最低高度5000cm。
- 俯冲T=1.5秒、N=10；N>1时发射时刻i*T/(N-1)，N=1时在0秒发射。发射时钟独立于目标扫描和网络上传节拍。
- 条带12000cm；每架从自己的进攻方向铺开，首枚落点为目标地面位置。本轮冻结落点，不追踪移动/死亡目标。
- 每架轰炸冷却8秒，从首枚开始；当前爆炸伤害30、半径4000cm，均为独立可调值（首版半径800cm，2026-09-10仅Wingman GroundWeapon放大5倍）。
- 僚机爆炸场参考半径与权威AOE一致为4000cm，因此公共字段缩放为1。按最新要求，Variant主体Scale=5，新增`AdditionalLayers`承载Scale=3.1的独立冲击波System。原项目副本只启用非冲击波层；`NS_WingmanGroundShockwave_Big_17`只启用`refr_mesh`与`smoke_shockwave`，原禁用的`refr_sprite`继续禁用。拆分组件变换保留冲击波所有局部空间输入，避免补偿曲线时遗漏速度或重复Owner.Scale。表现层按复制的Effect RandomSeed稳定派生 `[-180°, 180°]` Yaw，两层共享朝向与起点。`DissipationSeconds`与`MaximumLifetime`均为3秒，超时后停用归池；伤害半径不变，5倍视觉不承诺精确覆盖边界。
- 机枪伤害10、2发/秒、射程150000cm、前向半角20°；转入盘旋净距30000cm、期望净距20000cm。
- 中断取消未发，已发继续；单槽替换不重置编队和其他槽，保留更长旧冷却，清理受影响攻击状态。
- 每Flight的5Hz轨迹批次最多附带16条开火记录；按真实发序、轨迹、时间、版本和预算验证，不能仅放宽40条旧单发意图限额。

## 风险与备忘

### 武器升级的落点

- 编队继续使用 `Ship.Ability.Formation.SwarmOrbit`，不因武器替换重建25架Mass实体。
- 当前两个独立GA是 `UGuLiShipWingmanMachineGunAbility`、`UGuLiShipWingmanGroundMissileAbility`，绑定槽分别为 `AirWeapon`、`GroundWeapon`；稳定技能ID为 `Wingman.MachineGun`、`Wingman.GroundMissile`。
- 后续机枪换激光：在同一个 `AirWeapon` Binding 中替换 AbilityId/SkillId/GA/WeaponDefinition，并增加激光执行器和表现。服务端通过 `ServerApplyAbilitySet` 差量授予，发布新的 LoadoutRevision/ProfileRevision/DefinitionChecksum；旧版本未发请求失效，另一武器槽和编队保留。
- 单纯伤害、射速、导弹数量等升级：解析源表和升级修饰后生成新版冻结 Runtime Profile。当前表行由 Definition 的 `AttackProfileRow` 引用；不使用每发激活GA，也不给25架僚机增加ASC或AttributeSet。
- 服务器检查点按 `Emitter + SlotId` 保存更长冷却，按 SkillId/Checksum 判断攻击运行是否仍匹配。已经接纳的导弹持有发射时伤害/范围/落点及来源租约，换装不重写飞行中的弹体。

### 联机实施补充

- 原生协议升为v10，每Flight最多8个真实轨迹中间点、16条发射记录；抽样优先保留发射帧。
- 开火批次可靠上传；使用这两个武器的配置可靠回传轨迹确认，普通无开火位姿继续使用原有非可靠上传。
- 维持每Flight平均5Hz（获准时10Hz），允许一个包的到达抖动余量。全局Candidate预算和旧40次/秒单发意图预算保持原值。
- 客户端采样时钟读取唯一Mass积分器完成的固定步。保留实体的Resume不会把旧位姿虚标为新帧；原子重入等真实模拟进度超过冻结基线后再提交。
- 可靠恢复命令可能先于非可靠状态复制到达；客户端收到恢复命令即取消旧攻击，原子恢复包只提交运动基线。普通发射队列不交给原子恢复包消费，以免恢复包吞掉中间一枚。恢复后按保留冷却重新进场。
- 进场规划与首枚服务器准入共用 `GuLiWingmanAttackNavigation`，检查完整FlightNav分段、WorldStatic扫掠和沿线离地高度。正在攻击时保留物理分离/避障，关闭编队弱对齐对攻击方向的干扰。

- 初值不是最终平衡值。末测每端25架自然错开进攻；已验证有界批次、完整齐射和双端表现。25架强制同步发出250枚的性能峰值及视觉池压力未专项验收，视觉裁剪不能减少伤害数量。
- Big_17含11个Emitter并包含GPU发射器；普通PIE已覆盖双客户端真实多实例生成与回池，但目标硬件上的同屏峰值、GPU时间和打包运行未专项测量。
- 机头仅前向开火与稳定盘旋意味着多数盘旋时间停火，这是用户明确选择。
- 本轮开始前协议v9已存在，历史ProtocolV7 GoldenBytes夹具尚未迁移；不擅自修改未获授权的其他测试文件。
- 模型可见机头是局部-X，Owner/Remote表现已有Yaw180°修正；逻辑+X和权威朝向不得反转。
- 最终原生构建必须使用D:\UnrealEngine-5.7，记录退出码及引擎/项目/涉及插件BuildId。
