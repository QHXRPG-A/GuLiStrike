## 当前增量：2026-10-10网络指标

`GuLiNetworkOverlayStats.h/.cpp`由现有`GuLiCommanderHUD`持有并读取，按真实时钟每秒采样一次。Canvas按全部行计算背景尺寸及DPI缩放，沿用已有性能条配色及输入行为。没有新增Widget、定时器、RPC、复制字段、带宽配置或协议改动。

| 显示项 | 统计范围及含义 |
|---|---|
| 网络收/发/合计KB/s | 本客户端ServerConnection的InTotalBytes/OutTotalBytes差除以真实秒；包含引擎计入的PacketOverhead，1KB=1000B。合计为收+发，不是某一方向的预算占用。 |
| 包收/发及丢包收/发每秒 | In/OutTotalPackets及In/OutTotalPacketsLost的采样差；丢包是引擎检测计数，不是丢包百分比。 |
| 本端额度 | 本端CurrentNetSpeed发送预算；非下行实测速率。 |
| 可靠待确认 | 本端OpenChannels的NumOutRec之和，即可靠bunch待ACK数；并非全部应用队列。 |
| 欠账KB | max(QueuedBits,0)/8000；发送预算欠账，不等于排队事件字节数。 |
| 飞行事件收/s与载荷KB/s | MulticastFlightBatch成功解码事件及Payload字节；包含初始化快照，属于总接收的应用载荷子集，不能重复相加，也不是实际播放量。 |
| 平均估龄ms | 此采样窗内非bootstrap、当前epoch事件的估计服务器当前时间减SampleTime；保留符号，可能含同步误差。无新年龄样本显示--。 |
| PIE服务端数据 | WITH_EDITOR且同进程PIE中，用MatchId+PlayerGuid找到本客户端对应的服务端连接，显示下行额度/待ACK/欠账及FlightPeers中尚未提交RPC的条数。不会汇总其他客户端。 |
| 队首事件年龄 | 服务端当前时间减队首SampleTime；包括事件生成后的其他等待，不等同于在本队列中的停留时间。空队列显示--。 |

累计连接计数按uint32差值处理溢出；新连接先建立基线，重置计数不产生异常速率。未知连接和跨进程服务端数据使用占位。本地服务端/单机视口明确标为本地，不用零值冒充客户端数据。每秒只遍历连接通道和PIE玩家控制器，不扫描单位或整个待发队列。

源表`data/Excel/GuLiStrikeGameTexts.xlsx/Texts`通过excelize新增11项，原229项逐行保留；复用标准`export_game_texts`校验与导出，未改行结构或其他表。使用VibeUE `DataTableService.AddRow`原地添加，避免替换结束PIE后仍被GuLiGameText持有的DataTable UObject。240项全字段读回与JSON完全一致并已保存。

## 2026-09-23历史实现

`GuLiCommanderHUD.h/.cpp`在既有DrawHUD尾部绘制小型半透明条。Canvas拥有显示，现有HUD生命周期负责销毁；没有额外Widget、输入热区、计时器或委托。每个本地HUD缓存文本，按真实时钟与GFrameCounter差值计算0.5秒平均FPS，避免暂停或时间缩放污染；同进程PIE各视口共用引擎帧数，这不是专服Tick率。

客户端优先读取ServerConnection的AvgLag，回退RawPingInSeconds、PlayerState Ping；秒转毫秒并标RTT。无有效测量为“延迟 --”，非客户端为“延迟 本地”。DPI缩放后的(16,64)处位于现有Y=12..56顶部状态条下方，文本随视口可用空间约束。数据只读，无RPC或Actor扫描，保持原焦点和输入所有权。

使用excelize追加`GuLiStrikeGameTexts.xlsx/Texts`五个`UI.Performance.*`键，原186行保持不变；复用标准导出函数与限定单表导入，191行完整内容回读一致。生成结构及其他表未修改。
