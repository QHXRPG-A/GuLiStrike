## 实现与边界

`GuLiLocalTeamColors` 读取本地 `GuLiBattlePlayerState` 的真实阵营，与对象实际阵营比较后给出显示色。未知阵营返回透明，己方蓝、敌方红；不改服务器阵营、选兵权限、资源事务或网络协议。对象阵营优先读取建筑生命周期、工程车、Pawn PlayerState、战斗生命与轮廓组件的既有数据。

每个本地 `GuLiCommanderPlayerController` 创建一个不抢焦点的 `GuLiSceneUIWidget`，UMG 承载 `SLeafWidget`，最终通过 Slate 显示。基础图元复用顶点/索引批次，单批不超过 60000 顶点；纹理使用缓存材质实例和 Brush，销毁时解绑 PlayerState 委托并释放路线缓存和捕获对象。本地身份每 0.1 秒回查，并绑定现有身份变更通知；脚环每次绘制读取对象当前阵营和该玩家的选择快照。

场景 UI 主体 Alpha 为 1，放置与轮廓蒙版仅使用覆盖信息，不采用场景 RGB。捕获关闭灯光、阴影、雾、大气、后处理、曝光与泛光，使用本地视图的实际投影矩阵。最终 Slate 绘制发生在场景后处理之后；UI 纹理表面以二值覆盖隔离背景混色。功能颜色仍表示生命、路径与放置合法性。

处理六个齐次裁剪平面后再除以 W，覆盖相机后方与近裁剪；结合每玩家 ViewRect、ConstrainedViewRect、UMG Geometry 处理分屏、黑边与 DPI。总览继续遵守现有脚环/血条隐藏规则。小地图标记与己方显示标题采用本地配色，但统计、控制和归属数据仍按真实阵营计算。

原 Mesh、动画、LOD 和运行时材质/模型引用未切换，配置 `runtime_enabled=false`。本轮不新增 SSF 玩法类型。采矿车、建造车、Ground 玩家地面机甲与 DIY 飞船模型不在改色范围。

已披露例外：基础兵营和据点仍是现有 Cube/Cylinder 玩法占位件；矿厂按实际工厂蓝图的 Body/门/室内/坡道装配预览，只有 Body Armor 条带是候选。哨戒炮原导入材质底色权重为零，独立预览副本读取已赋值的底色纹理，原件未修；其分区与该预览修复均需用户核对。扫荡者保留既有无线稿例外；护盾青色功能发光固定，红蓝只改已标明的装甲/标识，不改功能光。

美术规则在本次源码与旧对照交付时更新到 v1.4。用户决定的是实施方向，**尚没有对这 18 组具体黄色候选区的通过决定**；审核后才接入实际模型显示，已有旧模型的过审记录不被覆盖。随后用户的十三模型配色反馈已转入[参考 A_v2 交付](20261008-十三模型配色参考与三视图A_v2.md)，规范接续到 v1.5；新 A 参考仍待逐模型决定，旧对照及本页 UI 验证边界保留。

### 玩家操作与预期结果

前置条件：另有明确授权后编译并加载本轮原生代码；双方选择 Commander 且真实阵营已分配。彼之矛施工入口还依赖其既有工作项的 Buildings Id8 / Soldiers Id6 正式数据安装状态，本轮不将 SummonOnly/ConstructionOnly 兵种强行加入初始部署。

1. 打开原型地图，通过 `SceneUI_ReviewCamera` 定位观察区，手动启动双方客户端。两端观察相同双方部署点：各自己方蓝脚环、敌方红脚环；服务器真实阵营保持原值。
2. 选择、Shift 减选、切换编队：选中出现四个同色外缘短标记，环带保持阵营色。选择先驱号按 Q 通过真实召唤流程观察扫荡者；通过 B 和己方工程车建造彼之矛后观察其环带，不绕过玩法限制。
3. 利用既有据点占领/赠品换主流程改变归属：本地显示应刷新；阵营尚未确定时不显示脚环。双方交换真实阵营后，己方显示仍蓝，敌方仍红。
4. 分次开启 `SceneUI_Profile_Night`、`SceneUI_Profile_ExposureBloom`、`SceneUI_Profile_ColorGrade` 的 Enabled；分别打开浓雾/彩色灯组件 Visible 并取消 HiddenInGame；打开黑/白背景同类开关。逐次手动启动并比较 UI 主体颜色。昼夜与阴影可调整既有太阳光朝向/强度，主体颜色应保持，场景环境应变化。默认开关关闭以便基线对照。
5. RMB 移动、Shift 排队移动、7 矩形/常用选择圈，检查绿色路线、指令/队列线、选区；造成伤害检查功能绿血条。按 B 检查合法/非法放置预览和网格，切总览检查世界图标，再切现有飞船席位检查世界面板。
6. 分辨率/DPI、视口边缘、近裁剪和相机后方各手动核对；退出/切角色后无残留。四种环带按世界边缘而非像素宽度判定。
