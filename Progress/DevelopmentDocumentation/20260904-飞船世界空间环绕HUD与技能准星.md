# 飞船世界空间环绕 HUD 与技能准星 — 技术方案

- 对应需求：[飞船世界空间环绕 HUD 与技能准星](../RequirementDocument/20260904-飞船世界空间环绕HUD与技能准星.md)

## 技术选型

- 使用项目已有 UMG、`UWidgetComponent`、Enhanced Input、GameplayAbilities 与 Native Gameplay Tags，不增加模块或插件依赖。
- `UGuLiShipAimComponent` 管理 GAS 能力生命周期、相机对齐、虚拟准星位置和只读瞄准射线；`UGuLiShipWorldHUDComponent` 只负责本地表现，避免 UI 反向修改玩法状态。
- 能力模式以 `AssetTags` 为唯一来源，范围数值使用 `FGuLiShipReticleConfig`；不把数值编码进 Tag 名。
- 节点使用 World Space Widget、项目内无深度材质、固定 DrawSize 与手动重绘；材质在 Motion Blur 后绘制。节点每帧以 `MakeFromXZ(-CameraForward, CameraUp)` 重建真正的屏幕朝向，避免对 Rotator 直接加 180° 在非零 Pitch 时产生歪斜/翻面。
- 舰体投影只累计相机前方角点，并把穿越近裁面的 12 条 AABB 边裁到 10cm 深度；若仍无法形成有效投影，则回退到相机前方平面与视口中心。临时相机/投影失败不改变三个常驻面板的可见状态。

## 风险与备忘

- 新增反射类型后必须完整编译并重启编辑器，不能依赖 Live Coding。
- 当前正式能力都不设置 Reticle Tag；视觉验收通过非 Shipping 调试入口切换模式。
- UI 状态只在拥有客户端存在；瞄准射线不形成任何权威网络合同。
- 三个常驻面板只有失去有效本地拥有关系、Dedicated Server 或明确死亡时才隐藏；瞬时投影失败必须保留上一帧可见状态。
- 节点和材质均保持单面；持续相机朝向保证正面可见，同时避免首次 PIE 依赖额外双面 Shader permutation。
- 工作树已有未提交修改，所有共享文档只做增量补丁，不覆盖用户内容。
