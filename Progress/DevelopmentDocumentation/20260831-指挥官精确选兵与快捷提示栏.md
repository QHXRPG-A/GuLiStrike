# 指挥官精确选兵与快捷提示栏 — 技术方案

- 对应需求：[指挥官精确选兵与快捷提示栏](../RequirementDocument/20260831-指挥官精确选兵与快捷提示栏.md)

## 技术选型
继续使用原生C++输入/UMG布局/Slate几何，直接BindKey，不引入新输入插件。点选传单个目标hint与射线，框选传相机四角视锥，服务器验证并生成成员。UnitTypeId默认1贯通权威快照/可靠名册，协议v4；不允许客户端提交最终兵员列表。

选择工具与形态分离。Shift为Add，存活成员并集改变时重建最多25人组，禁止外部补员。Alt候选全图按二维距离/SoldierId排序截断1000。客户端FIFO等待ACK及已追上其revision的选择副本；移动绑定具体选择请求，由统一发出事件启动预测，失败取消。`MovesAwaitingSelection` 按选择请求 ID 分别保留移动，只合并同一次选择的连续目标；A→移动A→B→移动B不能互相覆盖。移动A回执前不发后续选择B，避免不可靠RPC重排改变服务器成员。

视觉资源使用内置imagegen生成正式RGBA PNG，入库源图保存在 `data/CommanderUI/Selection/`（`cursor.png`、`box.png`、`radius.png`、`same_type.png`、`add_selection.png`），目标导入目录为 `/Game/Commander/UI/Textures/Icons/`；UE原生software cursor由Slate定位。诊断仅在非Shipping显式开启，记录mouse_input、prediction_begin、ACK、sample/render/resolve/frame；no_offset仅取消捕获期间位移叠加并自动恢复。

## 风险与备忘
- 单兵hint使用显示位置拾取，服务器保留权限及有界射线一致性验证，不以邻兵替代失败目标。
- 服务器点选身体校验使用脚点上方 500cm 的包围球，半径约 901.4cm，覆盖客户端 1000cm 高、750cm 半径的身体拾取尺度；另叠加有界速度窗口与点击半角。近景静止模型上部/侧边和远离射线拒绝已写入原生测试，不能只用脚点 200cm 容差替代。
- ACK与属性并无跨通道原子性，后续选择不得覆盖尚未收到回执的移动依赖。
- 编译前核对dirty packages；只修改计划内资产、单个编辑器写入，不保存无关包。
- 本次修改前NetworkGate绕过预测入口，历史PASS不能证明起步手感；本次预测发出已统一到NetSync委托，诊断仍须走真实鼠标链。
