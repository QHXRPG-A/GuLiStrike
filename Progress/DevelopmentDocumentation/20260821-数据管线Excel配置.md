# 数据管线：Excel 配置飞船数值 — 技术方案

- 对应需求：[数据管线：Excel 配置飞船数值](../RequirementDocument/20260821-数据管线Excel配置.md)
- 日期：2026-08-21
- 状态：实施中

## 技术选型

| 候选 | 结论 |
|---|---|
| **Excel → JSON → DataTable 资产（选定）** | UE 原生数据资产：打包自动烹饪、FTableRowBase 类型安全、蓝图可用；导入用编辑器 Python（CSVImportFactory+AutomatedImportSettings 通道，JSON 转 CSV 侧车）经既有 UnrealMCPython 通道自动化。 |
| 裸 JSON 运行时解析（FJsonObject） | 需新增 Json/JsonUtilities 模块依赖 + 打包 staging 配置，资产引用要手动路径加载；热改便利性收益不足以抵消打包/类型安全成本，弃。 |
| CSV → DataTable | UE 原生支持，但多 sheet 组织差、无嵌套结构；保留为 JSON 导入出问题时的降级后端（导出脚本可同时产 CSV）。 |
| 策略直接改蓝图 CDO（编辑器脚本写值） | 零运行时改动，但违背"运行时加载 data"的需求且数值仍散落各蓝图，弃。 |

关键依据：UDataTable/FTableRowBase 在 Engine 模块内，**Build.cs 无需新增依赖**；项目已打通编辑器内嵌 Python 通道（UnrealMCPython TCP 12029），导入步骤可全自动。

## 管线形态

```
Data/Excel/GuLiStrikeShip.xlsx     ← 策划唯一编辑入口（Parts / Tuning 两个 sheet）
   │ Tools/DataPipeline/export_data_from_excel.py（系统 Python + openpyxl，校验+导出）
   ▼
Data/Json/DT_GuLiStrikeShip_Parts.json / DT_GuLiStrikeShip_Tuning.json   ← 入库的可 diff 中间产物
   │ Scripts/import_data_to_engine.py（编辑器 Python，经 MCP 通道执行）
   ▼
Content/GuLiStrike/Data/DT_GuLiStrikeShip_Parts.uasset / DT_GuLiStrikeShip_Tuning.uasset（打包自动烹饪）
   ▼
运行时：InstallPart 按部件 PartId 查行覆盖实例数值；BeginPlay 按 TuningPreset 查行覆盖整机调参
```

**通用化设计（2026-08-22 重构，校验规则全部配置化）**：脚本不含任何具体表的字段知识——
- 表名派生规则：`DT_{Excel文件名主干}_{sheet名}`，由 `Tools/DataPipeline/tables.json` 统一登记，导出/导入两侧共享；
- tables.json 每张 sheet 携带完整规则数据：`schema`（C++属性名 → [类型, min/max或枚举值, Excel列名?]；vector 在 Excel 里是 `<前缀>X/Y/Z` 三列；aux 只校验不导出，如 Parts 的 Type 列）、`required`、`required_by`（按列值条件必填）、`compare`（跨字段比较）、`row_name`、`struct`、`assign_to`；
- 导出脚本只实现通用规则引擎（行名唯一非空/类型/范围/必填/条件必填/比较/向量拆列），遍历工作簿**所有** sheet：登记过 schema 的走配置校验，未登记的走推断兜底（类型自动推断 + X/Y/Z 合并向量）；
- 导入脚本只导入登记了 struct 的 sheet（CSV 侧车列名从 JSON 行键自派生），未登记的跳过并警告；
- **新增一张游戏表 = C++ 加 FTableRowBase 行结构 + tables.json 登记一段配置，脚本零改动。**

## 数值边界

- **进表**：部件行 = `PartMass`/`PartDisplayName` + 引擎 `Thrust` + 武器 `Damage`/`FireRate`/`MuzzleOffset`/`ProjectileClass`（软类引用）；调参行 = Stats 7 项 + Handling 12 项 + `HullMeshOffset`，字段名与 `AGuLiStrikeShip` 同名 UPROPERTY 一一对应。
- **不进表**：网格/`PartRelativeTransform`/`CompatibleSockets`（留蓝图 CDO）、运行时状态、输入资产绑定。
- 兜底：表为空、`PartId` 未设、行缺失 → 沿用蓝图默认值 + Warning，现状行为不变。

## 风险与备忘

- 无头 JSON→DataTable 导入对 FText/嵌套 FVector 的兼容性 → 降级 CSV 后端（导出脚本双格式输出）。
- FText 经 JSON 导入为 culture-invariant 文本，中文部件名可用但本地化管线以后接入时需迁移。
- 编辑器必须开着才能导入（MCP 通道）；关机批处理/commandlet 导入不进 v1。
- 系统 Python 需 `pip install openpyxl`（仅导出侧；编辑器侧只用内建 unreal API）。
- `ProjectileClass` 在部件安装时 `LoadSynchronous`——安装非高频事件，可接受；未来量大可改软引用异步加载。
- Excel 校验只能做表内一致性（范围/必填/唯一）；"PartId 与蓝图类型是否匹配"的交叉校验放在导入脚本侧（编辑器知道蓝图类）。
- 实施中发现的额外坑（详见归档）：`fill_data_table_from_csv/json_string` 收尾必挂游戏线程（弃用）；`delete_asset` 弹模态卡死（弃用）；python 直改蓝图 CDO 后须 `modify()`+强制保存否则静默不落盘；PIE 实例上 EditDefaultsOnly 表指针偶发为空（已加 CDO 兜底，根因待查）。
