## 学习目标

用现有测试与验收命令定位问题，区分源码推导、自动化测试和双端实测。

## UE 概念

单元测试能覆盖序列化、状态机，不能证明真实延迟、丢包和画面平滑。P95 是样本百分位，不是最坏延迟保证；必须同时记录样本数、链路配置、帧率与运行环境。

[StartNetworkGate](D:/UE5.7/test1/Source/GuLiStrike/Commander/Framework/GuLiCommanderNetworkGateCommands.cpp) 注册 `gs.Commander.NetworkGate 20`。它扫描第一个 NM_Client 的本地 CommanderPlayerController，而非直接使用控制台传入 World；再要求该玩家是已就绪 Commander。因此建议新建 Listen 两端会话，保留一个远端指挥官，避免先找到 Air 客户端。命令会改变选择与移动、使用较大请求编号，运行后重开会话再做普通输入验证。

仅在远端客户端设置以下合法组合；收到最终结果前不要重置：

```text
NetEmulation.Off
NetEmulation.PktIncomingLagMin 85
NetEmulation.PktIncomingLagMax 115
NetEmulation.PktLoss 5
NetEmulation.PktOrder 1
gs.Commander.NetworkGate 20
```

入站延迟提供约 100 ms 往返贡献与 30 ms 范围，出站设置丢包、乱序。不要再加出站 PktLag：UE 的 PktOrder 分支会优先处理，可能使配置数字看似齐全却没有实际出站延迟。结束后在相关 World 执行 NetEmulation.Off。

[CanPass](D:/UE5.7/test1/Source/GuLiStrike/Commander/Framework/GuLiCommanderNetworkGateValidation.cpp) 实际代码节选：

```cpp
&& Evidence.AckP95Milliseconds <= 150.0
&& Evidence.BandwidthSampleCount > 0
&& Evidence.BandwidthAverageMegabits <= 1.5
&& Evidence.BandwidthP95Megabits <= 2.0
&& Evidence.FreshPoseFrameCount > 0u
```

还需收齐目标移动 ACK、至少 20 个表现步进、相对观测起点位移达到 300 cm、步进 P95≤100 cm、有效时钟 RTT、种子士兵最大样本间隔≤0.5 秒、未标记硬跳变为零。链路须有 RTT≥100 ms、抖动≥30 ms、丢包≥5%及乱序证据。带宽来自客户端总入站 InBytesPerSecond；只有最终 `Commander network gate PASS` 才算通过，commands-collected 不够。

## 实测状态与易错点

2026-08-31 公共框架归档记录冷编译及 50/50 现有测试通过；本次文档修订仅做静态核对，没有重跑这些测试。Listen 两端指挥官身份、名册与同席复活通过；Fly01 原生销毁后同席复活，恢复移动与纠正；母船弱网换装和 GM 参数收敛，双方观察到 17 枚服务器弹丸，松键及原生失去占有后停火。独立客户端完成原生无缝战局重建和身份恢复；Ground 注入移动、两端可见、同席复活和比赛结束取消复活通过。混合会话填满 10 席，额外玩家被拒绝为观察者。这些冒烟结果不能代替完整键鼠与画面验收。

**NetworkGate 尚未整体通过**：首轮后台节流使环境无效；60 Hz 轮 ACK P95=159.9 ms；120 帧上限轮 ACK P95=146.4 ms、未标记硬跳变为 3；最终原生触发复测 ACK P95=138.1 ms、硬跳变仍为 1。切图、重连和其他未覆盖情形以[公共框架实现归档](D:/UE5.7/test1/Progress/Archive/20260831-公共战局框架与三类角色接入.md)的独立结论为准。不能只挑通过的指标宣布成功。

| 症状 | 优先查看 |
|---|---|
| 公共就绪卡住 | EnsureServerConnectionBootstrap：身份、代次、GS/PS 到达 |
| 指挥官不能下令 | CanProcessCommanderRequest：双门、角色；HandleMoveRequest：序号、选择版本 |
| 士兵无动作或跳变 | ClientReceiveSoldierPoseChunk、IngestPoseChunk、InsertPoseSample |
| 飞船不能动/反复纠正 | AcknowledgedPawn、ClientRestart、配置/装配屏障、SavedMove 回放 |
| 换装不完成/不开火 | ApplyReplicatedLoadout、CanAcceptServerIntent、武器冷却 |
| GM 目标已改而预测未变 | NotifySoldierMovementSpeedCommitted、配置提交与确认 |

## 练习与答案

1. **理解题：20 个 ACK 全成功就通过吗？** 不够，还要链路、带宽和表现证据达标。
2. **理解题：P95=146.4 ms、硬跳变 3 次能通过吗？** 不能，硬跳变要求为零。
3. **源码题：只设丢包、不设延迟抖动是否有效？** 查看 MeetsRequiredImpairment，不能；也应确认实际操作的是远端客户端 World，而非另一个 Standalone 或 Air 视角。
