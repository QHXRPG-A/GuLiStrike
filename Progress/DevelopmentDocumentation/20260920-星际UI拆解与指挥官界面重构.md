# 星际UI拆解与指挥官界面重构 — 技术方案

## 架构

原生HUD协调子面板，项目WBP保留入口和布局资产；展示快照将确认选择、可靠单位／工程车状态与本地查看类型分离。原生UI只产生操作意图，任务和能力仍由现有业务执行。保留Slate地图缓存、既有刷新频率与角色边界。

头像RPC仅允许对当前服务端合法选择做组选择／组减选／类型过滤；共用可靠序列和连接代次，协议15→17。展示层按兵种、Mass／Actor身份和稳定ID排序，每25名同类成员生成一个头像组；客户端只提交组内锚点，服务端从当前确认选择重建相同切片。24控件分页，类型／页码不改变命令成员。Q保持全部选择。模态菜单独占本地输入，普通装饰不拦世界点击；销毁清理所有绑定。

## 头像分组与日志复核补充

- 去掉头像格内 `#稳定实例ID`，每格只显示兵种头像和本组人数。同兵种超过25名时按稳定顺序拆成相邻组；不足25名显示实际人数。组血条使用组内当前生命／最大生命合计，避免用任一代表成员冒充整组状态。
- 头像悬停说明置空，不再显示“兵种·实例ID、生命、单击／Shift／Ctrl操作”。单位详情继续通过生命、护盾、速度、防御和载货图标加数值表达属性。
- 单击和Shift点击分别提交 `SingleGroup`、`RemoveGroup`；Ctrl和Ctrl+Shift仍按完整当前选择执行同类保留／移除。服务端不接受客户端成员数组，按锚点兵种及稳定排序重建最多25人的切片。
- 日志中的 `GULI_ACCESS_RAMP` 是22.8°地面超过15°建筑坡道限制后的保护性禁用；HTTP／EOS告警来自本机 `127.0.0.1:7890` 代理连接，不是HUD逻辑失败。
- `Authority pose discontinuity` 出现在建筑落地引发动态导航修复之后。导航修复会把位于新阻挡范围内的单位投影至合法导航点；旧实现未将这种权威重定位写入位移事件。现已在超过一个固定模拟步的修复位移上设置 `DisplacementFrameFloor`、位置和时间，使客户端按离散重定位处理并跳过连续运动误报。
