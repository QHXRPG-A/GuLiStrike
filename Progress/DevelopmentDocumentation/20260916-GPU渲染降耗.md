# GPU渲染降耗 — 技术方案与实施

## 实现边界

- 共用策略只由目标单位的表现路径调用，无复制字段或玩法权威变化，无逐帧策略遍历。
- 项目材质变体保留原图形节点，仅在最终粗糙度连接增加max(原值,0.8)。僚机复制项目父材质及材质实例，避免修改共享Interchange父材质。
- 原材质→变体映射由配置维护，运行时共享加载缓存并由UObject引用保活，不逐士兵创建MID。专用目录显式加入Cook范围。
- 初始化/复用/车辆子Actor重建应用；传送缓存恢复优化后的身体材质，受击使用原有叠加材质，残骸保留专用效果材质。
- 配置集中于DefaultEngine.ini，使用高于Scalability的SystemSettings优先级，实际值须从运行日志/编辑器查询核对。

## 配置目标

| CVar | 值 |
|---|---:|
| r.AntiAliasingMethod | 1 |
| r.VolumetricFog | 0 |
| r.Shadow.Virtual.ResolutionLodBiasDirectional / DirectionalMoving | 0 / 0 |
| r.Shadow.Virtual.ResolutionLodBiasLocal / LocalMoving | 1 / 2 |
| r.Lumen.ScreenProbeGather.DownsampleFactor | 32 |
| r.Lumen.ScreenProbeGather.RadianceCache.ProbeResolution | 16 |
| r.LumenScene.DirectLighting.UpdateFactor | 64 |
| r.LumenScene.Radiosity.UpdateFactor | 128 |

保持VSM覆盖和物理页容量、Lumen GI及异步调度。软件VRS最终保留开启：r.VRS.EnableSoftware=1、r.VRS.ContrastAdaptiveShading=1。

## 实施结果

- A组六轮完成，负载达标且服务端零丢步。新基线较此前报告更慢，最终收益仅以本轮A比较。
- 4个父材质、9个僚机MIC、12条原材质映射已创建；父材质编译通过。两类士兵运行时材质及5项排除标志已核对。
- 源码Editor/Game最终重编通过，7份BuildId一致。37项已有回归为32成功、2成功带提示、3失败；实际重新编译修改前源码后，复现相同3项错误（建筑定义ID、网络包大小、僚机攻击通道），不能标记全通过。
- B/C按每轮每种客户端数量交替采集，27份客户端样本、18轮服务端全部完成。所有优化后样本通过负载和P95门槛，服务端零丢步。
- GPUTime改为CSV行与同次ticker帧对应的共同30秒；行数相等，并检查零帧偏移的帧时间误差最小。整段40秒结果并列保留。trace原生Frame含队列空闲，不拿来替代GPUTime。
- B/C第三轮双客GPU约7.9～8.0ms，前两轮约16.3～19.1ms，存在明显轮间波动；完整CSV绘制图元/DrawCalls/实例数相近，未剔除样本。缺少连续GPU时钟和全机竞争记录，收益仅代表本轮中位数，不能保证跨时段幅度。
- 单客/双客C1/双客C2 GPU：A为9.204/23.318/22.223ms，最终B为6.334/17.344/18.405ms，下降31.2%/25.6%/17.2%；最终整帧P95为13.212/25.010/26.199ms。
- C关闭VRS后双客更快，但单客GPU比B恶化16.25%，不满足三个组合均改善至少3%的约定，因此保留VRS。
- TSR、体积雾事件在B/C消失，C的ContrastAdaptiveShading消失。LumenScreenProbeGather保持异步；事件跨度不用于相加估算收益。
- Visibility平均等待由3.944/18.301/17.040ms降为2.927/12.783/13.894ms；既有GPU遮挡查询依赖仍在。ShadowDepths反而由1.136/2.853/2.684ms变为1.167/3.092/3.203ms，后续需要地形/环境逐对象归因。
- 矿车/工程车初建与重建，各8个网格的身体材质/反射标志均正确，发光效果槽保留；主飞船仍引用原材质。13个新材质资产保存在项目专用目录。
- 同镜头截图显示金属高光减弱、细轮廓和阴影边缘更粗。远处移动/旋转单位抽样未整体消失；截图会打断渲染，不能证明无时域闪烁或覆盖快速转镜头的GI收敛，动态画质仍为partial。
- 编辑器恢复原关卡、镜头和最终B配置，清理临时预览且未保存地图；无脏资产/地图。
