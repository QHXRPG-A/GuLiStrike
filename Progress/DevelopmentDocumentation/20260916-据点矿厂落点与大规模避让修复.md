# 据点矿厂落点与大规模避让修复 — 技术记录

## 根因与方案

1. R3C4 入口高出矿厂中心 1190.606 cm，旧地面射线从中心 +500 cm 向下，起点已在入口地面以下。中心点通过不代表占地和入口可用；失败后的 `checkf` 为直接崩溃点。相关旧代码早于导航预烘焙。
2. `GuLiBuildings::Spawn` 在生成任何 Actor 前采样 footprint，并读取矿厂实际 Blueprint SCS 坡道模板。`ResolveGroundEdge` 同时服务于预检和 BeginPlay；无效坡道关闭碰撞、可见性和导航相关性，记录原因，可在地面恢复后重新拟合。
3. 原槽位先试，半径 7000/10500/14000/17500/21000 cm、八个方向、四种朝向构成有限候选，按距离稳定排序。每槽每 tick 最多四次，搜索中 0.2 s 继续，完整失败后保留原重试机制。成功永久标记，换主不重复生成。
4. 原压测期两套 NavData 剩余构建任务全为零；Insights 的 99.7% CrowdManager 时间落在 proximity。Detour 对 `collisionQueryRange == 0` 的 Mass 代理重复生成零半径墙体缓存。引擎补丁在代理进入空间索引后跳过其自身邻域查询；正半径工程车继续查询并避让全部代理。
