# Mass权威数据迁移与千单位对比

当前重复发布方案是本轮基线，不能使用上一轮历史数据代替。权威记录移入 Mass Fragment，移除副本同步。保留原主动侧绕、0.5 秒让路、同命令不让、只向同等或较大单位让路、下步传递请求、按 SoldierId 顺序即时更新圆索引。既有 NavMesh 修正及时间预算保留，不启用官方 Mass 避障。

## 实施与测量

- [x] 500、1000 移动单位；对穿与静止人墙；每组 3 次 30 秒。12/12 有效，证据 baseline-qualified.json。
- [x] 基线采完后迁移权威记录；核对导航、侧绕、让路函数及提交先后。
- [x] 源码版 GuLiStrikeEditor Win64 Development 构建，重跑同一快照。
- [x] 报告逻辑步均值、P95/P99、活动单位成本、实际活动数量、侧绕/让路工作量及轨迹差异。
- [x] 保存 `/Game/Maps/LVL_CommanderMassPrototype` 玩家入口并读取实体数据；视觉和手感由玩家判断。

大数量负载通过一次性 PIE 准备入口生成，保留原 632 单位开局。新增单位在当前进程本地模拟，走正式实体初始化、寻路规划、侧绕、让路与位移提交；新增负载不参与 Hybrid 网络分发，因此比较限定为移动 CPU 数据管线，不用于推断千单位网络吞吐。计时窗口外准备与预热，冻结位置、ID、命令与画质。

无零穿透门槛。耗时是否改善根据同版重复波动判断，不能把未移动或停住计作优化。时间预算导致的规划完成步变化与算法变化区分记录，不因函数文本一致宣称轨迹完全相同。

证据目录：`Artifacts/MassAuthority20261111`。

## 本轮基线

1000 对穿均值 7.653/7.875/7.768 ms，平均活动 825–864，峰值 1004–1007；1000 人墙 8.584/8.251/8.583 ms。500 对穿 4.461/4.310/4.678 ms；500 人墙 5.016/4.940/5.025 ms。额外移动负载为先驱号，实际圆半径 300 cm，使用已投影 NavMesh 的冻结位置，初始网格间距 900 cm。最初准备失败和重叠摆放样本单列保留，不计正式基线。

## 实现与结果

`FGuLiMassSoldierRuntimeFragment` 原样接收原单位运行时字段。目录只保留句柄和访问地址，移动步开始按 chunk 取得地址，再按原 SoldierId 顺序直接读写 Mass。移除权威 Transform、Velocity、Health、Stats、Order 副本、官方障碍网格组件及批量回写流程；客户端表现镜像和 StateTree 固定身份仍服务现有职责。Hybrid 序列化字段顺序和版本不变，恢复时保留本地目录索引。

实体/共享参数切换时更新目录地址；拥有数组和共享路径引用的 Fragment 使用 UE5.7 的明确非平凡类型声明，沿用原 TArray 的可重定位语义。没有新增移动回退、冷却、让路门槛或方向规则。

四组主线程均值（ms/10Hz逻辑步）：1000 对穿 7.765 → 7.544，1000 人墙 8.473 → 8.227，500 对穿 4.483 → 4.169，500 人墙 4.994 → 4.727。仅最后一组的 -5.3% 超过本轮重复极差，其每活动单位成本约下降 4.4%；其他组保持“未超出重复波动”的结论。

500 对穿有两轮新样本与旧版第一轮的完整 300 步位置/状态哈希一致（坐标精度 0.00001cm），圆检测、桶访问、方向探测、让路工作量分布相同。其余样本仍存在原有墙钟下令相位与导航预算造成的轨迹差异；旧版同场景自身也在第 6 步出现 300/0 个活动命令的差异。长时间往返和拥堵两版都有，本次保持算法，不宣称已解决。
