# 飞行物批量启停同步与实际时间网络预算 — 实施记录

## 实现

| 边界 | 文件 / 行为 |
|---|---|
| 连接额度 | `Battle/Network/GuLiIpConnection.*`；Tick 后按实际驱动时间和发送字节恢复，100ms 限制、分数位累计及诊断开关；`DefaultEngine.ini` 指定连接类 |
| 统一载荷 | `Gameplay/CombatEffects/GuLiFlightEvent.*`；精确位编码、批次长度、种子、冻结运动、可选目标、枪口和终止表现；协议 24 |
| 可靠启停 | `GuLiFlightReplication.cpp` 与 ReplicationComponent；每连接可靠队列服从正常预算，新通道一次性补建，周期状态只维护服务器本地注册表 |
| 客户端池 | `GuLiFlightVisualActor.*`、`GuLiClientFlightPresentation.cpp`；直线按时间求位置，固定 30Hz 曲线预测，Ship 本地静态几何反弹，复用原 Niagara / 激光 / 导弹批次池 |
| 攻击入口 | 指挥官数据弹池、Ground 武器、逻辑导弹、Ship 物理弹丸与僚机公共效果运行时；伤害始终由服务器提交账本 |
| 验收入口 | `GuLiFlightAcceptanceSubsystem.*`；显式服务器 `gs.Flights.Load 500 30` / `gs.Flights.Stop`，默认休眠；Editor `gs.Flights.PIE` 提供真实 Commander/Ground/Air/Commander 席位；`Scripts/FlightEvents/prepare_sources.py` 安装真实机库并启动负载 |

连接开关 `guli.Net.RealTimeBudget` 默认 1，诊断 `guli.Net.BudgetDiagnostics` 默认 0；飞行通道诊断 `guli.Net.FlightDiagnostics` 默认 0。保留服务器检测频率：Commander 直线弹 5Hz、其他数据弹及曲线效果 30Hz；这些频率不再对应网络飞行快照。

## 运行记录

原生 `GuLiIpConnection` 1608 条样本最大恢复偏差 0.002507%，债务差异 0；1.124736 秒卡顿恢复 100ms / 200000bit。406 单位双客户端无开火的开关隔离对照各约 30 秒，开启后最老待发姿态年龄 P95/最大值均 0ms；场景未饱和，不计算虚假的百分比提升。

Dedicated + 四客户端 30.031 秒观测，四域每域 125，普通战斗叠加峰值 508。飞行启停 RPC 每客户端 19449.72B/s，旧飞行快照/纠偏/Actor 复制为零；整套表现子系统更新 P95 为 1.22–1.48ms/客户端；池扩至 768 后复用，专服池 0，结束后活跃归零。该观测的单位 roster 为 2，四连接待发姿态 P95 为 0ms。实际整体 18.21Hz，不拿四客户端同进程结果承诺 FPS 提升。

第五客户端中途加入一次性补建 500 枚，各域 125，没有旧枪口重放。真实 Ground 开火 59 次，各客户端对应机甲表现 59 次；初次 Python 客户端入口没有真正发出 RPC，最终用服务器入口验证生产与表现，不冒充输入链路验收。来源销毁后已有飞行继续、回收正常。障碍测试服务器反向物理弹丸峰值 24、四客户端反向网格各峰值 31，客户端物理弹丸 0。

17 项唯一原生回归最终通过。首次旧表断言失败，核对现表后只修测试：WM01 半径 300cm、原扫荡者 ID 5；旧导弹 RPC 合约更新为统一可靠批次。Epoch 为可回绕的不透明标识，服务端对当前战局判等，客户端拒绝已退休标识；不再按数值大小判断新旧。见 [测试报告](../../TestResults/FlightEvents20261004/REPORT.md)。

增加单位的初次准备叠加关卡自动增援，触发 `GuLiGroundCrowdManager` 现有 1024 代理容量断言。该会话没有形成合格性能采集；重新打开 Editor，改用受控单位布置，不扩大原避障容量。该失败须与飞行物 500 负载区分。
