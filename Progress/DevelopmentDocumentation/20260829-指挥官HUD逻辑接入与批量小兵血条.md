# 指挥官 HUD 逻辑接入与批量小兵血条 — 技术方案

- 对应需求：[指挥官 HUD 逻辑接入与批量小兵血条](../RequirementDocument/20260829-指挥官HUD逻辑接入与批量小兵血条.md)

## 技术选型

- HUD 使用 UMG 布局 + 原生 `UUserWidget` 基类；权威数据通过原生委托推送，比赛时间和小地图分别使用 1Hz/10Hz 单一 Timer，不使用 UMG Tick 或属性 Binding。
- 战术地图使用一个原生自绘控件批量绘制单位点与视野框，不创建大量 UMG 子控件。
- 世界血条使用独立本地 Actor 上的单个 ISM、Engine Plane 与 UI 材质；它只读现有插值 Transform，避免改动性能任务的 PresentationActor。
- `Health/MaxHealth` 继续走可靠 Soldier FastArray；PoseChunk 结构保持不变，协议版本显式升级。
- Commander 继续沿用当前直接 `BindKey` 输入栈，本轮不迁移 Enhanced Input，避免扩大输入资产与 Config 范围。

## 涉及模块

| 变更点 | 路径/类 | 类型 |
|---|---|---|
| HUD 生命周期与世界反馈 | `Commander/Presentation/AGuLiCommanderHUD` | C++ |

| 运行时布局 | `/Game/Commander/UI/Widgets/WBP_CommanderHUD` | UMG |

## 实施结果

- `AGuLiCommanderHUD` 负责创建和销毁运行时 `WBP_CommanderHUD` 与本地血条渲染器；Canvas 只保留世界选区圆和命令反馈线。
- `UGuLiCommanderHUDWidget` 以原生委托和低频 Timer 刷新队伍、角色、同步状态、比赛时间、编队卡、ACK 与存续兵力；目标、比分、战术点和能量继续明确显示为未启用状态。
- `UGuLiCommanderMiniMapWidget` 以 10Hz 批量快照绘制地形、双方存活兵、选中强调和相机视野框，并通过透明地图按钮消费点击和执行跳转。
- `AGuLiCommanderPlayerController` 新增本地 `Select/Move` 工具状态，落实 `1/7/+`、一次性移动、右键立即移动、Shift Toggle 和 Esc 两阶段行为；已确认选择失效时自动退回 Select。
- `FGuLiSoldierStateItem` 增加可靠 `MaxHealth`，协议升级为 v3；权威快照在比较/复制前统一 Sanitize，`SnapshotRevision` 使用 RepNotify 且跨 MatchEpoch 单调推进，通过 `OnSoldierStatesChanged` 每次事实快照批量通知一次。
- `AGuLiCommanderHealthBarRenderer` 使用一个本地非复制 ISM、稳定 SoldierId 实例索引和 PerInstanceCustomData 绘制世界血条，不创建逐兵 Actor、Widget、WidgetComponent 或 Tick。显隐使用相机焦点 300m 平面距离，像素尺寸使用真实镜头距离；避免 RTS 高空相机把全部实例硬裁掉。
- `WBP_CommanderHUD` 已重设为原生 HUD 基类，并加入移动、选取、选取尺寸和小地图点击透明按钮；布局继续保持零 EventGraph、零绑定、零 MVVM、零动画和零 Blueprint Tick。

## 风险与备忘

- 工作区包含既存性能/导航/数据脏改动；所有补丁必须先回读，禁止回退或格式化无关代码。
- C++ 编译前关闭编辑器；资产编辑只允许一个 `-NoLiveCoding` 编辑器实例并逐包保存。
- `WBP_CommanderHUD` 被 Review Board 嵌套使用，原生初始化必须在 Design Time 或无 OwningPlayer 时保持静态视觉。
- 协议 v3 与 v2 不混用；不提供旧客户端兼容分支。
- 性能结论只有在固定地图、画质、分辨率、预热和采样窗口下达到门禁后才能标记完成。
