# 绿色引导线实时连接优化 — 技术方案

## 实现

表现Actor新增非反射只读C++接口`TryGetPresentedSoldierModelCenter(SoldierId, OutCenter)`。按当前实例的实际`BatchUnitTypeId`读取已缩放的模型/VAT包围盒，并用`TryGetPresentedVisualTransform`的朝向和位移（含预测、机械转向与悬浮）转换中心。使用`TransformPositionNoScale`避免再次缩放。缺少模型定义、有效表现或包围盒时返回false，不把地面原点冒充模型中心。

RouteLine组件在BeginPlay把所属表现Actor注册为Tick前置依赖，EndPlay解除依赖与事件绑定。每个PostUpdateWork帧先刷新全部已显示线，起点读取当帧模型中心，终点沿用`FinalDestination`。当前服务端普通移动把该字段写为共享`MoveIntent->Click`；没有改变服务器导航、随机站位、目标复用阈值或协议。

新增线另按128条/0.5ms预算消费队列，计时从跟随刷新完成后开始。已显示线不重新排队；订单/端点版本改变时先隐藏旧线，再接入新线。缺失表现的ID存入独立等待集合，每帧检查恢复，并在取消选择、移除、重置或失效时清理。待绘制计数包含该集合。诊断改为检查模型中心、订单/版本与有效目标，不再把下令起点当成移动中的线起点。

沿用原有分块和不可变渲染提交，只标记本帧发生变化的块；绿色线型及网络数据结构保持。2026-10-04追加专用材质接入，详见下方遮挡修复。

## 玩家操作与预期

加载本次原生代码后，由玩家自行在该Map进入真实指挥官玩法：

1. 把本方单位移到`QA_GreenGuideLine_Start`附近，按S停止，再选单个单位向`QA_GreenGuideLine_Goal`下移动令；近景观察模型中心跟随，以及转向/绕行期间目标端保持。
2. 对重防号重复操作，观察悬浮高度与转向时单位端仍连接模型中心。
3. 选择至少150名单位向合法目标移动；允许新增线分批出现，出现后的所有线应逐帧跟随。
4. 途中先点很近的目标，再点`QA_GreenGuideLine_RejectedGoal`，按当前目标复用/拒绝规则保留旧线；对相距明显超过当前复用阈值的可达位置改令后切换到新目标。
5. 取消选择、重新选择、按S停止及等待到达，分别确认隐藏、恢复与结束行为。
6. 从TerrainStart向TerrainGoal下令，近景/战术镜头及TerrainOverview低角度观察跨坡线；让山坡处于绿线与镜头之间，预期整条绿线仍连续可见。对单兵、重防号及至少150单位重复，同时复查前五步的模型中心、有效目标和隐藏行为。

场景保存与实体数据核对只证明布置正确，不等于运行效果验收，也未测量逐帧更新的运行耗时。
