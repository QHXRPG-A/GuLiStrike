# Hybrid状态应用耗时优化 — 技术方案

## 技术选型与边界

保留正式入口、序列次序与既有步频，优先消除同一步内重复计算及查询。缓存须按真实输入或修订失效，禁止跨身份、World 或所有权代次复用。内部实现不增加 Blueprint 公共 API。当前新增 Trace 范围不更改 `state_apply` 分类。

## 第一批正式实现

- AsyncClient 主线程增加有容量上限的对象地址缓存与 adapter token 缓存。每次命中比较完整对象身份；地址来自保留墓碑的有序目录，权限、Frozen、Dormant、OwnerEpoch 和生命状态仍实时读取。adapter 释放先撤销 token 缓存；不缓存查询失败。
- 保留每一个对象逻辑时钟更新，只在实际到期回调周围设置应用上下文；`NeedsAdvanceOnMain` 仍在原对象上下文中调用。
- Actor 绑定复用所属 World 的弱引用；绑定修订和 Actor 销毁检查保留。
- 组件缓存改为比较当前组件序列与完整弱身份、类型和名称；替换、改名、类重建和容器重排都会触发重建，回调继续持有不可变绑定租约。
- 单位任务 generation 直接读取同一 Hybrid 身份；工程单位及未登记对象保留原身份解析。任务已完成时先短路，避免重复权限查询。
- 工程移动与军队推进读取轻量导航状态，移除仅供诊断的 NavMesh NodeRef 校验；导航诊断接口原样保留。已建立的工程 Mass 实体不再重复查创建条件。
- 没有调整步频、任务轮次、碰撞射线、弹丸数量、地图、画质、命中规则或 `state_apply` 分类。
