## 初始静态诊断（下方运行时结果区分已证实项）

1. **首要嫌疑：偏移叠加后急退。** `ApplyPrediction` 在持续移动的权威插值基准上增加 SmoothStep 位移，又在 0.15s 撤销。默认 3600cm/s×0.25s=900cm，消退峰值额外反向速度为 9000cm/s；即使权威保持 3600cm/s，合成速度仍能反向。公式已计算，不是 PIE 结果。
2. **收样本与播放时间不一致。** `InsertPoseSample` 收到匹配 ActiveOrderId 就开始收敛，而 `RebuildLocalInstances` 求值服务器估计时间减 100ms。样本已到不等于画面已播放到新命令。
3. **连续命令丢弃旧偏移。** `BeginPredictedMove` 从当前显示位置算新方向后将旧预测结构清零；可能形成命令切换帧的位置不连续。
4. **本地与服务器轨迹不同。** 本地朝点击点直行，服务器走 NavMesh 共享路径、编队槽位、避让和加速；起步、转弯、拥堵、投影停速会放大误差。
5. **数据流可能放大停走。** 姿态目标 10Hz，分三个模拟步发送；100ms 插值/外推窗口在抖动、丢包时可能耗尽。三次插值只检测 NaN，没有一般过冲限制。
6. **高移速条件风险。** `CalculatePredictionDistance` 的第三参数是 fallback，不是硬上限；1000cm 硬校正使用包含预测的显示位置与新样本比较。高移速/反向命令更容易出现大差值。

修改前的 `NetworkGate` 直接 SubmitMoveRequest，绕过了旧 PC 内的预测入口，且主要在全部 ACK 后采样。本次主代理已将预测绑定到 `OnMoveReadyToSend`，因此直接提交也会触发预测；历史 PASS 仍不能代替新的真实鼠标和选择排队链验证。

## 风险与备忘

- `input` 是预测实际开始边界，`mouse_input` 才是 PC 鼠标入口标记；两者都不单独证明 OS 硬件注入。真实 Slate/鼠标验证要保留来源证据。
- `authoritative` 是客户端对服务器样本时间线的求值，不是同一时刻直接读取服务器位置。转向时沿点击方向的速度可合法为负，需结合服务器轨迹或仅表现反向指标判断。
- 默认只记录一兵；选择多兵后需明确固定 SoldierId，不能跨 A/B 混用不同单位或不同初始状态。
- no_offset 仅用于归因测试，不作为正式修复。后续若确认主因，应优先保持换令连续、对齐渲染交接时刻、按残差和受限纠偏速度收敛。
- 不宣称“已消除拖拽”；已实测归因，但默认移动算法未修改。

## 2026-08-31 运行时结论

### 条件与可信边界

Dedicated Server + 两个独立 PIE 客户端，红方 `UEDPIE_1`、500 兵，本次观察 SoldierId=55；蓝方存在但未混入本次单兵 A/B。真实 Slate `ProcessMouse*` → PlayerInput → PC 鼠标标记 → NetSync 选择依赖就绪 → BeginPredictedMove 全链路。每轮实际 3 个 mouse_input 和 3 个 input，未用直接 SubmitMoveRequest 冒充鼠标。

主代理为消除旧边缘滚屏在测试窗口失焦时移动相机的干扰，只临时固定两客户端相机 Actor tick/位置，服务器与小兵未冻结。环境证据在 `network-camera-fixture-v2.json`；这些 PIE 变更不落盘。A/B 之间正常走回，起始距离仍分别差 337.72cm、299.71cm，不能解释为严格同状态的统计实验。

正常网 ACK 约 16.67ms。弱网仅红客户端设置 outgoing 250ms + incoming 250ms，双向各 5% 丢包，`editor-runtime-final.log` 明确打印五个值，实测 ping=532.14ms。采样结束全部清零并记录 `PredictionTrace is inactive`，恢复后 ping=15.75ms。正常 Stop 的覆盖恢复已实证；超时/EndPlay/重连路径只有代码检查，不能写成全部运行验证。

正常网 6 次命令中，resolve 比 render_handoff 早约 33.33–100.11ms。首命令在 input 后 50ms 收到匹配样本并开始回收，到 116.67ms 才达到其渲染时间点。这是“收到样本就回收，而画面还没播放到”的实际时序证据。

弱网首版采样出现 2 次 replaced_prediction，每次都在 input 后 250ms 开始超时回收。ACK 晚于短命预测寿命，旧记录器在 PredictedMoves 循环中漏记，因此首版弱网 CSV 的 ack=null **不能解释为 ACK 丢失/拒绝**。现已增加独立 256 条命令历史，按真实 CommandId/cohort 去重记录迟到 ACK；不改变原预测生命周期。补强后的冷编译与复采另附。

### 根因优先级与最小改进建议

1. **已实证，主要原因：固定偏移叠加在权威基准上，再快速撤回。** 默认 `.25s` 的 900cm 前移与 `.15s` 撤回，不考虑权威目前是否已经向前走。正常网和弱网 no_offset 对照都移除了额外回退。证据代码 `GuLiCommanderPresentationActor.cpp:1417–1489`；默认参数 `GuLiCommanderPresentationActor.h:353–360`。下一步应从显示位置相对同一渲染时刻权威位置的剩余误差收敛，并限制纠偏速度；本次不改算法。
2. **已实证，弱网换令放大器：旧预测结构直接清零。** `BeginPredictedMove` 中 `Prediction={}` 丢弃尚有的 524.69cm 偏移；CSV 两次边界权威不动但显示跳跃。下一步新命令应承接上一帧显示位置/误差后再转向，不能把新命令当作位置重置。
3. **已实证，正常网起步放大器：样本到达与渲染交接错位。** `InsertPoseSample` 的匹配命令逻辑在到达时启动回收，渲染端另有 100ms backtime。下一步将交接对齐对应命令进入渲染时间线的时刻；仍需处理过期和拒绝，不可无限保留预测。
4. **已有权威时间线跳变证据，具体原因仍待区分：弱网插值/外推耗尽与服务器转向。** no_offset 仍出现两轨一致的跳步与沿新目标反向的旧速度。当前 CSV 的 authoritative 是客户端求值，不是同帧服务器 transform，因此不能把这些都判为服务器寻路问题。需进一步同时记录服务器固定步状态/包间隔。
5. **静态候选：本地直线、服务器导航/编队/避让不一致。** 服务器 `GuLiBattleAuthoritySubsystem.cpp:49–51,357,1788–1797` 使用 0.7/0.3 混合、导航点、避让与速度插值。本次未凭地图外观宣称绕障；下方已补一条现有 3 点 NavMesh 路径的实测，仍未证明转弯处的预测穿墙或路径求解缺陷。

仍保持约 532ms RTT、改为 0% 丢包，初始只选 55。真实点击 66 完成后立刻真实右键：after-click 与 after-right 快照仍选中 55，最终权威快照变为 `[66]`。自动绑定的实际 input 行 `soldier_id=66,command_id=15`，mouse_input→input 等待 **333.822ms**，5 项检查全过。说明本次移动等选择依赖就绪后才预测正确单位，没有用旧 55 集合开始预测。旧 55 两次显示快照的净变化为 5.83cm（不是累计路程）；未单独记录其完整权威轨迹，不能解释成已确认的权威微调。两个 QA 命令启动相隔约 295ms，证明选择仍未确认时紧接移动，不代表同帧/下一帧极限输入已经覆盖。

### 测试工具问题与修复

旧直接 RoutePointerMove/Down 路径可把按键状态送达 PC，却在按下/释放帧丢失 GetMousePosition；隐藏嵌入 PIE 窗口也干扰真实鼠标。测试工具改为标准 ProcessMouse*，检查窗口 visible 并 BringToFront，独立 PIE 已完成单次选中验证。没有修改生产 cursor 跟随行为。

首版 A/B 驱动的 Escape 在独立 PIE 被编辑器全局退出消费，导致该轮在采样前退出；当即通知主代理重启，失败 `ab-default/manifest.json` 保留，不算运行时移动证据。驱动已彻底移除 Escape。对同一集合重新点击不必增长 selection_revision，后续等待改为明确收到新 ACK 或新 revision，避免把旧选择副本当作新请求完成。
