# Ship 僚机三维往返缠斗与随机转向 — 技术方案与验证

- 对应需求：[Ship僚机三维往返缠斗与随机转向](../RequirementDocument/20260907-Ship僚机三维往返缠斗与随机转向.md)

## 最终架构

编队级 `FGuLiWingmanBehaviorStateTreeRuntime` 保留原职责，以 10Hz 决定 Formation、CatchUp、Recover、Emergency、Stale 和 Dead。每架 Mass Entity 的 `FGuLiWingmanAttackFragment` 增加轻量 C++ 攻击状态、转向计划、冻结远离点和入口序号；`TickAttackRuns` 在 30Hz 固定步只发布 `PreferredVelocity`。安全/分离处理器继续修正引导，`FlightIntegration` 仍是唯一 Transform/Velocity 写入者。

Emergency、受控恢复、死亡、租约或配置屏障失效先调用攻击取消：清空个体引导和待发记录，并设置 1 秒重试。攻击层不会覆盖编队恢复决策。地面攻击已进入 Dive/PullUp/Climb 后沿冻结路径完成本轮，再在回到 Idle 后消费最新目标状态。

## 个体对空状态机

| 状态 | 入口/行为 | 退出 |
|---|---|---|
| `AirApproachFire` | 45m/s朝实时目标闭合；仅此状态允许排队机枪记录 | 距离≤目标半径+僚机半径+300m时采样远离点并进入脱离转向 |
| `AirBreakawayTurn` | 沿随机控制点转向；控制点、远离点在入口冻结 | 距控制点≤75m、越过控制点平面或满10秒后进入 `AirRetreat` |
| `AirRetreat` | 直接前往冻结远离点 | 距远离点≤75m或越过到达平面后生成新的随机折返控制点 |
| `AirReturnTurn` | 沿新控制点折返目标 | 到达/越过控制点或满10秒后回到 `AirApproachFire` |

`NextAirDogfightPhase` 固化合法顺序，`CanQueueAirGun` 将开火阶段收窄为 Approach。10 秒超时直接推进到目的地引导：脱离转向超时后直飞远离点，折返转向超时后直飞实时目标。

## 确定性随机与三维区域

`MakeAirManeuverSeed` 依次混合 `AgentSeed / TargetRevision / AirStateEntrySerial / ClientTick / PhaseSalt / CandidateIndex`。同一入口与候选可复现；不同实体、目标版本、轮次和转向类型不会共用随机流。

`BuildAirTurnPlan` 先取目的地方向，再随机左右 40°–90° 偏航和 −30° 至 +30° 俯仰。物理转弯半径按 `Speed / radians(MaxTurnRate)` 计算，控制点距离固定为两倍半径；默认 4500cm/s、20°/s 得到约 25783cm。正常攻击飞行仍以最大转向率逐步改变真实速度方向；只有速度已降为0的导航脱困允许瞬时对准冻结逃逸方向。

`BuildRetreatCandidate` 以 `Target → Ship` 为走廊轴，纵向为走廊长度的随机 35%–60%，再取不小于 `max(45000cm, BreakawayBoundary + 7500cm)`；横向/垂直用单位圆盘均匀采样后分别缩放到 15000cm/10000cm 椭圆。走廊短于下限时纵向自然越过 Ship。

每次脱离入口最多生成 8 组候选。`AirSegmentClearsWorld` 对“当前位置→控制点”和“控制点→目的地”同时执行 FlightNav authoritative segment 校验及 WorldStatic 球扫掠；折返入口沿用同一套验证。全部失败时取消本机攻击并进入 1 秒重试。

## 目标迟滞与归队门

权威 Coordinator 从 `WingmanTargeting.Default` 读取 150000cm 获取半径、180000cm 释放半径、0.8 归队比例与 0.2 秒扫描间隔。指定目标在 1800m 内立即应用并解除归队锁；自动目标只在 1500m 内新获取。当前自动或指定目标越过 1800m时被清空并设置 `bAutoTargetingLockedForGuard`。

锁定期间读取服务器 Relay 的存活 roster、health 与每架最新 Accepted Pose。所有存活成员必须有不老于 1 秒的姿态；至少 `ceil(存活数×0.8)` 进入 Formation `CatchUpDistance`，且无人超过 `RecoveryDistance`，才重新开放自动索敌。当前 SwarmOrbit 配置对应 600m/900m。无效或死亡目标不会错误触发超距锁，可直接进入下一次扫描。

## 数据、协议与权威开火

`EGuLiWingmanAttackPattern::AirOrbit` 已替换为 `AirDogfight`，旧切向速度函数和 Orbit 表字段已删除。`WingmanWeapons` 新增 10 个明确的机动字段；`WingmanTargeting` 改成 Acquire/Release/GuardRejoin/Scan 四字段。Excel 是持久数值入口，JSON 和两张 DataTable 由现有管线生成，Definition 解析后发布冻结 Runtime Profile。

协议版本升至 v11，新参数加入稳定哈希与配置校验。按 25 架、0.5 秒机枪冷却计算，合法峰值为 50 发/秒，因此协议自动开火预算、Relay 令牌桶容量/补充率相应调整到 50发/秒与100容量；服务器仍逐发验证当前目标、来源姿态、版本、射程、前向射界、LOS、冷却和重复序列。

## 武器升级结论

编队、AirWeapon 和 GroundWeapon 保持三个独立绑定。激光、持续光束、散射炮等武器的命中模型、持续时间、网络事件和表现生命周期差异很大，应在同一武器槽替换 AbilityId、SkillId、GA、WeaponDefinition 与执行器。`ServerApplyAbilitySet` 会发布新的 Loadout/Profile Revision 和 DefinitionChecksum，使旧配置下尚未接纳的请求失效，同时保留编队和另一武器槽。

伤害、冷却、射程、导弹数量等同一种武器内部升级继续生成新版冻结 Runtime Profile。这样简单数值成长不增加技能种类，行为/表现改变也不会被迫塞进机枪执行器。

## 2026-09-08：FlightNav 边界停滞恢复

现场出现两架僚机长时间停住。第一层原因是 Integration 最终段拒绝越界后曾保留非零速度并丢弃该成员当帧剩余固定步；编队候选却共用同一个 `ClientSimulationTick`，该成员随后会相对逻辑钟落后，服务器再把追赶过程判成 `SpeedDelta/IntegrationError`。第二层原因是恢复锚点可能退化为当前边界位置，有限转向会持续朝无位移目标调整，无法形成新的安全离开段。

现在每架僚机在当前航向失去可执行下一步时冻结反向逃逸方向；最终段若实际拒绝，则用实际被拒航向的反向覆盖它。僚机先在最后合法点按最大减速度刹停，同时继续消费所有已安排的30Hz固定步；速度为0后可原地瞬时对准该冻结方向。原地旋转不产生位移，下一固定步的真实位移仍逐段通过 FlightNav、WorldStatic、碰撞和距Ship包络校验。服务器仍只接受 `Recover + 位置未动 + 速度未增加` 的约束刹停样本。

源码版 `GuLiStrikeEditor Win64 Development` 构建成功。最终攻击自动化7/7、Relay运动包络1/1；当前原型关卡主动对空采样250.63秒，25架均在689/689个相邻区间发生位移，最长停滞0秒，采样末端累计3306发机枪且普通/原子候选拒绝为0。对地采样85.83秒，25架均在299/299个区间发生位移，最长停滞0秒，导弹累计增至445。证据见[对空分析](../../TestResults/ShipAirCombatLevel/active_dogfight_stoppage_analysis.json)、[对地分析](../../TestResults/ShipAirCombatLevel/active_ground_stoppage_analysis.json)和[增量归档](../Archive/20260908-Ship僚机FlightNav边界停滞恢复.md)。

验收完成后已移除本轮加入的 Integration、Relay 空间包络、无位移和武器批次高频诊断输出及其命令行开关；运动恢复逻辑与安全门保持不变。清理后再次使用源码引擎构建成功，攻击专项7/7、Relay运动包络1/1通过；报告见[攻击专项](../../TestResults/ShipAirCombatLevel/AutomationNoValidationLogs_Attack_20260908/index.json)和[Relay运动包络](../../TestResults/ShipAirCombatLevel/AutomationNoValidationLogs_RelayEnvelope_20260908/index.json)。
