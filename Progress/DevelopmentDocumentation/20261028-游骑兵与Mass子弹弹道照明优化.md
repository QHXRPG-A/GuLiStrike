# 游骑兵与Mass子弹弹道照明优化

用户在2026-10-29要求“直接应用”，随后要求“开发内容直接应用，不需要额外提供一个开关来开启，旧代码需要被替换，不要保留”。本轮按此决定直接接入正式资源，撤销此前的候选启用流程；直接应用授权不记为已完成视觉审核。

## 正式实现

`UGuLiBulletTrailPresentation`由客户端表现子系统持有，按World隔离。Mass每256个稳定槽位共享一个GPU组件，Slot/Generation/Epoch隔离生命周期。出生数据、结束数据、颜色与代次分别按修订上传，统一相对时钟和完整可见Bounds逐帧更新。路径固定在世界空间，命中后停止延长，逐点消散；无GPU回读。专服不创建表现对象，CPU权威弹丸、伤害、碰撞与网络协议继续由原系统处理。

Ground继续使用CPU固定曲线，主体与尾部为#EE9D58、亮核#FEE4D9、发光8，保持24cm宽及0.12s停留/0.38s淡出。Mass为6cm宽、最长1200cm、弯曲12cm、0.06s停留/0.18s淡出，保留友黄敌红。

独立CPU粒子灯池共享最多6槽，玩家与Mass活弹按最近合格本地视图距离选择；72m准入、88m退出并淡出。半径800cm、亮度25，无阴影、透明受光或体积雾散射。命中、过期及取消关闭弹头灯；尾迹自发光继续消散。

Excel正式ID8接入`NS_GroundBulletTrail_Orange`，ID38接入`NS_MassBulletTrail_GPU`，新增ID58 `BulletLightPool`接入`NS_BulletLights_CPU`。资源包沿用`/Game/GuLiStrike/FX/BulletTrails/Review_A1`。Catalog设置`BulletLightVfxId=58`、`MassTrailWidth=6`，其他源表行保持。经既有管线导出并只导入VFX表，未增加字段或模块。

## 2026-10-30：指挥官兵种弹道消失修复

玩家明确消失的是指挥官兵种弹道，并授权“你可以进场调试”。原始采样证明权威发射与命中仍在推进；异常位于Niagara表现池。

初始化模块从参数图读取`Engine.ExecutionIndex`，实际所有粒子的`TrailSlot`均为0。换成名为`Engine.ExecIndex`的MapGet仍然得到零默认值；最终改为Niagara HLSL内建`ExecIndex()`，保存独立槽位。发射器原为`Once`，不符合持续读取数组的承载；改为`Infinite`，同时启用`SpawnBurst_Instantaneous.UseLoopCountLimit=true`、`Loop Count Limit=1`，确保每次激活只分配一组固定粒子。单独改循环会重复追加粒子，该中间方案已由完整修复取代。

改动仅涉及正式`NS_MassBulletTrail_GPU`、`NS_BulletLights_CPU`及`Scripts/Vfx/author_bullet_trails.py`。完整制作和定向修复共用同一池初始化函数，后续重做资源不会复发旧配置。Ground弹道、美术色值、宽度、伤害和网络逻辑均未修改。

- 两个系统编译0错误、0警告，VM为UpToDate，GPU编译完成；正式ID38/58路径回读及保存通过。
- 普通Commander对局24秒、13次采样，33个活跃组件样本全部为256粒子、256个唯一槽位、范围0–255；9次交火采样都有非零透明度粒子。4个组件参与交火，结束后回池。
- 同场累计发射3875、回收3875；这些是运行计数，不代表伤害逻辑或视觉已全面验收。
- 独立CPU灯池诊断在7.31秒内保持6粒子、槽位0–5，覆盖多轮Emitter循环及数组空闲/恢复输入。未把灯光开关布尔值的空读回冒充实际照明通过。
- 诊断回调已注销，自建PIE和临时灯组件已清理；原Ground默认席位及开局询问已恢复。原图28个部署点与正式资源回读留档，场景无需新增对象。

没有原生源码变更或新原生构建，没有新增/运行自动化测试，也未截图或读图。SimCache仅用于本次获准诊断读取粒子数字，正式玩法不增加GPU回读。证据及未通过的中间采样说明见[诊断记录](../../Artifacts/CommanderTracerFix_20261030/README.md)，[增量归档](../Archive/20261030-指挥官兵种弹道槽位与生命周期修复.md)。玩家重新Play选择Commander，观察正常兵种交火即可验收。

## 2026-11-02：Mass弹丸与弹道发黑修复

用户报告“当前Mass单位发射的子弹和弹道都是黑的，你可以自行打开PIE去看”。当前正式资源仍为ID38的`NS_MassBulletTrail_GPU`，其Sprite材质`M_MassBulletTrail`的`ParticleColor`默认RGB输出接入Custom的`Tint`，但HLSL读取`Tint.a`。当前编辑器SM6日志明确记录`vector swizzle 'a' is out of bounds`及`Default Material will be used in game`，第一处错误发生在材质输入类型与HLSL使用不一致。

仅将正式材质的这根连接改为`ParticleColor.RGBA → Custom.Tint`，并同步`Scripts/Vfx/author_bullet_trails.py`的制作接线，防止重建资源时复发。9个节点、其余16根内部连接、材质输出、色值、发光、宽度、寿命及Niagara系统均保持。只保存该材质，未修改Ground弹道、数据表、原生代码或地图。

- Python AST、差异检查及材质图前后对比通过；唯一图连接变化为Tint从RGB改为RGBA。正式ID38、Renderer材质与RGBA连接保存后回读正确。
- 修改后着色器编译任务完成，当前日志新增窗口未出现材质编译失败或Alpha越界；材质和Niagara诊断通过。修复前材质诊断曾返回`is_compiled_ok=True`，同时异步SM6日志仍报错，因此单次诊断布尔值不足以证明Shader可用。
- 普通Commander PIE采样20秒、11次采样，共12个活跃组件样本，均为256粒子和256个独立槽位。184条可见粒子观察记录没有黑RGB或非正发光；详细样本为友方黄色`(1,1,0,1)`、发光24。记录可能重复同一粒子，不作为独立发射数量；本次未采到可供列示的敌方红色样本，不宣称敌我视觉均通过。
- 首次诊断误用未暴露的`get_pawn`，在采样前退出；改用已确认的`GameplayStatics.get_player_pawn`后完成。失败尝试单独留档。最终回调注销、自建PIE及子进程清理完成，原Ground默认席位与开局询问恢复，Map和内容脏包均为空。
- 复用已保存的`/Game/Maps/LVL_CommanderMassPrototype`普通交火场景，当前30个部署Actor已回读；观察位置约`(-4300,54000,905)cm`。无需新增场景对象或开关。玩家重新Play选Commander，确认弹丸/尾迹恢复亮色、友黄敌红、命中后正常消散。

本次没有原生构建、自动化测试、截图读图或性能测量。画面与照明仍待玩家验收。证据见[诊断交付](../../Artifacts/MassBulletColorFix_20261102/README.md)，增量事实见[归档](../Archive/20261102-Mass弹丸与弹道黑色材质回退修复.md)。
