**最终平均帧时间目标已达到**：两次完整 CPU 采样为 13.567ms、13.586ms；按帧数加权 13.577ms，相比基线下降 47.64%。正常运行 8 秒窗口 13.076ms。两次 P95 19.320ms / 19.233ms，峰值约 27.5ms；不表示每帧均低于 15ms。详见 [最终验收报告](D:/UE5.7/PerformanceCaptures/GuLiStrike/optimization-15ms-20261020/report.md)及 [机器可复核证据](D:/UE5.7/PerformanceCaptures/GuLiStrike/optimization-15ms-20261020/acceptance.json)。

## 诊断

1. 原报告游戏线程主要成本包括 Hybrid 7.006ms、Windows 消息泵 4.647ms、完整进程 Slate 3.777ms、帧开始委托 1.630ms。这些区间有包含关系，不能相加。
2. 引擎 `FDynamicRHI::EnableIdealGPUCaptureOptions(true)` 在 RenderDoc 附加时持续启用绘制、材质和详细 RDG 标记。它只改变诊断元数据。此前同进程短测观察到 2.264ms 差异，本轮尚未重复确认精确收益。
3. `GuLiFrameProfilerSlate.cpp` 每帧调用 `GeneratePathToWidgetUnchecked`，对整个窗口重新布局和搜索，只为比较视口路径。改为启动时保存弱引用路径、每帧沿父链核验全部身份和边。
4. 本轮沿用的对局已运行半小时，600 战斗单位保持，但建筑已增长到 104 座以上、历史目录记录约 1.1 万。原生无 Trace 8 秒前台窗口 A1 平均 28.717ms/P95 46.068ms；关闭详细标记的 B1 平均 30.577ms/P95 48.806ms。这组不能证明优化收益，不能与原报告直接对比。
5. 关闭标记后完整诊断 [726AFACD](D:/UE5.7/PerformanceCaptures/GuLiStrike/20261020-122005-726AFACD/report.md) 为 34.643ms；消息泵 8.470ms、帧开始委托 1.672ms。另一次主动提前结束的 [消息诊断](D:/UE5.7/PerformanceCaptures/GuLiStrike/20261020-122310-E8284294/report.md) 仅作定位，不作完整验收；UE 窗口消息回调本身不到 0.001ms/帧，主要等待仍在消息泵内部或其外部钩子，根因尚未证明。
6. 消息诊断结束时首次脚本使用了跨调用变量，因桥接脚本命名空间隔离而未成功恢复诊断开关；随后已显式恢复 `WindowsApplication.EnableWindowMessageProfilerScopes=0` 并读回确认。没有改变玩法状态。

## 首批实现

- Slate 路径：缓存弱引用并检查每条父子边，拒绝失效、复用地址或重新挂接的路径；保留每帧视口、UI 层和回调配对校验。归属版本升至 4，分析器接受版本 2 及以上。
- 续查引擎路径实现后，补充 `ValidatePathToChild`：`SWidgetSwitcher` 切换活动页面时父指针可以不变，仍必须使旧视口路径失效。该检查沿父链执行，不恢复全窗口布局搜索。
- GPU 诊断标记：默认在插件初始化时恢复普通诊断成本；只在 CPU 窗口结束后的 RenderDoc 阶段开启详细材质和 RDG 名称，完成时恢复原值与设置优先级。首批曾保留 AutoAttach；后续根因对照后改为普通启动不附加，GPU 调试显式 `-AttachRenderDoc`。`gs.FrameProfiler.KeepDetailedGPUEvents=1` 可保留常驻标记策略。
- 新增 `gs.FrameProfiler.CaptureCPU`：使用相同 CPU/Slate/原生采样和分析路径，明确记录未请求 RenderDoc。最终 Alt+/ 普通启动采 CPU，GPU 调试启动自动执行 CPU 加 RenderDoc。
