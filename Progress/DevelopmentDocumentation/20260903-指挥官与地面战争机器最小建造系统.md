# 指挥官与地面战争机器最小建造系统 — 技术方案

- 对应需求：[指挥官与地面战争机器最小建造系统](../RequirementDocument/20260903-指挥官与地面战争机器最小建造系统.md)

## 技术选型

- 继续使用现有单一 `GuLiStrike` 模块：Engine、InputCore、NavigationSystem、UMG/Slate 与 Editor 资产依赖均已存在，不增加模块或插件。
- 在所有三类角色实际共用的 `AGuLiCommanderPlayerController` 上创建复制的 `UGuLiBuildingPlacementComponent`。Controller 只负责输入路由，组件拥有本地模式、预览、RPC、服务器校验和反馈。
- `AGuLiPlacedBuilding` 是服务端唯一写者；客户端输入只发送意图，建筑类型、阵营和建造者身份通过复制下发，不写入 SaveGame。
- 运行时碰撞采用独立 Box，而不是依赖商城 Mesh 的复杂碰撞；它继续阻挡普通物理角色。现场验证表明现有 Commander 导航回调会因一次建筑更新冻结全地图活动编队，用户决定本阶段暂不处理士兵碰撞，因此建筑不再贡献导航几何，NavModifier 保留但设为不相关。
- UI 复用 `AGuLiCommanderHUD::DrawHUD` 的 Canvas 层，事件驱动写入短消息；不创建或修改 WBP，也不改变输入模式/焦点。
- 资产只通过 UE Editor API 复制和保存。12 倍应用于 StaticMesh SourceModel BuildScale，Actor/Component Scale 保持 1。

## 风险与备忘

- 防空炮约 44 万顶点、32 个 Section/材质。资产继续保留 Nanite 数据，但第 21 槽玻璃为半透明，预览和已放置组件都强制使用 fallback 表示，避免每帧每 Section 的 Nanite 非法材质警告造成日志与内存持续增长；本轮不做材质图集或 LOD 重制。
- Sentry 异常的首个坏点已定位为材质实例 `DiffuseColorMap` 未覆盖、实际落到 Engine DefaultTexture；本轮只在复制品修复并用资产测试锁定。
- 当前 Recast 为 Dynamic。旧建筑同时贡献根 Box 导航几何和 `NavArea_Null`，触发 `HandleNavigationGenerationFinished` 后，该函数把所有存活士兵加入修复任务，并把所有活动士兵加入暂停集合；这就是“一栋建筑让全地图停一下”的直接原因。用户决定本阶段不处理碰撞后，建筑根 Box 与 NavModifier 均不再具有导航相关性。未来重启士兵绕行时必须改为局部路径失效，不能恢复当前全局冻结方案。
- Commander Mass 士兵的 ISM 表示仍无物理碰撞。放置校验通过权威士兵位置快照（远端客户端使用复制姿态）拒绝直接压住存活士兵，但这不等于运行时硬碰撞。
- 硬引用目录便于 MVP 确定性加载，但 Cook/打包不在本轮获准测试范围，不能据 Editor 结果宣称发布包已验证。
- `/Game/Assets` 受项目 `.gitignore` 规则忽略：两套规范副本已存在于本机目标路径，但默认不会进入 Git 提交；本轮按“保留无关改动”约束未调整忽略规则。
- 测试扩张硬门：任何新增测试组或扩大矩阵前，必须先向用户说明现有三组覆盖不到的风险、涉及文件/场景与成本，并获得确认。
