# 肉鸽牌关系图工具实施与交付

使用 Python 标准库本地服务及浏览器原生节点画布。入口为 [start.cmd](../../Tools/RogueCardGraph/start.cmd)，默认 [127.0.0.1:4322](http://127.0.0.1:4322/)。工具的验收场景是本地浏览器内的三个席位页签。

## 数据与保存

- 正式基线读取卡表、公共文本、效果和武器效果的现有 JSON 导出。卡名取标题文本，说明按当前配置展开预览，保存时保留文本键和原始说明模板的来源。
- 画布内显示一条有向前置或一条双向互斥。保存校验与 Excel 导出器共用同一份关系规则。当前空中席位可编辑草稿，正式导出器当前支持指挥官与地面卡。
- `data/Design/RogueCardGraph.json` 保存 `base`、`graph`、`changes` 和保存时刻。`base` 包含来源及指纹。`graph` 包含稳定 ID、席位、标题、描述、坐标和连线。`changes` 记录新增、删除及字段前后值。
- 同一服务以文件版本检测过期页面的保存。数据通过校验后原子替换草稿。若正式导出更新，已保存的设计保留原基线并提示后续复核。
- 正式接入时按草稿与当前源表对照。新卡分配正式 ID、机制和文本引用，修改前置与互斥时核对效果依赖和各席位运行入口。

## 验证记录

- Excelize 回读确认 12 张正式卡的席位、前置、互斥、标题及说明与导出一致。初始图为指挥官 5 张、地面 7 张、空中 0 张，共 6 条前置关系。
- 现有导出器 `--validate-only` 校验 43 张表通过。Python 语法检查和 JavaScript 语法检查通过。
- 浏览器以隔离草稿验证卡牌详情、节点拖动、前置拖线、互斥拖线、点选连线、增删、修改描述及撤销。保存用例包含新增 2 张空中草稿、删除 1 张指挥官卡、修改 3 张现有卡的关系。
- 页面刷新及重启本地服务均回读 13 张卡、8 条关系，节点位置和说明一致。循环前置、依赖链互斥、跨席位关系与旧页面覆盖保存均被拒绝，文件保留最后一次有效草稿。
- Windows 启动脚本使用带 BOM 的 UTF-8 兼容系统 PowerShell。双击入口及本地服务已核对。验证使用浏览器事件、DOM 与文件回读。
