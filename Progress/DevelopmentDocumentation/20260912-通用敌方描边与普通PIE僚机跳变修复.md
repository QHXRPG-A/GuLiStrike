# 实施

- `UGuLiTeamOutlineComponent`：Blueprint可挂组件，公开SetOutlineTeam和RefreshMeshes，静态/骨骼网格按阵营写CustomStencil。服务端不创建后处理效果。
- 公共玩家CameraManager：从当前PlayerState读取阵营，独立材质实例把敌方Stencil转为红色边缘。
- 材质：项目自有后处理，2像素外轮廓、深度遮挡，软引用纳入Cook。
- 诊断：扩展已有`log_ship_wingman_live_stats.py`采样，按世界Delta统计模型位移速度和跳变前后状态；不创建新测试文件。
- 远端时间轴：以生产端`ClientSimTick / 30`保留轨迹间隔，独立保存服务器接收时间供目标新鲜度查询；每Flight用连续播放时钟吸收抖动，回看0.2秒，不反向修改逻辑或攻击位置。
- Roster Cut：同一存活成员保留原模型、正在播放的历史区间和播放时钟，新快照只合并更新的姿态。死亡/对象池复用按完整成员身份和代次切断统计，不把新成员出现算作旧成员瞬移。
- 上传：移除普通姿态的5Hz/10Hz授权分档及每帧Flight名额，所有Flight每3个完成逻辑步发送一次当前姿态（基础10Hz）。
- 传输：同一轮普通Flight姿态合成一个上行RPC，普通姿态不再携带已不用的导航历史；射击段开始仍可靠提交精确捕获记录。服务端保留每Group/Flight最新值，每100ms按观察者合成一帧可靠下行，与死亡/补员边界有序到达，并省去拥有者自己的回环姿态。没有逐逻辑发网络消息。
- 表现：0.2秒源时间缓冲之外，远端模型以0.1秒时间常数连续融合外推纠偏；真实出生/对象池复用/显式位移直接建立新模型起点。根姿态与伤害、碰撞权威不接受这层模型反馈。
- 时钟与特效：模型融合使用`WorldTime - LastVisualTime`，同一帧多个Flight触发分配刷新不重复消费帧Delta；枪口/弹道的表现解析读取`PresentationRoot`，不读取未平滑的逻辑根。
- 全灭生命周期：允许Active Roster Cut的`RequiredFlightMask=0`，准确同步整组死亡；初始/原子建组仍使用其非空Flight契约。没有按样本年龄隐藏存活单位，也不增加飞行或开火门。

## 复现与当前证据

- 专用`QA.Start`会换GameMode、分离出生点、给Ship和固定靶百万生命，并手动指定固定靶；普通PIE保持原`GuLiShipTestGameMode`、真实出生点、自动选敌及死亡/补员。两条路径不能互相替代验收。
- 普通PIE未启用网络模拟：丢包、延迟均为0。采样看到相邻远端样本可相隔0.8–1.0秒，超出0.2秒缓冲；只加插值不能解决上游断流。
- 敌我描边：最终版本原始视口为`TestResults/WingmanAttack/ordinary_early_client1.png`及`ordinary_early_client2.png`；各自敌舰/敌僚机红边，己方无红边。`outline-runtime.json`证实两个相机材质的LocalTeam分别为1、2，DS不创建描边材质实例。未使用`QA.View`改相机或固定靶布景。
- 材质编译通过。既有Presentation 7/7通过；Presentation+Attack共18/19通过，唯一失败为未授权改动的`GuLiWingmanCombatCoordinatorTests.cpp`仍要求旧释放距离/重入门，不为迁就断言恢复已删除的游戏门。
- 首轮仅改时钟的采样仍有跳跃；第二轮合并快照历史仍发现断流。本次保留这些失败证据，不把中间构建通过当成实测通过。
- 确证传输根因：`ordinary-pie-rpc-drop.log`包含UE `Network saturated, not calling ...ServerSubmitCandidate`和`...ClientReceivePublicWingmanAcceptedBatches`；发送瞬间`IsNetReady`失败直接丢弃不可靠RPC。同期实际丢包为0、平均流量低于250KB/s预算，不能用这些平均指标排除瞬间拥塞。
- 中间复验：仅修正10Hz时，60秒普通PIE远端有572次超过200m/s的模型帧；改为合批上行/状态复制下行后，90秒普通PIE仅10次，均在前8秒，但仍未满足无跳变验收，因此继续处理外推纠偏。
- 模型融合首轮实现也未通过：`motion-normal-final.json`的13488次异常暴露同一渲染帧被多个Flight重复消费Delta的问题；改为实际经过时间后再复验，该文件名不代表通过结论。
- `motion-normal-renderclock.json`：90秒、4862个渲染帧、两端各25个Owner和Remote轨迹，模型超过200m/s为0；但一个远端模型原地保留4.728秒直到补员。证据显示整组已全灭、服务端不再生成该组姿态，而旧`RequiredFlightMask!=0`校验使全灭死亡Cut无法发布，最后一个旧模型变成假停机；本次继续修复并补入现有测试文件。
- OwnerOnly属性下行实验仍不足：`motion-normal-all-dead.json`中全灭残留消失，但开局服务端连续10Hz Accepted、客户端轨迹却有1.5秒缺口，仍产生343次异常模型帧。最终下行改为低频可靠合并帧；不把这个失败版本当作通过基线。
- 可靠合帧复验：`motion-normal-reliable-frame.json`，普通PIE从开局采样90.005秒/4846帧，Owner和Remote各50条轨迹（跨两个客户端），超过200m/s的模型帧均为0；Owner峰值124.11m/s、Remote134.31m/s，最长静止分别0/0.139秒，存活身份的最长收到新姿态间隔0.150秒，采样错误0。
- 最新Editor/Game构建：`build-editor-reliable-frame.log`、`build-game-reliable-frame.log`均Succeeded；Engine/Project BuildId一致。`RegressionReliableFrame/index.json`为21/22通过，新增通用描边、纯模型纠偏、全灭死亡Cut三项均通过，唯一旧Coordinator释放距离/重入门断言仍失败。
- 独立重新开局复验：`motion-normal-reliable-repeat.json`，60.002秒/3046帧，Owner和Remote各50条轨迹，超过200m/s的模型帧均为0，峰值分别150.00/164.48m/s，最长静止分别0.018/0.192秒；开局最长新姿态接收间隔0.287秒，采样错误0、超过0.2秒停滞事件0。
- 两轮均是原地图普通Dedicated Server + 2 Clients单进程PIE、原GameMode/出生点/真实生命和自动目标，未使用`QA.Start`。这里的通过指记录期未出现所定义的异常模型速度与长停滞，不代表已测公网持续丢包、所有帧率/分辨率或长时间运行。
- 截图附带观察：部分较晚的截图相机曾进入舰体附近，仅保留为原始证据，不用于宣称描边画面验收；最终使用上述独立开局原始相机截图。没有借本需求重写Ship相机或复活流程。
