# Soldiers统一单位与全局法术场及矿车调度

## 模块边界

所有新增运行时代码仍在GuLiStrike模块；不新增插件、引擎修改或Build.cs依赖。目标依赖为：Commander/矿车→通用单位目录；Commander技能/Ship武器/通用战斗特效→全局法术场目录；矿车→矿车Manager→资源事实查询；矿车→矿厂上传接口。法术场与单位目录不反向包含Commander控制器或资源玩法。

| 所有者 | 公开合同 | 生命周期和权威 |
|---|---|---|
| UnitData目录 | 按Soldiers UnitTypeId读取基础属性、运行类和表现；提供Mass子集 | 每World初始化一次，服务器/客户端只读缓存 |
| SpellFieldData目录 | 按全局ConfigId读取Combat/Teleport配置，武器通过ID引用 | 每World加载一次；效果创建时服务端冻结数值 |
| MiningVehicleManager | 生成/登记矿车，申请/释放节点，查询占用，加入矿车互相忽略集合 | World持有；节点分配仅服务器；结束/销毁释放 |
| MiningVehiclePawn | 寻路、移动、采矿、命令、调用矿厂上传；组合表现和血量组件 | 原有服务器状态机与Actor复制 |
| ResourceWorld | 矿石位置、矿量、领地许可、原子扣减及动态矿簇障碍 | 保留服务器事实与公开矿量差量 |
| ResourceFactoryActor | 所属车辆/门状态、每车停靠会话和幂等上传、FIFO | 取消单车独占限制，每车单独记录提交状态 |

表结构扩展通过excelize-cli编辑，再由既有Excel导出器生成行结构。Soldiers保留既有Mass模型路径，新增可选ActorClass/PresentationClass及统一表现缩放；矿车数据不再在经济配置重复维护基础HP/速度/表现。经济配置仅引用矿车兵种ID及资源专属规则。

全局法术场工作簿`GuLiStrikeSpellFields.xlsx`的`Fields`包含现有WM01导弹和传送行，并加入WingmanGroundMissile。Ship WingmanWeapons保留飞行/开火配置，新增EffectConfigId，移除独立爆炸半径字段；AOE基础伤害只在全局Fields定义。技能修饰后的伤害通过明确的法术场ID与冻结伤害合同传入，通用特效运行层不查询Commander技能目录。

卸货位置仍为(-500,-600)，上传后在原地设置厂房前向rotation，再从(4000,-600)驶出。旧Turning枚举保留序号兼容但不再有半圆过程；矿车之间忽略移动碰撞和厂内通行扫描，墙/门/地板继续检查。

## 遗留与实际限制

场外最大速度实测达到约4500cm/s，但返厂路径绕矿簇时出现明显减速和一次重新寻路，整趟返厂约93秒。因此本次交付证明三倍速度配置与实际最高速度，不宣称整趟周期缩短三倍。矿车仍是Actor+AIController，没有新增Mass移动或车群避障架构。

既有批量耗矿触发Renderer距离场矩阵ensure，未修改引擎或掩盖日志。矿车专属受击视觉、Dedicated/丢包及性能矩阵未在本次授权五项中扩展。当前厂内截图较暗，保留实际渲染。
