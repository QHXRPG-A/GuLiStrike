## 技术选型与边界

使用 `LevelEditorSubsystem.new_level_from_template` 从 `/Game/Maps/LVL_CommanderMassPrototype` 复制新地图，随后只在新地图设置 Ship Test GameMode、重建玩家出生点和战斗中心。新地图不共享 Commander 图的 FlightNav DataAsset；部署脚本按目标地图生成独立资产并回写 FlightNavigationVolume。

航速继续走 Excel → JSON → DataTable 的现有管线，不在蓝图或 C++ 中增加第二套覆盖。运行值由 `CurrentMaxSpeed = BaseMaxSpeed × clamp(ThrustRatio / NominalThrustRatio, Min, Max)` 计算；Dreadnought 空装配落在 `0.5` 下限，因此 `1800×0.5=900` 改为 `5400×0.5=2700cm/s`。加速度字段未改，空装配有效加速度仍为 `600×0.5=300cm/s²`。

## 关卡布局与导航

战斗中心为 `(50000, 82500, 15000)cm`。四个 `PlayerStart` 位于 `(10000/30000, 102500/122500, 15000)cm` 的矩形角点并朝向区域内部；最远两点相距 `28284.27cm`。任一出生点距红/蓝军中心的最大距离为 `132098.45cm`，低于当前僚机 `150000cm` 获取半径。四点都处在相同的东南侧地形攻击走廊，避免随机出生点让全部对地航线被地形判定拒绝。

地图专属 FlightNav 使用源图中同一 FlightNavigationVolume 的空间范围重新烘焙，但 `source_world_package` 和 `source_volume_path` 均指向新地图。最终生成 29905 nodes、11010 cells、32365 portals、64730 links；Formation 导航合同 `satisfied=true`。

## 风险与备忘

早期一次源码编辑器在保存带 Landscape edit layers 的关卡时进入 `ALandscape::PrepareTextureResources → ALandscape::UpdateLayersContent → ALandscapeProxy::PreSave` 崩溃。目标地图和 FlightNav 已保存；随后全新源码编辑器进程正常打开目标图并完成交互式PIE实弹采样，因此该历史崩溃不再阻塞本功能验收。

最初的交互式PIE“有目标但不开火”还受到编辑器默认后台降频影响：Codex位于前台时，固定步由30Hz降到约12Hz，而地面进场超时按世界时间推进。项目新增 `DefaultEditorSettings.ini` 关闭该选项；新进程回读为false后，固定步、候选上传、Relay心跳与实弹时序恢复一致。

长时间运行还暴露了第二个独立问题：一架僚机到达FlightNav边界时，Integration正确拒绝了越界位移，却恢复上一帧非零速度并丢弃该成员当帧剩余固定步。客户端Trail因此同时出现“位置没动但仍有速度”和逐机固定步落后，服务器随后以`TrailInvalid`拒绝普通Candidate并撤销Relay。继续实测又发现，恢复锚点可能退化为当前边界位置，使停稳成员没有可执行离开方向。现在客户端冻结实际拒绝航向的反向，沿原航向刹停且继续消费固定步；速度为0后允许瞬时原地对准冻结逃逸方向。旋转帧没有位移，下一固定步的位移仍通过FlightNav、WorldStatic、碰撞和距Ship包络最终门。服务器只对`Recover`、前后位置差不超过2cm且速度没有增加超过2cm/s量化误差的样本跳过恒速预测，其余门禁不变。

现有扩展回归仍保留旧protocol-v7测试配置，无法创建当前v11 owner group；这导致三项Avoidance和四项Mass测试在进入行为断言前失败。完整Wingman集合还会在`FGuLiWingmanRelayRegistryWorldHookLifetimeTest::RunTest`的测试代码第232行访问冲突。它们不影响本次真实v11关卡运行，但在迁移测试夹具并消除测试崩溃前，不声明完整Wingman回归通过。

独立运行第 0 帧出现一次 `Ship source is missing, dead, or registered to a different team`。源码路径会在每个 Ship Tick 依次刷新 Combat 注册和 Relay，再重试 Coordinator；下一帧 25 架僚机组进入已编写 StateTree，警告未重复且进程无 Fatal。该现象记录为启动顺序观察项。
