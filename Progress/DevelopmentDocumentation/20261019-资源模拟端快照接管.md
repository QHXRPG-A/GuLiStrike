# 资源模拟端退出：当前快照接管与旧请求中断

本页续接[同步替换验收](20261019-Hybrid同步正式替换验收.md)。2026-10-19用户明确批准本方案，替代此前资源端掉线后接续旧请求、补齐旧回执的规则。正常运行玩法、频率、表现不变，Slate共享顶点及后台并行保持关闭。

## 确认的恢复契约

- 在现有全局暂停内关闭受影响资源请求纪元，所有尚未结束请求仅通知一次“连接中断，以恢复状态为准”；清理旧回调、重试及未提交暂存，不重提玩家指令。
- 正常退出取得原子状态应用后的最终快照；异常退出使用最新完整副本，允许丢失之后未同步变化。余额、库存、人口、出生及进度以选定快照为准，不额外退款。
- 当前生产、加工和采矿任务保留，旧在途标记清除，后续动作使用新请求。暂停不推进逻辑年龄或冷却。
- 完整快照暂存、校验、恢复、确认后才能启用新模拟者；旧请求、旧结果、旧回调按纪元拒绝。
- 5秒交接、15秒离线预算不变，所有收尾和安装耗时计入；无有效快照或超时明确失败。
- 每资源组一个备用客户端，仅存储；常规成功采集后间隔5秒再采集（2026-10-20用户将100ms改为5秒），首次建立和退出最终快照仍即时采集。首次或基线失效发送全量当前状态。仅保存最近两份完整校验快照；发送最多保留正在发送和最新待发版本。
- 协议31→32，交接2→3；Manifest24、玩家存档和普通Blueprint玩法入口保持。旧房间不迁移，资源组不回退全历史接管。

## 2026-10-20离线检查与范围调整

用户随后明确要求快照改为5秒一次。`ResourceSnapshotIntervalSeconds=5.0`仅作用于周期备份，60Hz模拟、正常命令及退出最终采集不使用该定时器。源码UE5.7 Editor目标重编成功，离线脚本验证首次即时、5秒内不重复采集、到期恢复采集及现有完整核心契约；异常断线可能恢复到更旧副本，5秒不是最大丢失时间保证。具体产物与证据见[5秒周期归档](../Archive/20261020-资源备用快照调整为5秒.md)。下列520版等数值属于先前100ms周期记录，未覆盖改写。

新增实际问题：用户报告Mass操作卡顿，30秒原生采样只推进约825～882tick。快照缓存和发送队列有界，但采集屏障完成后可占住逻辑时钟500ms，补推进又丢失超过四步的累计时间。已修复为有序消费后立即释放废弃采集结果、每批最多三步保留全部累计时间及限幅器的小数步余量；真实全局暂停不补生产/冷却时间。`offline-clock-before`复现，`offline-clock-after-02`的20步及前后半步保留、废弃屏障200ms以内释放和全套核心契约通过。重编后600单位移动写入平均774→113ms，665个本地Mass为139ms；运行时按World时间保持约60Hz，额外Windows消息泵停顿使墙钟频率不足，详见[同步替换当前结果](20261019-Hybrid同步正式替换验收.md#2026-10-20最新范围与当前结果)。先前低耗时不能作为同模拟频率优化成绩。

用户明确取消长时验收，资源异常边界改为脚本和静态分析，不开PIE。固定业务状态下，当前快照大小由对象、任务和有效预留决定；已完成历史不得进入副本。发送端必须合并中间版本，不能因为备用端暂时不可达积累队列。
