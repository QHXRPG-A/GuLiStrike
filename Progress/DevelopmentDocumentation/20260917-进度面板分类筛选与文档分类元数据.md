# 进度面板分类筛选与文档分类元数据 — 技术方案

## 技术选型与边界

- 分类写在 front matter（`categories`，紧跟 `areas` 之后），而不是前端关键词推断：快照、索引、AI catalog 与面板共享同一事实源。
- 取值 `art / gameplay / performance`；由 `progress_docs.py` 的 `CATEGORY_AREA_MAP` 从 `areas` 确定性推导（`suggest_categories`），规则单一可审计。
- 一致性策略：需求/开发根文档按 `work_id` 组取并集；`role: detail` 子页继承父文档；归档取关联 `work_items` 分组并集 ∪ 自身 `areas` 推导。
- 回填不更新 `updated`（属元数据维护，不是事实变化，避免时间线被 273 篇同日更新淹没）。
- 前端筛选为多选并集（OR），与关键词筛选叠加（先分类后 globalFilter）；玩法模块视图不加筛选。

## 风险与备忘

- `gameplay` 覆盖 268/273 属语料现状（绝大多数工作项最终落到玩法模块），筛选区分度主要来自美术与性能优化；如需调整归类，改 `CATEGORY_AREA_MAP` 后重推导即可。
- 需求/开发两视图复用同一 `DocumentTable` 实例，React 状态在两视图间保留（切换视图时筛选延续，计数按当前视图重算）；归档时间线是独立组件，状态独立。
- UI/网络/数据管线类文档可能分类为空数组——不属三类即空，属预期而非缺数据。
