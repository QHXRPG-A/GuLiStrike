## 1. 深入分析与复用结论

### 1.1 权威运行已经共用

僚机在 `GuLiWingmanAttackCombat.cpp` 构造真实对地发射请求，经 `ExecuteWingmanAttack → LaunchPointProjectile → LaunchPointProjectiles` 进入公共服务。重防号 Q 也进入该服务。公共逻辑预检 Definition、运动、冻结爆炸场和来源，取得来源租约、建立效果状态并发布可靠创建；运行阶段预测位置、进行静态世界 Sweep、判定固定落点或提前碰撞，创建爆炸场并发布结束。

因此本项不需要把僚机迁移为另一套服务器弹丸，也不需要逐枚生成服务端 Actor。复用重点是客户端管理能力与预警接入。

| 层次 | 当前情况 | 本项处理 |
|---|---|---|
| 权威弹丸运行 | 定点发射、碰撞、到达、来源租约与爆炸场已共用 | 沿用，保留原顺序和合同 |
| 僚机玩法入口 | 俯冲、条带、发序、租约及武器版本校验 | 保留，仅填写可选预警样式 |
| 重防号玩法入口 | Q、左右挂点、弧线、齐射配额和引导批次 | 保留，不调用它来替代僚机投弹 |
| 客户端预测 | 既有稳定数据池及最终显示位置 | 一次计算供新表现器复用 |
| 飞行表现 | 僚机旧资源逐枚组件；重防号已批次化 | 抽取管理帮助逻辑，新增僚机光点尾迹表现器 |
| 地面预警 | 样式、稳定 ID、共享贴花及独立期限已具备 | 接入每枚冻结落点和 AOE 半径 |

### 1.2 不能直接把僚机切到重防号现有资源

`UGuLiProjectileEffectDefinition::UsesMissileClusterRendering()` 通过 `MotionProfileRow`、`UnitTypeId=2`、`SlotId=MissileLauncher` 及资产身份检查选择重防号表现。僚机 Definition 没有该表行，复用 ID 2 并不表示已经走批次路径。不能伪造兵种或武器表行来绕过路由。

`UGuLiMissileClusterPresentation` 的组件池、稳定槽位、Generation、空槽复用、Bounds、质量档和静态/动态上传缓存值得复用；其机体、尾焰、烟迹尺寸、历史时长和重防号专属设置不符合本项“球形脉冲点＋实体收细尾迹”。新增可选表现配置，按配置选择独立表现器，默认空引用保持已有路径。

抽取仅涉及模块内部管理帮助逻辑。新旧表现器分别持有资源、视觉数据和尾迹规则，避免修改重防号正式资源时牵连僚机，也避免本项的 0.55 秒尾声覆盖重防号历史参数。

### 1.3 预警能力已有，僚机请求尚未填写

当前 `FGuLiCombatAttackRequest` 和效果状态已具备 `GroundWarningStyle`，公共 `PreparePointProjectile` 将它写入状态，并使用冻结爆炸场设置 `State.Radius`。客户端已有 `UpdateGroundWarning`，`UGuLiGroundWarningSubsystem` 支持稳定效果 ID、共享圆引用、单来源结束、过期清理及池化。僚机真实投弹请求目前填写 Definition、运动和冻结爆炸场，没有填写样式。

接入方式是在僚机真实权威发射分支解析 Definition 的可选预警样式并写入现有请求，继续使用既有复制、快照和结束机制。客户端根据该枚 `LastTargetLocation / Radius / StartTime / EndTime` 调用服务，不由表现器另算命中时间或 AOE。

重防号 `GuidanceBatchId`、共享配额和整台分批规则保持专属。本项不生成整轮引导圆；僚机采用每枚 ID 的普通预警，相同位置、半径、样式及原合并键一致时共享贴花。

### 1.4 性能范围与预期

逐枚旧 Niagara 的组件激活、变换和多发射器更新预计可通过批次减少，上传由每枚转为每批提交。但新尾迹历史、实体网格段和红圈会增加 CPU、几何及贴花成本，Opaque 也不能单独证明整帧变快。须分组实测。

此前 `BP_ShipProjectile` 的创建、销毁补建和物理移动峰值归属 Ship 舰载炮。僚机已经是公共数据型定点弹丸，本项不处理该 Actor 路径。[600/500 压力截帧记录](../Archive/20261009-600移动单位500弹丸PIE截帧耗时分析.md)是背景依据，不能作为新表现收益或真实对地导弹定向负载的结果。

表现配置拟保存：模式、批次资源 ID、`W₀` 与派生直径、周期 0.5 秒、尺寸倍率 1.5–2.5、发光倍率 1–4、尾迹最大长度 10–50 米（默认 50）、头宽 0.35W₀、尾声 0.55 秒和质量档段数。配置加载/校验在激活时完成，资产由反射对象持有；运行槽位只保存轻量数据与代次。

拟采用统一生命周期：

| 入口 | 合同 |
|---|---|
| `BeginFrame` | 接收服务器时钟、World/Epoch 及表现开关；每 World 每帧一次，准备计数与工作数组 |
| `Submit` | 接收完整效果身份、配置及既有最终显示位置/方向/发射时间；更新同一槽位，不再次预测；返回是否接管表现 |
| `Finish` | 按权威结束移除光点；保留该槽尾迹的 0.55 秒消散或立即清理，重复调用幂等 |
| `EndFrame` | 处理退出/消散槽位，更新完整 Bounds，按修订上传及回池，汇总计数 |
| `Reset` | 换局、销毁或重置时清空 ID 映射、轨迹、槽位和组件；Epoch 不跨局复用 |

World、Epoch、效果 ID 与 Slot Generation 共同确定槽位身份。批次句柄不进入网络。网络继续沿用现有 Flight 格式、创建/结束可靠机制及每批 16 条/1000 字节限制；新增表现参数通过 Definition 资产解析，不复制逐帧网格或粒子。

## 4. 批次、网格尾迹与上传策略

### 4.1 分组和稳定槽位

默认每批 32 枚，按 World、表现配置和空间单元分组。分组用于分配与可见性管理；飞行时保持稳定槽位，不因跨单元每帧迁移或重启尾迹。若确需重新分配，按明确的新 Generation 合同清空旧历史。

每槽持有效果 ID、Generation、发射时间、最新显示位置、轨迹历史、结束时间及状态。退出后清理位置/尺寸/元数据和旧几何，回收时增加 Generation；Epoch、配置或身份变化清空历史。专服不创建表现器组件。

光点采用球形 Mesh，尾迹采用逐段收细的实体网格；正常直线合并为一段，显示修正造成的折线最多 8 段。质量档使用 8/4/2 段，保留头尾、整体长度上限和消散时长，避免低档变成短尾迹。

### 4.2 有界历史与分段

每枚每帧只取一次既有预测后的最终显示位置。沿实际显示路径累计弧长，保存有界采样；近共线样本合并。超过配置最大长度时，从尾端删除超长历史并插值得到精确裁切端点。

折线简化后生成最多 8 段，保留方向变化和连接连续性。每段头尾宽由其在完整尾迹中的弧长位置决定，尾端到零；接缝与转角需在可播放候选中检查。既要限制点数和工作容量，也要按弧长限制可见长度，不能只保存“最近若干帧”替代 50 米合同。

屏外继续推进既有预测；完整表现范围完全离屏后停止尾迹生成并清理隐藏历史，暂停组件或上传不取消逻辑飞行。回屏使用当前脉冲相位，从当前位置积累新尾迹，不补画屏外轨迹。仍可见的历史尾迹和消散段计入完整范围。晚加入只从收到状态后的显示轨迹积累，不补造接收前未观察的长尾，也不重放已结束效果。

### 4.3 材质动画与时间

光点与尾迹均为 Opaque + Unlit，通过几何形状、尺寸和发光实现表现，保留正常深度遮挡。光点无逐枚动态灯；尾迹结束采用收细至零，不能靠透明度淡出。

批次提交共享服务器时间以及每槽发射时间，材质/批次动画计算统一脉冲：

```text
u = (1 - cos(2π × max(0, ServerTime - LaunchTime) / 0.5)) / 2
Diameter = W₀ × (1.5 + u)
Emission = 1 + 3 × u
```

颜色从美术规范选取：光点 `#FEE4D9`、尾迹 `#EE9D58`，按 sRGB 转换线性值。发光倍率为初始候选值，不把 Bloom 后屏幕亮斑直径当作球形网格尺寸基准。

### 4.4 配置、数据和时间分开提交

静态配置在批次创建或配置变化时提交；动态位置、方向、尺寸、尾迹和代次数据仅在对应修订变化时提交；时间参数独立维护。缓存包含组件身份、配置修订、数据修订、帧号和上传时间，同帧同修订不重复上传。组件重建必须使上传缓存失效，即使数据修订没变也重新绑定。

只准备活跃槽位及上次使用后待清理槽位，复用数组容量。可见运动按帧刷新，时间心跳不能被误当作静态配置重上传。Finish 与退出槽位明确写入零尺寸或无效代次，防止尾迹串到新弹丸。

Bounds 覆盖最大 2.5W₀ 光点、完整尾迹、折线中段及消散槽位。调用既有 World 效果 Bounds/LOD 查询，任一合格本地视图可见即显示；不能只检查弹头或尾端位置。预警有独立生命周期，不随飞行表现早返回而遗漏结束/过期处理。

## 5. 红圈接入与结束合同

在僚机真实对地发射分支读取 Definition 的 `GroundWarningStyle`，成功请求携带现有样式字段；保留冻结 `TargetLocation`、`FrozenField.Radius` 和寿命。公共运行服务继续发布已有状态，无需新增网络粒子信息。

客户端复用 `UpdateGroundWarning`，用该枚稳定效果 ID 登记圈。样式默认复用已审红圈，双方可见；颜色不按敌我改写。相同合并键的来源共享现有贴花，独立期限和结束记录维持引用计数；相近但不同的落点不能为了减量擅自扩大或合并 AOE。

| 事件 | 光点/尾迹 | 地面预警 |
|---|---|---|
| 发射成功 | 当前相位光点，尾迹从零增长 | 冻结落点和半径开始显示 |
| 目标移动/死亡 | 沿冻结航程继续 | 圆心不跟随目标 |
| 正常命中 | 光点移除，尾迹 0.55 秒收细 | 立即移除此来源 |
| 提前碰撞 | 采用权威实际结束位置处理尾声 | 原目标圈移除此来源；爆炸由原服务在碰撞位置结算 |
| 取消/超时 | 按原结束合同清理，防止静止残留 | 移除此来源，最后来源回池 |
| 晚加入 | 当前光点相位，接收后积累尾迹 | 恢复当前有效圈，不恢复已经结束的圈 |
| Epoch/World 结束 | 清空所有槽位、历史、组件和引用 | 清空该 World 来源与圆 |

圈的投影尺寸继续使用现有材质边界补偿，实际可见外圈等于冻结 AOE 半径；不把原始贴花包围尺寸当作半径验收结果。圈结束不等待尾迹尾声。
