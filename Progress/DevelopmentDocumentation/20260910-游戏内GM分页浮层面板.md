# 游戏内 GM 分页浮层面板 — 技术方案

## 技术选型与边界

- 继续使用现有 Runtime 模块；代码式 Slate 更适合无美术资产依赖、动态分页的开发者工具。
- PlayerController 只管理每本地玩家的视口挂载、焦点和输入恢复；Slate 不直接写玩法状态。
- 类型化 Model 调用 RuntimeTuning、ArmySkill、BattleAuthority 和相机的现有 API；不通过 `ConsoleCommand` 字符串执行。
- 仅在 `!UE_BUILD_SHIPPING` 绑定 F10 并构造 UI；不新增 RPC、复制和持久化。

## 涉及模块

| 变更点 | 路径/类 | 类型 |
|---|---|---|
| GM 类型化操作与权限策略 | `Source/GuLiStrike/Development/GM/` | 新增 C++ |
| 右侧分页浮层 | `SGuLiGMPanel` | 新增 Slate |
| 呼出、关闭与角色输入恢复 | `AGuLiBattlePlayerController` / `AGuLiCommanderPlayerController` | 扩展 C++ |
| 稳定技能来源 ID | `GuLiSkillGMUtilities` | 抽取共享函数 |
| Slate 运行时依赖 | `GuLiStrike.Build.cs` | 依赖调整 |

## 风险与备忘

- 普通客户端没有复制全局 RuntimeTuning Registry、技能来源账本和权威导航详情；UI 必须显示不可用，不能把本地 baseline 冒充服务器值。
- 指挥官 PlayerController 会根据角色动态重设输入模式；面板打开期间必须阻止该路径覆盖 UIOnly。
- 10000 人 Bench 同步执行会暂时占用游戏线程，必须保留二次确认和明确说明。

## 实施结果

- [GuLiGMPanelModel](../../Source/GuLiStrike/Development/GM/GuLiGMPanelModel.cpp) 封装权限、稳定排序/分页、严格解析、5 秒确认和全部类型化操作；不执行控制台字符串。
- [SGuLiGMPanel](../../Source/GuLiStrike/Development/GM/SGuLiGMPanel.cpp) 是右侧 42% × 84% 透明视口宿主中的固定浮层；四个分区均使用滚动内容，列表过滤后每页 10 条，底部结果区固定，并在预览键路由中保证文本框聚焦时 Esc/F10 仍可关闭。
- [GuLiBattlePlayerController](../../Source/GuLiStrike/Battle/Framework/GuLiBattlePlayerController.cpp) 通过 `AddViewportWidgetForPlayer` 按本地玩家挂载，打开时释放已按键、忽略 Move/Look 并进入 UIOnly；关闭及 EndPlay 对称清理。
- [GuLiCommanderPlayerController](../../Source/GuLiStrike/Commander/Framework/GuLiCommanderPlayerController.cpp) 在面板打开期间不重写输入模式；关闭后从当前角色重建 Commander Game+UI/光标或 Ground/Air GameOnly。
- [GuLiSkillGMUtilities](../../Source/GuLiStrike/Gameplay/Skills/GuLiSkillGMUtilities.cpp) 抽取原控制台命令的 Team+Label MD5 SourceId 规则，面板和命令共用，不改变原命令行为。
- 客户端 `Skill.Get` 只返回已复制 committed final，Registry、base/source/override 账本和权威导航都显式不可用；没有新 RPC、复制字段、存档或 Blueprint API。
