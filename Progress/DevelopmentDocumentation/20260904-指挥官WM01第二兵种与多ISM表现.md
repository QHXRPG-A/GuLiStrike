# 指挥官 WM01 第二兵种与多 ISM 表现 — 技术方案

- 对应需求：[指挥官 WM01 第二兵种与多 ISM 表现](../RequirementDocument/20260904-指挥官WM01第二兵种与多ISM表现.md)

## 技术选型

- 使用临时 `UPoseableMeshComponent` 从 WM01 SkeletalMesh 参考姿势构造确定性固定战斗姿态，再由现有 `MeshUtilities` 冻结为临时 StaticMesh，并复用 `MeshMergeUtilities` 材质合并、三张 2K 贴图和 LOD 生成流程。不会保存或依赖 AnimSequence、PoseAsset，也无需启用新插件。
- 固定姿态只修改六个髋骨的局部 Z 旋转：`Leg_01e/03e/05e = +0.30 rad`，`Leg_02e/04e/06e = -0.30 rad`；其余骨骼沿用参考姿势，`Mainbody` 保持中性。源网格、LOD、六个骨骼及变换在创建输出包前统一校验。
- 保留默认原生 ISM 作为 UnitTypeId=1/兼容入口，其他有效兵种在 BeginPlay 按数据目录动态创建 ISM；每个类型一次批量更新，避免逐兵组件。
- 一个共享 Ring ISM 与按类型 Unit ISM 使用独立稳定索引。类型变更通过每批次空闲槽回收迁移，避免 RemoveInstance 导致索引交换。
- GAS 保持现有一个 ServerOnly ArmySkill GA；`Skills` 是行为定义，`UnitSkills` 是兵种槽位装备/参数，Mass Runtime 只消费各兵种默认 `BasicAttack` Profile。

## 风险与备忘

- 固定姿态是首版 Crowd 静态代理的确定性替代方案，不代表 WM01 后续正式 Idle/Walk 动画；以后接入动画或 VAT 时不得把这六个旋转常量当作动画资产规范。
- ID2 数值是集成验证值，不代表正式平衡结论。
- VAT、武器外观切换、第三兵种出生比例数据化均不在本次范围。
- 兵种选择 UI、第二兵种 HUD 卡和指令矩阵缩小均明确延期；本轮未修改 `WBP_CommanderHUD`、HUD C++ 或 UI 构建脚本。
