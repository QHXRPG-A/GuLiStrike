# 飞船（DIY 模块化装配）

## 模块概述

玩家驾驶可自由改装的太空飞船。当前公共战局 Air 角色默认配置为 `BP_CombatAvatarFly01`（Dreadnought 无畏舰）：仅该子蓝图把继承的根 Scale 覆盖为 1，父 `BP_GuLiStrikeShip` 仍保持 0.3；舰体资源已烘焙为原始资源的 0.5，运行尺寸约 `19378×45023×6985 cm`。装配模型：**主体是 Character，部件是组件，槽位是舰体网格上的 socket，部件携带可接入槽位名集合**。换装在飞行中按键请求，由服务器确认后复制装配结果；引擎/武器的数值差异影响飞行性能与火力。当前子蓝图实际没有 socket 和默认装配，属于空舰体；下文四部件配装与 virgon 槽位基线属于母 `BP_GuLiStrikeShip`，不能套用为当前无畏舰已安装的部件。

飞船现在还拥有随Pawn生命周期创建的独立Ship ASC，以及由Ship能力统一授权的25架僚机。空舰体只表示没有“飞船自身部件武器”，不再表示没有僚机编队或僚机武器。

## 机制细节

### 公共战局与 Air 身份

- 飞船作为 Air 角色 Pawn 接入 [GuLiBattleGameMode](../../Source/GuLiStrike/Battle/Framework/GuLiBattleGameMode.cpp)，与 Commander、Ground 共用 GameState、PlayerState、PlayerController、席位和重生流程；不需要把三个独立 GameMode 在同一个 World 拼合运行。
- 原 Commander GameMode 保留兼容类名，组合三类 Pawn 配置及士兵发布组件；`AGuLiShipTestGameMode` 只把初始分配顺序改成 Air→Ground→Commander，仍通过同一张席位表，不允许客户端直接指定角色。
- [GuLiPlayerNetSyncComponent](../../Source/GuLiStrike/Battle/Network/GuLiPlayerNetSyncComponent.cpp) 先完成战局/身份握手并确认 `BattleReady`。飞船操作不等待 `SoldierStreamReady`；它还要等待本舰装配和移动配置就绪。指挥官 HUD/输入已按角色关闭，飞船只给本地 Air 拥有者安装自己的输入映射。
- 当前已审计 `BP_CombatAvatarFly01`：无 socket、DefaultParts 为空；空装配可以形成合法版本并完成移动就绪，但不会产生引擎/武器部件。母 `BP_GuLiStrikeShip` 有四个默认部件，可作为换装/开火验证对象；本轮没有给无畏舰擅自添加槽位或默认武器。

### 空战原型关卡

- `/Game/Maps/LVL_ShipWingmanAirCombatPrototype` 基于 `LVL_CommanderMassPrototype` 独立复制，WorldSettings 使用 `AGuLiShipTestGameMode`。首个玩家优先取得 Air 席位并生成带 V3 25 架僚机能力组的 `BP_CombatAvatarFly01`。
- 四个空中 PlayerStart 位于东南侧已通过实弹验证的攻击走廊：`(10000/30000, 102500/122500, 15000)cm`，最远间距约282.84m；任一出生点距最远敌军中心不超过1320.98m，处于僚机1500m自动获取半径内。地图使用自己的 FlightNav DataAsset，并已加入 Cook 与 RequiredWorldPackages。
- 项目级 `DefaultEditorSettings.ini` 关闭“编辑器失去焦点时降低CPU占用”。该选项开启时，PIE只有约12个僚机固定步/秒，但地面进场45秒超时仍按世界时间推进，导致僚机尚未就位就取消攻击。另一个长时故障来自FlightNav边界：Integration拒绝越界位移后曾冻结位置却保留非零速度并丢弃该成员剩余固定步，随后服务器会拒绝失步Trail。现在边界成员冻结实际拒绝航向的反向，按最大减速度刹停且继续消费固定步；停稳后允许原地瞬时对准冻结方向。旋转本身不位移，下一步仍执行FlightNav、物理障碍和距Ship包络校验。主动对空250.63秒与对地85.83秒逐架采样中，25架最长停滞均为0秒，Relay全程Active且普通/原子拒绝为0。

### Ship GAS 与僚机技能

- `AGuLiStrikeShip`拥有随Pawn创建和销毁的复制ASC，Mixed复制模式，`OwnerActor=AvatarActor=Ship`。它与PlayerState上的Army ASC完全分离；Army ASC继续只服务指挥官军队。
- Ship与每架Mass Wingman都不新增`AttributeSet`。Ship生命、速度、伤害继续来自自定义Health、基础表、部件和修饰源，并只通过`RecomputeStats`/CMC配置屏障提交；GameplayEffect不得修改这些数值。
- PlayerState只保存会话级稳定AbilityId。新Ship重生时创建新ASC并重授能力，旧AbilitySpecHandle、活动实例、临时效果和冷却全部丢弃。
- 当前默认能力为`Ship.Ability.Formation.SwarmOrbit`、`Ship.Ability.Weapon.Wingman.MachineGun`和`Ship.Ability.Weapon.Wingman.GroundMissile`，由 `DA_ShipAbilitySet_WingmanV3` 授权，均为服务器自动激活的常驻技能。旧基础武器、右键主动导弹和DoubleRing仍保留在目录中供旧配置使用；V3的两个武器消费统一目标自动攻击。
- Ship GA只负责组级授权、互斥、取消、共享冷却和GroupAbilityConfig投影。每架Wingman不创建ASC，逐架编队、导航、避障、索敌和开火意图由客户端Mass处理。

### 僚机对地轰炸与对空三维缠斗

- 权威Ship以自身为中心扫描三维球形范围。自动目标在1500m内获取，自动与指定目标都可保持到1800m；有效指定目标优先。目标超出1800m后清空并锁住自动索敌，等服务器最新Accepted Pose满足至少向上取整80%的存活僚机进入Formation的600m CatchUp范围、且无人超过900m Recovery范围后再开放。对外提供 `SetWingmanAttackTarget`、`ClearWingmanAttackTarget`、`GetWingmanAttackTarget`，这一版没有新增选敌按键或UI。
- 地面目标为Commander Soldier，空中目标为Ship/Wingman。25架各自就位、自然错开发起攻击，共享同一Ship目标命令。
- 对地依次进场、对准、45°俯冲投弹、平滑拉起、45°爬升。固定投弹时段为1.5秒，默认每架10枚；进场、转弯、爬升不计入投弹时长。45m/s、20°/s转弯初值下，投弹段从离地约147.73m开始，100m开始拉起，圆弧最低点约62.24m。完整航线检查FlightNav、物理障碍和至少50m离地高度。
- 每架从自己的来向生成120m条带，首枚落点是目标地面位置，后续导弹朝不同条带落点发射。俯冲开始后冻结来向与条带，目标移动或死亡不会改变已开始的这一轮。
- 导弹复用WM01的飞行与爆炸资源，通过公共CombatEffects执行固定点飞行和纯AOE；碰撞不另加单体伤害，同一枚对同一目标最多结算一次。伤害来源保留Ship及具体发射僚机身份。
- 对空由每架独立状态机循环 `接近并开火 → 随机脱离转向 → 前往冻结远离点 → 随机折返转向`。进入目标半径+僚机半径+300m后脱离；远离点位于目标到Ship的三维区域，纵向35%–60%且至少450m，横向/垂直为150m×100m椭圆。只在接近状态且机头射界、射程、LOS、冷却均合法时发射机枪。
- 每次脱离和折返都重新随机左右40°–90°与俯仰±30°，控制点距离为2×物理转弯半径；到达/越过控制点或10秒超时后推进。安全候选最多尝试8组并检查FlightNav与WorldStatic，本轮远离点冻结；全部失败时该机取消引导、等待1秒重试。
- 紧急避障、死亡、失去租约或对应武器替换会取消未发部分，不补喷。已由服务器接纳的导弹继续使用发射快照；已经开始的地面俯冲先完成冻结轮，再响应目标超距。正常攻击保留僚机间分离、有限转弯率和世界避障。
- 空中武器绑定 `AirWeapon / Wingman.MachineGun`，地面武器绑定 `GroundWeapon / Wingman.GroundMissile`。将来激光替换同槽技能、Definition与执行器；单纯伤害、射速、弹量升级更新数值配置。编队技能和未替换的另一武器槽保留。
- 调参入口是 `Data/Excel/GuLiStrikeShip.xlsx` 的 `WingmanTargeting`、`WingmanWeapons`。经现有Excel导出与引擎导入管线更新两张DataTable，两个武器Definition的 `AttackProfileRow` 读取对应行。

### 世界空间 HUD 与技能准星

- 本地拥有飞船创建顶部状态、左侧飞行、右侧武器、准星与受限范围框五个 3D `WidgetComponent`；远端飞船和 Dedicated Server 不创建这些运行时节点。旧 `/Game/Ship/UI/Widgets/WBP_ShipHUD` 仅保留为 Gate 2 历史资产，不与新 HUD 同时显示。
- 三个常驻面板每帧按舰体主网格的八个包围盒角点投影，距舰体外缘 28px，并保留 24px 视口安全边距；穿越相机近裁面的包围盒边会先裁剪，极端投影失败则回退视口中心。只要本地飞船仍有效，镜头环绕、贴近或越过部分舰体边界都不能隐藏常驻面板。
- 节点每帧以相机 Forward/Up 重建正面朝向，始终平行玩家屏幕；并以相机距离、水平 FOV 与视口宽高换算厘米/像素，因此缩放、FOV 和分辨率变化不改变逻辑像素尺寸。
- 面板只显示真实数据：Ship Ready/Alive 与舰体生命、当前/最大速度和 Boost、基础武器与僚机导弹可用/冷却状态。数据最多 10Hz 且仅在显示值变化时请求重绘；节点无碰撞、无硬件输入、不可聚焦，使用无深度且 Motion Blur 后绘制的材质，镜头运动时仍保持清晰。
- 技能以互斥 `AssetTags` 声明 `Ship.Ability.Reticle.Omni` 或 `Ship.Ability.Reticle.Bounded`。无 Tag 不改变相机/准星；冲突 Tag 和越出 `[0,1]` 的受限矩形配置失败关闭。最近激活且仍有效的技能拥有准星，结束/取消后回退上一项，没有有效拥有者则默认隐藏。
- 进入瞄准态立即把相机前向对齐船头、去除视觉 Bank Roll、关闭旋转滞后并隐藏系统光标；瞄准期间持续跟船，`LookAction` 改为移动虚拟准星。退出恢复原旋转滞后与光标状态，但不恢复进入前视角，普通鼠标环绕从当前方向继续。
- 准星对外只提供归一化屏幕位置与反投影世界射线。本轮不做目标选择、确认发射、RPC 或服务器命中；现有编队、基础武器和右键导弹都没有准星 Tag，行为不变。

### 僚机编队与空中三维导航

- Ready飞船默认拥有25架僚机，分成5个Flight。第一套默认跟随技能为 SwarmOrbit：以飞船 Position 为平移锚点，用每 Flight 共享的缓慢进动旋流、每成员稳定 Curl Noise、240~520m 软活动带、140m 舰体排斥、上下约140m厚度、局部分离和弱对齐直接生成 Preferred Velocity。它不追逐精确槽位，不继承船头 Yaw 或舰体 Pitch/Roll，也不允许算法直接改写 Transform；初始化从静止开始，由唯一 Integration 按有限加速度包络起飞。
- DoubleRing 兼容方案恢复为 V1 原始语义：内环13架（600m、+150m、顺时针）和外环12架（900m、-150m、逆时针），仅作为旧方案回退。Formation 切换会重新投影确定性种子/参数，但保留每架当时的 Transform 与 Velocity。
- 当前SimulationLease Owner客户端以30Hz运行Mass StateTree、Guidance、固定翼积分、分离、避障和恢复；巡航Candidate为5Hz，得到服务器战斗/避障授权时最高10Hz。Active期间Relay按真实Mass固定步保留30Hz中间轨迹，每批最多选8点并优先包含发射帧；协议v11每Flight最多附带16条发射记录，服务器逐段验证真实飞行路径后接纳开火。开火批次和新武器配置的确认可靠传输，平均上传预算不变，允许一个包的到达抖动余量。
- 空中路径继续来自独立`GuLiFlightNavigation`插件的预烘焙八叉树、Portal和连通分量数据，本轮不换底座、不改格式、不重烘。常态 Orbit/Follow 不运行 A*；只有 CatchUp/Recover 才按 Flight 异步寻路到稳定恢复锚点。A* 输出只提供安全走廊；逐架 heading probe 同时给出战略方向和下一固定步安全方向，按实际剩余净空与刹车距离动态限速，必要时允许安全停至0。Integration 最终段检查仍 fail-closed；服务器只在 Candidate 到达时读取同一数据做版本、运动、净空和 Sweep 校验，不运行 Wingman StateTree、A*、Steering 或 Transform 积分。
- 表现可见性与模拟新鲜度分离：存活且仍在 roster 中的实例在短时断流后最多外推0.5秒，随后冻结最后姿态且不可交互；换 Lease Owner 时也保留旧表现直到新时间线首帧。只有死亡、roster 移除或 Group 终局结束才回收。
- 僚机逻辑Transform始终以局部`+X`对准速度；当前`SM_Wingman_Mass`的可见机头实际朝局部`-X`，因此只在Owner/Remote HISM实例最终提交时叠加局部Yaw 180°。该修正不反转速度，不进入Candidate/Accepted Snapshot，也不改变Remote Mass镜像、武器朝向或导航校验。
- Relay 客户端逻辑钟与 Mass 固定步进都把单帧追赶上限设为4 tick，并丢弃启动卡顿的超额余量，避免服务器按11个逻辑tick验位、客户端却只积分4个tick而产生`IntegrationError -> InvalidIdentity -> Lease Stale`。一架僚机没有安全下一步时只让该成员Recover，不再把Emergency通过Flight组级OR扩散给另外四架；服务器收到Trail后也不再把0.2秒弧线误判成穿出Portal拐角的直线弦。`gs.Wingman.Stats`可直接对照活动模式、半径、速度和首架位置。
- 单机最终位移被FlightNav或物理门拒绝时，积分器保留最后合法位置、冻结被拒航向的反向并刹停，同时继续推进该成员的固定步时钟。速度为0后可以瞬时旋转到冻结逃逸方向；下一帧只有真实位移段通过导航、碰撞和Carrier精确门才会移动。这个例外优先消除可见停滞，正常编队和攻击转向仍使用有限转弯率。
- 其他客户端只插值服务器已接纳快照并做有界视觉外推。运行期 Candidate 断流按1秒Stale、2秒Unavailable、3秒活动租约撤销推进，但3秒状态保留Roster/Health/AbilityConfig/Accepted Snapshot，不等于终局`Lifecycle::Revoked`。无备份Offer获胜时，原Owner按不高于1Hz复用RequestResume，经可靠Bootstrap与全Flight原子候选重新校验后才回Active；服务器不会替飞，也不放宽世界门。Ship销毁、显式拆组或初始化失败的真正Revoked仍为终局。

### 装配与热切换
- 触发：R = 循环换引擎，T = 循环换武器（飞行中随时）
- 流程：本地 R/T 通过 `ServerRequestCycleParts` 提交循环换装意图；按槽位更换通过 `ServerRequestPartChange` 提交 socket 与服务端目录索引。服务器校验当前 Air 拥有者、比赛阶段、就绪状态、装配版本/屏障代次、100ms 请求间隔，再检查真实 socket、非抽象部件类及兼容表；新组件注册/挂接成功后才卸旧件，发布新版 `LoadoutState` 并重算移动配置。
- 反馈：客户端在装配属性到达后重建本地部件并显示结果；服务器拒绝不兼容/缺 socket 配置时保留合法状态并记录原因。客户端调用旧 `InstallPart` 的 bool 返回 false 只表示没有本地同步安装成功，不能当作服务器已拒绝异步请求。
- 完整性：默认部件只由服务器在 BeginPlay 安装。客户端 `OnRep_LoadoutState` 与 BeginPlay 共用应用入口，要求全部条目成功；资产、socket、组件注册/挂接或蓝图回调造成不完整时保持未就绪并低频重试，不会确认半套装配。

### 6DOF 飞行
- 触发：W/S 前进/反推减速、A/D 左右平移（**平移不转向**，含 W+侧移组合；侧移时机身向侧移方向轻倾 5°、松手归位）、Space/C 升降、Q/E **偏航转向（角速度惯性模型）**、鼠标控制**摄像机环绕**、**滚轮缩放相机（Dreadnought：6666.667/格，期望臂长钳 13333.333~83333.333，默认 25000；上滚拉近）**、Shift 加力（×2）
- 流程：`UGuLiShipMovementComponent` 继承 CharacterMovement，仍使用 MOVE_Flying；当前 Air Dreadnought 空装配的有效极速为2700cm/s、有效加速度为300cm/s²，飞行刹车为60。**偏航带惯性**——按住 Q/E 角速度平滑爬升到 ±40°/s（YawResponseSpeed=3），松开后按阻尼衰减继续转约 2-3 秒才停（YawStopDamping=1，越小滑得越远）；转向时同样轻倾 5°，压弯跟随**实际角速度**（惯性旋转期间保持倾斜，转停回正）
- 反馈：相机完全独立于飞船姿态（AbsoluteRotation），只跟鼠标走；松手后按 60 减速漂移（巨型舰惯性）
- **相机避障（单系统，只认舰船与地形）**：SpringArm 自带探测**关闭**（幽灵回缩，另案）；全部由飞船 Tick 调 `ResolveCameraArmCollision()` 校验（2026-08-25 起函数化，单写者），**命中过滤谓词只认 `AGuLiStrikeShip`（含他舰/舰上部件）与 `ALandscapeProxy`**——道具/方块等一切其他实体不参与镜头避障（2026-08-25 对照实验：相机可停进 10km 方块内）。判据两级：端点重叠门控（Dreadnought 探针半径 3333.333 cm，在期望机位压不到相关几何体→直接用期望臂长）→ 压到则**两段式**由外向内扫掠推出（第一段=舰体包围球短走廊覆盖自身舰，无相关命中退全长 ZoomMax 走廊覆盖地形/他舰；凸包内起步向外扫掠引擎不报命中）。Dreadnought 滚轮期望臂长 13333.333~83333.333、默认 25000；位置滞后关、旋转滞后开。舰体资产约定：SIMPLE_AND_COMPLEX + 凸包分解

### 网络移动与装配/调参屏障

- [GuLiShipMovementComponent](../../Source/GuLiStrike/Gameplay/Ship/GuLiShipMovementComponent.cpp) 是飞船运动的唯一写者。推进、侧移、偏航和加力进入 CMC SavedMove/packed move；服务器重放输入，拥有客户端预测并接受位置/旋转及偏航积分状态校正，远端代理消费服务器姿态和平滑。没有把 Ship Tick 的本地位移再通过另一套 RPC 同步。
- 服务器把装配与 `GMRuntimeState` 修饰汇总成完整 `FGuLiShipMovementConfig`，连同 ConfigRevision、RequiredLoadoutRevision、BarrierGeneration、当前连接身份以及位置/速度/偏航/滚转基线成组复制。客户端计算的 UI 数值不能直接改写权威飞行参数。
- 装配、GM 参数或拥有身份变化会建立新屏障，暂停旧配置下的操控。拥有客户端等所需装配版本完整应用后，清理旧预测历史但保留 CMC 时间戳，应用服务器基线并发送精确配置 ACK；服务器复核身份、版本和代次后确认放行。Listen 主机的本地拥有者在同样条件满足时本地确认；远端模拟代理不代替拥有者 ACK。
- 装配/GM RepNotify 可能先于 BeginPlay，也可能互相先后到达，不能据其中一次 OnRep 就开始飞行。`IsShipReady()` 同时要求本舰当前装配已完整应用、移动配置及身份屏障已确认；旧代次移动、迟到换装或开火不能启动新代次。
- 换装会中止当前持续开火；失去就绪时清理飞行输入和按住开火状态，失去本地 Air 身份、占有或 EndPlay 时还会移除输入映射。相机环绕、滚轮和避障仍属于本地显示，不复制相机状态。
- Excel/DataTable 仍提供持久数值基线；`gs.GM.*` 是服务器当前 World 的临时修饰，不写回表。新生飞船由 Registry 初始化 GMRuntimeState，已有客户端通过 RepNotify 消费，最终飞行参数统一走上述配置屏障。
### 数值（推重比）
- 装配或数值修饰变更后重算：推重比 = Σ引擎推力 ÷ (舰体质量 + Σ部件质量)。
- 极速 = 当前调参预设的 `BaseMaxSpeed × clamp(推重比 ÷ 6, 0.5, 2)`；加速度使用同一个推重比倍率，但取独立的 `BaseAcceleration`。
- Dreadnought 0 引擎落在0.5下限：基础极速1800→5400后，有效极速900→2700cm/s；基础加速度保持600，所以有效加速度仍为300cm/s²。`Default` 行保持基础极速1800、基础加速度600。

### 开火
- 触发：鼠标左键按住
- 流程：拥有者通过可靠 `ServerSetFiring` 发送开始/停止意图，不为每一发弹丸发 RPC。[GuLiStrikeShip](../../Source/GuLiStrike/Gameplay/Ship/GuLiStrikeShip.cpp) 在服务器校验当前已占有 Pawn、Air、BattleReady、比赛进行中及配置版本/屏障；服务器遍历已装武器，由部件按射速冷却，从权威舰体/槽位变换加 MuzzleOffset 生成复制弹丸。
- 权威边界：炮口排除 Listen Server 外观平滑偏移；弹丸运动、碰撞、命中与销毁由服务器执行，客户端只显示复制结果，不自行做碰撞或寿命销毁。停火在就绪撤销后仍可执行，旧配置的迟到开始开火会被拒绝。
- 反馈：现有飞船部件武器仍保持物理弹丸链，不迁移为GA；其命中通过`GuLiShipProjectileLedgerBridge`接入统一Target Adapter和幂等Damage Ledger。空舰体不会产生这类部件弹丸，但僚机技能不依赖Ship socket或DefaultParts。

### 旧僚机武器兼容行为（V3不默认装备）

- 初始自动武器由Ship被动GA授权全编队。每架存活Wingman独立选择三维球形范围内的最近合法敌人，维护自己的2秒冷却、DomainFireSequence和Accepted状态引用；攻击不让僚机进入追击。
- 主动导弹由鼠标右键请求，客户端只显示预测锁定。服务器重新验证Ship/Group、目标敌我、2500m范围、LOS、能力版本和8秒Ship共享冷却，再选择一个稳定Flight齐射；没有合法Emitter时不进入冷却。
- 每个合法成员产生一条服务器逻辑导弹，不生成复制Actor。逻辑弹体30Hz推进、Segment/Sphere Sweep、发射后不换目标；客户端消费Launch/Correction/Impact或Expire事件构建视觉。

### 飞船与僚机生命

- Ship生命由自定义服务器Health Component写入，Wingman生命由服务器Roster/生命周期数据写入；两者不使用GAS AttributeSet。
- 基础武器、导弹和Ship物理弹丸都经Damage Ledger幂等结算。Wingman死亡后停止移动、索敌和FireIntent；母舰存活且组为Active时每15秒补1架。
- Ship死亡取消全部能力、失效旧GroupAbilityConfig并结束旧组。公共重生生成新Ship、新ASC、新GroupGeneration和新Wingman身份，只恢复稳定AbilityId载荷。
