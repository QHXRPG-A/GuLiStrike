# 飞船（DIY 模块化装配）

- 最近更新：2026-09-03（新增Ship Pawn独立GAS、25架僚机双环编队、初始自动武器和主动导弹；本机自动化与短时Listen通过，正式硬Gate待完成）

## 模块概述

玩家驾驶可自由改装的太空飞船。当前公共战局 Air 角色默认配置为 `BP_CombatAvatarFly01`（Dreadnought 无畏舰）：仅该子蓝图把继承的根 Scale 覆盖为 1，父 `BP_GuLiStrikeShip` 仍保持 0.3；舰体资源已烘焙为原始资源的 0.5，运行尺寸约 `19378×45023×6985 cm`。装配模型：**主体是 Character，部件是组件，槽位是舰体网格上的 socket，部件携带可接入槽位名集合**。换装在飞行中按键请求，由服务器确认后复制装配结果；引擎/武器的数值差异影响飞行性能与火力。当前子蓝图实际没有 socket 和默认装配，属于空舰体；下文四部件配装与 virgon 槽位基线属于母 `BP_GuLiStrikeShip`，不能套用为当前无畏舰已安装的部件。

飞船现在还拥有随Pawn生命周期创建的独立Ship ASC，以及由Ship能力统一授权的25架僚机。空舰体只表示没有“飞船自身部件武器”，不再表示没有僚机编队或僚机武器。

## 机制细节

### 公共战局与 Air 身份

- 飞船作为 Air 角色 Pawn 接入 [GuLiBattleGameMode](../../Source/GuLiStrike/Battle/Framework/GuLiBattleGameMode.cpp)，与 Commander、Ground 共用 GameState、PlayerState、PlayerController、席位和重生流程；不需要把三个独立 GameMode 在同一个 World 拼合运行。
- 原 Commander GameMode 保留兼容类名，组合三类 Pawn 配置及士兵发布组件；`AGuLiShipTestGameMode` 只把初始分配顺序改成 Air→Ground→Commander，仍通过同一张席位表，不允许客户端直接指定角色。
- [GuLiPlayerNetSyncComponent](../../Source/GuLiStrike/Battle/Network/GuLiPlayerNetSyncComponent.cpp) 先完成战局/身份握手并确认 `BattleReady`。飞船操作不等待 `SoldierStreamReady`；它还要等待本舰装配和移动配置就绪。指挥官 HUD/输入已按角色关闭，飞船只给本地 Air 拥有者安装自己的输入映射。
- 当前已审计 `BP_CombatAvatarFly01`：无 socket、DefaultParts 为空；空装配可以形成合法版本并完成移动就绪，但不会产生引擎/武器部件。母 `BP_GuLiStrikeShip` 有四个默认部件，可作为换装/开火验证对象；本轮没有给无畏舰擅自添加槽位或默认武器。

### Ship GAS 与僚机技能

- `AGuLiStrikeShip`拥有随Pawn创建和销毁的复制ASC，Mixed复制模式，`OwnerActor=AvatarActor=Ship`。它与PlayerState上的Army ASC完全分离；Army ASC继续只服务指挥官军队。
- Ship与每架Mass Wingman都不新增`AttributeSet`。Ship生命、速度、伤害继续来自自定义Health、基础表、部件和修饰源，并只通过`RecomputeStats`/CMC配置屏障提交；GameplayEffect不得修改这些数值。
- PlayerState只保存会话级稳定AbilityId。新Ship重生时创建新ASC并重授能力，旧AbilitySpecHandle、活动实例、临时效果和冷却全部丢弃。
- 首版能力为`Ship.Ability.Formation.DoubleRing`、`Ship.Ability.Weapon.Basic.Auto`和`Ship.Ability.Weapon.Missile.Salvo`。双环与初始武器是服务器自动激活的长驻被动；鼠标右键通过`InputTag.Ship.Wingman.Missile`请求主动导弹齐射。
- Ship GA只负责组级授权、互斥、取消、共享冷却和GroupAbilityConfig投影。每架Wingman不创建ASC，逐架编队、导航、避障、索敌和开火意图由客户端Mass处理。

### 僚机编队与空中三维导航

- Ready飞船默认拥有25架僚机，分成5个Flight。双环为内环13架（600m、+150m、顺时针）和外环12架（900m、-150m、逆时针）；飞船悬停时僚机仍持续盘旋，不能悬停或每帧吸附槽位。
- 当前SimulationLease Owner客户端以30Hz运行Mass StateTree、Guidance、固定翼积分、分离、避障和恢复；巡航Candidate为5Hz，得到服务器战斗/避障授权时最高10Hz。
- 空中路径来自独立`GuLiFlightNavigation`插件的预烘焙八叉树、Portal和连通分量数据。客户端异步A*并平滑，服务器只在Candidate到达时读取同一数据做版本、运动、净空和Sweep校验，不运行Wingman StateTree、A*、Steering或Transform积分。
- 其他客户端只插值服务器已接纳快照并做有界视觉外推。Owner失联后服务器不会替飞；组按1秒Stale、2秒Unavailable、3秒Revoke阈值停止战斗、隐藏和换主。

### 装配与热切换
- 触发：R = 循环换引擎，T = 循环换武器（飞行中随时）
- 流程：本地 R/T 通过 `ServerRequestCycleParts` 提交循环换装意图；按槽位更换通过 `ServerRequestPartChange` 提交 socket 与服务端目录索引。服务器校验当前 Air 拥有者、比赛阶段、就绪状态、装配版本/屏障代次、100ms 请求间隔，再检查真实 socket、非抽象部件类及兼容表；新组件注册/挂接成功后才卸旧件，发布新版 `LoadoutState` 并重算移动配置。
- 反馈：客户端在装配属性到达后重建本地部件并显示结果；服务器拒绝不兼容/缺 socket 配置时保留合法状态并记录原因。客户端调用旧 `InstallPart` 的 bool 返回 false 只表示没有本地同步安装成功，不能当作服务器已拒绝异步请求。
- 完整性：默认部件只由服务器在 BeginPlay 安装。客户端 `OnRep_LoadoutState` 与 BeginPlay 共用应用入口，要求全部条目成功；资产、socket、组件注册/挂接或蓝图回调造成不完整时保持未就绪并低频重试，不会确认半套装配。

### 6DOF 飞行
- 触发：W/S 前进/反推减速、A/D 左右平移（**平移不转向**，含 W+侧移组合；侧移时机身向侧移方向轻倾 5°、松手归位）、Space/C 升降、Q/E **偏航转向（角速度惯性模型）**、鼠标控制**摄像机环绕**、**滚轮缩放相机（Dreadnought：6666.667/格，期望臂长钳 13333.333~83333.333，默认 25000；上滚拉近）**、Shift 加力（×2）
- 流程：`UGuLiShipMovementComponent` 继承 CharacterMovement，仍使用 MOVE_Flying（加速 800、刹车 60、极速 2400@母蓝图默认配装）；**偏航带惯性**——按住 Q/E 角速度平滑爬升到 ±40°/s（YawResponseSpeed=3），松开后按阻尼衰减继续转约 2-3 秒才停（YawStopDamping=1，越小滑得越远）；转向时同样轻倾 5°，压弯跟随**实际角速度**（惯性旋转期间保持倾斜，转停回正）
- 反馈：相机完全独立于飞船姿态（AbsoluteRotation），只跟鼠标走；松手后按 60 减速漂移（巨型舰惯性）
- **相机避障（单系统，只认舰船与地形）**：SpringArm 自带探测**关闭**（幽灵回缩，另案）；全部由飞船 Tick 调 `ResolveCameraArmCollision()` 校验（2026-08-25 起函数化，单写者），**命中过滤谓词只认 `AGuLiStrikeShip`（含他舰/舰上部件）与 `ALandscapeProxy`**——道具/方块等一切其他实体不参与镜头避障（2026-08-25 对照实验：相机可停进 10km 方块内）。判据两级：端点重叠门控（Dreadnought 探针半径 3333.333 cm，在期望机位压不到相关几何体→直接用期望臂长）→ 压到则**两段式**由外向内扫掠推出（第一段=舰体包围球短走廊覆盖自身舰，无相关命中退全长 ZoomMax 走廊覆盖地形/他舰；凸包内起步向外扫掠引擎不报命中）。Dreadnought 滚轮期望臂长 13333.333~83333.333、默认 25000；位置滞后关、旋转滞后开。舰体资产约定：SIMPLE_AND_COMPLEX + 凸包分解

### 网络移动与装配/调参屏障

- [GuLiShipMovementComponent](../../Source/GuLiStrike/Gameplay/Ship/GuLiShipMovementComponent.cpp) 是飞船运动的唯一写者。推进、侧移、偏航和加力进入 CMC SavedMove/packed move；服务器重放输入，拥有客户端预测并接受位置/旋转及偏航积分状态校正，远端代理消费服务器姿态和平滑。没有把 Ship Tick 的本地位移再通过另一套 RPC 同步。
- 服务器把装配与 `GMRuntimeState` 修饰汇总成完整 `FGuLiShipMovementConfig`，连同 ConfigRevision、RequiredLoadoutRevision、BarrierGeneration、当前连接身份以及位置/速度/偏航/滚转基线成组复制。客户端计算的 UI 数值不能直接改写权威飞行参数。
- 装配、GM 参数或拥有身份变化会建立新屏障，暂停旧配置下的操控。拥有客户端等所需装配版本完整应用后，清理旧预测历史但保留 CMC 时间戳，应用服务器基线并发送精确配置 ACK；服务器复核身份、版本和代次后确认放行。Listen 主机的本地拥有者在同样条件满足时本地确认；远端模拟代理不代替拥有者 ACK。
- 装配/GM RepNotify 可能先于 BeginPlay，也可能互相先后到达，不能据其中一次 OnRep 就开始飞行。`IsShipReady()` 同时要求本舰当前装配已完整应用、移动配置及身份屏障已确认；旧代次移动、迟到换装或开火不能启动新代次。
- 换装会中止当前持续开火；失去就绪时清理飞行输入和按住开火状态，失去本地 Air 身份、占有或 EndPlay 时还会移除输入映射。相机环绕、滚轮和避障仍属于本地显示，不复制相机状态。
- Excel/DataTable 仍提供持久数值基线；`gs.GM.*` 是服务器当前 World 的临时修饰，不写回表。新生飞船由 Registry 初始化 GMRuntimeState，已有客户端通过 RepNotify 消费，最终飞行参数统一走上述配置屏障。
### 数值（推重比）
- 装配或数值修饰变更后重算：推重比 = Σ引擎推力 ÷ (舰体质量 + Σ部件质量)
- 极速 = 1200 × clamp(推重比 ÷ 6, 0.5, 2)；加速度同比例
- 0 引擎 → 极速 600（下限，当前空装配无畏舰适用）；母蓝图默认配装（2 标准+1 重型引擎）→ 推重比 13.75 → 极速 2400（上限）。上述为无额外 GM 倍率的配置基线，不是新网络移动实测结果。

### 开火
- 触发：鼠标左键按住
- 流程：拥有者通过可靠 `ServerSetFiring` 发送开始/停止意图，不为每一发弹丸发 RPC。[GuLiStrikeShip](../../Source/GuLiStrike/Gameplay/Ship/GuLiStrikeShip.cpp) 在服务器校验当前已占有 Pawn、Air、BattleReady、比赛进行中及配置版本/屏障；服务器遍历已装武器，由部件按射速冷却，从权威舰体/槽位变换加 MuzzleOffset 生成复制弹丸。
- 权威边界：炮口排除 Listen Server 外观平滑偏移；弹丸运动、碰撞、命中与销毁由服务器执行，客户端只显示复制结果，不自行做碰撞或寿命销毁。停火在就绪撤销后仍可执行，旧配置的迟到开始开火会被拒绝。
- 反馈：现有飞船部件武器仍保持物理弹丸链，不迁移为GA；其命中通过`GuLiShipProjectileLedgerBridge`接入统一Target Adapter和幂等Damage Ledger。空舰体不会产生这类部件弹丸，但僚机技能不依赖Ship socket或DefaultParts。

### 僚机武器与导弹

- 初始自动武器由Ship被动GA授权全编队。每架存活Wingman独立选择三维球形范围内的最近合法敌人，维护自己的2秒冷却、DomainFireSequence和Accepted状态引用；攻击不让僚机进入追击。
- 主动导弹由鼠标右键请求，客户端只显示预测锁定。服务器重新验证Ship/Group、目标敌我、2500m范围、LOS、能力版本和8秒Ship共享冷却，再选择一个稳定Flight齐射；没有合法Emitter时不进入冷却。
- 每个合法成员产生一条服务器逻辑导弹，不生成复制Actor。逻辑弹体30Hz推进、Segment/Sphere Sweep、发射后不换目标；客户端消费Launch/Correction/Impact或Expire事件构建视觉。

### 飞船与僚机生命

- Ship生命由自定义服务器Health Component写入，Wingman生命由服务器Roster/生命周期数据写入；两者不使用GAS AttributeSet。
- 基础武器、导弹和Ship物理弹丸都经Damage Ledger幂等结算。Wingman死亡后停止移动、索敌和FireIntent；母舰存活且组为Active时每15秒补1架。
- Ship死亡取消全部能力、失效旧GroupAbilityConfig并结束旧组。公共重生生成新Ship、新ASC、新GroupGeneration和新Wingman身份，只恢复稳定AbilityId载荷。
