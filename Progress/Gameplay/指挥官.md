# 指挥官

- 最近更新：2026-08-31（底坞改为中文斜切标题与单一横向士兵卡，仅汇总所选存活士兵血量；选取半径仅保留键盘 `+`，脚环改为单面中空网格；保留协议 v3、Unit 1000m 硬切和 Crowd 资产优化）

## 模块概述

指挥官从大地图视角观察战场，通过圆形范围临时组织附近友军并下达移动指令。玩家能够操控的最小组织粒度是最多 25 名小兵，但这 25 人不是永久编制：每名 Soldier 始终独立，下一次选择可以重新组合。

当前原型生成红蓝双方各 250 名 Soldier，共 500 名。服务端裁决身份、选择、单位指令、移动、避碰、生命和伤亡；客户端负责即时输入反馈、平滑显示、小地图和指挥 UI。

## 机制细节

### 圆形选取与动态 ControlCohort

- 触发：本地工具默认是“选取”；左键点击有效世界地面提交选取，Shift+左键执行整组 Toggle。按 `7` 或点击选取槽幂等返回选取；仅在选取模式下，通过数字键盘 `Add` 或主键区 `Shift+Equals` 按 `80→200→450→80m` 循环，裸 `Equals` 不触发，移动模式不改变半径。底坞不再提供 `+` 按钮。
- 流程：客户端只提交圆心、半径档、Replace/Toggle 和 Revision，不提交 SoldierId。服务端从圆内存活、同队、可控 Soldier 中取种子，以动态质心确定性聚合最多 25 人；最后一组欠编时可从圆外 300m 内补员。
- 空地：圆内没有有效种子时不从圆外凭空拉人。
- 欠编：可用友军不足时允许少于 25 人。
- Replace：重新生成当前所有临时组。
- Shift/Toggle：命中既有 Cohort 任一成员即移除整个 Cohort；保留组不重排，未被旧组占用的新兵另组。
- 冻结：成员在当前 SelectionRevision 内冻结；死亡不补员；全灭后移出选择。
- 反馈：选中 Soldier 脚环为金色，未选为队伍色；底部将当前唯一兵种 `DefaultSoldier` 的多组选择合并为一张“士兵”卡，显示去重后的存活人数、存活者合计生命和指令状态，不再按 CohortId 拆卡。底层最多 25 人的 ControlCohort 与选择、移动 RPC 保持不变。

### 移动指令与 OrderFormation

- 触发：已有已确认选择时，按 `1` 或点击移动槽进入一次性移动工具；下一次有效世界左键提交移动后自动回到选取，无效点击继续保持移动。右键仍立即提交移动，成功后回到选取；若已确认选择因全损、清空或换局而失效，工具自动回到选取。
- 取消：移动模式下 `Esc` 只取消移动工具；选取模式下 `Esc` 才发送现有清空选择请求。
- 流程：每个选中 Cohort 在服务器上复制为独立 OrderFormation；同一批次的所有 Formation 使用同一个 NavMesh 投影目标。最新被接受的移动指令覆盖重叠 Soldier 的旧 ActiveOrderId，旧 Formation 剩余成员继续前进。
- 选择与指令解耦：重新选择、Clear 或 Esc 不会停止已经接受的旧移动指令。
- 路径：每个 Formation 共享一条 `CommanderSoldier` NavMesh 路径，不为 25 人分别寻路。
- 阵形：途中依据可走宽度在 1–5 列间弹性调整；真正进入最后接近阶段后取消槽位修正，不再恢复 5×5，由 Mass Avoidance 和局部分离在目标域内自然铺开。
- 碰撞：服务端使用 7.5m Mass AgentRadius、Mass Avoidance 和局部分离；不使用 500 个 Chaos 刚体。
- 到达：到达域按本批移动指令的初始接受人数计算；25/50/100 人半径约为 50m/65m/95m。同批次须等待引导点、末弯和所有仍存活且仍跟随本指令的成员共同满足后统一结束；死亡或改令成员不阻塞。
- 拒绝：目标无法在一个 AgentRadius 内投影时返回 `InvalidTarget`；路径无效或 Partial 时返回 `PathFailed`。
- 反馈：命令线 Pending 为橙黄、Accepted 为青绿、Rejected 为红色；三态均带流水箭头和目标标记。

### 双端权威与即时表现反馈

- 服务端以 30Hz 模拟每名 Soldier，是位置、速度、朝向、指令、碰撞、生命和伤亡的唯一权威。
- 服务端以 10Hz 发送逐兵 PoseChunk；可靠 Soldier FastArray 同步身份、队伍、生命、最大生命和 ActiveOrderId，协议版本为 v3。权威快照在比较/复制前执行 Sanitize；SnapshotRevision 使用 RepNotify、跨 MatchEpoch 单调推进，只在事实快照或 MatchEpoch 变化时向 HUD、地图和血条发出一次批量通知。
- 客户端默认在服务器时间后 100ms 渲染，用带速度的 Hermite 插值位置、最短弧插值 Yaw；缺帧最多外推 100ms。
- 点击移动后立即进行最长 250ms 的表现预测；最大距离由复制的有效 Soldier 移速推导，默认 `3600cm/s × 0.25s = 900cm`。拒绝或权威 Pose 到达后用 150ms 融回。
- Teleport 或误差超过 10m 才允许硬校正；预测不参与选取、碰撞、命中或伤亡。
- 无动画：FourFRobot 使用静态代理，但移动时持续更新位置、Yaw 和地面贴合。

### 指挥官 UI 与战场反馈

- 相机：WASD/屏幕边缘平移、Q/E 旋转、滚轮缩放；透视相机 Pivot 跟随 Landscape，不是固定高空俯视。
- HUD：运行时使用顶中战况条、左下战术地图和底部指挥坞三岛布局；WBP 只负责布局，全部数据和输入逻辑位于原生 C++。
- 顶栏：显示真实比赛时长与蓝/红队；当前没有权威来源的目标和比分显示“目标未启用”与 `-- : --`。
- 底坞：保留本地队伍、角色、“在线／同步中”和己方存活数/初始总数；“编队”“指令矩阵”使用中文斜切底板标题，不再使用双斜杠分隔的英文标题。战术点和轨道能量显示 `--`，未实现命令保持禁用。
- 士兵卡：当前唯一兵种使用一张横向卡；按选中 SoldierId 去重后，只统计可靠状态中仍存活的士兵，多 Cohort 不拆卡。人数显示存活人数，血条按“存活者当前生命总和 ÷ 存活者最大生命总和”填充，同时显示两个合计值；阵亡者减少人数并退出血量分子与分母。例如 25 名满血士兵阵亡 5 名后显示 20 人，余下士兵仍满血时血条保持 100%。
- 卡片状态：没有选择或已确认没有存活成员时折叠；已收到选择但可靠状态尚未就绪、缺少成员状态或未完成本局同步时显示“同步中”，人数与生命显示 `--`，不展示假满血。卡片继续只读，并由选择、可靠状态和命令回执事件刷新；换局清除旧选择，避免复用跨局 SoldierId。
- 小地图：左下角以 10Hz heading-up 批量绘制 Landscape、双方存活兵、选中强调和相机视野框；左键点击地图消费输入并聚焦对应世界位置。
- 选区：选取模式显示当前 80m、200m 或 450m 的世界选区圆；移动模式通过既有命令反馈线显示 Pending、Accepted 或 Rejected。
- 单位脚环：未选为队伍色，选中为金色；保留常显和穿透场景遮挡的行为。Soldier 摧毁后模型隐藏，暗红脚环保留 5 秒后隐藏。
- 世界血条：双方存活 Soldier 在“本地选中或受伤”且距相机焦点不超过 300m 时显示；一个本地 ISM 批量绘制约 84×12px 的黑底、左到右红色连续血条、四分位线和选中青框，接受地形深度遮挡。
- 输入保护：顶栏、小地图和底坞使用实际 Slate 像素几何阻止世界 LMB/RMB，兼容 DPI、窄屏和超宽画幅。

### 表现层性能与本地调参

- Unit 与 Ring 继续使用两个稳定 `UInstancedStaticMeshComponent`；始终保持 `SoldierId → InstanceIndex`，不按距离增删实例，也不使用 HISM。
- Unit 以每个实例到当前客户端摄像机的距离计算裁切，默认在 `100000cm` 硬切；Ring 不做距离裁切，因此远距、选中和残骸状态仍可通过脚环读取。
- Unit 默认关闭阴影、距离场照明、动态间接光和光追可见性；Ring 固定关闭同一组重型渲染功能，但继续正常 Raster 显示。
- Ring 网格改为 64 段、128 三角形的单面中空圆环，模型外/内半径为 48/34cm；保留实例缩放 12，世界外/内半径为 576/408cm。材质精简为 6 节点，保留 RGBA 色值、原有发光 `RGB × 3` 和透明度 `A × 0.58`；不改变队伍色、选中色、穿透、无限距和死亡保留时长。
- 正常 Soldier 模型为 `SM_CommanderFourFRobot_Crowd`：单材质、单 Section，LOD tris 为 `18999 / 964 / 238`；旧 FourFRobot 只保留为烘焙源和回退。
- 非 Shipping 构建可用 `gs.Commander.Presentation.List/Get/Set/Reset` 修改当前客户端 World 的六个表现白名单 key；Override 不复制、不写 Config 或磁盘，World 销毁后清空。
- 表现调参优先级为 C++ 默认值 `<` Config `<` 当前 World 本地 Override；非法值拒绝，不静默 Clamp。

### Soldier 数据与运行时 GM

- 当前 500 人统一使用 `DefaultSoldier`。移速、最大生命、静态模型、攻击力、防御力和攻击范围来自 `GuLiStrikeCommander.xlsx / Soldiers`，经 JSON 与 UE DataTable 导入。
- 每个 Game/PIE World 初始化时解析一次；缺表、缺行、非法值或非 `UStaticMesh` 模型会回退安全默认值，不在 Tick 查表。
- 非 Shipping 构建可用 `gs.GM.List/Get/Set/Reset` 在当前 World 会话中覆盖 Soldier 与飞船白名单数值；Override 不写回 Excel、DataTable、ini 或磁盘。
- Soldier 移速在下一次 30Hz 服务端权威步应用到 500 个 Mass Entity；最大生命按原生命比例换算，死亡单位保持 0。
- 攻击力、防御力和攻击范围已经进入权威 Soldier Stats，但当前没有攻击 AI、目标选择或伤害公式消费这些字段。
