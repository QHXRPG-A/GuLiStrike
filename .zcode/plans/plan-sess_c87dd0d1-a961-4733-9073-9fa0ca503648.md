## 为什么必须在编辑器内移动

`.uasset` 包之间的引用（材质→贴图、地图→网格体等）以绝对路径 `/Game/包名/...` 存储。直接在文件系统移动会全部断裂。编辑器内移动会自动生成重定向器（Redirector）保持引用有效，之后再修复引用并删除重定向器。编辑器当前正在运行（UE 5.7.4，unreal-mcpython 已连接），通过 `execute_python` 脚本化完成。已确认 C++、Config、uproject 均无对这些路径的引用。

## 实施步骤

### 1. 前置检查（MCP execute_python）
- 确认当前打开的地图不是资产包内的地图（应是 LVL_Main），包内地图未被加载
- 用资产注册表确认 8 个源路径的资产数量与探索结果一致（约 4,600）

### 2. 编辑器内批量移动（保留重定向器）
对 8 个包逐一执行 `AssetTools.rename_assets([AssetRenameData...])`，路径映射：
- `/Game/City_of_Brass_Enviroment` → `/Game/Assets/Environments/City_of_Brass_Enviroment`
- `/Game/MafiaBarnPack` → `/Game/Assets/Environments/MafiaBarnPack`
- `/Game/Stylized_Medieval_Town` → `/Game/Assets/Environments/Stylized_Medieval_Town`
- `/Game/KiteDemo` → `/Game/Assets/Environments/KiteDemo`
- `/Game/ParagonProps` → `/Game/Assets/Props/ParagonProps`
- `/Game/KEStatues_Lite` → `/Game/Assets/Props/KEStatues_Lite`
- `/Game/SampleMap` → `/Game/Assets/SampleMaps/SampleMap`
- `/Game/Lighting` → `/Game/Assets/SampleMaps/Lighting`

按包分批（每批约 250 个资产），记录进度，每批完成后核对成功数量。

### 3. 修复重定向器并删除
在旧路径下枚举所有 Redirector，逐个重命名到目标路径（即编辑器"Fix Up Redirectors"的脚本化等价操作），重写引用者包后删除重定向器。由于包间内部引用量大，这一步会重存几乎所有包（SampleMap 的 343MB 烘焙数据最慢），预计总耗时 10–30 分钟。

### 4. 保存并验证
- `save_dirty_packages` 保存全部
- 验证：旧路径下无残留资产/空目录；`/Game/Assets` 下资产数与迁移前一致；输出日志无 missing reference 报错
- 抽查打开 MafiaBarn 与 ParagonSample 地图确认加载正常（选一个轻量的验证）

### 5. 处理 __ExternalActors__（MafiaBarnPack 专属）
`Content/__ExternalActors__/MafiaBarnPack/...`（148 个外部 Actor 文件）按路径约定与地图路径镜像。检查编辑器移动地图时是否已自动迁移到 `__ExternalActors__/Assets/Environments/MafiaBarnPack/...`；若未自动迁移：关闭编辑器后在文件系统把该子树移动到镜像新路径，再打开编辑器验证 Level Instance 地图 Actor 完整。

### 6. 收尾
- `git status` 确认新路径出现在未跟踪列表、旧路径消失（这些包本来就是未跟踪状态，不做提交，除非你要求）
- 清理后报告最终目录结构与资产计数

## 风险与对策
- **引用断裂**：重定向器 + 修复流程保证引用完整；若 LVL_Main 引用了包资产也会被自动重写
- **OFPA 外部 Actor**：第 5 步专门处理，有文件系统兜底方案
- **编辑器 UI 状态**（Content Browser 历史路径）指向旧路径，无害且会自愈
- 中途失败可重跑：脚本按包记录进度，已完成的包跳过
