# 矿车入厂停住：历史根因诊断

后续变更：用户要求删掉不必要的厂内通行逻辑，已移除以下诊断针对的接地采样、姿态拟合和碰撞扫掠，改为沿固定路线直接进出。本报告保留当时的原因与证据，不代表当前运行时仍执行该算法。旧只读探针和复现脚本分别保存在[legacy-probe.cpp.txt](legacy-probe.cpp.txt)、[legacy-diagnose_factory_ground.py.txt](legacy-diagnose_factory_ground.py.txt)；当前回归见[实施记录](../../../Progress/DevelopmentDocumentation/20260918-游戏对象与效果统一缩放至0.2倍.md)。

## 结论

`AGuLiMiningVehiclePawn::CalculateFactoryGroundPose` 的向下接地射线起点仍是 `BaseZ + 500cm`。工厂表现及其物理几何已缩至0.2，屋顶碰撞顶面从原模型的1990cm降到398cm，但这个500cm常量未适配，射线现在从屋顶上方射下。

接地过程没有区分地板和屋顶，直接取Visibility首个命中，并在倾斜后二次采样中用最大高度支撑整车。车底采样点跨入屋顶覆盖区后，屋顶被误当成地面，生成高约3.60m的错误车身目标。随后完整车体扫掠正常命中厂体，拒绝移动。最后的碰撞阻挡是保护结果，首次错误发生在接地采样。

## 首次异常与单变量对照

同一个卡住位置、同一套模型及碰撞，唯一变量为**只读诊断函数**的射线起点高度，正式 `GuLiMiningVehiclePawn.cpp` 未改。

| 检查项 | 现有500cm起点 | 对照100cm起点 |
|---|---:|---:|
| 工厂基准Z | -5857.818723 | 相同 |
| 倾斜二次采样 `tilted_ground_2_1` 的世界Z | -5459.818723（屋顶） | -5833.818723（地板/入口平台） |
| 同一采样点相对基准高度 | 398cm | 24cm |
| 最终候选车身世界Z | -5347.246067 | -5707.519312 |
| `body_sweep_blocked` | true | false |

首次平面9点采样仍命中地板/坡道；坡度拟合得到5.69328°。带车底高度的旋转偏移令前排点从工厂局部X约247.29cm移到235.28cm，跨过屋顶碰撞的X=240cm前缘，第二次采样先命中屋顶。两种候选车身高度差360.273cm。

局部X=440cm时原探针尚无异常，X=435cm开始出现屋顶误采样。屋顶碰撞与作者脚本 `UCX_SM_RPF_Body_07` 一致：中心19m、厚1.8m、前缘12m；乘0.2后顶面3.98m、前缘2.4m。不是一个不应存在的封口碰撞盒。

## 假设排序及排除

1. **接地高度未随尺寸适配，误选屋顶（高概率/低验证成本）**：源码、二次射线命中、屋顶几何及单变量对照共同确认。
2. **门仍参与碰撞（低成本）**：实际Door为NoCollision；原门阻挡位置已越过，本次命中是Body，排除为当前首次故障。
3. **厂门开口太小或实心碰撞封口（中等成本）**：同位置保留所有厂体碰撞，仅修正诊断起点，完整车体扫掠即无阻挡，排除为此停点原因；未据此声称全路线所有姿态都通过。
4. **导航/客户端插值导致停顿（中等成本）**：在服务器只读几何查询里确定性复现；不依赖网络、时间缓冲或寻路推进，排除为当前直接原因。

## 建议修复及回归边界（本轮未实施）

- 修正接地查询起点的尺度归属，依据最终车辆脚底/工厂局部净空选取合理起点，防止头顶屋顶成为支撑面；不要直接关闭Body碰撞。
- 对照100cm在本停点有效，但不能把一个诊断常量直接视为所有地形的完整方案。保留真实地形高度覆盖，检查可踏步高度、坡面及连续支撑约束。
- 复用现有失败姿态检查“采样命中地板、Z连续、下一步无阻挡”；再跑真实坡道进厂、卸货、转向、出厂、两客同步及无重复缩放的既有验收。
- 原始22条探针包含多个固定高度位置，属于空间采样而非连续行车。靠内位置沿用冻结Z，会出现初始几何不贴地；不能把它们当作修复后的完整路线通行结果。
- 根因置信度：高。正式修复与全闭环回归：未实施/未通过。
