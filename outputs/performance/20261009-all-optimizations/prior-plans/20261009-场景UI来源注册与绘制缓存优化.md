# 场景 UI 来源注册与绘制缓存优化 — 技术方案

## 当前状态与验收边界

四阶段A–D已在现有GuLiStrike运行模块内实施并加载。客户端World来源注册表、修订驱动、模板/投影缓存、Capture名单与动画分离及HUD双缓冲均已接通；稳态全世界来源发现迭代为0。玩家效果验收待完成，不以静态检查或来源计数代替UI视觉确认。

本次不是完整旧UI构建A/B：运行时回退只关ProjectionCache等局部开关，来源注册与模板始终存在。没有已证实的“四阶段UI整帧降幅”；独立叶节点拆分无新增收益证据，保留现有叶节点内部缓存。不会以总GT变化推算UI收益。

## A：World弱来源注册与生命周期

新增 [UGuLiSceneUISourceRegistry](../../Source/GuLiStrike/Commander/UI/GuLiSceneUISourceRegistry.h)，提供 `RegisterSource / UnregisterSource / NotifyChanged / GetSnapshot`及来源/Membership/Content/Pose修订。只存弱UObject、类别、代次和修订；本地选择、视图阵营、颜色/MID和投影仍归LocalPlayer/Widget，不在World表中持有本地选中集合或跨World资源。

每客户端World初始化一次，初始来源接入后用Actor生成/EndPlay和来源自己的重建通知维护；尚未完整注册的组件/晚到身份进入小范围Pending重试，Widget重挂载只读注册快照，不重新全世界发现。现有Presentation、Pawn环、据点Halo与Outline来源分别接入。

已接通最终Mass插值、据点变化、工程旅行状态、模型Mesh及本地队色更新；Ship节点最后姿态与Mesh更换通知，拥有/失去拥有、晚到PlayerState、重生与席位切换更新来源。场景注册不修改服务器玩法、颜色规则或选择顺序。

## B：内容修订与逐帧活动状态分离

选择/归属/血量/路线/资源/模型变化触发Content或Membership；最终插值/机械姿态完成后通知Pose。按来源身份/代次/修订与ViewSignature重建相应内容；不在Paint中重建世界来源和业务状态。活动血条、路线、面板仍逐帧跟随和处理期限，Capture动画也继续更新。

`UGuLiSceneUIWidget::EndHUDFrame()`与Begin组成待提交/已提交双缓冲；HUD用作用域提交所有返回路径，空帧提交明确清空。帧F内容可用至F+1，F+2主动过期；World、OwningLocalPlayer/Widget重挂载变化均失效，不能因为没有下一次Begin留下永久旧内容。无Viewport时也保持提交/期限合同。

## C：模板、投影批次和完整裁剪

固定形状模板包括Ring64、Halo48、Disc32及预览网格，复用三角/索引结构。按来源/视图/选择顺序及内容/姿态修订缓存整个投影批次，摄像机或来源移动会正确失效。复用本地模板并不意味着移动场景几何可无限缓存。

裁剪用完整图元范围；线段横跨屏幕、图元中心屏外但面积仍在屏内及近裁剪面走原完整裁剪路径，未改成“中心不在屏内就丢弃”。保留投影顺序、绘制层次及60000索引上限，布局/世界切换按依赖失效。

Capture名单、捕获内容与Slate几何独立：名单只在成员/阵营/Mesh修订时重建，RT里动画仍继续捕获；建造预览内容单独更新。不把停止重建ShowOnly名单误当成停止动画捕获。材质/纹理引用由反射对象保持，Render线程使用的MID/RT不会因普通缓存GC丢失。

## D：按依赖Paint失效与进一步候选

[Widget](../../Source/GuLiStrike/Commander/UI/GuLiSceneUIWidget.cpp)按几何/内容/活动状态修订触发Paint失效；现有叶节点内部模板与批次缓存优先落地。来源、捕获、投影、Slate几何、Paint分别记录Scope。当前高运动负载单客户端Update约0.2–0.3ms，OutlineCapture约0.08–0.13ms，Paint约0.16–0.21ms；这些子项与Update/Paint不相加。

整体Slate还有Prepass/Paint/Input等非本Widget成本，单纯拆叶不保证额外收益。尚无拆叶候选的三对功能/收益证据，因此不采用额外叶节点层级，也不默认扩大Volatile范围。保持已有交互、焦点、构建预览及Ship面板合同。
