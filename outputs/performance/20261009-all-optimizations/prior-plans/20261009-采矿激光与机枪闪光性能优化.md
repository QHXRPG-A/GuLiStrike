## P0：独立、可重跑的视觉候选

`Scripts/Vfx/tool_laser_candidates.py`冻结实际W并写最终绝对1.5W，断言源基准未变化，重跑不叠乘；采矿历史5/25cm冲突已统一为源基准5cm、候选7.5cm。`Scripts/build_electromagnetic_miner.py`只重建基准5cm，候选发布由独立脚本负责。

候选主体使用 `/Game/GuLiStrike/FX/Mining/M_ToolLaser_Opaque`：Opaque、Unlit、ParticleColor RGB→Emissive，保留深度遮挡、Ribbon结构、原宽度曲线与组件缩放。原透明淡出转为 `max(0, RibbonWidth × saturate(Color.a))`宽度包络；不会以不透明材质的Opacity口模拟透明淡出。原有端点Spark及禁用次级发射器状态保留。开始/峰值/停止对照已录制，用户已认可该版本的宽度、端点、遮挡和停止表现。

每个激光独立保存Source、WideAdditive、Opaque、Nodes16、Nodes8、NoPresentationCollision、NoSolver、GPU对照。合计17个候选系统及1个材质通过Native Niagara/材质编译、保存与读回。蓝图资产默认空直引并使用ID36/45、相对缩放1，未二次叠乘。

## P1：范围准入与持续/瞬时生命周期

[LOD](../../Source/GuLiStrike/Commander/Presentation/GuLiCommanderLODSubsystem.cpp)新增 `ShouldRenderWorldEffectBounds`，复用每帧视图缓存，任一合格本地视图可见即可。持续光束覆盖枪口—落点整段，建造包括实际建筑、枪口、扫描及现有组件范围；飞行/尾迹使用自己的完整范围，未只看弹头。

采矿为Inactive/Visible/Suspended，独立0.05秒检查、全不可见宽限0.15秒，暂停Blueprint Tick、Niagara模拟及端点写入，恢复仅读最新任务。唤醒不依赖已停Tick；独立状态检查合同≤0.10秒。建造Visible逐帧、Suspended 0.05秒轻量检查，扫描起始时间在暂停期间保留。专服作业、服务器碰撞和网络启停保持。

瞬时枪口/命中在生成前做范围查询；不可见机械枪口回池，去重、过期、结束与墓碑继续维护，回屏不补播旧事件。未知动态供应商系统没有认证发射范围时保守放行，不能用任意小固定Bounds造成误裁剪。三个项目枪口/命中候选具备4096cm未缩放发射包络，包含最大2000cm/s速度、800cm/s²重力、1.25s生产/跟随寿命、尺寸曲线、相机偏移和生成半径；原动态模拟Bounds保留。原材质链只有Emissive/Opacity输出、无顶点位移，见[认证](../../outputs/performance/20261009-implementation/flash-certified-envelopes.json)。机械枪口还累计历史发射范围和已存活粒子的组件Bounds。

EffectType/Scalability未改变项目既有碰撞、端点和激活合同；使用明确的运行时状态机与范围入口，不依赖引擎Cull Reaction猜测。局部回退 `gs.Effects.BoundsCull 0`可恢复原准入。

## P2：枪口/命中拆分与模块评估

枪口和命中已分别复制到项目目录，原Glow、Flash、RibbonCore、RIbbonTrailFollower、Sparks、Debris六层及位置事件生产/跟随链保留，没有无收益证据地删除层。独立枪口NoCollision候选只取消Sparks/Debris表现碰撞，保留其他模块；GT系统独占下降约35.64%、所有CPU工作量下降22.82%，但绝对GT约减少0.04ms，整帧+0.89%在波动内，故不采用精简候选，保留原模块。

目的资源独立及认证Bounds已正式接入ID5/52；其他没有认证包络的动态资源仍保守准入。保持原ID、比例、事件及网络去重；原Vendor资源没有被覆盖。

## P3/P4：节点、碰撞、力求解与GPU结果

所有模拟候选以加宽Opaque为视觉基准，各三对10+30秒。两个激光的启用主光束均建立80/16/8节点对照，禁用次级结构保留。

| 候选 | GT系统独占 / 所有CPU工作量中位变化 | 整帧 / GPU平均变化 | 采用决定 |
|---|---:|---:|---|
| 仅1.5倍加宽 | −0.26 / −0.38% | −0.64 / +0.33% | 用户指定视觉；性能收益未证实 |
| Wide→Opaque | −0.81 / −0.85% | +1.84 / +0.27% | 用户指定视觉；性能收益未证实 |
| 80→16节点 | −0.03 / +0.02% | +2.12 / +0.05% | 不采用，保留80 |
| 80→8节点 | −3.59 / −3.38% | +3.60 / +0.01% | 不采用，收益不稳定 |
| Spark取消表现碰撞 | −82.14 / −75.12% | −18.11 / −0.27% | 默认保留原Spark，仅供单独审核 |
| Beam取消力求解 | −3.60 / −3.49% | −2.79 / 约0% | 不采用，三对收益不稳定 |
| Beam GPU，Spark CPU | −2.73 / −1.63% | −2.96 / +47.71% | 不采用，GPU P95+86.65% |

**碰撞归因勘正：Beam/Beam001没有Collision模块，当前激光表现碰撞在落点Spark。** NoPresentationCollision关闭的是Spark Collision，因而会改变落点火花行为；与“保留现有端点”的正式Opaque版本分开。不能把75%的所有CPU降幅说成光束主体不透明或仅取消Beam碰撞的收益。服务器碰撞未变。最终模块回读见[原/新碰撞配置](../../outputs/performance/20261009-implementation/laser-collision-final-readback.json)。该候选虽超20%成本目标，视觉/行为尚未通过，默认不接入。

GPU只是兼容Beam的评估副本，事件跟随/端点继续CPU；有GPU退化证据，不因“GPU模拟”名字推算收益。16/8节点、力求解或GPU不满足采用标准，保留原配置并归档结论。
