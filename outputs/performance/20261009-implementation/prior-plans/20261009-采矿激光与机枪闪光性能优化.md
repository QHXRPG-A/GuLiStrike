# 采矿激光与机枪闪光性能优化 — 技术方案

## 1. 目标与开发顺序

降低采矿、建造激光及机枪枪口/命中闪光的客户端表现开销，优先减少游戏线程上的无效工作。采用 **运行裁剪 → 枪口与命中拆分 → 光束与碰撞精简 → 选择性 GPU 迁移** 的顺序，每阶段保留独立结果与回退入口。

本文将“剪枝”落实为两类改动：运行时跳过不可见表现的生成、模拟和参数更新；资产内部减少不必要的发射器、粒子节点与模块。只隐藏渲染不能作为模拟已停止的完成证据。

本轮开发范围是表现代码、Niagara 候选及特效目录接线。采矿产量、建造进度、权威遮挡/伤害判定、射速、网络事件和稳定 VfxId 保持既有契约。现有弹道照明、导弹和其他特效继续使用各自规则，避免一次修改共享可见性入口影响所有表现。

本文件是独立开发方案，关联已有需求与分析证据；`planned / not_run` 表示优化尚未实施，文档交付不等于游戏性能或视觉验收通过。

## 2. 基线、事实与验证边界

### 2.1 已有性能证据

| 项目 | 结果 | 口径 |
|---|---|---|
| 引擎与平台 | Windows、UE 5.7.4 编辑器 | 源码版 UE5.7；非打包运行 |
| 地图 | `/Game/Maps/LVL_CommanderMassPrototype` | 后续对比沿用此图 |
| 网络与窗口 | 同一编辑器进程，1 个专用服务器、2 个客户端 | 多 World 成本汇总，不能当成单客户端结果 |
| 确认采样 | 15.075 秒、330 帧 | 平均约 21.89 FPS |
| Frame / GameThread / GPU | 45.681 / 45.698 / 12.536 ms | 平均值；主要瓶颈在游戏线程 |
| 采矿激光计时 | 1.359 ms/帧 | 对齐 Trace 窗口，以 323 个引擎帧归一化的独占 CPU 时间 |
| `NS_Flash` 计时分组 | 1.337 ms/帧 | 尚未拆分枪口、命中及具体用途 |

两项相加约 **2.696 ms/帧**，约为平均帧时间的 5.9%。这是优化机会的量级，不是可全部清零的承诺；新增裁剪检查、组件管理和 GPU 提交也有成本。不能用粒子减少比例推算相同比例的 FPS 提升。

### 2.2 当前资产读回

| 系统/发射器 | 当前配置 | 对开发的影响 |
|---|---|---|
| Mining / Beam | CPU、Ribbon；生成配置 80 个节点；CurlNoiseForce 已禁用 | 可逐档验证节点精简；曲线、宽度和材质效果仍需检查 |
| Mining / Spark | CPU、Sprite；生成配置 20 粒子；Collision 启用 | 碰撞是成本候选，实际占比待拆分 |
| Mining / Beam001、Spark001 | 已禁用 | 不重复计入新的运行时优化收益 |
| Flash / Glow、Flash | CPU、Sprite；生成配置各 1 粒子 | 适合作为轻量枪口候选基础，优先减少发射器数量 |
| Flash / RibbonCore | CPU、无 Renderer，包含 GenerateLocationEvent | 负责生成事件，不能按“没有渲染器”直接删除 |
| Flash / RIbbonTrailFollower | CPU、Ribbon，包含 ReceiveLocationEvent | 与事件源一起评估；现有事件链不能直接转 GPU |
| Flash / Sparks、Debris | CPU、Sprite、Collision 启用；Debris 生成配置 5 粒子 | 先判断枪口/命中是否需要，再评估碰撞或 GPU |

两套系统均未绑定 Niagara Effect Type，未开启系统 Scalability Override；系统固定包围盒开关关闭，发射器报告为 Dynamic Bounds；没有预热配置。固定包围盒字段的 ±100 cm 未启用，不能据此认定现有包围盒错误。

生成配置不等于常驻粒子数。部分模块输入 API 返回空列表，静态分支、链接输入、循环和实际生命周期需在实施前补全读回。本次读取时 PIE 已结束，没有新增运行实例或模块 A/B 测量。

### 2.3 现有裁剪缺口

闪光已经使用 ManualRelease 对象池、过期事件过滤与 `IsVisibleLocation` 检查。但 `ShouldRenderWorldEffect` 在指挥官近景/战术视角直接放行，概览视角禁止；该入口没有视锥判断。非指挥官视角使用距离限制，当前 Catalog 值为 20000 cm。因此“调用了可见性函数”不代表屏外实例已被剔除。

采矿表现的 Blueprint Tick 持续调用左右炮口更新，包括端点、旋转、可见性及 `Activate(false)`；开始采矿开启 Tick，停止采矿关闭 Tick，没有整束视锥检查。`Activate(false)` 不能当成每帧 Reset 的证据。建造也使用同一激光资源，每帧更新扫描端点。概览的按视图隐藏只控制渲染，不自动停止上述更新或 Niagara 模拟。

当前矿车资产仍有 `MiningRangeCm` 计算与端点限长节点，与制作脚本的部分历史描述不同。以实际资产为基线；端点长度差异另行记录，不在性能优化中擅自改写采矿表现契约。

## 4. 分阶段实施方案

### P0：冻结基线与表现契约

记录两套资源的发射器、模块启用状态、关键静态分支、生成数量、生命周期、材质、缩放、包围盒、组件 Scalability 标志，以及所有 ID 5/52/36 消费者。保存候选/生产版本和源表变更清单，区分枪口、命中、采矿和建造。

补充观测：每客户端活跃实例与粒子数、生成/裁剪计数、屏外比例、持续激光暂停数、端点写入数及回池数。优先复用现有诊断计数和采样工具；必要的计数只服务本范围，不引入新的测试框架或全局 Gate。

### P1：生成前裁剪与持续表现暂停

**查询范围。** 新查询内部复用 LOD 子系统缓存视图，返回按包围盒判断的准入结果。先仅接入 ID 5/52/36 消费路径，不直接改变所有 `IsVisibleLocation` 调用者。维持近景/战术/概览规则，以及非指挥官的既有距离规则；同一 World 有任意合格本地视图可见时保留表现。

**瞬时闪光。** 用资源最大可见范围、当前基础/动态缩放计算保守包围盒，加入屏幕边缘余量。完全屏外且无合格视图时，在分配/激活组件前略过。已生成枪口退出可见范围后及时终止并回池；继续遵守错过出膛时间窗口不重放的规则。命中短暂尾迹是否立即终止按候选视觉决定，不能造成边缘突然消失。

**整束激光。** 包围盒覆盖炮口到实际端点，以及光束宽度、曲线偏移和存活火花范围；先确认静态分支，不只用矿车中心或炮口判断。若有弯曲光束，不能仅以两个端点的直线 AABB 代替曲线范围。

**暂停与唤醒。** 显式区分权威工作状态和客户端显示状态：

| 表现状态 | 行为 | 转换 |
|---|---|---|
| Inactive | 不生成、不更新；清理尾迹和表现引用 | 工作开始后评估可见性 |
| Visible | 激光模拟；仅在必要时写入端点/旋转；建造扫描保持必要更新 | 不可见持续超过宽限后转 Suspended |
| Suspended | 停止 Niagara 与昂贵 Blueprint 表现更新，保留最新工作状态和目标 | 可见时恢复当前表现；工作结束时转 Inactive |

暂停不能依赖被关闭的 Blueprint Tick 自己恢复。采矿适配组件或既有客户端更新入口需维持轻量可见性检查，且在网络状态、目标、相机层级变化时重评；允许按客户端 World 汇总待恢复对象。暂停期间收到的新目标、停工、销毁和运输状态更新缓存，恢复只显示最新状态，不播放旧特效。

建议实验值：可见性重评间隔 0.05 秒、不可见宽限 0.15 秒，恢复观察目标 ≤0.10 秒。均为待验证调参值，最终按实际相机和任务数量记录。普通静态目标使用位置/旋转变化阈值减少重复写入；阈值实施时确定，不能省掉运动炮口或建造扫描的必要更新。

**Niagara Scalability。** 为目标资源规划 Effect Type，检查组件允许 Scalability、可见性策略、实例重要性和 Cull Reaction。持续激光使用可恢复语义，瞬时闪光不恢复过期事件。按视图规则与 Effect Type 相容后再启用距离/实例预算，避免默认距离把高空战术镜头下的可见光束裁掉。必要表现优先于装饰细节，最终预算由基线和视觉结果确定。

### P2：枪口与命中资源拆分

先从商城闪光复制项目候选，ID 52 评估保留 Glow/Flash，删减事件拖尾、碎屑和碰撞；只有在行为与材质绑定兼容时，才将两个发射器合并为更少发射器/多个 Renderer。ID 5 保留独立命中候选，根据真实命中距离评估细节分档。

RibbonCore 与 RIbbonTrailFollower 必须作为依赖链一起评估。轻量枪口可以在视觉批准后去掉整条链；完整命中若需要拖尾，保留 CPU，或另行制作事件替代候选，不能留下悬空事件接收者。

候选需覆盖重防号双枪、扫荡者、移动/转向开火、单位与地形命中。沿用已有造型和配色参考；减少细节导致时序或外观变化时，提交可播放候选对照，依据[项目美术规范](../RequirementDocument/GuLiStrike美术规范.md)及[特效技能](../../.agents/skills/ue5-vfx-production/SKILL.md)记录审核后再切正式引用。现有审核仅按其版本与范围复用。

### P3：采矿光束与表现碰撞精简

Beam 节点按 **80 → 16 → 8** 逐档制作候选，检查各距离/角度下的曲线、宽度、UV、纹理和目标切换。数值是实验档位，不是已确定终值。已禁用的 Beam001/Spark001、CurlNoiseForce 不计作新增收益；审查 SolveForcesAndVelocity 是否仍有有效输入，核实后才精简。

Mining.Spark、Flash.Sparks、Flash.Debris 的碰撞分别比较原配置、简化平面或无碰撞、远处关闭细节等候选。表现碰撞调整与权威采矿遮挡/伤害查询分离。保留必要的接触和弹跳，先分项测量再决定取舍。

### P4：选择性 GPU 候选

| 发射器 | 决策方向 | 必须先解决 |
|---|---|---|
| Mining.Spark、独立火花/碎屑 | 候选 | 模块/DI 支持、GPU 碰撞方法与视觉偏差、包围盒及并发量 |
| Mining.Beam | 精简后再比较 CPU/GPU | Ribbon/Beam 模块兼容、目标更新延迟与正确边界 |
| Glow/Flash | 保留 CPU 作为首选比较项 | 单次各 1 粒子；优先减少发射器和系统实例 |
| 位置事件拖尾链 | 保留 CPU 或先重构 | 现有事件不支持 GPU，不能只切换 Sim Target |

GPU 只改变粒子 Spawn/Update/Simulation Stage 的执行目标，System/Emitter 脚本、组件与参数管理仍有 CPU 开销。CPU Collision 与 GPU 深度/距离场碰撞不是等价实现，按实际项目可用能力选择，不为本任务默认开启新的硬件光追设施。

GPU 候选明确边界：闪光使用覆盖最大位移与缩放的合理固定范围；变长激光按实际端点/曲线设置组件局部范围，核对世界/局部坐标、旋转、缩放和火花尾迹。不能直接启用现存 ±100 cm 值，也不能用无限大包围盒规避裁剪错误。编译成功和视觉一致分别记录，再按同场景决定是否采用。

若 P1～P4 后仍显示大量实例固定成本，再提出批量共享闪光系统方案；先依据生成密度判断是否值得，不在首阶段改造整条战斗表现架构。

## 5. 性能对比与采用判据

### 5.1 可复现场景

使用 `/Game/Maps/LVL_CommanderMassPrototype`，记录镜头位置/层级、两客户端视口尺寸、质量设置、单位/矿车数量、采矿/建造任务、开火负载、网络模式及有效资源版本。沿用当前质量、帧率限制和 VSync 设置，任何变化单独记录。资产加载和预热完成后采样。

| 场景 | 观察目的 |
|---|---|
| 全部可见：采矿、建造及真实交火 | 精简候选的开销与视觉 |
| 同负载移出镜头，仅保留边缘实例 | 生成准入、暂停和边缘余量 |
| 光束中段可见但矿车/端点在屏外 | 整束裁剪不误杀 |
| 近景、战术、概览切换及不同客户端视角 | 按 World/本地视图判断，恢复正确 |
| 停止开火/采矿、目标切换、销毁/切图 | 不重放旧事件、无残留和池泄漏 |

复用 [capture_live_pie.py](../../Scripts/Performance/capture_live_pie.py)，每次只改变一项，在稳定负载下采集至少 15 秒；为识别编辑器噪声，每个有效候选与当前基线各对比 3 组。实际负载无法匹配时记录原因，不能继续引用旧绝对值声称收益。

报告 Frame/GameThread/GPU 的中位数、P95；相关独占计时、实例/粒子数、生成/裁剪/回池数、端点写入数与视觉结果。资源改名后将原资源与新枪口/命中/激光分组合并比较，并计入新增查询及更新入口，不能靠离开 `NS_Flash` 名称分组制造表面收益。

### 5.2 拟议目标与完成判据

以下是开发初始目标，不是已有用户验收或优化承诺：

| 范围 | 采用/完成判据 |
|---|---|
| 完全屏外瞬时闪光 | 无合格视图时新增目标实例为 0；旧事件不会在回屏重放 |
| 完全屏外持续激光 | 宽限后目标模拟与端点写入停止；轻量唤醒检查继续，恢复目标 ≤0.10 秒 |
| 可见表现与尺寸 | 光束不断裂/误裁剪；重防号枪口 2 倍、扫荡者 1 倍、机枪命中 2 倍；按现有审核契约记录 |
| 生命周期 | 停工/停火后活跃实例归零；复用无旧参数，切图后清理；专服不激活目标视觉模拟 |
| 性能工作目标 | 同场景相关表现 CPU 成本争取降低 ≥20%；不按发射器数量比例推算 |
| 候选采用 | 成本下降在重复样本中稳定可见，视觉/功能通过；Frame 与 GameThread 中位数/P95 无可重复回退 |
| GPU 候选 | CPU 收益有效且 GPU 总帧时间仍保有余量；粒子更多或“已转 GPU”本身不作为采用理由 |

若 ≥20% 目标未达到，仍如实记录有效收益与剩余固定成本，交付性能待验收，不虚填通过。若采样波动掩盖差异、GPU 增耗抵消收益或视觉退化，保留原配置。
