# PIE游戏线程耗时与避障候选查询优化 — 技术方案

## 结论与本轮边界

当前瓶颈在游戏线程。两轮有效CSV平均帧时间42.95/45.68ms，GPU平均12.39/12.54ms，约22–23FPS。同一进程同时承担一个专用服务器和两个客户端的工作；这些数据代表当前联机PIE配置，不能直接代表单客户端或打包游戏。

预测避障的主要成本在“找出并排序候选”，不是之后的避让力求解。建议保留已验收的预测转向、迎面靠右、近距离分离及停止友军让行，先减少重复计算和容器操作。关闭预测层、缩短预测时长或降低单兵调度频率都涉及行为变化，暂不作为本方案的第一批实现。

本轮交付分析和实施方案，没有修改游戏C++、配置、地图或资产。之前的性能采样来自用户已开启的PIE；本轮追加只读观察时编辑器返回`worlds=[]`，未重新启动游戏，也未取得新的避障计数。下面明确区分实测、源码确认与假设推算。

查询约占处理器87.34%，约占同期游戏线程均值5.73%；后者因CSV/trace边界略有差异仅作近似。查询批次单次调用平均2.627ms、中位2.080ms、P95为4.273ms、最大5.205ms。一个批次包含本帧所有到期接收单位，不是单个单位花费2.62ms。

即使理想地消除全部查询成本，保持其他工作不变，45.68ms也仅降至约43.06ms；这不是已测优化收益，也不足以单独达到60FPS。

## 避障候选查询的作用与必要性

候选查询先利用空间网格找附近的单位和环境障碍，过滤自身、无效参与者、高度差和距离，再按“已经重叠 → 预测碰撞时间 → 距离 → 稳定键”选出危险对象。保留最多24项，随后求解只读取前12项；存在环境候选时，最多两个环境项被放到列表开头，占用这12个位置。

处理链如下：

```text
服务器Mass位置/半径/速度 + 动态环境障碍快照
    → 空间网格
    → 到期移动单位的候选查询和危险排序
    → 最多12项的预测避让加速度（包括迎面靠右）
    → 权威移动的期望速度
    → 近距离软避障速度约束
    → 现有导航/环境约束与实际位移
```

项目另有`SolveSoftAvoidanceVelocities`，使用0.5秒尺度的近邻速度约束、稳定单位对顺序和三轮修正；友军被动让行的速度上限为正常速度的25%。预测层使用2.5秒时域，并提供迎面相遇时的靠右偏置。两者服务的时间尺度和输出不同，不能因为都是“避障”就视为重复功能。

候选查询作为算法并非唯一选择，可以用另一种邻居索引或查询实现替代；但保留当前预测求解时，必须给它正确的邻居输入。删除查询和预测输出后，近距离约束仍存在，却不能据此保证提前转向、通行吞吐和迎面解锁仍符合既有验收。近距离约束也不是严格零穿透保证。本轮没有执行关闭预测层的A/B，不能宣称其无影响。

## 调度已经做了什么

处理器只在Standalone/Server运行，当前要求GameThread执行。策略以30Hz推进相位，按`SoldierId % 3`分成三组；未改令且持续移动的单位常规约10Hz求解。低帧率时一个引擎帧可以合并多个到期相位，每单位在该次执行仍只查询一次；停顿追赶最多三步。

命令版本变化会绕过本单位相位限制，但仍需本次存在到期相位；求解后记录处理版本，避免把同一版本持续当成强制求解。未移动、死亡、相位状态等按现有条件排除。静止但可参与的单位仍需要作为其他单位的障碍。

因此第一批优化不应再提出“把每兵30Hz降成10Hz”，当前已有这个频率。整批改令可能扩大当帧接收集合，后续用`ForcedSolveCount`的窗口增量区分常规与改令压力；本次未取得其分布。

## 源码确认的成本来源

### 扫描范围与候选上限是两件事

当前接收单位的搜索半径与格子尺寸为：

```text
R = max(1200,
        自身半径 + 全局最大参与单位半径
        + (自身最大速度 + 全局最大参与单位速度) × 预测时间
        + 自身半径 × 0.35)
S = max(300, 2 × 全局最大参与单位半径)
C = ceil(R / S)
网格查找次数 = (2C + 1)²
```

单位为cm、cm/s、s。预测时间在权威共享参数初始化中设为2.5秒。最大速度还参考实际/期望速度和共享参数上限，可能受兵种、运行时调参及肉鸽倍率影响；不能把类默认720cm/s当成当前所有实体的实值。

每次查询遍历整个正方形网格范围，即使大部分格子为空仍要做哈希查找；候选24只是最终保留量，不能限制访问量和精确判定量。大体型同时扩大S，因此“全局半径更大一定访问更多格子”也不成立，需同时观察空格查找与桶占用。

下面只展示公式的量级，**不是本次现场半径和速度的测量**。均假设自身与全局速度上限为720cm/s、预测时间2.5秒：

| 自身/全局最大半径 | R | S | C | 每查询网格查找数 |
|---|---|---|---|---|
| 150 / 150cm | 3952.50cm | 300cm | 14 | 841 |
| 150 / 625cm | 4427.50cm | 1250cm | 4 | 81 |
| 625 / 625cm | 5068.75cm | 1250cm | 5 | 121 |

直接改成固定3×3邻格或仅1200cm会破坏高速/大半径对象的覆盖边界，不能作为等价优化。

### 环境多格条目与每查询去重

单位只把中心写入一个格子，环境障碍按半径包围的XY范围写入多个格子。同一个大环境障碍可能在一次查询里被反复访问，当前用每查询新建的`TSet<int32> Seen`去重。

单位也进入该集合，虽然其条目没有跨格重复。`Seen.Contains`和`Seen.Add`发生在参与状态、高度和距离过滤之前，存在可减少的哈希和分配工作。环境重复条目的具体比例尚未测得，不能据此断言它占了2.62ms中的多少。

### 距离、碰撞时间与候选维护

每个唯一对象先做`FVector::Dist2D`开方。普通单位分支随后又把中心距离平方，用于范围与排序；可改为直接计算XY距离平方，并用半径和的平方判断重叠。环境排序使用表面净距，仍需保持其语义。

通过距离过滤的每个对象都计算威胁信息，并线性插入已排序的小列表；列表满24后仍继续扫描、判定和比较。不能仅凭距离比当前第24名远就丢弃：更远对象可能更早碰撞，排序先比较重叠和碰撞时间。

环境临时列表最多4项，最终只拿前2项；单位列表最多24项，当前消费者只取最终前12项。这是缩短候选维护列表的依据，但不会自动减少被扫描对象数量。

### 已有计数存在可见性缺口

`SelectNearestCandidates`已返回`BucketEntriesVisited`和`ExactCandidates`。前者在去重前递增，包含重复环境条目；它不包含空格子的哈希查找。处理器只累加后者，尚未把前者发布到状态/诊断。

现有`CandidateCount`是**通过精确范围过滤的全部对象数**，不是最多24项的保留数。`ColliderEvaluationCount`才反映最终求解处理量。`MaximumObservedBucketOccupancy`是历史峰值，也不是当前平均密度。`gs.GM.Commander.Nav.Stats`能打印这些已有统计，读数来自当前仍保留的实体片段汇总；实体删除会影响窗口差分，不能无条件把两个累计读数相减当成采样窗口总量。

已有纯策略测试中的空间查询示例使用默认DetectionDistance、未覆盖处理器动态半径的完整场景；历史测试不能替代当前现场的访问量和耗时证据。本轮没有运行或新增测试。

## 第一批实施方案：保持现有行为

| 顺序 | 变更 | 完成判据与边界 |
|---|---|---|
| A0 | 补查询工作量统计 | 用处理器/世界窗口增量记录查询次数、强制查询数、R/S分布、格子查找/命中数、桶条目访问、环境重复数、唯一对象数、精确候选数、保留数、实际求解数；与现有Trace作用域对齐。采用聚合统计，避免逐兵逐候选日志。 |
| A1 | 去除单位去重；复用环境查询标记 | 单位仍只入一个格子，直接进入过滤；环境用快照索引对应的代次标记数组替代临时TSet。每查询代次独立，溢出清零；快照变更时重新配置。只保留当前执行阶段需要的容量，无按单位永久增长的集合。 |
| A2 | 普通单位用距离平方 | 保持XY距离、高度阈值、有限值检查和严格重叠比较；环境净距仍按旧语义。边界浮点舍入可能有差异，静态审查不能把它描述成逐位相同。 |
| A3 | 仅维护实际消费的候选前缀 | 目标为单位前12项、环境前2项，合并后只保留最终前12项；危险排序、稳定键和环境前置顺序保持。精确候选计数仍覆盖所有通过对象，不改成保留数。 |
| A4 | 简化快照复制和临时容量 | 当前建网格时构造一份PolicyAgents，读取接收参数后又构造一份；评估复用同一连续快照和工作数组。保持同一次执行的索引、位置和半径对应关系，避免跨帧陈旧状态。此项优先级低于2.62ms查询热点。 |

A3的等价依据：设环境前置数为`e=min(2, 环境数)`，求解只消费`12-e`个单位候选；保留单位排序前12已经覆盖所需前缀，环境排序前2覆盖全部会被使用的环境项。现有代码没有第二处运行时消费者使用第13–24项。但函数合同、诊断和已有断言可能依赖列表长度，实施时必须一并审查；不在本轮新增或扩充测试框架。

A1–A4保持30Hz三相调度、改令版本语义、2.5秒时域、实际体型、预测力/靠右偏置、近距离软避障、停止/敌我/相位规则、导航合法性和网络协议。预测与近距离网格覆盖尺度不同，第一批不强行合并两层求解或共享跨帧网格。

## 后续扫描优化与行为调整的界线

如果计数表明主要耗时仍在扫描而非临时容器，后续评估按体型/速度分组的索引、普通单位查询格子的几何裁剪，以及大环境障碍单独索引。必须先证明候选覆盖条件，分别处理“单位中心距离”和“环境表面净距”；不能对两类对象套相同的中心圆裁剪，也不能在尚未发现局部高速对象前用局部最大速度缩小查询范围。

保持最终前12项一致需要保留当前对“无预测碰撞时间但距离较近”的对象排序。按2.5秒可达范围剔除这类旧候选，可能改变求解输入，应作为行为调整评估，而不是直接称为等价。

降低预测时长、查询频率或求解项数，以及取消预测层，均需重新验证迎面、交叉、停止友军让路、环境边缘和命令响应。并行计算属于更大的实现范围：快照必须不可变，工作线程不能访问World/UObject或注册表，结果需要在GameThread按实体/命令版本复核提交；当前不建议首先改变处理器线程约束。
