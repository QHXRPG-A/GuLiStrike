# 场景 UI 来源注册与绘制缓存优化 — 技术方案

## 结论与范围

四项改造应按“来源生命周期 → 数据更新边界 → 几何构建 → Slate 失效”依次推进。持续移动的对象和镜头仍需要及时更新投影；优先省掉重复发现、重复解释数据和重复构造固定形状的工作，再决定哪些绘制可以复用。

范围为脚环／选中标记、据点光环、血条、路线、建造预览、Commander HUD命令及Ship世界面板；其他UI与模拟热点单独处理。

保持[现行美术规范第8节](../RequirementDocument/GuLiStrike美术规范.md)：场景后处理之后绘制、不透明主体、环境颜色隔离、本地己方蓝／敌方红、未知阵营不显示脚环、世界径向宽度 20 cm、四个同色选中标记，以及血量／路径／放置合法性的功能色。使用现有正式模型和材质，不重新设计配色。重防号沿 `WM01 / UnitTypeId=2` 定位；玩家 Ground 地面机甲沿独立角色路径定位。

## 已知证据与收益边界

证据来源是[2026-10-09 PIE耗时分析](../../outputs/performance/PIE耗时分析_20261009.txt)、[确认窗口CSV汇总](../../outputs/performance/20261009-084725-confirmed/csv-summary.json)和[Insights汇总](../../outputs/performance/20261009-084725-confirmed/trace-summary.json)。一个编辑器进程内包含专用服务器和两个客户端，Map 为 `/Game/Maps/LVL_CommanderMassPrototype`。

| 指标 | 已采集结果 | 解释 |
|---|---:|---|
| 两轮平均帧时间 | 42.954 / 45.681 ms | 约23.3 / 21.9 FPS；场景会自动生产、扩建，不是优化前后对照 |
| 确认窗口 GameThread / GPU | 45.698 / 12.536 ms | 游戏线程占主导，GPU不是本次主要限制 |
| CSV UI 分类 | 6.913 ms/帧 | 游戏线程 Exclusive 分类；包含双方客户端及其他UI |
| SceneUI Widget Tick | 约1.434 ms/帧 | 对齐Insights窗口，两个客户端合计 |
| SceneUI Paint | 约0.883 ms/帧 | 同一窗口，两个客户端合计；与Tick合计约2.317 ms |
| Slate PaintSlowPath | 约4.342 ms/帧 | Inclusive，包含子项，不再与SceneUI Paint相加 |

因此，不能把全部 6.913 ms 归因于场景 UI，也不能声称删除 `Invalidate(Paint)` 就能回收该时间。当前捕获 GPU 成本、各子图元耗时和每次来源扫描尖峰还缺少独立分项。本方案先补分项，再用受控场景确认收益，不预设60 FPS达标或固定提速比例。计时采用相同窗口、同一线程和一致的 Inclusive／Exclusive 口径，参照[Epic Insights计时说明](https://dev.epicgames.com/documentation/unreal-engine/using-the-timers-and-counters-tabs-in-unreal-insights-for-unreal-engine?application_version=5.7)。

## 一、来源注册替代定期全场扫描

### 所有权与接口

建议增加一个客户端 `UWorldSubsystem`：`UGuLiSceneUISourceRegistry`，源码放在 `Gameplay/Presentation/`。它只维护UI可用来源、弱引用、代次和版本；不持有Widget／Slate／MID，不保存本地选择、不计算阵营显示色、不复制网络状态。注册头文件仅暴露普通C++类别、弱引用和原生委托；Subsystem本身按UE要求反射，不扩大Blueprint接口。

LocalPlayer容器订阅本World增减并维护快照，Overview继续管理总览／Visual。每World允许一次种子发现，Widget重新挂载不重复执行；若使用Overview初始集合，由表现适配层传入，来源表不反向依赖Commander UI。

建议原生接口为 `RegisterSource(Source, Kind)`、`UnregisterSource(Handle)`、`NotifySourceChanged(Handle, Flags)`、`OnSourcesChanged(Delta)`。操作幂等，验证来源属于同一World且不是模板对象；只在游戏线程修改。Handle包含弱对象身份、来源类别与注册代次，不能把实例槽号或裸指针当成可永久复用的身份。

### 分类型生命周期

| 来源 | 注册边界 | 更新／撤销边界 |
|---|---|---|
| Mass表现容器 | Presentation Actor BeginPlay／完成依赖初始化后 | EndPlay注销；名单、阵营批次、实例重分配和模型更换更新成员／资源版本；SoldierId附表现代次 |
| 据点光环 | Outpost组件成功创建VisualMesh之后 | ApplyOwnerState更新归属；EndPlay／组件撤销注销；VisualMesh重建重新注册 |
| 工程车辆脚环 | EngineeringTravel组件及拥有者已可用时 | OnRegister／OnUnregister与BeginPlay／EndPlay配合；传送开始／结束更新可见状态 |
| 玩家Pawn脚环 | 项目玩家Pawn就绪，身份未到也可登记候选 | Pawn的PlayerState变化、Controller占有／更换、重生、EndPlay；团队未知时不显示 |
| 血条／路线 | 原有每本地视图Renderer／RouteData建立后绑定 | 保持原所有权；实例销毁／替换时解除旧绑定并重新建立 |
| 捕获候选 | 单位／建筑可捕获Mesh就绪后登记候选，Mass批次单独登记 | 归属、死亡／相位、显隐、模型／组件／LOD替换更新；动画变形属于捕获内容变化 |

Actor生成时组件、PlayerState或复制数据可能未就绪，需由组件／Pawn回调补注册。兼容路径预算重试已知未就绪对象，不重新扫世界；覆盖动态新增组件和重新注册。

本机UE5.7的 `APawn::OnPlayerStateChanged`、`OnRep_PlayerState` 和 `AController::OnPossessedPawnChanged` 可作为相应适配入口；实施时接到实际玩家类，并保留Super调用。当前本地 `OnCommanderPlayerStateChanged` 继续用于身份事实变化，但PlayerState对象自身替换还需解除旧对象并绑定新对象。

### 稳态约束

稳定运行时，SceneUI来源发现的AActor／APawn全世界迭代次数应为0；弱引用失效清理只访问已登记集合。Dedicated Server、编辑器非Game World不创建UI来源表。关闭PIE、切World、切Controller、移除并重新挂载Widget时都应清理委托和代次，不保留前一World的来源。

不要只把 `RefreshSources` 换成定期遍历 `Overview->GetActors()`：它减少迭代器调用，却仍每次检查全部Actor。轮廓也要从已分类捕获候选更新ShowOnly名单，避免留下独立的0.1秒全Actor名单重建路径。按来源类别分别推进，未接通某类时保留该类兼容发现，并记录计数，不能提前删除导致漏显示。

## 二、事件数据与每帧位置更新分离

### 版本与触发源

快照分为“成员／样式”和“最终表现位置”。事件只标脏或记录变化ID，在一个刷新边界内合并；不在每个事件回调中立即Gather、构造几何或Capture。

| 版本／依赖 | 触发来源 | 消费者 |
|---|---|---|
| SourceRevision | 注册、注销、重新注册、来源重建 | 本地来源绑定、成员快照 |
| MembershipRevision | 名单增减、生命／相位／显隐、团队批次及模型变更 | 脚环成员、血条活动槽、捕获候选 |
| SelectionRevision | NetSync OnSelectionChanged；含工程车辆ActorIds | 本地选择集合、四标记、血条样式、路线成员 |
| IdentityRevision | 本地PlayerState更换、真实阵营／席位变化 | 本地配色、模式可见性和轮廓敌我过滤 |
| PoseRevision | 插值／预测／机械表现完成，工程车移动、据点悬浮、世界面板变换 | 世界位置、投影、路线起点；不替代网络Revision |
| AppearanceRevision | 生命值、选中样式、合法性、尺寸／半径变化 | 血条填充、环尺寸、放置功能色 |
| TimeRevision／Deadline | 受击显示到期、HUD命令过期、可见动画 | 移除旧图元或推进动画，不等待业务事件 |
| ViewSignature | ViewTarget、相机与投影矩阵、模式、分屏Rect、DPI、Geometry变换／裁剪 | 可见性和屏幕几何 |
| ResourceRevision | RT／纹理对象或尺寸、Brush／材质绑定、资源重建 | 资源句柄和对应绘制命令 |

现有 `OnVisualStatesChanged` 在处理可靠状态后发布变化ID；连续插值修改 `DirtyRingTransformSlots` 时没有保证逐次走这一事件。不能仅订阅它就关闭位置更新。应在Presentation更新最终缓存之后发布轻量姿态版本／变化槽位；机械模型变形和脚环位置分别记依赖，避免模型在原地动画而轮廓被冻结。

血条继续以Renderer的活动集、生命事件和受击期限为准，增加有效快照版本与可见槽索引；未活动的历史分配槽不参与每次Gather。当前0.1秒Maintenance还负责依赖维护与到期策略，只在这些职责被对应回调／期限唤醒覆盖后收紧，不直接删除计时器。路线沿现有OnSelection、OnEndpoints、OnRoster及增量队列更新版本，保留新增预算、同帧起点跟随、新指令立即隐藏旧路线。

### 刷新顺序与降频边界

1. 各来源完成本帧表现更新，提交成员／外观变化及最终姿态版本。
2. 本地视图合并变化，更新受影响的只读快照；选择集合在选择变化时重建。
3. 用实际相机／视口签名重新判断可见性；可见动态元素读取最终位置。
4. 仅为受影响批次重新投影／构建几何，随后提交Slate绘制。

Presentation、血条和路线目前均在 `TG_PostUpdateWork`；路线已对Presentation设置Tick prerequisite。同一TickGroup不等于有稳定先后顺序。实现必须保留该先决关系，并核对UI刷新与Camera／HUD的实际顺序；必要时增加有明确先决依赖的本地刷新适配组件，不能只依靠Subsystem和Slate Tick的默认顺序。最终Geometry只在Slate绘制边界可用，因此依赖Geometry的投影／缓存检查留在该边界，业务状态Gather移到其前面。

镜头移动、可见单位移动、据点悬浮、鼠标拖选／建造、世界面板随镜头转动，继续逐帧更新必要部分。屏幕外对象保持身份／数值事实同步，省掉投影、细分图元和非必要面板重绘；再次入屏或镜头变化时立即重新评估。来源注册不得随镜头裁剪反复注销。

不要统一改成10 Hz导致脚环／路线错位；统计文字和兼容重试沿原有低频节奏处理。

## 三、缓存固定内容并提前裁剪

### 两级几何缓存

局部形状固定，不代表投影后的屏幕顶点固定。采用两级缓存：

- 形状模板：复用脚环现有64方向；补充48段光环、32段HUD圆盘的方向表；放置网格按Footprint尺寸／间距生成局部线段。保持原段数、20 cm环宽和选中标记几何。
- 本地视图批次：缓存已投影顶点／索引及资源引用，键包含数据版本、ViewSignature、DPI／Geometry变换、裁剪、图层和资源代次。镜头或对象变化时，只重建相应批次；相机与对象都稳定时才复用屏幕顶点。

脚环可在完全处于视锥内时采用直接投影快路径，避免每个三角形重复六平面裁剪；与视锥／近裁剪面相交时保留现有齐次裁剪路径。快路径的包围体必须覆盖完整环带和选中标记，且投影W／深度有效，不能用中心在屏幕内作为判据。

复用容量／固定索引／资源句柄，保持每批60000顶点及 `SlateIndex` 范围约束，不创建逐单位Widget或提交过期资源。

### 分类型可见性

| 图元 | 提前筛选 | 缓存失效条件 |
|---|---|---|
| 脚环／选中标记 | 先排除未知团队、隐藏／相位／无效尺寸，再用包含标记的保守包围体 | 成员、样式、半径、最终位置、视图变化 |
| 据点光环 | 对完整相机朝向椭圆做保守视锥测试，再展开48段 | VisualMesh Bounds中心随悬浮变化；相机朝向、归属、尺寸变化 |
| 血条 | Project检查深度后，与视口相交的完整86×14像素背景矩形再生成填充 | 最终中心、血量／选择、期限、视图／DPI变化 |
| 路线／世界线 | 线段包围体粗筛＋现有齐次线段裁剪 | 起终点、指令有效性、视图；端点都在屏幕外仍可能穿过视口 |
| 放置网格 | 先筛整块Footprint，局部网格模板复用后再投影线段 | 尺寸、预览Transform、合法性、视图变化 |
| 世界Widget面板 | 完整面板四边形／包围体粗筛，边缘处保留UV插值裁剪 | 面板Transform／Size／Pivot、视图或资源绑定变化 |
| HUD屏幕图元 | 完整矩形／线宽范围与视口相交 | 命令变化、过期、视口／DPI变化 |

当前血条 `Project()` 只检查W与深度，不排除X/Y屏幕外；可在生成三个矩形前补完整范围判断。据点当前逐段裁剪，尚未先筛整圈；其中心来自悬浮VisualMesh，不能在归属事件后永久固定。既有距离显示规则继续有效，不为减少CPU擅自加入远距离消失策略。

保持普通／选中脚环、轮廓／放置底层、HUD文字／面板的叠放次序；不按颜色重排遮盖关系。拆批新增的提交成本与内存计入收益判断。

### RT内容与捕获名单

轮廓／放置蒙版包括三个独立层次：候选Mesh名单、SceneCapture内容、Slate屏幕四边形。

- 候选成员、敌我身份、显隐、模型／LOD／组件变化才更新ShowOnly名单。团队切换后在下一次捕获前去掉已变友军的Mesh；放置名单不在预览组件不变时逐帧Clear／重加。
- 相机／投影、被捕获对象姿态、实例变换、骨骼／机械动画或影响剪影的材质动画变化，仍需更新捕获内容。缺少完整变形通知时保留每帧捕获，不能凭Actor根Transform不变就冻结。
- RT对象和绑定不变、屏幕四边形不变时，RT像素变化不要求重建Slate顶点。这是对材质外观不储存在顶点缓冲中的情况的应用；参照[Epic Invalidation Box说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-the-invalidation-box-for-umg-in-unreal-engine?application_version=5.7)。RT重新创建、资源绑定／尺寸／四边形变化则需要刷新相应缓存。

本阶段不默认降低捕获分辨率、帧率或加Retainer。CPU只记录Capture设置／提交耗时；实际捕获GPU开销必须另测，不能由Widget Tick耗时推断。

## 四、按依赖失效，处理帧内写入与生命周期

### 失效粒度

当前 `SGuLiSceneUI` 是一个自绘 `SLeafWidget`，不是由多个UMG子控件组成的树。包一层Invalidation Box无法自动分辨内部哪些数组发生变化。首先增加分项快照／批次版本，在现有叶节点内复用未变化的数据；再按收益拆出少量固定Overlay、世界图元、HUD命令叶节点。

世界投影更新如果只改变叶节点内部绘制顶点、没有改变Widget布局，使用 `Paint` 失效；实际Widget尺寸／布局、子树结构变化再使用相应Layout／ChildOrder机制。不要对整容器每帧调用 `InvalidateLayoutAndVolatility`。

对已经单独拆出的持续动态图元叶节点，可以评估Volatile；固定Overlay保留缓存。Volatile仍会逐帧计算绘制几何，不能等同“免费刷新”。全局Invalidation是否开启要按实际配置检查，不能假定当前无条件Invalidate就是全部SlowPath来源，也不顺便修改全项目开关。[Epic失效机制说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/invalidation-in-slate-and-umg-for-unreal-engine?application_version=5.7)指出Retainer增加RT内存与重绘开销，因此本方案优先处理已有批次与失效边界。

### HUD命令提交协议

[Commander HUD](../../Source/GuLiStrike/Commander/Presentation/GuLiCommanderHUD.cpp) 的 `DrawHUD()` 调用 `BeginHUDFrame()`，然后通过 `AddScreen* / AddWorldLine` 写入命令。Widget NativeTick和HUD生产命令是不同边界；只在NativeTick末尾检查脏标记，会漏掉之后写入的命令。

建议保留Begin／Add接口并增加 `EndHUDFrame()`：

1. Begin建立本帧待提交缓冲；Add只写该缓冲，不逐条触发重建。
2. DrawHUD结束时通过作用域收尾提交完整命令快照，包括空快照；只在内容或有效状态变化时推进HUDRevision并使对应Paint失效。等价判断由生产者版本或一次提交边界的比较完成，不每Tick哈希整套世界数据。
3. HUD快照沿现有规则在生产帧及下一帧有效；若生产帧为F、之后未再提交，则在F+2首次失效。过期边界必须主动标记Dirty并清空旧几何，不能依赖Paint执行后才发现过期。
4. showhud关闭、Canvas无效、模态隐藏、Controller变化或HUD生产停止时，按同一协议清除／到期，不遗留选择框、指令线或统计文字；恢复后强制提交最新快照。

增加资源引用维护：以最后已提交且仍有效的HUD／世界面板快照维持纹理、MID和Brush，不在Widget Tick先按旧命令清除材质后，又由本帧HUD AddImage重新创建。资源引用／绑定变更时更新缓存；撤销所有引用并使相关Slate缓存失效后再释放，防止已缓存DrawElement继续引用被回收资源。

### 合并与提交规则

维护Sources、Membership、Appearance、Pose、View、HUD、Resources、CaptureList分项Dirty；来源完成／HUD提交推进版本，绘制边界按Geometry消费快照。清Dirty只表示已消费对应版本，不能覆盖之后到来的事件。

隐藏时暂停几何构建、蒙版捕获和面板非必要重绘，继续接收注册／数值事件并维护期限。恢复可见后强制检查所有版本、ViewSignature和过期状态。LocalPlayer、World、Controller／Pawn、Slate资源重建分别形成生命周期边界；重新挂载必须重新绑定、重建首次快照，注销必须幂等。

路线现有 `RecordSceneUISubmission()` 记录移动延迟的 `render-submit` 事件。重构后仍在有效路线首次真正提交到Slate时记录；Gather、排队或仅缓存快照不算提交。缓存复用不能重复记录同一批次，也不能因Paint次数减少而漏记新批次；该事件仍是CPU提交证据，不改称GPU完成或已显示证据。
