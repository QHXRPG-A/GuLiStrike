# 增量归档与里程碑策略

仅在新增归档、写里程碑、勘误或讨论删除历史时读取。

## 增量记录

- 每次完成一段可独立复现的工作，新增一篇归档，写明准确路径、关键决策、验证证据和遗留边界。
- 创建后原则上不可改写。允许修复纯格式或坏链，但不得悄悄改变历史结论。
- 没有执行的验证写 `not_run`；只覆盖部分范围写 `partial`；失败必须明确写 `failed`。

## 里程碑摘要

- 只在跨多次增量、需要形成阶段入口时创建。
- 汇总结论、当前基线和剩余风险，并链接每篇增量归档。
- 不复制全部实现细节、日志或验证矩阵；事实继续由增量归档承载。

## 勘误链

- 新增勘误归档，不覆盖错误发生时的原文。
- 新文档通过 `relations.supersedes` 指向旧归档；旧文档状态可改为 `superseded` 并通过 `relations.superseded_by` 回指新文档。
- 勘误正文说明旧结论哪里不准确、新证据是什么、哪些结论仍有效。

## 删除边界

- 默认不物理删除归档，也不因“已经有总归档”而删除增量事实。
- 只有文件完全重复、所有引用已迁移且用户明确要求删除时，才允许物理删除。
- 删除前精确解析目标并检查入链；删除后运行 `build`、`check`，在回复中说明删除内容及可恢复性。

2026-08-30 的非 Markdown 测试附件清理是已知历史事件。缺失的日志、截图、采样和临时报告只给提示，不视为 Markdown 结构错误。
