# 玩法优先的白盒（Blockout）方法

适用：场景将被用于实际玩法（战斗、跑酷、解谜），而非纯观赏。核心原则：**先定指标 → 白盒 → 试玩验证 → 再做美术**，绝不能反过来。"only dress when it plays well"——玩起来没问题才装饰。

## 1. 玩家指标先行

建任何几何体之前，先从项目里确认玩家角色的能力指标（GuLiStrike 是俯视角双摇杆射击，重点不同，见下）：

- 移动速度（走/跑）、闪避距离
- 跳跃最大高度与最大距离（如适用）
- 相机类型与视野范围（决定走道宽度、遮挡高度）
- 武器射程与弹道（决定掩体间距是否合理）

有这些数字后推导安全值：
- `SAFE_GAP := MAX_JUMP_DIST * 0.7`（公平跳距，普通路径只用这个）
- `HARD_GAP := MAX_JUMP_DIST * 0.95`（技能考验，仅用于可选奖励路线）
- 俯视角射击：掩体高度需挡住角色但露出敌人上半身；掩体间距 ≧ 玩家闪避距离的 1.5 倍，保证有反应空间

## 2. 白盒搭建

- 全部用无贴图基本体（正确比例）搭完整个关卡，验证流线、视线和可达性，**不上任何美术资产**
- 关卡建模为「房间 + 门控」的图结构：
  - 关键路径：起点 → 目标的最短序列
  - 黄金路径：大多数玩家实际走的路线，引导资源优先给它
  - 可选/秘密路径从主路径分出，不穿越主路径
- 用图遍历（脑内或脚本洪水填充）验证**关键路径不会软锁**：门控所需的钥匙/能力都能在到达门之前按序获得

## 3. 俯视角射击（GuLiStrike 类型）专项

- **掩体布局**：掩体组之间保持交叉火力与迂回路线，避免一条直线走廊（站桩输出）
- **敌人出生点**：不在玩家视野正中刷新；出生点与玩家之间留 2-3 秒反应距离
- **视野公平**：俯视角下屏幕边缘=危险边缘，重要威胁不要只从极边缘切入
- **竞技场节奏**： Encounter 之间留拾取/喘息区

## 4. 节奏设计（Pacing）

张力和休息刻意交替，避免连续 combat-combat-combat：

- 强度曲线**锯齿状上升**，不是直线，也不能长期高位平坦
- 高潮（Boss/大战）前安排休息区和补给
- 教学循环：安全环境引入机制 → 练习 → 压力下测试；绝不让玩家在致命场景首次遇到新危险
- 多房间场景可列一张 BEATS 表（房间名 | 类型 teach/combat/rest/climax | 强度 0-1）检查曲线

## 5. 白盒验收清单

- [ ] 所有必需跳跃/间隙 ≤ SAFE_GAP
- [ ] 几何全部以玩家单位为尺码（走道宽度满足相机、台阶/掩体高度在合理范围）
- [ ] 图遍历证明目标可达，无软锁死路
- [ ] 单向路径已 telegraph（提前示意）
- [ ] 节奏曲线有起伏，高潮前有休息
- [ ] 每个机制先安全教学再考核
- [ ] 白盒阶段通过试玩后，才进入美术化（回到 SKILL.md 的构建顺序第 4 步）
