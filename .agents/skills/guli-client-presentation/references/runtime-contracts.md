# 运行合同与缓存

在实现前记录以下项目，并链接现有生产入口。

| 合同 | 必须明确 |
|---|---|
| 身份 | 来源完整身份、射击/结束身份、Epoch；局部 Slot 与 Generation 不进网络 |
| 坐标 | 出生世界变换、局部属性、后续跟随姿态；每层 Scale 的应用位置 |
| 时间 | 权威发射时钟、历史姿态时间、接纳帧、发布帧、实际出生与期限 |
| 可见性 | 主体、中段、历史尾迹及消散段完整范围；未知范围保守准入并计数 |
| LOD | 同 World 合格本地视图取最高需求；资源缺失逐档回退；切档是否允许重启 |
| 结束 | 死亡/停止/完成/过期/离屏/来源失效独立处理；回屏是否重新增长 |
| 输入 | 颜色、种子、寿命、版本、认证元数据和资产引用所有权 |
| 回退 | 运行开关、同档单次资源、保持约定延迟及不重播 |

高频事件池初始容量与增长步长是容量策略，不是反馈数量上限。使用 `GuLiPresentationSlotPool.h` 维护稳定槽位、代次和 Epoch。反射对象持有资产/组件引用；数组容量可复用，不能在热路径同步加载。

上传修订按数据职责拆分：静态配置准备时写，姿态随实际变化写，出生/代次随生命周期写，时钟与可见运动保持必要频率。缓存失败也缓存；缓存键包含全部影响结果的输入和 World。UploadStamp 的同帧保护不能吞掉随后改变的出生数据。

网络样本、可靠启停、结束、时钟和屏外预测始终处理。暂停呈现的唤醒检查要独立于被暂停的 Tick。瞬时事件生成前裁剪，持续离屏回收保留原宽限；不允许回屏补播已经丢弃的枪口/命中。

场景 UI：来源注册表按 World 初始化，LocalPlayer 决定选择与阵营；修订在最终插值/机械姿态完成后发布。HUD 双缓冲所有返回路径提交，空提交清空，遵循既有 F 到 F+1 有效/F+2 过期。保留引用、完整图元裁剪、层次和索引上限。
