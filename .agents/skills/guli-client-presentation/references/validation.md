# 验证与交付

先静态检查，再用源码 UE5.7 构建 `GuLiStrikeEditor Win64 Development`，核对退出码、加载 DLL 和 BuildId。不打断玩家正在进行的 PIE；当前会话的用户授权优先。资源只保存明确修改的项目资产，不 Save All。

功能验证采用真实生产入口。批量资源检查 CPU VM/粒子输入、实际 F+1 出生、Follower 初始化、独立 Ribbon、出生时钟、代次失效、空闲唤醒、退出顺序、双 World。接口存在或图编译成功不能代替实际运行检查。

对照先固定视口、质量、镜头、人口、移动、开火和资源版本。每种候选三轮配对，10 秒热身、30 秒记录。测量窗口内不截图、枚举对象或写资产；窗口外截图和 ProfileGPU。比较即时单次、F+1 单次与 F+1 批量，分别隔离延迟与批量收益。

报告实际接纳/出生事件、活跃量、移动和位置变化，列整帧/FPS、GT、GPU、平均/P95、内存、组件、姿态查询、上传、Ribbon Dispatch 与每千次反馈成本。区分子系统父 Scope、Niagara 自身、同步等待和帧尾；不能把含子项父 Scope 再相加。不同场景旧数字不能直接计算收益，差异在配对波动内记为未证实。

性能比较前先核对反馈吞吐。到达过晚而被丢弃、零接纳或明显不同出生量的样本，不能用于承载收益结论；完整负载/整帧诊断仍可保留并明确适用范围。额外压力入口、自然交火的实际总活跃量和预览特效分开记录，预览不能替代真实生产反馈。

配置的每连接字节预算不等于实测流量，应用层 PayloadBytes 也不等于服务器总出口。诊断上游积压时同时检查队列增长、发送频率、每次包数上限、实际编码条数、时钟与反馈过期；提高预算不能自动证明瓶颈已解除。表现优化范围内不擅自改变服务器玩法或既有可靠协议。

用开始、峰值、停止、移动跟随及回屏可播放证据交付视觉。技术输入验证、性能结果、玩家视觉决定分别记录；没有玩家答复时保持视觉待验，不虚构认可。最终在现有地图保存默认停用验证入口及指南，回读实体/引用。

Progress 维护需求、开发任务和增量归档，关联既有记录；运行 `progress_docs.py build` 和 `check`。未执行项目保留真实状态。

## 技能路由自检案例

- 维护命中批量：本技能负责身份/F+1/资源输入/池与诊断；VFX 技能负责图和视觉制作；Excel 技能负责正式软引用；不修改玩法判定。
- 适配枪口：本技能复用射击去重、完整姿态缓存和回退，要求出生/跟随变换；VFX 技能保留三档外观及生产/跟随事件；使用独立 Channel。
- 开发场景 UI：本技能负责注册、修订、投影/几何缓存和捕获生命周期，协同 `ue5-ui-umg-slate`；不强制将 UI 改成 Niagara 或事件批量。
