# GuLiStrike 客户端表现管线

本技能负责当前项目的表现数据流、调度、资源合同和运行验证。先定位真实生产入口、所属 World、资产和现有缓存，再修改。保留已交付优化；不要因为调用本技能而迁移无关系统。

## 职责与路由

- 单位：网络样本与时钟持续处理，昂贵呈现可按可见性降频；枪口、目标及历史姿态从最新样本按需求值，使用完整身份缓存。死亡、改令和必要本地挂载不能随呈现暂停。
- 瞬时世界反馈：高频枪口、命中优先事件批量；低频或特殊效果保留适合的独立路径。持续光束、飞行和尾迹使用稳定槽位。先证明共享承载能保持原合同。
- 场景 UI 与描边：使用 World 来源注册及修订通知、LocalPlayer 投影和颜色决策；分开管理内容修订、动画、Capture 名单与捕获、Slate 几何和 Paint 失效。仍需逐帧跟随的活动内容继续更新。
- 资源设计、颜色、层次和材质制作协同 `ue5-vfx-production`；代码使用现有单一 GuLiStrike Runtime 模块。表字段和正式软引用经 `excelize-cli` 管线维护；文档、验证场景和归档使用 `gulistrike-progress`。

技术适配保留已审视觉、基础 Scale 和生产/跟随事件。视觉改变先读[项目美术规范](../../../Progress/RequirementDocument/GuLiStrike美术规范.md)，不在本技能复制色库。

## 开发流程

1. 读回生产调用、资源、运行变换和计数，写出来源身份、World、坐标空间、时钟、出生/结束、随机输入、完整 Bounds、LOD 和失败回退合同。服务器继续拥有玩法判定；本地句柄不进入网络。
2. 选择事件批量、稳定槽位或独立承载。复用视图、姿态、预测和上传缓存；同 World 多视图取最高需求并只发布一次，总览沿用现有规则。
3. 独立派生项目资源，将组件变换、系统年龄和随机输入改为逐事件数据。制作脚本写最终绝对值，重跑不叠乘；强引用由反射对象持有，准备阶段解析，专服不加载。
4. 实现 Slot/Generation/Epoch、结束去重和空闲唤醒；动态姿态、出生时间、代次各自维护上传修订。屏外仍推进逻辑，回屏不重播旧瞬时事件；尾迹恢复遵循该用途的明确合同。
5. 编译图和源码、读回保存结果、检查实际运行输入与 F+1 时序，再接入正式引用。缺 Channel、元数据或兼容输入时回退对应 LOD 单次路径。资源认证表示这些技术检查通过，不等于玩家视觉验收。
6. 用真实生产入口验证死亡、失效、停止、离屏/回屏、混合 LOD、槽位复用、Epoch、晚加入和双客户端隔离。按 World 记录吞吐、活跃槽位、组件、姿态查询与提交；额外日志默认关闭。
7. 在固定负载下配对测量，分开报告 CPU/GPU/整帧/内存和反馈吞吐；剔除嵌套 Scope 重复累加和同步等待。保存默认停用的可播放验证入口，回读引用；技术、性能、玩家视觉状态分别记账。
