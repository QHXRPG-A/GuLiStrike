# 获得卡牌后的批量升级特效

只在修改卡牌升级表现时读取。完整Niagara制作流程使用项目 [ue5-vfx-production](D:/UE5.7/test1/.agents/skills/ue5-vfx-production/SKILL.md)，本页维护卡牌接口与当前版本边界。

## 资源、尺寸与颜色

- 当前系统 `/Game/GuLiStrike/FX/RogueCards/NS_RogueUpgrade_Lite`，材质 `M_UpgradeGlow`、`M_UpgradeRingMotes`，网格 `SM_UpgradeCylinder`。
- 只读参考 `/Game/Assets/VFX/NiagaraUpgradeGlow/Particles/P_UpgradeGlow04_Converted`，原资源不改。
- 表字段 `UpgradeVfx / UpgradeVfxScale / UpgradeVfxColor`，默认己方色取原主要光圈起始值：线性HDR `(R=20,G=6.930114,B=0.933554,A=1)`，不是sRGB十六进制。
- 敌方按**每个观看客户端自己的阵营**覆盖红色，保留亮度/淡出节奏；不要以服务器队伍固定涂色。运行时颜色与材质亮度参数分别核对。
- WM01当前统一缩放6，源于实际宽约12.5m、高约7.5m与原特效太小。新增单位需根据最终网格包围盒和PresentationScale适配，不能全军乘6或重复缩放。

## 当前随机光粒基线

2026-09-28最新修订：两个GPU发射器，持续约1秒。高/中/低质量每单位 **1辉光网格＋1主光圈＋18/6/0个独立短光粒**。材质每粒子只有一个柔光短点；旧“6个面片、每片3个点”的固定三点簇已被用户否定，不再作为制作模板。

光粒按单位槽和粒子序号做稳定散列：角度、半径、高度、尺寸、旋转、出生延迟、上升速度与横向漂移独立变化。当前延迟0–0.30s、寿命0.42–0.70s，错时亮起和消退。随机值跨帧固定以避免跳动；同槽后续可能复用序列，不宣称每次随机种子都不同。不要用等间距旋转、同龄上升或重复小簇冒充自然散布。

每块1024单位槽，共用一个Niagara组件，GPU容量 **20480**（1024网格＋19456精灵），即使低质量仍是该预分配结构，未使用槽通过透明度/尺寸隐藏。`User.UpgradeParameters` 为(age,scale,moteCount)，高质量可见预算为20×可见单位数；预算不是屏幕当帧实际可见亮点数。原版块容量8192已不是当前配置。

同步修改点：

- `Scripts/Cards/author_rogue_upgrade_vfx.py`：完整生产源，材质/槽分配/运动。
- `Scripts/Cards/refine_rogue_upgrade_motes.py`：增量资源修改与编译回读。
- `Source/GuLiStrike/Gameplay/CombatEffects/GuLiRogueUpgradePresentation.cpp`：质量18/6/0、数组与计数。修改粒子容量时需一起核对分母、burst、索引和运行时数量，不能只改贴图或表说明。
- `Tools/DataPipeline/extend_rogue_upgrade_fields.py` 与Cards `_说明`：表契约/预算文字。

## 触发与清理

服务器成功结算时冻结当前存活受益单位集合；之后新生单位继承加成但不补播。卡牌与模糊完全退出后客户端发送就绪通知，服务器验证战局/会话与成功结果，广播一次表现事件。

死亡/失效单位跳过，重复通知去重，旧战局事件丢弃；单位位置跟随更新，尊重各客户端可见性与视锥，不能通过特效暴露不可见敌人。播放完成释放槽，空块回池。专用服务器只处理逻辑/表现事件，不创建渲染组件。VFX加载失败不能撤销已经获得的属性。

## 验证边界

修改资源后编译材质和Niagara、保存、重新读取模块/renderer/参数/引用与burst；运行检查按当前任务授权。检查起始/峰值/消退、动中跟随、死亡/离屏、结束回池与敌我色；用户不让看图时保存阶段截图供用户审，不读取截图后自判。

最新专项证据在项目 `Artifacts/RogueCards/Upgrade/random-motes-*.json`、`mote-randomization.json`：125个受益单位、最多37个可见、1个共享组件、740粒子预算，结束清空。只证明该次流程/数据通过，视觉仍待用户确认。

历史100/500/1000性能报告来自缩放1、旧6粒子版本；当前缩放6、18独立粒子及20480容量**未完成同规模性能重测**，不得引用旧数字声称新版达标。需要性能比较时固定硬件、镜头、分辨率、单位数和画质，区分预分配容量、可见预算、组件数、游戏线程与GPU；现有夹具包含旧参数，运行前核对它是否真的代表当前生产配置。

若需要新增大量单位夹具，注意场景既有单位占用Crowd容量；之前1000额外单位曾超过默认1024。仅在获准测试中做可恢复临时调整，结束恢复正式容量/人口，不因压测永久改游戏配置。
