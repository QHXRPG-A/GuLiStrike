# 全画布分层、逐层补绘与HTML视差

## 默认制作路线

以用户选定的最终参考图为基准，按用户指定六个内容分组制作。初稿和用户Qwen阶段见[完整工作流](image-to-html-workflow.md)；已有定稿不重走前置阶段。新分层使用**逐层生成的完整对象图**，装配为共同画布、同一外扩矩形与源图窗口。不要把各层裁成包围盒后独立居中排版。

先确定对象位置、大小、归属和最大运动范围，再逐层调用内置生图生成完整对象、遮挡面及外沿。用户允许时，抠图或分割仅作参考输入；禁止脚本抠图时不执行。交付图的可见内容和透明区域均来自生成结果，不能回贴原图像素或用旧分割蒙版再次挖空生成图。静态对位完成后，所有成品共用一套基础 Scale/Offset，视差按深度产生相对运动；对位的允许范围见下文。

历史3×2图集用于维护已有资产，兼容条件见文末。不要默认让生成模型一次重画六格来替代同坐标拆层，也不要为了统一格式重做已交付的旧卡。

## 用户分组与对象完整性

六层的语义与编号由用户指定，绘制顺序单独记录。当前折射子弹六层为近景、速度线、机甲、场景、折射弹道和三个敌方机甲、远景，详见[本次示例](image-to-html-workflow.md#本次折射子弹示例)。下表仅供维护旧WM01卡时参考：

| 层 | 内容 | WM01例子 |
|---|---|---|
| 1 | 最近前景 | 近处残骸、最近自由导弹、前景速度线；无合适内容可为空 |
| 2 | 能力动作与分离物体 | 独立装配机械臂、飞行导弹及随动标记 |
| 3 | 完整机械与附着效果 | 机身、武器、可见腿盘与支架；炮口火光、刚出膛导弹、盘底附着光 |
| 4 | 环境中景 | 被击溃部队与爆炸、远处导弹、地面结构 |
| 5 | 环境远景 | 烟柱、工业剪影、远处部队 |
| 6 | 补全的最远底图 | 天空、地平线、安静地面；整层不透明 |

按实际连接与用户指定分组，不为填满六层重复放同一对象或把机械支架两端拆到不同深度。导弹及附着尾焰、同一机械臂及其工具/光效、绑定物体的符号通常随同一层运动。特殊层位记录为该卡决定，不推广到所有卡。

**每个对象只归属一层，所属层交付完整对象。** 归属互斥不要求不同图层的非透明像素互斥：对象在同一坐标前后重叠是正常遮挡。两层尘埃应有各自的完整尘浪及碎屑，交叠处补各自隐藏表面，不能切成互不重叠的拼图片段。机械补齐实体内部和隐藏结构，弹道/电弧保持所属路径连续，越框物件补至最大运动可见范围之外。描边、残影、光晕与半透明边缘随所属对象进入同一层；每层只生成列明的内容，不能用其他层对象填空。

**单层与遮挡。** 独看先清空画布，只绘制所选完整主图；原图仅用于对照。前后遮挡需要时，引用同一主图的互补技术蒙版，共用采样、位移和透明度，不能重复叠加同一对象的 alpha。技术分次绘制不新增内容层；反过来，一层只有一次绘制也不能证明图内没有串层残片。核对来源、遮挡分配和透明度，完整性与接合由用户逐层验收。

用户指定纯色背景时，直接生成同一 RGBA 值的全画布 PNG，含外扩边缘，alpha 全为 255。关闭原图像素回贴、渐变和调色。保存后验证整张图只有一个 RGBA 值。

承担最远底图的层全不透明，其他层对象外真正 alpha=0；上表旧WM01及本次示例均对应第1–5层透明、第6层不透明。背景生成完整环境，不残留其他层对象、轮廓或弹道；前景生成完整实体，不继承输入切片的错误孔洞。对象外透明不等于内容残缺，也不要求在 alpha=0 的区域暗藏其他层图案。保留有意的战斗破损与分离零件，不能把透明棋盘画进图中。

## 补绘、对齐与HTML装配顺序

1. **冻结参考与制作范围。** 记录最终参考的实际尺寸、哈希、六层归属和允许修改范围；生图前确定原图窗口、共同画布、最大平移/倾斜、深度和滤波余量。初稿、参考和分层生成记录分开保存。
2. **定义坐标与对象清单。** 以同一参考图记录每层对象名称、数量、位置/包围框、大小、方向、连接点及排除内容，注明坐标单位。可直接用参考图和这些约束生图，不要求先脚本抠图。获准使用的切片仅作输入锚点。
3. **逐层生成完整主图。** 每次生成一层的完整 RGBA 图，补齐实体、隐藏面、连续效果与外沿；透明层物体外留真实 alpha，背景不留主体剪影或其他层残片。提示词列出目标并不代表已完成，要保留实际工具输出与生成来源。
4. **静态对位后统一装配。** 读取真实输出尺寸与 alpha，必要时对生成结果做有记录的平移、等比缩放等静态对位，再写入共同画布；保留原始输出、变换和映射关系。若对象相对位置、比例或连接已改写，或内容残缺，修正输入并重新生成，不能靠逐层运行时基础 UV 补偿。后续外沿修复可保护已确认的完整生成图核心，不能把冻结参考图的抠图片段当作“核心”回贴。
5. **按最终清单装配 HTML。** 六张主图共用基础映射，支持原图/原位/视差、开关、独看、透明度、回正和下载。连接内容共用运动参数；遮挡由同一主图和技术蒙版处理，不挪动正确源坐标。所有呈现和导出引用同一批最终 PNG。
6. **分别记录各项验收。** 助手检查元数据、实际合成指标、映射、资源、着色器初始化与控件；用户检查单层完整性、中心/四边/四角、最大运动、连接与风格。按项目规则不做助手截图/结果读图测试。UE接入时再核对实际父材质、窗口、引用和参数；未执行项保持未验证。

HTML模板与当前补绘脚本见[工作流实现](image-to-html-workflow.md#可复用实现与边界)；HTML不等于UE最终渲染。`Scripts/Cards/audit_wm01_registered_sources.py`包含尺寸、alpha、来源哈希及局部坐标分析，运行会写旧批清单，新卡须先适配路径。数值特征与生产对位不代表整图相同或用户视觉验收通过。

## 原位保真

**原图与原位叠合至少有 80% 相似度。** 比较对象是冻结的最终参考图，不得替换成上一版生成图或本次合成图。六层全开、各层滑杆均为 100%、视差与倾斜归零，在原图窗口内实际合成保存后的 PNG，保留各自 alpha 与正常遮挡。生成时保持原图构图、轮廓、色块和主要位置，补齐隐藏结构及外沿；原图只在对照模式显示，禁止整图兜底、原图切片回贴或重复绘制对象来提高分数。

数值检查使用原窗口全幅 RGB SSIM，统一 0–1 通道范围、11×11 高斯窗口和 σ=1.5，以 **0.80** 为下限，显示为 SSIM × 100%。这是结构相似度指标，不是相同像素占比或用户视觉通过率。记录参考图与六张成品的哈希、窗口、合成顺序、指标参数、阈值和实测结果；更改规则不改写旧版本的实测值与当时验收记录。

验收项分开记录：原位 SSIM、对象完整性、跨层归属、最大位移/倾斜的接合、页面与导出一致性。达到 0.80 不能抵消其他项的失败；纹理覆盖窗口或 alpha 无孔洞不能证明接缝自然，一次绘制也不能证明没有重复内容。数值检查由助手执行，画面完整性与自然程度由用户验收。

## 单层补绘提示词与输入

每层单独写生产 prompt，列出完整画布、原图窗口、本层对象及排除项，明确每张输入图的用途；可以直接引用冻结参考图，边缘修复则引用已确认的完整生成层。只有用户允许时才加入切片参考，不将其规定为必备输入。工具要求时只做必要的本地编辑输入检查。可用以下结构：

> 依据指定参考生成第 N 层的完整独立 RGBA 图。共同画布 W×H，参考图窗口 [x0,y0,x1,y1]，所有坐标使用……单位。本层对象及数量：……；各对象的位置、大小、方向和连接点：……；必须排除的其他层内容：……。参考图只约束身份、结构、构图、色块与风格，不把整张场景重画进本层，不自动居中或裁掉共同留白。
>
> 只生成本层所属对象及其描边、残影、附着光效和软边；完整生成其实体内部、被遮挡的结构、连续弹道/电弧及指定外沿。对象外真正 alpha=0，最远背景层则完整不透明。不要继承切片中的孔洞、矩形缺口或其他层残片。保留设计上有意的战斗破损和分离零件；不要六格拼图、标签、棋盘、卡框或UI，已审图内符号按该卡例外保留。
>
> 保持最终参考的主要特征、清晰轮廓、色块和光效。外沿修复时列明被保护的完整生成层版本与矩形，只补所需隐藏面和外沿；不要复制第二份对象、重排主体或改变画风。

使用工具实际支持的透明背景选项；坐标、尺寸和排除项只是生成约束，不是结果保证。读取真实输出后再对位和装配。模型裁掉透明留白时，可用中性底布局输入约束画布，但仍须让生图工具输出真正 alpha；不以脚本去底或旧蒙版裁切冒充完整生图。装配只处理已生成内容的坐标、画布与合成，不替代对象生成。

## 倾斜露边与背景补绘

外扩范围必须在生成前确定：牌面窗口与共同映射 → 实际深度和最大位移/倾斜 → 滤波余量 → 生图补齐隐藏面及外沿 → 整体位移与窗口裁切。足够大的透明画布不代表物体已延伸到外沿，纹理矩形覆盖窗口也不代表接缝自然。Clamp、重复/镜像边缘像素、单独放大前景或只降低视差，都不能代替缺失内容的补绘。

只修复外沿时，可保留用户已确认的完整生成层核心 RGBA，记录源文件哈希、保护矩形和允许补绘范围；外沿也须来自生图，并装配成同一张连续主图供预览与下载。这里保留的是完整生成层，不是从定稿原图抠出的片段。历史独立背景外沿纹理仅用于对应旧材质维护，不作为新卡的额外兜底层。

对用户明确接受并要求保留的图层记录源文件哈希、许可范围及决定；修改这些表现前遵守该用户约束。已授权的外沿补绘可以继续，不重复请求同一许可，也不扩大成整图重绘。

## 前景完整表面、遮挡蒙版与窗口边缘

前景抠掉机甲后直接留下机甲形状的透明洞，平移时会露出错误背景；先让内置生图补成连续的烟尘、墙岩和地面表面。若前景同时出现在机甲前后，保留一张完整前景主图，另用二值技术蒙版分配前后显示，不必新增用户内容分组。

本次例子白色为前景前方、黑色为机甲后方：远景 → 场景 → 敌人与弹道 → 前景×(1-蒙版) → 机甲 → 前景×蒙版 → 速度线。同一前景图与蒙版采用相同坐标、深度运动、开关和透明度，二值分配避免同一软边重复叠加。其他卡按真实遮挡关系设计，不硬套此顺序。

同一物件只能归属一个内容层，其轮廓、材质、连接部件和附着火焰采用同一个刚性变换。不能把同一装甲、腿、岩石或火焰残片画进多个可独立移动的层，也不能让物件边缘和内部采用不同的位移系数；后者即使只有一张纹理，也会产生果冻式拉伸。出画面按固定牌面窗口整体裁切，露边通过足够外扩和完整补绘解决，不使用局部UV渐变固定物件边缘。

前后遮挡需要时，保留一个完整物件源图并共用同一刚性位移，通过局部遮挡合成处理，不拆成有独立位移／深度的物件片段。2026-10-29两张灼烧卡已取消边缘固定采样和旧环切割蒙版；WebGL以一次完整环／机甲合成处理遮挡。`ricochet_foreground_renderer.js`外侧2%固定、至12%过渡属于旧卡历史方案，不作为新卡默认；本次不批量修改其他已审卡。PNG源图切口必须位于可见窗口及最大位移留量之外，不能把被裁掉左右端的环缩进画面中部。

外扩量按实际渲染映射计算。只有平移时，水平源像素余量至少为 `最大水平显示位移 × |深度权重| × 原窗口宽 / 显示宽 + 滤波余量`，竖向使用对应高度；若位移已是源像素则不再换算。倾斜/透视会改变采样范围时，按各极限姿态反算窗口采样边界并取并集，不能只套平移公式。记录单位、外扩矩形、源窗口、真实生成尺寸与共同映射，不固定套用历史尺寸或百分比。用户检查外沿与隐藏面是否连续，助手不从边界覆盖通过推断画面已无破绽。

- 导弹仓三只机械臂、钢板、焊接及扫描光统一第2层；雨点蓝色半透明导弹、绿色不透明“+1”和自身尾焰统一第2层。“+1”是用户批准的图内符号例外。
- 用户接受当前扫描光浓度与加长尾焰，后续改动前先确认；本次仅授权补实验室/天空外沿。两份第2层保护哈希和决定保留于v4清单。
- 专属父材质`M_WM01RegisteredCardLayers_v1`；各层共同Scale=(0.92,0.745)、Offset=(0,-0.0875)。原UV范围内保留原第6层，外沿用`(UV+0.25)/1.5`映射，表示每侧25%外沿。

## 材质与旧图集兼容

- 独立纹理绑定对应的`Layer N Map`；复用兼容父材质或另建本次父材质，避免改动共享父材质影响旧卡。卡框与正文固定在牌面，不随插画深度漂移。
- 旧`M_CelCardParallax_ModelComic_v9`使用3列×2行图集，每格是同一竖版2:3虚拟画布，编号从左到右、从上到下。维护旧卡时逐格核对同坐标关系、真实格尺寸、边界留量及防串色；不要把独立纹理直接当成此类图集。
- 历史v9曾请求3072×3072和四边40%外扩，实际为1254×1254、每格418×627。原prompt在`ArtSource/UI/WarMachineTarotCards/ModelComic_v9/Production/Prompts/*_Layers.txt`，作为历史输入保留，不能作为新默认拆层模板。
- 本批现有插画窗口为卡UV x=0.045–0.955、y=0.043–0.772；修改前读实际材质。`BaseColor Map`、`Ability Layer Map`与各层引用按所用父材质核对，不能一律绑定同一旧图集。
- 核对sRGB、alpha、压缩与Clamp寻址。现有机械alpha的`smoothstep(0.12,0.72,A)`仅是素材适配，不能修复错误抠图。BC7、常驻/流送策略按纹理数量评估；独立大图层不等于已优化内存或性能。

## 交付记录

维护一份最终交付清单，记录参考图、六张主图及必要蒙版的路径/哈希、生成来源、实际尺寸/alpha、对象归属、静态对位、核心保护、共同映射、合成顺序、深度和运动范围。HTML、独看、PNG下载和素材包都引用这份清单选定的相同文件；更新时同步资源版本，核对实际加载与下载文件的哈希。

交付六张主图、必要蒙版、HTML/渲染脚本、完整 prompt、来源与参数、素材包；复用同一页面迭代。分别记录原位实测、技术检查、用户美术验收和任务状态。用户要求完成/收尾可以关闭任务，但不能据此把未验收或失败项改成通过。清理前核对清单、页面、素材包和重建脚本依赖，保留必要原始生成图、输入、提示词与参数；历史实测与当时验收条件原样保留。
