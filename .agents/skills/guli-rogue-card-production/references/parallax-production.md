# 全画布分层、逐层补绘与HTML视差

## 默认制作路线

以用户在 ComfyUI/Qwen 处理后选定的参考图为基准，按用户指定六个内容分组制作。初稿和用户Qwen阶段见[完整工作流](image-to-html-workflow.md)。新分层使用**独立全画布纹理**：保持源坐标、构图和共同留白，新增外沿时所有层使用同一外扩矩形与源图窗口。不要把各对象独立裁切、居中、缩放或旋转。

先提取原图像素/分割锚点，再用内置生图模型逐层补齐完整对象、被遮挡表面和新外沿，提供无视差原位叠合与原图对照供用户验收。所有层共用一套基础Scale/Offset，视差按深度产生相对运动。补绘发生自动放大、居中或局部比例改变时，修正编辑输入或补绘源图；不能把不同基础UV当成修复。

历史3×2图集用于维护已有资产，兼容条件见文末。不要默认让生成模型一次重画六格来替代同坐标拆层，也不要为了统一格式重做已交付的旧卡。

## 用户分组与对象完整性

六层的语义与编号由用户指定，绘制顺序单独记录。当前折射子弹六层为近景、速度线、机甲、场景、折射弹道和三个敌方机甲、远景，详见[本次示例](image-to-html-workflow.md#本次折射子弹示例)。下表仅供维护旧WM01卡时参考：

| 层 | 内容 | WM01例子 |
|---|---|---|
| 1 | 最近前景 | 近处残骸、最近自由导弹、前景速度线；无合适内容可为空 |
| 2 | 能力动作与分离物体 | 独立装配机械臂、飞行导弹及随动标记 |
| 3 | 完整机械与附着效果 | 机身、武器、可见腿盘与支架；炮口火光、刚出膛导弹、盘底附着光 |
| 4 | 环境中景 | 被击溃部队与爆炸、远处导弹、地面结构 |
| 5 | 环境远景 | 烟柱、工业剪影、远处部队 |
| 6 | 补全的最远底图 | 天空、地平线、安静地面；整层不透明 |

按实际连接与用户指定分组，不为填满六层重复放同一对象或把机械支架两端拆到不同深度。导弹及附着尾焰、同一机械臂及其工具/光效、绑定物体的符号通常随同一层运动。特殊层位记录为该卡决定，不推广到所有卡。

承担最远底图的层全不透明，其他层对象外真正alpha=0；上表旧WM01及本次示例均对应第1–5层透明、第6层不透明。移除前层对象后用生图补齐隐藏背景；机械内部误抠裂缝、串层残片、被速度线截断的表面也要修复。保留有意的爆炸破甲与分离零件，不能把透明棋盘画进图中。

## 补绘、对齐与HTML装配顺序

1. **冻结最终参考。** 记录用户选定的Qwen结果、实际尺寸、哈希、六层内容及允许补绘范围。初稿、Qwen参考和后续拆层/补绘prompt分别留档。
2. **同源提取锚点。** 每层以同一参考图约束结构和坐标。在当前工具授权内提取源像素与蒙版；输入切片不能混入其他层的装甲、白线、火焰或环境片段。
3. **逐层模型补全。** 每次只编辑一层，内置生图补齐截断表面、内部色岛、隐藏部件、移除主体留下的环境缺口及新外沿。生成完整、可遮挡的对象，不把原始抠图中的孔洞直接当成成品。
4. **装配源图坐标。** 读取实际输出尺寸、alpha和生成来源。必要时对生成补绘做特征或对象级对位，并保护原图核心；这些是生产操作，记录处理范围与变换，不改原图核心坐标。关联弹道和多个敌人要分别保持位置与连接，不能用单一局部匹配代表整组对齐。
5. **装配同一HTML。** 六张主图共用基础映射，加入原图/原位/视差切换、分组开关、透明度、回正和下载。前后遮挡不正确时调整合成与技术蒙版，不挪动正确的源坐标。前景需要完整隐藏表面及边缘处理，见下文。
6. **区分技术与画面验收。** 助手核对元数据、共同映射、页面资源、着色器初始化和控件状态；用户检查中心、四边、四角、最大倾斜、连接与风格。按项目规则不做助手截图/结果读图测试。用户要求UE接入时，再读取当前父材质与窗口并保存回读引用、共同Scale/Offset、深度与透明度；没有执行的检查保持未验证。

HTML模板与当前补绘脚本见[工作流实现](image-to-html-workflow.md#可复用实现与边界)；HTML不等于UE最终渲染。`Scripts/Cards/audit_wm01_registered_sources.py`包含尺寸、alpha、来源哈希及局部坐标分析，运行会写旧批清单，新卡须先适配路径。数值特征与生产对位不代表整图相同或用户视觉验收通过。

## 单层补绘提示词与输入

为每层单独写生产prompt，填入共同完整画布、原图所占矩形、该层对象和补绘范围，不改写初稿或用户参考的生成记录。图1为已对位切片编辑目标，图2为最终参考图、只提供设计和风格上下文；工具要求时只做必要的本地编辑输入检查。可用以下结构：

> 在图1完整画布上补绘指定层，原图占据给定矩形。保持原本可见部位的身份、数量、装配、透视、大小和原位置；补齐被其他层挡住的同一对象表面、误抠裂缝和指定新外沿，移除串层残片。不独立居中、不缩放对象、不自动裁掉透明留白。图2只用于理解原设计和风格，不把图2整张重画进本层。
>
> 列明本层全部对象、附着效果及必须排除的其他层内容。透明层物体外alpha=0，实物内部完整，烟尘/光晕保留适当软边；最远背景层则完整不透明。不得保留原图主体剪影洞口、矩形缺口、错误的断肢或错层速度线。已有战斗破损与故意分离的零件保留。不要六格拼图、标签、棋盘、卡框或UI；已审图内符号按该卡例外保留。
>
> 保持最终参考图的清晰轮廓、色块、阴影档位与光效。只补本层需要的隐藏/缺失内容，保留冻结的主要机械特征与构图，不加入写实纹理或改变整张画风。

提示词中明确工具实际支持的透明背景设置；尺寸要求只代表请求，读取真实文件后再装配共同画布。模型将透明边框当作可裁空间时，可用不透明中性底编辑输入约束整个画布，要求输出去掉中性底并取得真正alpha；不要用不透明彩底冒充透明图。生成与补绘继续使用内置imagegen，程序提取、核心回贴与装配遵守会话已有工具授权。

## 倾斜露边与背景补绘

处理顺序为：确认牌面窗口与共同UV → 确认实际深度和最大位移 → 用生图补齐隐藏表面及外沿 → 接入边缘采样与遮挡 → 交给用户检查。足够大的透明画布不代表物体已经延伸到外沿。Clamp、重复/镜像边缘像素、单独放大前景或只降低视差，都不能代替缺失内容的补绘。

已审中心画面需要保持时，可将外沿作为独立背景纹理：原画布UV [0,1]内继续使用原背景，补绘仅在外部参与采样；接缝过渡也不得改动受保护的中心。外扩量由最大视差、宽高比和倾斜决定，不固定套用历史40%。核对补图实际输出与材质映射，不能因请求了更大尺寸就声称已得到该尺寸。

对用户明确接受并要求保留的图层记录源文件哈希、许可范围及决定；修改这些表现前遵守该用户约束。已授权的外沿补绘可以继续，不重复请求同一许可，也不扩大成整图重绘。

## 前景完整表面、遮挡蒙版与窗口边缘

前景抠掉机甲后直接留下机甲形状的透明洞，平移时会露出错误背景；先让内置生图补成连续的烟尘、墙岩和地面表面。若前景同时出现在机甲前后，保留一张完整前景主图，另用二值技术蒙版分配前后显示，不必新增用户内容分组。

本次例子白色为前景前方、黑色为机甲后方：远景 → 场景 → 敌人与弹道 → 前景×(1-蒙版) → 机甲 → 前景×蒙版 → 速度线。同一前景图与蒙版采用相同坐标、深度运动、开关和透明度，二值分配避免同一软边重复叠加。其他卡按真实遮挡关系设计，不硬套此顺序。

同一物件只能归属一个内容层，其轮廓、材质、连接部件和附着火焰采用同一个刚性变换。不能把同一装甲、腿、岩石或火焰残片画进多个可独立移动的层，也不能让物件边缘和内部采用不同的位移系数；后者即使只有一张纹理，也会产生果冻式拉伸。出画面按固定牌面窗口整体裁切，露边通过足够外扩和完整补绘解决，不使用局部UV渐变固定物件边缘。

前后遮挡需要时，保留一个完整物件源图并共用同一刚性位移，通过局部遮挡合成处理，不拆成有独立位移／深度的物件片段。2026-10-29两张灼烧卡已取消边缘固定采样和旧环切割蒙版；WebGL以一次完整环／机甲合成处理遮挡。`ricochet_foreground_renderer.js`外侧2%固定、至12%过渡属于旧卡历史方案，不作为新卡默认；本次不批量修改其他已审卡。PNG源图切口必须位于可见窗口及最大位移留量之外，不能把被裁掉左右端的环缩进画面中部。

共同外扩量按最大屏幕位移、深度权重、原图/显示宽度与滤波余量选择：例如每侧源像素余量至少覆盖`最大位移px × |深度权重| × 原图宽度 / 显示宽度`，再留边缘余量。外扩矩形、源窗口、实际生成尺寸和共同映射要一起记录。用户检查物体外沿是否自然、隐藏表面是否连续，助手不从尺寸通过推断画面已无破绽。

## 旧WM01两张导弹卡的维护基线

`ArtSource/UI/WM01MissileCards/Production_v4`是当前分层来源；导弹仓原图为Review_v2，雨点原图为Review_v3。Production_v1–v3图集存在重新构图，保留作历史，不再作为重导入口。

- 1024×1536独立全画布纹理，仍使用六个深度槽；导弹仓第1层为空。
- 导弹仓三只机械臂、钢板、焊接及扫描光统一第2层；雨点蓝色半透明导弹、绿色不透明“+1”和自身尾焰统一第2层。“+1”是用户批准的图内符号例外。
- 用户接受当前扫描光浓度与加长尾焰，后续改动前先确认；本次仅授权补实验室/天空外沿。两份第2层保护哈希和决定保留于v4清单。
- 专属父材质`M_WM01RegisteredCardLayers_v1`；各层共同Scale=(0.92,0.745)、Offset=(0,-0.0875)。原UV范围内保留原第6层，外沿用`(UV+0.25)/1.5`映射，表示每侧25%外沿。
- 外沿请求1536×2304、实际1024×1536；记录真实尺寸。10处局部结构抽查中9处最佳平移量在0–1像素，工装台一处为(+4,-1)；这不是逐像素还原或用户终验。
- 重导入口为`Scripts/Cards/import_wm01_registered_layers.py`，旧`import_wm01_missile_card_art.py`已转发；不要重新使用v3图集脚本。

当前本批的内部`Layers global depth=4`，层深度`0.10 / 0.04 / 0 / -0.40 / -0.75 / -1.10`；整牌`MaximumTilt=16`表示每轴±16°。二者独立。`CardAreaMultiplier=2`表示宽高各乘√2，厚度倍率单独为2；新卡读实际参数再按画面适配，不把这组数值视为所有卡的默认保证。

## 材质与旧图集兼容

- 独立纹理绑定对应的`Layer N Map`；复用兼容父材质或另建本次父材质，避免改动共享父材质影响旧卡。卡框与正文固定在牌面，不随插画深度漂移。
- 旧`M_CelCardParallax_ModelComic_v9`使用3列×2行图集，每格是同一竖版2:3虚拟画布，编号从左到右、从上到下。维护旧卡时逐格核对同坐标关系、真实格尺寸、边界留量及防串色；不要把独立纹理直接当成此类图集。
- 历史v9曾请求3072×3072和四边40%外扩，实际为1254×1254、每格418×627。原prompt在`ArtSource/UI/WarMachineTarotCards/ModelComic_v9/Production/Prompts/*_Layers.txt`，作为历史输入保留，不能作为新默认拆层模板。
- 本批现有插画窗口为卡UV x=0.045–0.955、y=0.043–0.772；修改前读实际材质。`BaseColor Map`、`Ability Layer Map`与各层引用按所用父材质核对，不能一律绑定同一旧图集。
- 核对sRGB、alpha、压缩与Clamp寻址。现有机械alpha的`smoothstep(0.12,0.72,A)`仅是素材适配，不能修复错误抠图。BC7、常驻/流送策略按纹理数量评估；独立大图层不等于已优化内存或性能。
