# 初稿、Qwen参考图与六层HTML工作流

适用于新卡图、换卡图、分层重做及“只做牌面、不做逻辑”。按用户当前已完成的阶段接续，最终参考图已给出时直接制作六层。风格与六层内容服从用户本次要求。

## 三个阶段与职责

| 阶段 | 操作者 | 产物与下一步 |
|---|---|---|
| 1. 内置生图生成初稿 | 助手 | 用真实单位模型/用户参考约束身份、装配、镜头与能力表现，交付初稿、输入图和完整提示词 |
| 2. ComfyUI中用Qwen生成参考图 | 用户 | 用户导入初稿、调节参数与提示词并选图，将最终图片交给助手；助手不自动提交用户的Qwen任务 |
| 3. 指定六层的补绘与HTML展示 | 助手 | 冻结最终参考图，按用户指定的六个内容分组提取锚点、逐层补绘、对位、装配并交付可交互HTML |

第2阶段尚无选定图片时，请用户提供Qwen处理结果的本地路径或附件，独立的分组、提示词与交付准备可继续；不能把初稿冒充用户最终选择。用户已经指定某张现有图片作为最终参考时沿用该选择，不要求重跑前两阶段。协助本地Qwen环境或工作流时再读取 [local-image-gen](C:/Users/a/.codex/skills/local-image-gen/SKILL.md)。

## 第3阶段的制作步骤

1. **冻结参考与分组。** 保存用户选定的原始参考图、实际尺寸、哈希和允许修改范围；记录六个分组的名称、对象、附着效果与用户编号。绘制顺序另行设计，不把用户列举顺序当成固定遮挡顺序。
2. **提取原图锚点。** 在会话已有工具授权内，用原像素抠层、分割蒙版或已有分层保留位置、比例与主要可见结构。抠图只是编辑输入；带截断表面、透明裂缝、串层残片和主体剪影孔洞的切片不作为最终图层交付。
3. **逐层用内置生图补全。** 每次只编辑一层，明确编辑切片与最终参考图各自用途。补齐机械连接、隐藏装甲、被其他对象挡住的环境和外沿，清除不属于该层的速度线、装甲、火焰等残片；保留原本有意的破甲和飞散零件。细节见[全画布分层与补绘](parallax-production.md)。
4. **装配共同画布。** 记录生成原文件的真实尺寸；将生成补绘装配到统一的源坐标与外扩矩形，保留受保护的原图核心。自动居中或放大需要修正补绘源图/编辑输入，不能靠每层不同的基础UV隐藏。必要时以不透明中性底编辑输入固定整张画布，输出仍须取得真正透明通道。
5. **处理遮挡与外沿。** 前景需有完整表面和真实补绘余量。前景与机甲互相遮挡时，用同一张完整前景图加技术蒙版分配前后显示；窗口外沿可固定采样、内部逐渐恢复视差。蒙版、补绘图和采样必须使用同一坐标。具体方法与参数选择见分层参考。
6. **交付HTML并迭代。** 提供原图、原位叠合、交互视差、六组开关/透明度、回正、逐层PNG下载及完整素材包。用户反馈后更新同一任务的页面与地址，刷新资源版本；无需另建ComfyUI分层工作流。美术验收由用户完成。

承担最远底图的层应全不透明，其他层对象以外应真正透明。用户编号不必等于深度顺序；技术蒙版、前后显示通道不改变六个内容分组。

## 本次折射子弹示例

这是用户指定的六层示例，不作为其他新卡的固定语义：

| 用户编号 | 内容 | 对象完整性 |
|---|---|---|
| 1 | 近景 | 墙岩、植被、急刹扬土与烟尘；补齐隐藏表面和外沿 |
| 2 | 速度线 | 白色漫画速度线；修复截断与串层残留 |
| 3 | 机甲 | 玩家地面机甲、直接附着的双股尾焰与枪口火光 |
| 4 | 场景 | 草原、石阶与中近景建筑残骸；补齐移除主体留下的缺口 |
| 5 | 折射弹道和三个敌方机甲 | 关联弹道、三个敌人、受击爆炸与相关碎片作为一组 |
| 6 | 远景 | 完整、不透明的天空、远处地形、建筑、烟柱和导弹尾迹 |

本次显示顺序为：远景 → 场景 → 敌人与弹道 → 近景后方部分 → 玩家机甲 → 近景前方部分 → 速度线。前景两个部分引用同一主图，通过一张二值技术蒙版分配；六组开关和透明度保持同步。

本次统一交付画布1536×1536，原1024×1024位于`[256,256,1280,1280]`；HTML基础映射为宽高150%、左上偏移-25%。近景窗口外侧2%固定采样，2%至12%平滑恢复内部视差；默认4px、最大8px。这些是本卡参数，后续按源图比例、窗口、最大位移和实际补绘覆盖重新选取。记录原始生成尺寸与装配尺寸，本轮实际原始输出1254×1254并不代表工具总会输出此尺寸。

本轮HTML资源载入、着色器初始化和控件状态已有技术检查，画面仍待用户验收。随后六层已导入UE，并以ArtworkId=6接入[美术资源目录](artwork-data-pipeline.md)；技术导入不代表美术审核通过。制作方法可以复用，不把未经用户确认的补绘效果标为已审美术基线。

## 可复用实现与边界

本次来源目录：`ArtSource/UI/GroundMechRogueCards/GroundMech_ChainRicochet/CardProduction_20261026_v1`。

| 项目内实现 | 复用内容 |
|---|---|
| `Scripts/Cards/repair_ricochet_source_layers.py`、`refine_ricochet_source_masks.py` | 原像素与分割锚点；按当前授权、工具和单位结构适配 |
| `Scripts/Cards/prepare_ricochet_layer_completion.py` | 六层编辑输入、完整提示词与有外扩余量的共同画布 |

| `Scripts/Cards/ground_ricochet_preview_template.html`、`ricochet_foreground_renderer.js` | 六组控件、原图/叠合/视差模式、前景遮挡与边缘固定采样 |

这些是含本卡路径、对象框、深度顺序及坐标的制作范例。为新卡适配目标目录、用户分组和参数后再运行，不原样执行覆盖本卡产物；不把本机分割工具或算法写成所有卡的必要依赖。

HTML依赖本地服务时，复用本任务的有效网址与端口，绑定`127.0.0.1`，以能在工具调用结束后继续运行的后台进程承载；Windows隐藏辅助进程窗口。检查HTML和所需资源的HTTP状态。网页关闭或服务停止后只重启本任务服务，不抢占用户其他服务的端口。

## 交付与核验

- 交付六张主图、所需技术蒙版、HTML/渲染脚本、完整提示词、来源/参数清单和素材包。保存初稿与用户Qwen参考图的角色、路径、哈希；各次生成的输入顺序、完整文字、原始输出、实际尺寸和透明通道分别记录。
- 助手核对文件、alpha、坐标映射、资源载入、着色器初始化与控件状态；分割和补绘对位是生产操作，不代表结构、构图或自然程度已通过视觉验收。按项目规则由用户检查原位、边缘、遮挡、动作、弹道连续性与倾斜效果。
- HTML标题和短语是预览标识，正式游戏文案继续走现有公共文本/Excel管线。只做牌面/HTML时不新增卡表、技能、奖励或玩法逻辑；UE导入和F4接入在用户要求对应阶段时继续，准备脚本与已执行导入分别报告。
