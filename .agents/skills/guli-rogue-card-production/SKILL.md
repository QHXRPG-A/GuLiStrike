# GuLiStrike 肉鸽卡牌制作

美术制作以“内置生图初稿 → 用户 ComfyUI/Qwen 参考图 → 用户指定六层的完整对象生成与 HTML 展示”为主流程。数据、UE 材质、文本和权威效果按用户当前任务接入；只做牌面/HTML 时交付该阶段，改文案无需重新生图，整理技能无需修改UE资产。

## 当前卡牌美术主流程

1. **助手用内置生图模型生成初稿。** 按用户的单位模型、构图、能力表现与画风要求制作，保存输入图和实际完整提示词。
2. **用户用 ComfyUI 中的 Qwen 模型制作参考图。** 用户操作图生图与参数调节，选定结果后交给助手。助手收到这张参考图再进入分层；已有用户选定的最终参考图时直接进入第3步。需要协助本地环境时另读 `local-image-gen`，不自动运行用户的 Qwen 任务。
3. **助手按用户指定的六个层级制作 HTML 视差牌面。** 冻结参考图、对象归属、坐标与最大运动范围，逐层用内置生图模型生成所属对象完整的 RGBA 图，包括遮挡面和所需外沿；再对位装配六张共同画布的主图及必要的技术蒙版。交付原位叠合、原图对照和交互视差 HTML；按用户反馈迭代同一页面。
4. **用户要求正式资源时，按固定卡框接入UE。** 制图前就按正式卡框的图片区比例确定可见窗口；已有成品先核对最终清单、玩法绑定和实际开口，再登记Excel、定向部署并保存回读，最后准备对应评审地图。不得为了适配卡图擅自改卡框大小/比例，也不得以留白或拉伸代替正确构图。现有不匹配资源按用户明确选择处理，不把临时裁切作为新制作标准。

**游骑兵Ground卡牌比例硬指标：** 原卡框画布保持 **宽1280×高1556，宽:高=320:389≈0.822622:1**；图片区开口为 **1177.6×1081.42，宽:高≈1.0889386:1**。整卡比例与插画窗口比例必须分开：完整卡片/排版用前者，新的插画可见窗口用后者；含视差外扩的PNG尺寸另行记录。不得用2:3插画比例反向改框。精确开口坐标与执行检查见[卡框比例硬指标](references/artwork-data-pipeline.md#卡框比例硬指标)。此指标针对当前Ground卡框，不覆盖其他席位已有框型。

**窗口适配也保持此比例。** 游戏窗口变化只允许整体等比缩放及位置/间距调整，不分别拉伸卡框宽高；以牌面回正时的比例为准，鼠标倾斜的透视变化不改变基础比例。

完整方法、折射子弹六层示例与本次可复用脚本见[初稿、Qwen参考图与六层HTML工作流](references/image-to-html-workflow.md)。层级内容、编号和风格由用户及最终参考图确定；示例不替代新卡的分层设计。

进入UE资源制作时，使用[卡牌美术目录与统一导入](references/artwork-data-pipeline.md)：在Excel登记ArtworkId、模板、图层与参数，再由统一入口部署和回读；已有单卡制作脚本不作为日常参数来源。

## 制作原则

1. **一行玩法配置定义一张卡，同类效果复用一个实现类。** 通过ArtworkId关联美术目录，导出为既有FrontMaterial；新等级或同机制的新数值通常只加数据，新结算机制才扩展类。类型是否已接通，以当前源表和运行时路由为准，不能只凭枚举或目录推断。仅美术入库不伪造玩法行，也不因标题相近替换另一张卡。
2. **文字来自公共文本表。** `TextIds` 引用 `GuLiStrikeGameTexts.xlsx/Texts` 的“文本id”，固定index 0标题、1说明。保留FText/StringTable；卡图和框不烘焙文字，Note不直接显示。
   效果说明最多一行，优先“单位＋属性＋增量”或“单位＋解锁＋能力”，例如“重防号 普攻射速+20%”；保留作用对象和准确增益，不写叠加、获取次数或卡牌获取前置条件，也不将这些说明转移为悬浮提示。单位、增益属性及数值统一黄色 `#FFD84A` 加粗，连接词暖白；标题保持独立。富文本用 `Unit`/`Gain` 标签，数值保留参数化。说明居中、关闭自动与固定宽度折行，超宽时仅向下等比缩放；先精简措辞，不删关键属性或用省略号截断。
   **文字和高亮样式都走Excel管线。** 文案及标签在公共文本表，字体、字号、字重、颜色和描边在`GuLiStrikeRogueCardUI.xlsx/TextStyles`；UE样式表仅为生成物，禁止在脚本或资产中另行维护一套数值。日常改表后重新导出、定向接入，不重跑初始化脚本覆盖源表。
3. **真实模型约束结构，重点部位表达能力。** 整机截图用于身份与部件数量，局部截图用于镜头与装配。两张都来自同一已确认模型版本；允许合理遮挡，不允许漏腿、孤立悬浮盘、错炮口或穿甲发射。
4. **参考图确定风格，逐卡确定构图。** 初稿服从用户要求，分层服从用户选定的最终参考图；旧美漫prompt只用于对应旧卡或用户要求复用的画风。需要“文字不变”时直接读取该版本完整prompt并校验哈希，禁止悄悄追加修订句。
5. **先定稿与运动范围，逐层生成完整图，再合成。** 生图前确定共同画布、原图窗口、对象坐标、深度、最大位移与滤波余量。六张主图的内容及透明区域来自逐层生图；抠图片段仅在用户允许时作为参考输入，不能充当交付层或回贴来提高保真。后续仅补外沿时可保留用户已确认的完整生成图核心，记录其来源与保护范围。
   **对象归属互斥，完整表面可以重叠。** 同一物件及描边、残影和半透明边缘只归一层；不同层在同一坐标遮挡是正常合成，不能为避免重叠而挖掉隐藏表面。每层补齐所属对象、连续特效和运动可见外沿，排除其他层内容。用户指定纯色背景时，全幅使用同一不透明 RGBA 值。
   **共用坐标，物件整体移动。** 提示词坐标不代表实际输出已对齐；读取真实尺寸与 alpha，记录生成图的静态对位后装配共同画布，运行时共用基础映射。连接物件同步移动，出画面由牌面窗口整体裁切；不以边缘固定、局部 UV 渐变或拉伸掩盖缺失补绘。独看只显示所选主图；前后遮挡需要时使用同一主图和互补技术蒙版。
   **原位叠合相似度至少 80%。** 六层全开、滑杆均为 100%、零倾斜与零位移，用成品 PNG 实际合成并保留自身 alpha；对冻结原图按[原位保真要求](references/parallax-production.md#原位保真)计算 RGB SSIM，须 ≥ 0.80。保真、对象完整、归属、极限位移接合和预览/下载一致性分别记录，不能用一个指标代替其他验收。
6. **数据、表现、权威结算分工明确。** UI展示并请求服务器确认；成功结算才播成功闪光，退出后才播部队升级特效。重复确认和清理必须幂等。
7. **文案、样式、控件和赋值代码一起接通。** RichTextBlock迁移要同步原生`SetLiveCardText`与蓝图`SetContent`，保留FText/StringTable。导出、编译、保存回读和玩家实际显示分别记录；说明空白时先核对控件类型与当前加载模块，不能只凭编译成功收口。

## 执行与审核边界

- 助手负责的初稿和完整图层生成使用可用的内置 `imagegen` 并遵守其工具说明；ComfyUI/Qwen参考图阶段由用户操作。程序抠图/分割仅在当前授权允许时制作参考输入；用户禁止时不执行。用户要求完整生图时，不以脚本抠图、原图像素回贴或旧蒙版裁切生成图替代完整生成。操作xlsx时用项目 [excelize-cli](D:/UE5.7/test1/.agents/skills/excelize-cli/SKILL.md)。工具不可用时如实记录缺口，不伪造生成、导入或审核结果。
- 修改现有模型时使用 [guli-model-production](D:/UE5.7/test1/.agents/skills/guli-model-production/SKILL.md)；改Niagara时使用 [ue5-vfx-production](D:/UE5.7/test1/.agents/skills/ue5-vfx-production/SKILL.md)。不因制作卡图就自动重做模型。
- 用户要求“先看图再接入”时先完成可审核图稿，在该边界等待；已经明确授权的版本替换直接继续。模型通过不等于卡图通过，原图通过不等于拆层或UE画面通过。
- 遵守项目当前视觉核验边界：结果图、截图、合成对比与UE视口的视觉验收由用户完成；助手可检查尺寸、alpha、哈希、坐标映射、页面资源载入、着色器初始化与控件状态。若生图工具要求读取尚未见过的本地编辑输入，按工具规则做必要输入检查，避免将其扩大成结果审图。生产中的分割和补绘对位不代表画面验收。
- 本技能不是原生编译、启动游戏或压测的长期授权。按 [gulistrike-progress](D:/UE5.7/test1/.agents/skills/gulistrike-progress/SKILL.md) 核对当前任务已有授权；只沿用同一任务、同一范围的明确许可，不重复询问已授权步骤。修改表结构/原生类型须说明模块是否已编译并加载。

## 交付应能复用

按本轮实际范围交付，不强行补齐未请求的阶段：

- 数据：Excel改动、文本键、导出/导入结果、效果与材质引用。
- 美术：原始输出、按顺序列出的输入图路径与用途、实际完整prompt、版本与哈希、用户审核状态。
- 分层：六层对象归属、坐标/外扩约定、生成来源、真实尺寸/透明通道、静态对位与运行参数、原位 SSIM 和极限位移的验证状态。
- HTML：同一可访问预览地址、原图/原位/视差模式、六组开关与透明度、PNG下载、完整素材包、遮挡/窗口裁切方式及用户视觉验收状态。页面、独看、下载和素材包使用同一份最终清单的路径与哈希。准备了UE脚本与实际完成UE导入分别记录。
- UE：最终资源路径、对应地图与入口、保存后回读、玩家操作步骤；区分静态检查、运行验证、性能测量、助手看图与用户美术验收。

需求/开发/归档记录使用项目Progress流程。任务收尾、技术检查与用户美术验收分别记录；用户要求结束任务不等于全部验收通过。清理前核对最终清单、HTML和素材包依赖，保留必要生成源图、提示词与参数。不得把脚本执行成功或prompt要求写成图像已达到要求；尺寸、部件数量、边缘覆盖和视觉自然程度分别记录证据。
