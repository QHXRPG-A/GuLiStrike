# GuLiStrike 模型制作

把项目认可的“规则、简约、硬朗”风格落实到真实网格，保留资产的用途、主要轮廓和既有配色。用户指定的新风格、参考和范围优先于本技能默认方案。

## 参考与风格

优先查看用户指定的实际资产。给出 Blueprint 路径时读取组件及其网格、材质引用，不按口头简称猜模型。现有基准和源文件见 [references/project-examples.md](references/project-examples.md)。

项目工业硬表面的默认语言：

- 大块平整装甲、笔直结构线、明确折角、小而一致的倒角语言。
- 对称部件、同轴圆柱、统一规格和等距重复件。机械上的圆形仍保持规则圆周，不必全部方块化。
- 大面积纯色，少量矩形、条形、规则三角标记；保留青灰、砖红、赭黄等既有配色关系。
- 面板、支架、散热片、轴承和指示灯应有结构或功能依据，减少无意义划线、符号和碎片色块。

用户反馈“软、糊、线条不规则”时，先用统一灰材质定位原因：轮廓波浪和鼓包属于几何；平面异常高光可能是法线；表面糊纹、拉伸和错位属于 UV 或贴图。不要只改颜色来应付几何问题。

## 制作与迭代

1. 确认参考、交付位置、静态/骨骼类型和需要活动的机械组件。结合现有尺寸及工程约定决定比例；缺乏依据的尺寸标注为建模假设。
2. 将主结构拆成可解释的盒体、直线截面挤出、切角板、规则圆柱/环、梁和对称组件。使用确定性 Blender 构建方法整理失真的生成网格；生成结果可以辅助概念探索，但扭曲的主结构要重建。
3. 保留命名分件和可编辑修改器源文件，再为导出合并。从正面、侧面和三分之四视角检查轮廓、平面、接缝和装配关系。大改几何时用灰模新旧对比直接说明改动。
4. 几何稳定后制作材质和 UV。保持色块边界清楚，使用真实几何倒角产生边缘高光；不添加虚假的密集雕刻或随机凹凸。
5. 按交付范围导出、回读和检查。只要求制作模型时不扩展为 UE 玩法集成；明确要求导入时继续完成引擎内验证。

建模、图集烘焙、机械绑定和导出操作见 [references/blender-production.md](references/blender-production.md)。

## 机械骨骼

区分固定件、旋转件和俯仰件，轴心放在真实机械关节上。刚性零件的每个顶点只绑定一个骨骼，权重为 1，避免插值让金属弯曲。

本次重防炮实例为 `root → base_yaw → barrel_pitch`：基础固定、转台水平转动、上部炮轨随俯仰轴运动。这是实例接口，不应强加给所有模型；新资产的骨骼名、转轴、朝向和限位由需求决定。

检查活动范围两端及组合运动：基础是否静止、子件是否跟随、刚体是否变形、是否穿地或存在明显机械干涉。导入后同时检查实际播放的尺寸与关节位置，旋转曲线正确仍可能存在单位缩放错误。演示动画只证明运动；需要游戏内可调的瞄准逻辑时，另行完成实际要求的 Animation Blueprint、Control Rig 或控制接口，并在 UE 验证。

## UE 导入与交付

需要导入 UE 时读取 [references/unreal-import.md](references/unreal-import.md)，结合项目 `ue5-mcp-live-control` 技能操作当前编辑器。

按任务选择交付内容：项目 ArtSource 中的分件源、整理后 Blender 文件、实际导出文件和制作脚本；静态/骨骼 FBX 及需要时的 GLB、独立演示动画；材质贴图、成品预览和必要的灰模对比；引擎资产路径及检查结果。

验收重心是实际外观和用途：规整的轮廓、平面与色块，可信的机械运动，以及目标格式/引擎中的一致性。面数和贴图尺寸是预算，不能替代视觉检查。区分“文件已导出”“UE 资产已导入”“游戏控制逻辑已实现”，只记录与交付相关的检查，不扩展成无关测试或审批流程。
